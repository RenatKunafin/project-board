## Purpose

Реестр типов виджетов: платформа принимает определения типов от приложения при инициализации, обеспечивает уникальность идентификаторов, определённое поведение для неизвестных типов и контракт данных экземпляра (идентификатор, настройки, ограничения размеров окна).

## Requirements

### Requirement: Регистрация типа виджета при сборке

Платформа SHALL принимать типы виджетов только через список определений, переданный приложением при инициализации. Определение типа SHALL содержать непустой идентификатор, название, компонент содержимого, стартовые настройки и ограничения размеров окна, а также MAY содержать иконку и дескриптор документной поддержки (модуль, тип документа, версия схемы и фабрика содержимого нового документа). Фабрика содержимого SHALL создавать начальное содержимое без названия: название документа задаётся пользователем и передаётся сервису документов при создании. Повторная регистрация типа с уже существующим идентификатором SHALL отклоняться ошибкой регистрации с указанием конфликтующего идентификатора. Пропсы компонента виджета SHALL включать, помимо идентификатора экземпляра и настроек, опциональные ссылку на документ (`documentId`) и сервис документов (`documentService`), передаваемые платформой при создании экземпляра.

#### Scenario: Успешная регистрация типа

- **GIVEN** приложение инициализирует платформу списком из одного определения с идентификатором `demo`
- **WHEN** платформа создаёт реестр
- **THEN** реестр содержит тип `demo` с переданным названием, компонентом, стартовыми настройками и ограничениями размеров

#### Scenario: Дубликат идентификатора отклоняется

- **GIVEN** список определений содержит два типа с идентификатором `demo`
- **WHEN** платформа создаёт реестр
- **THEN** создание завершается ошибкой регистрации, сообщение содержит `demo`

#### Scenario: Экземпляр с документом получает ссылку и сервис

- **GIVEN** платформа создаёт экземпляр типа, работающего с документом, для документа `doc-1`
- **WHEN** компонент экземпляра рендерится
- **THEN** компонент получает `documentId = "doc-1"` и `documentService` через пропсы наряду с `widgetInstanceId` и настройками

#### Scenario: Каталог отображает иконку и название

- **GIVEN** зарегистрирован тип с иконкой и названием
- **WHEN** платформа открывает каталог типов
- **THEN** каталог отображает иконку и название зарегистрированного типа

#### Scenario: Создание документа через фабрику и сервис

- **GIVEN** зарегистрирован тип с документной поддержкой (модуль `checklist`, тип `list`, схема 1)
- **WHEN** пользователь создаёт документ с названием «Покупки»
- **THEN** начальное содержимое создаётся фабрикой без названия, а название «Покупки» хранится в метаданных документа

### Requirement: Обращение к неизвестному типу виджета

При запросе типа по идентификатору, отсутствующему в реестре, платформа SHALL предоставлять определённое состояние «неизвестный тип виджета» без прерывания работы приложения.

#### Scenario: Неизвестный идентификатор

- **GIVEN** реестр содержит только тип `demo`
- **WHEN** платформа запрашивает тип `checklist`
- **THEN** запрос возвращает состояние «неизвестный тип» и приложение продолжает работу

### Requirement: Контракт компонента виджета

Компонент зарегистрированного типа SHALL получать идентификатор экземпляра виджета и его настройки. Ограничения размеров определения SHALL задавать допустимые границы окна экземпляра.

#### Scenario: Компонент получает данные экземпляра

- **GIVEN** зарегистрирован тип `demo` со стартовыми настройками `{"title": "Панель"}`
- **WHEN** платформа создаёт экземпляр с идентификатором `w-1`
- **THEN** компонент получает `widgetInstanceId = "w-1"` и настройки с заголовком «Панель»

#### Scenario: Окно получает ограничения размеров

- **GIVEN** тип `demo` объявлен с ограничениями «минимум 2×2, максимум 6×4 ячейки»
- **WHEN** платформа создаёт окно экземпляра типа `demo`
- **THEN** окно получает эти границы как ограничения изменения размера

## Purpose

Реестр типов виджетов: платформа принимает определения типов от приложения при инициализации, обеспечивает уникальность идентификаторов, определённое поведение для неизвестных типов и контракт данных экземпляра (идентификатор, настройки, ограничения размеров окна).

## Requirements

### Requirement: Регистрация типа виджета при сборке

Платформа SHALL принимать типы виджетов только через список определений, переданный приложением при инициализации. Определение типа SHALL содержать непустой идентификатор, название, компонент содержимого, стартовые настройки и ограничения размеров окна, а также MAY содержать иконку, краткое описание назначения типа для каталога и дескриптор документной поддержки (модуль, тип документа, версия схемы, фабрика содержимого нового документа и опциональные миграции содержимого). Фабрика содержимого SHALL создавать начальное содержимое без названия: название документа задаётся пользователем и передаётся сервису документов при создании. Актуальная версия содержимого SHALL объявляться версией схемы дескриптора. Миграции содержимого SHALL задаваться упорядоченными шагами «от версии → к версии» с чистой функцией преобразования содержимого; шаги одного документа MUST NOT иметь разрывов между хранимой версией и актуальной при восстановлении. Повторная регистрация типа с уже существующим идентификатором SHALL отклоняться ошибкой регистрации с указанием конфликтующего идентификатора. Пропсы компонента виджета SHALL включать, помимо идентификатора экземпляра и настроек, опциональные ссылку на документ (`documentId`) и сервис документов (`documentService`), передаваемые платформой при создании экземпляра.

#### Scenario: Успешная регистрация типа

- **GIVEN** приложение инициализирует платформу списком из одного определения с идентификатором `demo`
- **WHEN** платформа создаёт реестр
- **THEN** реестр содержит тип `demo` с переданным названием, компонентом, стартовыми настройками и ограничениями размеров

#### Scenario: Дубликат идентификатора отклоняется

- **GIVEN** список определений содержит два типа с идентификатором `demo`
- **WHEN** платформа создаёт реестр
- **THEN** создание завершается ошибкой регистрации, сообщение содержит `demo`

#### Scenario: Экземпляр с документом получает ссылку и сервис

- **GIVEN** платформа создаёт экземпляр типа, работающего с документом, для документа `doc-1`
- **WHEN** компонент экземпляра рендерится
- **THEN** компонент получает `documentId = "doc-1"` и `documentService` через пропсы наряду с `widgetInstanceId` и настройками

#### Scenario: Каталог отображает иконку и название

- **GIVEN** зарегистрирован тип с иконкой и названием
- **WHEN** платформа открывает каталог типов
- **THEN** каталог отображает иконку и название зарегистрированного типа

#### Scenario: Каталог отображает карточку с описанием типа

- **GIVEN** зарегистрирован тип с описанием «Диаграмма Ганта: задачи, сроки, зависимости»
- **WHEN** пользователь открывает каталог виджетов
- **THEN** карточка типа показывает название и описание; поиск находит тип и по тексту описания

#### Scenario: Создание документа через фабрику и сервис

- **GIVEN** зарегистрирован тип с документной поддержкой (модуль `checklist`, тип `list`, схема 1)
- **WHEN** пользователь создаёт документ с названием «Покупки»
- **THEN** начальное содержимое создаётся фабрикой без названия, а название «Покупки» хранится в метаданных документа

#### Scenario: Дескриптор с миграциями принимается реестром

- **GIVEN** определение типа с дескриптором документной поддержки, содержащим миграции «0 → 1» и «1 → 2» и актуальной версией схемы 2
- **WHEN** платформа создаёт реестр
- **THEN** дескриптор доступен платформе с полным списком шагов и актуальной версией

### Requirement: Обращение к неизвестному типу виджета

При запросе типа по идентификатору, отсутствующему в реестре, платформа SHALL предоставлять определённое состояние «неизвестный тип виджета» без прерывания работы приложения.

#### Scenario: Неизвестный идентификатор

- **GIVEN** реестр содержит только тип `demo`
- **WHEN** платформа запрашивает тип `checklist`
- **THEN** запрос возвращает состояние «неизвестный тип» и приложение продолжает работу

### Requirement: Контракт компонента виджета

Компонент зарегистрированного типа SHALL получать идентификатор экземпляра, его настройки, а также видимость экземпляра (`visible`: активная вкладка И окно не свёрнуто) и опциональный колбэк `onResize` для подписки на размеры содержимого окна. Виджет SHALL приостанавливать тяжёлую отрисовку при `visible: false`, сохраняя подписки на документ. Ограничения размеров определения SHALL задавать допустимые границы окна экземпляра.

#### Scenario: Компонент получает данные экземпляра

- **GIVEN** зарегистрирован тип `demo` со стартовыми настройками `{"title": "Панель"}`
- **WHEN** платформа создаёт экземпляр с идентификатором `w-1`
- **THEN** компонент получает `widgetInstanceId = "w-1"` и настройки с заголовком «Панель»

#### Scenario: Окно получает ограничения размеров

- **GIVEN** тип `demo` объявлен с ограничениями «минимум 2×2, максимум 6×4 ячейки»
- **WHEN** платформа создаёт окно экземпляра типа `demo`
- **THEN** окно получает эти границы как ограничения изменения размера

#### Scenario: Развёрнутый экземпляр получает видимость

- **GIVEN** платформа создаёт экземпляр на активной вкладке, окно развёрнуто
- **WHEN** компонент экземпляра рендерится
- **THEN** компонент получает `visible: true`; после сворачивания окна платформа доставляет `visible: false`

### Requirement: Единые иконки встроенных типов виджетов

Платформа SHALL отображать встроенные типы виджетов контурными иконками по прототипу: план — календарь диапазона, ресурсы — группа людей, чек-лист — список задач. Одинаковый тип SHALL иметь одинаковую иконку в рамке окна и местах выбора виджета/представления, поддерживающих графические иконки. Декоративные иконки MUST NOT изменять доступные названия действий. Технические ключи иконок MUST NOT отображаться пользователю вместо названия.

#### Scenario: Иконка типа совпадает в каталоге и рамке

- **GIVEN** пользователь выбирает встроенный тип виджета в каталоге
- **WHEN** виджет добавлен на вкладку
- **THEN** рамка показывает ту же контурную иконку типа, что и каталог
- **AND** название типа и доступные названия действий сохранены

#### Scenario: Выбор типа в нативном списке

- **GIVEN** тип документа выбирается нативным списком, поддерживающим только текст
- **WHEN** пользователь открывает список
- **THEN** видит понятное название типа без технического ключа иконки

### Requirement: Название команды каталога виджетов

Кнопка открытия каталога виджетов в верхней панели SHALL показывать только текст «Виджеты», без иконки и знака «+». Её доступное имя SHALL быть «Виджеты».

#### Scenario: Открытие каталога из верхней панели

- **GIVEN** пользователь находится в рабочем пространстве
- **WHEN** нажимает кнопку «Виджеты» в верхней панели
- **THEN** открывается каталог виджетов

### Requirement: Панель каталога виджетов и выбор документа

Панель каталога виджетов и панель выбора документа SHALL размещаться у своей кнопки с учётом краёв экрана и доступной высоты: целиком в viewport, длинное содержимое прокручивается внутри панели. Панели SHALL закрываться по Escape и клику вне с возвратом фокуса на кнопку-якорь, при открытии фокус SHALL переходить первому полю панели. Панели являются интерактивными (поиск, поля, выбор) и MUST NOT получать семантику списка команд с перехватом стрелок. При открытом модальном редакторе виджета панели шапки MUST NOT принимать фокус и ввод.

#### Scenario: Панель у края экрана целиком в viewport

- **GIVEN** окно приложения сужено
- **WHEN** пользователь открывает каталог виджетов и затем выбор документа
- **THEN** обе панели целиком помещаются в viewport у своей кнопки

#### Scenario: Escape возвращает фокус на кнопку

- **GIVEN** открыта панель выбора документа, фокус в поле поиска
- **WHEN** пользователь нажимает Escape
- **THEN** панель закрывается без изменения документов, фокус возвращается на кнопку каталога виджетов

#### Scenario: Модальный редактор блокирует панели шапки

- **GIVEN** открыт модальный редактор виджета плана
- **WHEN** пользователь пытается взаимодействовать с кнопками шапки
- **THEN** панели шапки не открываются и не принимают фокус, ввод остаётся в редакторе

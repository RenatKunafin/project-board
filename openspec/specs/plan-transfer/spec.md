# plan-transfer Specification

## Purpose

Перенос одного плана в файл и обратно: версионированный собственный формат полного переноса (конверт с маркером формата, версией формата, названием плана и версией содержимого), сериализация, полная валидация при десериализации со структурированной диагностикой, отклонение будущих версий и политика независимого импорта (файл всегда создаёт новый план; идентификаторы сущностей не связывают планы). Семантика дат — ADR PBT-003: календарные даты ISO, окончание включительно. UI импорта и экспорта — `document-management`/представления; эта capability определяет формат и его проверки.

## Requirements

### Requirement: Экспорт полного плана в файл

Модуль планирования SHALL сериализовать план в текстовый JSON-файл собственного формата, включающий маркер формата, версию формата, название плана и полное содержимое: рабочий календарь, типы работ, ресурсы, вложенные группы, задачи, FS-зависимости и периоды недоступности. Производные значения (сводные сроки групп, длительности в рабочих днях, диагностики конфликтов) MUST NOT включаться в файл. Файл MUST быть пригоден для чтения в текстовом редакторе.

#### Scenario: Полный план переносится целиком

- **GIVEN** план со всеми разделами: календарём с праздником, двумя типами работ, ресурсами, вложенными группами, задачами с назначениями, FS-зависимостью с лагом и периодом недоступности
- **WHEN** план сериализуется в файл
- **THEN** файл содержит название плана и все перечисленные данные без потерь

#### Scenario: Производные значения не попадают в файл

- **GIVEN** план с группой, имеющей сводный интервал, и задачей с рабочей длительностью
- **WHEN** план сериализуется в файл
- **THEN** файл не содержит вычисленных сводных сроков, рабочих длительностей и диагностик конфликтов

### Requirement: Импорт файла с валидацией

Модуль SHALL десериализовать файл собственного формата с полной проверкой до выдачи плана: корректность JSON, наличие и типы полей конверта, совпадение маркера формата, поддержка версии формата и версии содержимого, валидность содержимого плана. Повреждённый или чужой файл MUST NOT выдаваться за план: результат SHALL содержать перечень диагностических сообщений с кодом, местом и причиной; входные данные MUST NOT изменяться. Проверка содержимого SHALL повторять полную валидацию плана при чтении, включая структуру, форматы дат, уникальность идентификаторов, внутренние ссылки и циклы групп.

#### Scenario: Повреждённый JSON даёт диагностику

- **GIVEN** текст файла обрезан и не является корректным JSON
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику синтаксической ошибки JSON
- **AND** план не создаётся

#### Scenario: Чужой формат распознаётся

- **GIVEN** файл с маркером формата, не совпадающим с маркером приложения
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику неизвестного формата
- **AND** содержимое файла не интерпретируется как план

#### Scenario: Невалидное содержимое даёт полный перечень проблем

- **GIVEN** файл формата приложения, содержимое которого ссылается на несуществующую группу и содержит цикл вложенности групп
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику обеих проблем с указанием места
- **AND** план не создаётся

#### Scenario: Валидный файл выдаёт план с названием

- **GIVEN** файл формата приложения с корректным содержимым и названием плана
- **WHEN** выполняется десериализация
- **THEN** результат содержит план, эквивалентный содержимому файла, и название для создаваемого документа

### Requirement: Отклонение будущей версии формата

Файл с версией формата или версией содержимого больше поддерживаемой SHALL отклоняться с диагностикой о несовместимости: файл создан более новой версией приложения. Данные файла MUST NOT интерпретироваться как план частично и MUST NOT уничтожаться.

#### Scenario: Файл будущей версии не импортируется

- **GIVEN** файл с версией формата больше поддерживаемой
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику несовместимой версии
- **AND** план не создаётся, файл остаётся доступным без изменений

### Requirement: Импорт создаёт независимый план

Десериализованный файл SHALL использоваться только для создания нового независимого документа плана: замена содержимого существующего плана файлом в этой версии формата не поддерживается. Идентификаторы сущностей внутри плана SHALL сохраняться из файла, а ссылки между сущностями SHALL оставаться внутренними для содержимого плана. Совпадение идентификаторов или названий сущностей разных планов MUST NOT создавать связи между планами.

#### Scenario: Два импорта одного файла дают независимые планы

- **GIVEN** один файл формата приложения, импортированный дважды
- **WHEN** содержимое одного из полученных планов изменяется
- **THEN** содержимое второго плана остаётся без изменений
- **AND** совпадающие внутренние идентификаторы сущностей не связывают планы

### Requirement: Round-trip без потерь

Последовательные сериализация и десериализация плана SHALL восстанавливать название и все разделы содержимого без изменений, включая поддержанные дополнительные поля внутри сущностей содержимого. Повторный экспорт десериализованного плана SHALL давать эквивалентный файл.

#### Scenario: Round-trip контрольного плана

- **GIVEN** план со всеми разделами модели
- **WHEN** план сериализуется в файл и десериализуется обратно
- **THEN** название и все разделы содержимого эквивалентны исходным

#### Scenario: Дополнительное поле сохраняется при переносе

- **GIVEN** файл, в содержимом которого у задачи присутствует неизвестное приложению поле
- **WHEN** файл десериализуется и результат сериализуется снова
- **THEN** дополнительное поле задачи сохраняется в полученном файле

## Purpose

FS-зависимости между задачами плана: связь «окончание → начало» с неотрицательным рабочим лагом, структурная защита графа (самоссылки и циклы отклоняются при создании) и диагностика временных нарушений — на ребро, с идентификаторами и объяснением, без изменения расписания (правила C1–C5 ADR PBT-003, раздел 9 решений).

## Requirements

### Requirement: Создание и изменение FS-зависимости

Модуль планирования SHALL предоставлять команды создания, изменения лага и удаления FS-зависимости между двумя задачами. Лаг SHALL быть целым числом рабочих дней не меньше нуля; отрицательный или дробный ввод SHALL отклоняться. Повторное создание существующего ребра с тем же лагом MUST NOT дублировать связь; создание ребра с другим лагом при существующей паре задач SHALL отклоняться с подсказкой изменить лаг. Изменение SHALL затрагивать только лаг. Операция над несуществующей задачей или зависимостью SHALL отклоняться целиком.

#### Scenario: Зависимость с нулевым лагом создаётся

- **GIVEN** план с задачами A и B
- **WHEN** создаётся зависимость A → B с лагом 0
- **THEN** ребро добавлено в план с уникальным идентификатором

#### Scenario: Отрицательный лаг отклоняется

- **WHEN** создаётся зависимость с лагом −3
- **THEN** результат — отклонение лага, план без изменений

#### Scenario: Повтор с тем же лагом не дублирует ребро

- **GIVEN** зависимость A → B с лагом 1
- **WHEN** та же зависимость создаётся с тем же лагом
- **THEN** план содержит одно ребро и не изменяется

#### Scenario: Тот же ребро с другим лагом отклоняется

- **GIVEN** зависимость A → B с лагом 1
- **WHEN** создаётся зависимость A → B с лагом 3
- **THEN** результат — отклонение дубликата с подсказкой изменить лаг

#### Scenario: Смена лага существующего ребра

- **GIVEN** зависимость с лагом 0
- **WHEN** лаг изменяется на 2
- **THEN** ребро хранит лаг 2, концы связи не изменяются

### Requirement: Структурная защита графа зависимостей

Зависимости SHALL связывать только задачи. Создание зависимости с самоссылкой или создающей цикл (включая косвенный путь через другие зависимости) SHALL отклоняться целиком с диагностикой; документ MUST NOT изменяться. Несколько предшественников у одной задачи и несколько последователей у одной задачи SHALL быть допустимы.

#### Scenario: Самоссылка отклоняется

- **WHEN** создаётся зависимость A → A
- **THEN** результат — отклонение цикла, план без изменений

#### Scenario: Косвенный цикл отклоняется

- **GIVEN** зависимости A → B и B → C
- **WHEN** создаётся зависимость C → A
- **THEN** результат — отклонение цикла, план остаётся без изменений

#### Scenario: Ветвление допустимо

- **GIVEN** задача A и последователи B и C
- **WHEN** создаются зависимости A → B и A → C
- **THEN** оба ребра добавлены

- **GIVEN** предшественники A1 и A2
- **WHEN** обе зависимости ведут в задачу B
- **THEN** задача B имеет двух предшественников

### Requirement: Диагностика временных нарушений FS

Модуль SHALL вычислять для каждого ребра FS ожидаемое начало последователя как рабочий лаг, отсчитанный по календарю плана от включительного окончания предшественника: лаг 0 — ближайший рабочий день, каждый единичный лаг пропускает ещё один рабочий день; праздники внутри задержки учитываются. Начало последователя раньше ожидаемого SHALL выдаваться как нарушение ребра с идентификаторами и объяснением; нарушение MUST NOT изменять даты задач. Позднее начало нарушением не является. Результат вычисления SHALL зависеть от календаря плана.

#### Scenario: Нулевой лаг переносит на следующий рабочий день

- **GIVEN** предшественник пн 12.10 – пт 16.10.2026 и последователь с началом пн 19.10.2026, календарь пн–пт
- **WHEN** вычисляются нарушения ребра с лагом 0
- **THEN** нарушений нет

#### Scenario: Каждый единичный лаг пропускает рабочий день

- **GIVEN** предшественник пн 12.10 – пт 16.10.2026, календарь пн–пт
- **WHEN** последователь начинается во вторник 20.10.2026 при лаге 1
- **THEN** нарушений нет
- **WHEN** последователь начинается в понедельник 19.10.2026 при лаге 1
- **THEN** нарушение ожидает начала во вторник 20.10.2026

#### Scenario: Праздник внутри задержки

- **GIVEN** предшественник пн 12.10 – пт 16.10.2026, лаг 1 и праздник во вторник 20.10.2026
- **WHEN** последователь начинается в среду 21.10.2026
- **THEN** нарушений нет

#### Scenario: Нарушение выдаёт идентификаторы без исправления дат

- **GIVEN** предшественник с окончанием пт 16.10.2026 и последователь с началом пт 16.10.2026 при лаге 0
- **WHEN** вычисляются нарушения
- **THEN** результат содержит идентификаторы ребра и обеих задач, ожидаемое и фактическое начало и объяснение
- **AND** даты обеих задач остаются без изменений

#### Scenario: Календарь меняет результат при тех же датах

- **GIVEN** две версии плана с одинаковыми задачами: последователь начинается в понедельник 19.10.2026 после предшественника, закончившегося в пятницу 16.10.2026, лаг 0
- **WHEN** в первой версии понедельник 19.10.2026 рабочий, во второй — праздник
- **THEN** первая версия не имеет нарушений, вторая выдаёт нарушение с ожиданием вторника 20.10.2026
- **AND** даты задач в обеих версиях совпадают и не изменяются

### Requirement: Редактор предшественников задачи

Форма создания и редактирования задачи SHALL позволять просматривать список FS-предшественников, добавлять предшественника с рабочим лагом, изменять лаг и удалять связь в общем черновике задачи. Эти действия MUST NOT записывать документ до общего сохранения; отмена формы SHALL отбрасывать изменения связей вместе с остальными полями без изменения документа и редакции. При сохранении команды ядра SHALL проверять самоссылки, циклы, повторные связи и целые неотрицательные лаги с объяснением причины отказа; ошибка MUST NOT приводить к частичной записи. Точное повторение связи с тем же лагом MUST NOT создавать дубликат, изменение лага существующей связи SHALL сохранять её идентификатор. Редактирование связей MUST NOT изменять даты задач.

#### Scenario: Два предшественника с независимыми лагами

- **GIVEN** в плане есть задачи A, B и C
- **WHEN** пользователь добавляет задаче C предшественников A (лаг 0) и B (лаг 2)
- **THEN** черновик содержит две связи, сохранённый документ ещё не изменён
- **WHEN** пользователь сохраняет форму
- **THEN** документ содержит две FS-связи в C с указанными лагами, даты всех задач не меняются

#### Scenario: Попытка замкнуть цикл отклоняется

- **GIVEN** существует цепочка A → B → C (FS)
- **WHEN** пользователь добавляет задаче A предшественника C и сохраняет
- **THEN** операция отклоняется с объяснением о цикле, документ и редакция остаются без изменений, ввод формы сохранён

#### Scenario: Создание задачи вместе с зависимостями

- **GIVEN** в плане существуют задачи A и B
- **WHEN** пользователь создаёт C, выбирает A и B как предшественников с лагами 0 и 2 и сохраняет
- **THEN** задача C и обе связи появляются одной операцией документа
- **AND** ошибка связи не оставляет в документе отдельно созданную C

#### Scenario: Отмена правки связей

- **GIVEN** у задачи C есть входящая связь от A
- **WHEN** пользователь удаляет её в черновике, добавляет связь от B, меняет название C и подтверждает отмену формы
- **THEN** исходная связь, название и редакция документа остаются прежними

#### Scenario: Обновление лага без дубликата

- **GIVEN** в документе есть связь A → C с лагом 0
- **WHEN** пользователь меняет лаг на 2 и сохраняет
- **THEN** единственная связь A → C сохраняет идентификатор и получает лаг 2
- **AND** исходящие связи C и даты задач остаются прежними

### Requirement: Сохранение списка предшественников

Список предшественников и лаги SHALL восстанавливаться после перезагрузки страницы и SHALL быть доступны другим экземплярам представления того же плана.

#### Scenario: Перезагрузка сохраняет связи и лаги

- **WHEN** пользователь добавляет и изменяет связи, затем перезагружает страницу
- **THEN** список предшественников и лаги соответствуют сохранённым значениям

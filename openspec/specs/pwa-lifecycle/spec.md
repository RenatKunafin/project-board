# pwa-lifecycle Specification

## Purpose
Установка Project Board как приложения на рабочем столе, первоначальная подготовка необходимых ресурсов и автономный запуск с локальными документами. Возможность работать без сети подтверждается отдельно от состояния сохранения документов.

## Requirements

### Requirement: Установка приложения на рабочий стол

Приложение SHALL поддерживать установку средствами Chrome и Edge на десктопе с именем Project Board и собственной иконкой. Установленное приложение SHALL открываться в отдельном окне. В остальных целевых браузерах приложение SHALL сохранять обычный браузерный способ работы; установка доступна по возможностям браузера и ОС.

#### Scenario: Запуск установленного приложения

- **GIVEN** приложение открыто по HTTPS или localhost в поддерживающем установку десктопном браузере
- **WHEN** пользователь устанавливает приложение средствами браузера и запускает его
- **THEN** открывается отдельное окно Project Board с правильным именем и иконкой
- **AND** доступны документы того же адреса и профиля браузера

### Requirement: Подготовка к офлайн-работе

Приложение SHALL подготавливать необходимые ресурсы после первоначального онлайн-запуска и показывать готовность к работе офлайн только после успешной подготовки. Состояние подготовки SHALL отличаться от состояния сохранения документов. Неудачная подготовка MUST NOT показываться как успешная и MUST NOT блокировать доступную работу приложения онлайн.

#### Scenario: Первоначальная подготовка

- **GIVEN** приложение впервые открыто с доступной сетью
- **WHEN** необходимые ресурсы успешно подготовлены для автономного запуска
- **THEN** пользователь видит «Готово к работе офлайн»
- **AND** состояние сохранения документов отображается независимо

#### Scenario: Ошибка подготовки

- **GIVEN** подготовка офлайн-работы началась, но обязательный ресурс недоступен
- **WHEN** подготовка завершается ошибкой
- **THEN** приложение сообщает, что офлайн-режим недоступен, без ложного подтверждения готовности
- **AND** доступное онлайн-редактирование продолжает работать

#### Scenario: Повторный запуск подготовленного приложения

- **GIVEN** ресурсы приложения успешно подготовлены и сохранены браузером
- **WHEN** пользователь повторно открывает приложение
- **THEN** состояние готовности определяется по доступному механизму автономного запуска без обязательного повторного скачивания ресурсов

### Requirement: Запуск после закрытия без сети

Подготовленное приложение SHALL запускаться без сети после закрытия всех его окон в том же браузерном профиле и по тому же адресу, если локальные данные приложения сохранены. Оно SHALL восстанавливать сохранённые документы и рабочее пространство по существующим правилам платформы.

#### Scenario: Холодный офлайн-запуск

- **GIVEN** подготовка завершена, чек-лист и рабочее пространство сохранены, все окна приложения закрыты
- **WHEN** пользователь запускает приложение без сети
- **THEN** открываются сохранённые вкладки, окна и чек-лист с ранее сохранённым содержимым

### Requirement: Работа с чек-листами без сети

Приложение SHALL позволять без сети читать и редактировать существующие чек-листы, создавать новые документы списков и сохранять изменения локально. Подтверждённо сохранённые изменения SHALL восстанавливаться после повторного открытия без сети.

#### Scenario: Изменение существующего списка

- **GIVEN** подготовленное приложение открыто без сети с существующим списком
- **WHEN** пользователь добавляет пункт и отмечает его выполненным, дожидается сохранения и повторно открывает приложение
- **THEN** пункт и отметка выполнения восстановлены

#### Scenario: Создание списка офлайн

- **GIVEN** приложение работает без сети
- **WHEN** пользователь создаёт новый чек-лист через каталог, добавляет пункт, дожидается сохранения и перезапускает приложение
- **THEN** новый документ доступен в каталоге, его окно и содержимое восстановлены

### Requirement: Полнота автономных ресурсов

Автономный запуск SHALL обеспечивать загрузку оболочки и подключённых представлений вместе с необходимыми скриптами, стилями, шрифтами и иконками без внешней сети. Пользовательская инструкция SHALL различать первоначальную онлайн-загрузку и готовность к автономной работе.

#### Scenario: Ресурсы доступны без сети

- **GIVEN** подготовка приложения завершена и сеть отключена
- **WHEN** пользователь открывает приложение и подключённые представления
- **THEN** оболочка, чек-лист и представления плана загружаются с локальными стилями, шрифтами и иконками

#### Scenario: Инструкция подготовки

- **GIVEN** пользователь ещё не подготовил приложение к офлайн-работе
- **WHEN** он читает инструкцию установки
- **THEN** инструкция объясняет необходимость первого онлайн-запуска, ожидания готовности и сохранения данных браузера

### Requirement: Обнаружение и откладывание обновления

Приложение SHALL сообщать пользователю о полностью подготовленной новой версии и предоставлять действие обновления. Обнаружение обновления MUST NOT автоматически перезагружать текущую сессию. Пользователь SHALL иметь возможность отложить обновление и вернуться к нему позже.

#### Scenario: Подготовлена новая версия

- **GIVEN** пользователь работает в текущей версии приложения
- **WHEN** новая версия полностью подготовлена к применению
- **THEN** приложение показывает «Доступна новая версия» и действие «Обновить»
- **AND** документы, открытые формы и рабочее пространство продолжают работать без перезагрузки

#### Scenario: Пользователь откладывает обновление

- **GIVEN** приложение предлагает доступную новую версию
- **WHEN** пользователь выбирает «Позже»
- **THEN** текущая сессия продолжает работать
- **AND** пользователь может снова вызвать действие обновления

### Requirement: Подтверждение и сохранение перед обновлением

Приложение SHALL запрашивать подтверждение перезапуска и напоминать о сохранении правок открытых форм. После подтверждения оно SHALL блокировать новые пользовательские изменения на время подготовки и применять обновление только после подтверждения записи документов, рабочего пространства и настроек представлений. Отмена подтверждения MUST NOT применять обновление.

#### Scenario: Правка непосредственно перед обновлением

- **GIVEN** новая версия доступна, пользователь только что изменил документ и расположение окна
- **WHEN** пользователь подтверждает обновление
- **THEN** приложение дожидается подтверждённой записи актуального документа, расположения и настроек представлений
- **AND** только затем применяет новую версию и перезапускает текущую страницу

#### Scenario: Отмена подтверждения

- **GIVEN** пользователь открыл подтверждение обновления
- **WHEN** он выбирает «Отмена»
- **THEN** приложение не перезагружается и позволяет продолжить работу

### Requirement: Ошибка сохранения откладывает обновление

При ошибке, конфликте или превышении времени ожидания сохранения приложение MUST NOT применять обновление или перезагружать страницу. Оно SHALL сообщать причину, сохранять доступ к текущей сессии и позволять повторить попытку после устранения проблемы.

#### Scenario: Хранилище отклоняет запись

- **GIVEN** пользователь подтвердил обновление с ещё не записанной правкой
- **WHEN** сохранение завершается ошибкой
- **THEN** приложение остаётся в текущей версии с доступным состоянием сессии и сообщением об ошибке
- **AND** новая версия не применяется

#### Scenario: Повтор после устранения ошибки

- **GIVEN** обновление было отложено из-за сбоя записи, хранилище снова доступно
- **WHEN** пользователь повторяет обновление
- **THEN** приложение сохраняет актуальные данные и применяет новую версию после подтверждения записи

### Requirement: Применение обновления при одном открытом окне

Для применения обновления пользователь SHALL оставить одно окно или вкладку Project Board на текущем адресе. Если открыты другие окна приложения, система SHALL попросить их закрыть и повторить попытку; она MUST NOT принудительно закрывать или перезагружать эти окна.

#### Scenario: Открыта другая вкладка приложения

- **GIVEN** Project Board открыт в двух вкладках или в обычной вкладке и установленном окне
- **WHEN** пользователь пытается применить обновление
- **THEN** приложение просит закрыть другие окна Project Board
- **AND** обе сессии остаются открытыми без принудительного применения обновления

#### Scenario: Пользователь оставил одно окно

- **GIVEN** обновление ранее было отложено из-за других окон, пользователь их закрыл
- **WHEN** он повторяет обновление в оставшемся окне
- **THEN** после подтверждения записи приложение применяет подготовленную версию

### Requirement: Восстановление данных и автономная работа после обновления

Обновлённое приложение SHALL восстанавливать сохранённые документы, вкладки, окна, раскладки и настройки представлений. Зарегистрированные миграции SHALL выполняться по существующим правилам восстановления. После успешного применения новой версии подготовленное приложение SHALL повторно запускаться без сети с ресурсами этой версии.

#### Scenario: Данные и миграции после перезапуска

- **GIVEN** перед обновлением сохранены документы, рабочее пространство и настройки, для старого документа зарегистрирована миграция
- **WHEN** приложение запускается обновлённой версией
- **THEN** документы и рабочее пространство восстановлены, документ приведён к поддерживаемой версии существующим механизмом миграций

#### Scenario: Обновлённая версия запускается без сети

- **GIVEN** новая версия успешно применена и все окна приложения закрыты
- **WHEN** пользователь повторно запускает приложение без сети
- **THEN** открывается обновлённая версия с сохранёнными данными
- **AND** её скрипты, стили, шрифты и иконки доступны без подмешивания несовместимых ресурсов прежней сборки

### Requirement: Постоянный опубликованный адрес приложения

Приложение SHALL быть доступно по документированному постоянному HTTPS-адресу. На этом адресе SHALL работать установка, повторное открытие и автономный запуск после подготовки ресурсов. Публикация SHALL сохранять локальный характер хранения пользовательских документов.

#### Scenario: Установка опубликованной версии

- **GIVEN** пользователь впервые открывает постоянный HTTPS-адрес в поддерживаемом браузере с сетью
- **WHEN** приложение подготовило офлайн-ресурсы, пользователь сохранил документ и установил приложение
- **THEN** установленное приложение открывается с того же адреса и показывает сохранённый документ
- **AND** после закрытия оно повторно запускается без сети

#### Scenario: Размещение в подпути

- **WHEN** приложение открывается по постоянному адресу с подпутём
- **THEN** интерфейс, шрифты, иконки, манифест и офлайн-ресурсы доступны из соответствующей области приложения
- **AND** установленное приложение повторно открывает этот адрес

### Requirement: Согласованность ресурсов при публикации

Публикация новой версии SHALL позволять продолжающей работать подготовленной версии сохранять доступ к необходимым ресурсам во время проверенного перехода. Новая опубликованная версия SHALL обнаруживаться штатным механизмом обновления без очистки пользовательских данных или ручной очистки кэша. После явного применения обновления SHALL восстанавливаться сохранённые документы и рабочее пространство.

#### Scenario: Выпуск следующей версии

- **GIVEN** предыдущая опубликованная версия подготовлена для офлайн-работы и содержит сохранённые документы
- **WHEN** на том же постоянном адресе публикуется следующая версия
- **THEN** текущая сессия продолжает работать, а подготовленное обновление предлагается пользователю
- **AND** после подтверждения обновления сохранённые документы и рабочее пространство восстанавливаются
- **AND** обновлённое приложение повторно запускается без сети

### Requirement: Выпуск по опубликованному релизу

Публичная версия SHALL выпускаться из тега опубликованного GitHub Release, коммит которого входит в историю main, после успешных проверок этого коммита. Обычный push или merge в main, создание тега без опубликованного Release и draft-релиз SHALL сохранять текущую опубликованную версию.

#### Scenario: Публикация проверенного релиза

- **GIVEN** тег релиза указывает на коммит, входящий в main
- **WHEN** GitHub Release опубликован и проверки его коммита завершились успешно
- **THEN** на постоянном адресе публикуется сборка этого коммита
- **AND** тег, коммит и адрес доступны в журнале публикации

#### Scenario: Изменения до выпуска релиза

- **WHEN** изменения смёржены в main либо создан тег или draft-релиз без опубликованного Release
- **THEN** публичная версия приложения не изменяется

#### Scenario: Релиз вне основной ветки

- **WHEN** опубликован Release на теге, чей коммит не входит в main
- **THEN** публикация приложения отклоняется и текущая публичная версия сохраняется

#### Scenario: Неуспешные проверки

- **WHEN** проверки коммита опубликованного релиза завершаются ошибкой
- **THEN** этот коммит не публикуется и текущая публичная версия сохраняется

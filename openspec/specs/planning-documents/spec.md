## Purpose

Документ плана модуля Гантта: формат v1 (календарь, типы работ, ресурсы, вложенные группы, задачи, FS-зависимости, недоступности), фабрика пустого плана, валидация содержимого при чтении с диагностикой, независимость планов и регистрация модуля через общий контракт (ADR PBT-003, ADR PBT-017).

## Requirements

### Requirement: Формат документа плана

Модуль планирования SHALL хранить план как документ с версионируемым содержимым, включающим: рабочий календарь (рабочие дни недели, праздники, рабочие исключения), типы работ с признаком параллельности, ресурсы, вложенные группы, задачи, FS-зависимости с неотрицательным лагом и периоды недоступности ресурсов. Даты SHALL храниться как календарные даты без времени суток в формате ISO `YYYY-MM-DD`; окончание задачи SHALL быть включительным. Модель плана MUST NOT зависеть от типов UI-библиотек представлений.

#### Scenario: Пустой план содержит все разделы

- **GIVEN** приложение зарегистрировало модуль планирования
- **WHEN** создаётся пустой план
- **THEN** содержимое содержит календарь с рабочими днями пн–пт и пустые коллекции типов работ, ресурсов, групп, задач, зависимостей и недоступностей

#### Scenario: Окончание включительно в данных

- **GIVEN** план с задачей «пн 12.10.2026 – пт 16.10.2026»
- **WHEN** документ читается и проверяется
- **THEN** окончание хранится как `2026-10-16` и интервал покрывает 16 октября

#### Scenario: Отрицательный лаг отклоняется

- **GIVEN** прочитанный документ содержит зависимость с лагом −3
- **WHEN** выполняется валидация содержимого
- **THEN** результат содержит диагностическую ошибку лага, документ не становится рабочим

### Requirement: Фабрика пустого плана

Модуль SHALL предоставлять фабрику пустого плана: календарь по умолчанию с рабочими днями пн–пт без праздников и исключений и пустыми коллекциями остальных разделов. Идентификаторы генерируемых сущностей SHALL быть уникальными. Название плана задаётся при создании через каталог и хранится в содержимом.

#### Scenario: Создание плана через каталог

- **GIVEN** модуль планирования зарегистрирован в приложении
- **WHEN** пользователь создаёт новый план «ОКАД» через каталог
- **THEN** создаётся документ модуля `gantt` типа `plan` со схемой версии 1 и фабричным содержимым с названием «ОКАД»

#### Scenario: Сохранение и открытие по идентификатору

- **GIVEN** пустой план создан и сохранён локально, приложение перезапущено
- **WHEN** документ открывается по его идентификатору
- **THEN** содержимое и редакция соответствуют сохранённым, план доступен второму экземпляру виджета

### Requirement: Валидация содержимого при чтении

При чтении содержимого модуль SHALL проверять структуру и правила данных: форматы дат, диапазон дней недели, целочисленность и неотрицательность лага, уникальность идентификаторов внутри коллекций, существование ссылок между разделами, отсутствие циклов вложенности групп, корректность интервала задачи (окончание не раньше начала) и наличие хотя бы одного рабочего дня календаря. Повреждённое содержимое MUST NOT подменяться рабочим значением: результат валидации SHALL содержать перечень диагностических сообщений с указанием места и причины.

#### Scenario: Повреждённый документ даёт диагностику

- **GIVEN** сохранённое содержимое плана повреждено (ссылка задачи на несуществующую группу и дата в неверном формате)
- **WHEN** содержимое проверяется при чтении
- **THEN** результат не является рабочим планом, перечень диагностики называет обе проблемы, документ остаётся неизменённым

#### Scenario: Корректный документ проходит проверку

- **GIVEN** содержимое плана, созданное фабрикой и заполненное валидными задачами и зависимостями
- **WHEN** содержимое проверяется
- **THEN** результат — рабочий план без диагностических сообщений

### Requirement: Независимость планов

Документы разных планов SHALL быть независимыми: ресурсы, календари и прочие разделы одного плана MUST NOT разделяться с другим планом даже при совпадении названий. Изменение одного плана MUST NOT отражаться в другом.

#### Scenario: Одинаковые названия ресурсов в двух планах

- **GIVEN** два плана, в каждом ресурс с названием `QA`
- **WHEN** в первом плане переименовывается или дополняется ресурс
- **THEN** содержимое второго плана, включая его ресурс `QA`, остаётся без изменений

### Requirement: Регистрация модуля плана

Модуль планирования SHALL регистрироваться через общий контракт модулей: тип виджета «План» с документной поддержкой (владелец `gantt`, тип документа `plan`, версия схемы 1, фабрика содержимого). Каталог приложения SHALL предлагать тип «План», а созданные планы SHALL открываться в зарегистрированном виджете. Модуль MUST NOT проверять внутренние таблицы платформы и модифицировать платформенный код.

#### Scenario: Тип «План» доступен в каталоге

- **GIVEN** приложение инициализировано с модулем планирования
- **WHEN** пользователь открывает каталог типов
- **THEN** каталог отображает тип «План» с иконкой и названием

#### Scenario: Экземпляр плана получает документ

- **GIVEN** существует сохранённый план
- **WHEN** создаётся второй экземпляр типа «План» с этим документом
- **THEN** оба экземпляра ссылаются на один документ и отражают его текущее содержимое

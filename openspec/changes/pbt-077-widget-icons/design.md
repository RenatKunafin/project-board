# PBT-077 — Иконки виджетов

## Context

Проверен исходный прототип `/Users/brom/Documents/workspace/flexi-dashboard-hub/src/components/dashboard/Dashboard.tsx`: gantt → CalendarRange, resources → Users, todo → ListTodo, h-4/w-4. В проекте icon?: string в SDK прямо документирован как временный emoji; строка рендерится в нескольких независимых местах. Нативный select каталога документов содержит текстовые option.

## Decisions

1. Предложение для ревью: сохранить строковый контракт icon, использовать общие ключи `lucide:calendar-range`, `lucide:users`, `lucide:list-todo`. Модули выбирают ключ, платформа рисует его общим WidgetIcon. Платформа не выбирает иконку по предметному ID виджета и не импортирует модули (ADR PBT-002 ADR-3).
2. Только статические импорты нужных Lucide-иконок, размер 16×16, currentColor и токены текущего контекста: muted в рамке, primary в плитках каталога. Размер SVG не зависит от шрифта emoji.
3. Общий рендерер применяется в WidgetWindow, WidgetCatalogPanel, DocumentPickerPanel, DocumentCatalogPanel и меню «открыть с помощью» App. Пустая/неизвестная именованная иконка получает нейтральную Puzzle/FileText по контексту. Существующие произвольные текстовые значки сохраняют поддержку, чтобы не ломать строковый SDK.
4. В нативном option оставить только название: SVG внутри option переносимо не отображается; идентификатор `lucide:*` пользователю не показывать. Доступное имя кнопок остаётся названием, SVG aria-hidden.
5. Никаких миграций: определения типов собираются из кода, документы/настройки иконку не хранят. Нет расширения типа SDK, но его комментарий должен объяснять ключ и совместимый текстовый вариант.

## Validation

Lint/typecheck/unit/build, существующие браузерные проверки каталогов и окон, проверка SVG встроенных типов и отсутствия технических ключей в UI. Скриншоты до/после на 1024×778 и широком экране, консоль MCP. Полный test:browser — после остановки dev/MCP и свежего production build. Не добавлять unit-тесты, повторяющие таблицу соответствий.

## Результаты реализации

- Общий `WidgetIcon` со статическими Lucide-импортами и таблицей ReadonlyMap: неизвестные ключи не обращаются к свойствам прототипа объекта, старые текстовые символы поддерживаются. Встроенные типы выбирают графические ключи, строковый контракт SDK сохранён.
- Рамки, каталог виджетов, пикер, каталог документов (фильтры и плитки) и меню выбора представления используют общий рендерер. В option только названия. SVG 16×16, aria-hidden/focusable=false; muted в рамках и primary в плитках, цвета проверены через computed styles.
- Новый интеграционный browser-сценарий проходит путь каталог → план → ресурсное представление того же документа → каталог документов → выбор представления; проверяет согласованность SVG, доступных имён и отсутствие технических ключей в UI.
- Первый полный browser-прогон: 127 успешных, 2 отказа — старые проверки `getByText('📅')` и `getByText('☑️')`; обновлены под соответствующие Lucide SVG в существующих сценариях. Это ожидаемое изменение визуального контракта.
- MCP: изолированный временный контекст, пользовательские документы основного профиля не менялись. Снимки до/после 1440×900 и 1024×778, отдельный снимок каталога документов. Ошибок консоли/pageerror нет. Предсуществующие предупреждения SVAR `Writable _progressLinePoints is not defined` присутствовали до и после правок (также отмечены в design PBT-028); к иконкам не относятся.
- Для production browser-прогона dev-сервер остановлен, все MCP-страницы закрыты, старого preview на 4173 нет.

Итоговые проверки: `npm run lint`, `npm run typecheck`, `npm test` — 480/480 (36 файлов), `npm run build` — успешно (precache 85 файлов, 2054.33 KiB), `npm run test:browser` — 129/129 на финальной сборке (26.9s). `openspec validate pbt-077-widget-icons --strict` и `openspec validate --all --strict` — успешно, локально 20/20 (включая незакоммиченный change PBT-078, который в PR не входит).

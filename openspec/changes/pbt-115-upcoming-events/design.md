## Context

PBT-110–114 уже дают общий документ календаря, валидированный формат событий/типов/ручных дней, повторяющиеся вхождения и общую форму редактирования. Платформа передаёт документный `WidgetProps` и штатно выбирает документ через каталог; `switchDocument` и `updateSettings` уже существуют, но виджетам не передаётся список всех документов. Эталон интерфейса — `UpcomingPrototype`.

## Goals / Non-Goals

**Goals:**

- добавить второй тип виджета, читающий тот же документ календаря;
- точно определить границы ближайшей выборки, фильтрацию сегодняшних событий и стабильную сортировку;
- хранить фильтр отдельно для каждого окна и сохранять его через существующие настройки экземпляра;
- открыть существующий редактор события/серии с теми же revision/conflict правилами;
- повторить плотность, группировку, пустое состояние и доступные подписи прототипа.

**Non-Goals:**

- новый SDK callback для перечисления документов;
- отдельный предметный документ или копирование событий;
- новые правила повторения, цели, аналитику или связь с Ганттом.

## Decisions

### 1. Выбор календаря остаётся платформенным

Тип «Ближайшие события» получает ту же `documentSupport`, что и «Календарь». Пользователь выбирает или создаёт документ в существующей панели каталога; экземпляр получает `documentId`. Внутри виджета не добавляется второй список документов: текущий SDK не предоставляет безопасного перечисления документов предметному модулю, а дублирование каталога нарушило бы границу платформы.

**Альтернатива:** добавить `listDocuments` в публичный SDK и встроенный селект как в прототипе. Отклонено для PBT-115: это отдельное изменение контракта платформы, не требуемое карточкой; визуальный и сквозной аудит двух виджетов остаётся в PBT-116.

### 2. Чистая выборка ближайших вхождений

Новый helper получает `CalendarContent`, локальное `now` и лимит диапазона. Он вызывает существующее вычисление вхождений для диапазона от сегодняшней локальной даты до даты `today + 365` по календарным дням, фильтрует timed-вхождения сегодняшнего дня по локальному `HH:mm`, оставляет all-day события и сортирует по `date`, времени (пустое время после timed), названию и стабильному ключу. Лимит 100 применяется после фильтра типа, как в прототипе.

**Альтернатива:** материализовывать будущие копии событий в документ. Отклонено: повторение уже хранится одной записью, список должен быть производным.

### 3. Фильтр — настройка экземпляра

Настройка `typeFilter` имеет значение `all` либо ID типа. При изменении вызывается только `updateSettings`; документ и его revision не меняются. При обновлении документа недействительный ID нормализуется в `all`, сохраняя список доступным.

### 4. Общая форма и снапшот сохранения

Список передаёт выбранную `CalendarOccurrence` в общий `CalendarEventDialog` с тем же `CalendarDocumentSnapshot` и save-адаптером, что и календарь. Для повторяющейся серии форма продолжает явно сообщать об операции над всей серией. Успешная запись приходит по общей подписке документа в оба виджета; конфликт оставляет черновик формы.

### 5. Время и обновление текущего дня

Текущие дата и местное время вычисляются без UTC-сдвига. Видимый виджет пересчитывает их после `visibilitychange`/`focus` и локальной полуночи; скрытый экземпляр не держит постоянный таймер. Для тестов helper принимает явный `now`.

### 6. Композиция и стили

`UpcomingWidget` имеет верхнюю область выбора фильтра, прокручиваемый список групп дат и нижнюю строку «Ближайшие 12 месяцев · N событий». Строка события использует существующие календарные точки, шрифты и токены; цвет не является единственным способом различить тип — название типа и доступное имя обязательны. При отсутствии документа и при пустом результате используются разные сообщения.

## Risks / Trade-offs

- [Risk] При лимите после фильтра пользователь может увидеть меньше 100 событий, хотя в документе есть больше → [Mitigation] считать и ограничивать уже отфильтрованный производный список, явно показывать фактическое `N`.
- [Risk] Граница «сегодня + 365» может быть истолкована как 365 или 366 календарных дат → [Mitigation] закрепить в helper-тесте эталонную границу `addDays(today, 365)`, совпадающую с прототипом.
- [Risk] Удаление выбранного календаря во время отображения → [Mitigation] существующее состояние недоступного документа, без создания пустого или замены содержимого.
- [Risk] Редактор серии из списка может потерять источник occurrence → [Mitigation] передавать исходную запись события и стабильный occurrence key, а не копию данных в настройках.

## Migration Plan

Регистрация нового типа не меняет существующие документы и настройки. Старые рабочие пространства получают тип после обновления приложения; новый экземпляр создаётся только явным действием через каталог. Откат удаляет регистрацию и компонент, не затрагивая документы календаря.

## Open Questions

Нет: выбор документа остаётся платформенным, фильтр — состоянием экземпляра, а границы списка и поведение времени закреплены выше.

# Design — PBT-071 Разворачивание окна на весь дашборд

Референс: `flexi-dashboard-hub/src/components/dashboard/Dashboard.tsx` (`expandedWindow`, `previousScroll`, `toggleMaximize`), `WidgetFrame.tsx`; скриншот `screenshots/redesign-ref/02-widget-maximized.png`.

## D1. Механизм: DOM-перенос узла окна в overlay-слой

В обоих режимах лейауты рендерят окно как `item.node` внутри собственной обёртки (`.tiled-grid__cell` у RGL, `Rnd` у каскада). Переносить React-узел между ветками дерева нельзя без размонтирования, а вторая копия окна — двойной монтаж виджета (две подписки, раздельное состояние). Решение — **императивный перенос DOM-узла эффектом**:

- `TabSurface` рендерит внутри `.tab-surface` (после лейаута) контейнер `<div className="widget-maximize-layer" hidden={!hasMaximized}>`; `.tab-surface` получает `position: relative` (css).
- `WidgetWindow` принимает `maximized?: boolean`; эффект при `maximized` запоминает исходного родителя (`parentNode`) и переносит корневой div в `.widget-maximize-layer` своей вкладки (`closest('.tab-surface')`); при сбросе — возвращает на исходное место.
- React продолжает рендерить компонент в том же DOM-узле (fiber держит ссылку на элемент) — состояние виджета и подписки живы; StrictMode-двойной эффект идемпотентен (cleanup возвращает узел).
- Обёртки лейаутов не трогаем: ячейка RGL остаётся пустой (RGL не измеряет детей), пустая `Rnd`-обёртка остаётся под слоем; drag/resize развёрнутого окна недоступны автоматически (ручки принадлежат обёрткам) — как в прототипе.
- Закрытие развёрнутого окна: React удаляет узел из фактического родителя (overlay) — возврат не требуется.

## D2. Состояние — память вкладки (развилка карточки)

`App`: `useState<Record<tabId, instanceId | null>>` — не персистится (после перезапуска обычный вид; максимизация — сиюминутное состояние). Сброс: повторная кнопка, сворачивание развёрнутого окна (D5), закрытие окна, исчезновение вкладки. Переключение вкладки состояние не трогает (у каждой вкладки своё). Прокидывание: `maximizedInstanceId` в `TabSurface` (+ `tabSurfaceAreEqual` учитывает поле); `TabSurface` размечает maximized-окно и `hiddenByMaximize` соседей в `paneToItem`.

Альтернатива — settings экземпляра (персист) отклонена: переживающий перезапуск «разворот» конфликтировал бы с восстановленной раскладкой и ломал бы ожидание «перезапуск → рабочее пространство как было» (PBT-024).

## D3. Сокрытие соседей и SDK visible

- Соседи: `hiddenByMaximize` → класс `widget-window--maximize-hidden { display: none; }` — keep-mounted (PBT-027), как `hidden` в прототипе.
- `WidgetPane.visible` = `visible && !collapsed && !hiddenByMaximize` — контракт ADR-6.5: пауза тяжёлой отрисовки скрытых, подписки живы.
- Развёрнутое окно активно (фокус при развороте — `activatePane`, как `focusWidget` прототипа).

## D4. Оверлей и скролл

- `.widget-maximize-layer { position: absolute; inset: 0; z-index: 40; }` — непрозрачным делает само окно (фон `--surface`); рамка/радиус окна сохраняются (как в прототипе: inset:0 внутри канваса, скругления по углам области).
- Скролл: при развороте вкладка получает класс `tab-surface--maximized` (`overflow: hidden`), позиция прокрутки канваса запоминается и сбрасывается в 0; при возврате класс снимается, позиция восстанавливается (паттерн `previousScroll` прототипа; целевой элемент прокрутки — контейнер области сетки — уточняется на живой проверке, каскад не прокручивается).

## D5. Поведение кнопок

- Кнопка Maximize2/Minimize2 между сворачиванием и закрытием; aria: `Развернуть на весь дашборд {title}` / `Вернуть прежний размер {title}` (паттерн существующих подписей с названием экземпляра).
- `onToggleMaximize`: разворот = фокус + установка; повтор = сброс.
- Сворачивание развёрнутого окна (`onToggleCollapse` при maximized) — сначала сброс максимизации, затем сворачивание (прототип: collapse сбрасывает maximize).

## D6. Тесты

- e2e (новая спека `widget-maximize.spec.ts`): (1) разворот — окно занимает вкладку, сосед скрыт, содержимое живо; (2) возврат — прежняя раскладка (позиция в сетке не изменилась), сосед вернулся, скролл восстановлен; (3) сворачивание развёрнутого — обычный вид + свёрнуто; (4) перезапуск — обычный вид; (5) каскад — геометрия сохранена. Существующие спеки не меняются (кнопка новая, aria существующих прежние).
- Unit: при необходимости — рендер WidgetWindow с `maximized` (кнопка/aria); логика переноса покрывается e2e.

## D7. Риски

- **DOM-перенос против React:** узел возвращается до возможного удаления/перемещения только при переходе maximized→normal; анмаунт в overlay валиден (React удаляет от фактического родителя). Паттерн устойчив при неизменной структуре обёрток; e2e и живая проверка (drag/resize после возврата в обоих режимах) обязательны.
- **RGL с «пустой» ячейкой:** RGL позиционирует по layout-данным, дети не измеряются — пустая ячейка не меняет раскладку.
- **Прокрутка:** поведение различается между режимами (сетка растёт вниз, каскад фиксирован) — закрыто классом `tab-surface--maximized` и живой проверкой.
- **memo TabSurface:**新增 поле в `tabSurfaceAreEqual` — забытость приведёт к стагнации UI; проверяется e2e.

## D8. Гантт при развороте (живая проверка владельца, 2026-10-20)

Симптом: при развороте Гантта «шкала откручивается влево». Корни: (1) SVAR после пересборки по resize отрисовывает шкалу виртуализированно (видимая область + буфер) **от начала диапазона** — при запасе −60 дней слева развёрнутое окно занимает пустая зона до плана, полосы за краем, `scroll-chart` клампится (контента для прокрутки нет); (2) разворот свёрнутого окна оставлял контент скрытым (исправлено по прототипу: `hidden={collapsed && !maximized}`, +сценарий спеки).

Решение: подписка `onResize` (SDK PBT-027) в PlanGanttWidget — при скачке ширины >40% (разворот/возврат всегда даёт такой скачок, обычные ресайзы окон — нет): короткое размонтирование чарта на кадр (`chartHidden`) и старт шкалы от якоря плана (−2 дня) — SVAR строит колонки от `start`, план у левого края в обоих размерах. **Отклонённая альтернатива:** суффикс эпохи в `chartRemountKey` — стабильно ломал применение жестов drag/resize (план-гантт e2e краснели; корень — взаимодействие смены формата ключа с подавлением remount своей записи D7 PBT-039); размонтирование на кадр честно пересоздаёт чарт, не трогая механику ключей.

Проверки: e2e «разворот Гантта: задачи видимы» (создание→задачи→разворот→сворачивание→повторный разворот→возврат→раскрытие); полный набор — жестовые план-гант зелёные.

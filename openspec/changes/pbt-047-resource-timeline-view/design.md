# Design — PBT-047 Resource timeline view

## Context

Ядро даёт всё для дорожек: `plan.assigneeIds` (PBT-034), `plan.unavailability` (PBT-034), `resourceConflicts(plan)` — union `parallel-work` / `unavailability` с рабочими интервалами (PBT-036), календарь `nonWorkingDayKind` (PBT-037). RCT 0.30.0-beta.19 проверен спайком PBT-015: `stackItems` укладывает пересечения, дни подсвечиваются классами/`verticalLineClassNamesForTime`, React 18 peer. Спайковый код не переносится — адаптер с нуля (ADR-6 PBT-017).

## Goals / Non-Goals

- Goals: дорожка на ресурс, укладка пересечений, отпуск у своего ресурса, нерабочие дни по календарю плана, видимое различие конфликта и допустимого пересечения, оба вида на одном документе.
- Non-Goals: см. proposal (жесты, лента занятости, фильтры).

## Decisions

### D1. Второй widgetType «Ресурсы»

`createGanttModule()` возвращает два типа: `plan` (без изменений) и новый `plan-resources` (title «Ресурсы», icon 👥) с тем же `documentSupport` (moduleId gantt, documentType plan, schemaVersion 1, тот же createContent). Каталог покажет два вида одного документа; выбор в пикере — «дополнительное представление» (ADR-6.6 PBT-002). `sizeConstraints` как у плана (minWidth 4 / minHeight 3 — шкала требует ширины, наблюдение PBT-037).

### D2. Адаптер `resource-timeline-adapter.ts` (план → RCT)

`planToTimelineGroups(plan)`: ресурсы в порядке массива документа → `{ id: resourceId, title }`. Групп без дорожек нет (пустая дорожка = свободный ресурс — видима).

`planToTimelineItems(plan)`: 
- назначения: для каждой задачи × каждый `assigneeId` → `{ id: '<taskId>:<resourceId>', title: task.title, group: resourceId, start: полночь(task.start), end: полночь(task.end + 1 день), canMove: false, canResize: false }` (D1: дорожка каждого ресурса; A1: включительное окончание → исключительная граница RCT; D2: без `assigneeIds` задача не отображается).
- недоступности → `{ id: 'u-<unavailabilityId>', title: 'Недоступен', group: resourceId, start/end — так же, canMove/canResize: false, className: 'rtl-item--unavailability' }`.
- даты — локальные полночи в мс (день-точность; UTC-полночь даёт смещённые полосы в локальных часовых поясах — спайк PBT-015).
- конфликтность: параметр `conflictTaskIds`/`conflictUnavailabilityIds` (ReadonlySet) → `className: 'rtl-item--conflict'` на соответствующих элементах. Множества строит виджет из `resourceConflicts(plan)` (не сам адаптер — адаптер остаётся чистым маппером).
- Задача с несколькими назначениями даёт независимые элементы; переименование/перенос задачи обновляет все её элементы одним пересчётом (производное, без записей).

### D3. Подсветка календаря плана — собственный слой дней

Календарь настраиваемый (PBT-044: любые workingDays, праздники, рабочие исключения), поэтому жёсткие классы недели RCT (`rct-day-0/6`) не годятся. **Уточнение владельца 2026-10-15:** подсветка должна быть как в проектном Гантте — сплошные колонки дней при любой единице шкалы. Первая реализация через `verticalLineClassNamesForTime` зависела от единицы шкалы беты (`getMinUnit` от видимой ширины: в узких окнах RCT укрупняет колонки до недели/месяца, и подсветка отдельных дней пропадала — компромисс Risks). Заменена **собственным слоем дней**: React-портал в канву RCT (контейнер `.rct-vertical-lines`), колонки нерабочих дней в canvas-координатах элементов — `left = (день − canvasTimeStart) × px/день`, `px/день = scrollWidth / canvasSpan`; canvas-диапазон даёт `onBoundsChange` (при первом монтировании не вызывается — инициализация default-диапазоном), ширина — `scrollWidth` хоста. Слой `z-index: 25` — под линиями (30), строками (40) и элементами (80), `pointer-events: none`. Каждый день от `canvasTimeStart` до `canvasTimeEnd` проверяется `nonWorkingDayKind` (рабочее исключение без подсветки); колонки несут `data-day` (e2e-локаторы). Дефолтная краска субботы/воскресенья RCT перекрыта нейтральным сбросом (спайк: усиленный селектор).

### D4. Конфликты vs допустимые пересечения

Виджет вычисляет `resourceConflicts(plan)` и передаёт адаптеру множества: `parallel-work` → `firstTaskId`+`secondTaskId`; `unavailability` → `taskId` + `unavailabilityId`. Конфликтные элементы получают опасную рамку/заливку (`rtl-item--conflict`); допустимые пересечения (Разработка+ПСИ, ПСИ+ПСИ — `isParallelAllowed` ядра) остаются обычными. Пересчёт — производный при рендере, записей не создаёт (прецедент PBT-046 D3).

### D5. Read-only v1

`canMove: false`, `canResize: false` на всех элементах (данные, не props-надежда), жестовые обработчики (`onItemDrag` и пр.) не передаются. Клик-выделение RCT остаётся (не меняет документ). Полная изоляция API беты — в адаптере/виджете нет ни одного импорта жестов (`interactjs` — peer RCT, напрямую не используется). Жесты — PBT-048 по схеме ADR-5 PBT-017 (выделение → жест → «факт → правила ядра → применение»).

### D6. Стиль — только токены

Дефолтный itemRenderer беты мерджит стили так: `Object.assign(дефолты, selected-стили, …, itemProps.style)` — **поле `item.style` бета игнорирует** (находка отладки 2026-10-15). Стили полос задаются в `itemProps.style` через переменные `:root` (токены в `index.css` приложения, прецедент PBT-037): задача — accent, конфликт — опасная палитра списка проблем (PBT-046), недоступность — полупрозрачный danger. Бордер обычной задачи — тёмный оттенок accent (`--color-rt-task-border`): у стыкующихся вплотную задач полосы без контрастной границы сливаются в одну (правка владельца 2026-10-15). Хексы запрещены вне файла токенов; `className` остаётся для e2e-локаторов. `resource-timeline.css` перекрывает дефолты RCT (красный header, кремовые выходные, границы `#bbb`) усиленными селекторами (прецедент спайка PBT-015); дефолтная краска субботы/воскресенья снимается — подсветка нерабочих дней только по календарю плана (D3).

### D7. Диапазон шкалы и обновление данных

`defaultTimeStart/End` (мс) с запасом −5/+25 дней от min/max задач и недоступностей. Поправлено дважды в отладке 2026-10-15: исходные −60/+365 и затем −7/+38 давали полосы в 3–6 px и/или поднимали единицу шкалы RCT выше дня — `getMinUnit` беты выбирает единицу от видимой ширины контента (день требует ≥ 17 px/день): 40-дневный диапазон держит дневные колонки при контенте от ~680 px (типовые окна сетки на 1920). Пустой план — соседние месяцы. Зум RCT доступен (minZoom 7 дней / maxZoom 2 года). RCT скроллит внутри диапазона сам (свой скролл, ограничение SVAR-шкалы не переносится). Обновление документа — remount по `document.revision` (key, прецедент PBT-037): прокрутка сбрасывается, для v1 допустимо; в PBT-048 (жесты проектного вида будут remount'ить ресурсный вид на каждую запись) пересматривается на контролируемый `visibleTimeStart/End` — отмечено в Risks.

## Risks / Trade-offs

- **Предсуществующие красные e2e SVAR-вида (вне границ PBT-047, находка 2026-10-15):** `plan-gantt.spec.ts` (3 теста: подсветка праздника, drag, resize) и `dependencies.spec.ts` (инлайн-лаг) падают на прод-сборке при живой dev-сессии с тем же сценарием. Воспроизводится чистым прогоном на коммите PBT-046 (383b9ae, отдельный worktree, собственная сборка и сервер) — не регресс PBT-047; собственные e2e ресурсного вида зелёные. Факты отладки: стор SVAR корректен (`start/end` −60/+365 залиты, `scroll-chart` применён — `xArea 57–63`), но DOM отрисовывает частичную зону без скролла (`scrollW = clientW = 640`, подсветка только 2 колонок) — рассинхронизация «сторм/отрисовка» прод-сборки обёртки SVAR (D6 PBT-037). Дата (14/15.10, clock.setFixedTime) и изменения lock-файла исключены. Требует отдельного анализа до финального PR серии (заявлено владельцу).
- Бета RCT: API нестабилен (спайк: `onItemDrag` вместо `onItemMove/onItemResize`); v1 read-only сужает контактную поверхность до props рендера — самая стабильная часть. При поломке беты — план Б ADR-2 (собственный рендер, отдельная PBT).
- Единица шкалы RCT адаптивна (`getMinUnit` от видимой ширины): в узких окнах колонки укрупняются до недели/месяца. **Компромисс снят уточнением владельца 2026-10-15** — подсветка дней переведена на собственный слой (D3), независимый от единицы; текст заголовка шкалы при укрупнении остаётся поведением RCT.
- Remount по ревизии (D7): записи жестов PBT-039/048 вызывают пересборку ресурсного вида ~раз в 1,5 с во время жеста в соседнем виджете. Бюджет монтирования ADR-7 (10 виджетов ≤ 1000 мс) соблюдён с запасом (PBT-016: 145 мс); при наблюдаемых дефектах — контролируемый диапазон до PBT-048.
- Подписи на коротких (1–2 дня) элементах обрезаются шириной полосы — заголовок доступен в `title` (всплывающая подсказка); полная проработка подписей вне v1.

## Migration Plan

Схема документов не меняется (чтение v1). Новая capability `resource-timeline`, новые зависимости с точными пинами.

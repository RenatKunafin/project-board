## Context

Карточка PBT-002 требует принять решения до каркаса (PBT-004). Фактическое состояние — `.docs/project-decisions.md`: React + TypeScript + Vite, React Grid Layout, react-rnd, Dexie, SVAR React Gantt, React Calendar Timeline имеют статус **кандидатов**; менеджер пакетов, целевые браузеры, точная форма SDK, поведение удаления вкладки/документа не обсуждались. Структура `apps/` + `packages/` предложена. Модули подключаются при сборке (согласовано), установка плагинов пользователем отменена (раздел 23 решений).

## Goals / Non-Goals

**Goals:**

- Один ADR, закрывающий технические развилки первой версии: стек, менеджер пакетов, структура и направления зависимостей, целевые браузеры.
- Стартовая схема хранения и минимальный SDK, достаточные для PBT-004–PBT-011.
- Словарь сущностей (модуль / тип виджета / экземпляр / документ) и уточнённые пользовательские детали из карточки.

**Non-Goals:**

- Выбор компонентов Гантта (PBT-014–PBT-017), детальный дизайн представлений, миграций и форматов обмена.
- Реализация любого кода, включая каркас.
- Решения по undo/redo и резервным копиям (PBT-062–PBT-065, Proposed).

## Decisions

**Итог ревью владельца (2026-10-07):** утверждены D1, D3, D4, D5, D6, D7, D8 по рекомендациям; в D2 выбран **вариант B — npm workspaces** (рекомендация pnpm отклонена). ADR записывает принятые решения; этот раздел сохраняет ход рассмотрения.

Формат: варианты → рекомендация. Итоговый выбор фиксирует владелец на ревью; ADR записывает результат.

### D1. Стек приложения

- Вариант A (рекомендация): утвердить **React 18/19 + TypeScript + Vite** как решение. Основание: единый стек для платформы и модулей, статическая сборка PWA, зрелость; все кандидаты-библиотеки уже отобраны под React.
- Вариант B: SolidJS/Svelte/Vue — меньше веса рантайма, но переотбор всех кандидатов Гантта и тайлинга; стоимость не оправдана.

### D2. Менеджер пакетов — принят npm workspaces

- **Принято владельцем: npm workspaces.** Без внешних инструментов и новых требований к окружению; Node 22 уже зафиксирован в `.docs/openspec-setup.md`.
- Отклонено: pnpm workspaces (рекомендация ревью) — сильнее изоляция и быстрее CI, но требует установки стороннего инструмента; отклонено владельцем.
- Компенсация слабой изоляции npm: контроль фантомных зависимостей — линтером границ (D3) в PBT-005 и инспекцией `package.json` каждого пакета в ревью каркаса.

### D3. Структура и направления зависимостей

Утвердить предложенную структуру решений (раздел 3.3) как контракт:

```text
apps/project-board → packages/{dashboard, widget-sdk, gantt, checklist}
packages/gantt, packages/checklist → packages/widget-sdk
packages/widget-sdk → (ничего из перечисленных)
```

Запреты, проверяемые линтером границ (PBT-005): `dashboard` не импортирует `gantt`/`checklist`; модули не импортируют внутренности `dashboard`; `widget-sdk` не зависит от UI-библиотек виджетов.

### D4. Целевые браузеры и платформы

- Вариант A (рекомендация): **десктоп**: две последние мажорные версии Chrome, Edge, Firefox, Safari; PWA-установка — гарантированно Chromium-десктопы (Chrome/Edge), Safari/macOS — по возможностям платформы. Мобильные браузеры вне гарантий первой версии (макеты и сценарий — рабочий стол).
- Вариант B: только Chromium — минимальный объём тестирования, но отказ от части аудитории без явной причины.
- Basis: ES2022, `browserslist` в каркасе (PBT-004).

### D5. Стартовая схема хранения

Утвердить предложения раздела 15 решений как стартовые: IndexedDB через **Dexie**; хранилища `settings / tabs / widgetInstances / documents`; один документ — одна запись с общими полями (`schemaVersion`, `revision`); транзакционная запись после завершённой операции; проверка `revision` для обнаружения устаревшей записи. Гарантии автосохранения и поведение конфликта редакций — детализация PBT-010, не здесь.

### D6. Минимальный SDK (v0)

Состав первого публичного контракта `widget-sdk`, достаточный для ветки PBT-006–PBT-011:

1. Регистрация типа виджета: id, название, иконка, компонент, ограничения размеров, стартовые настройки.
2. Контекст экземпляра: ссылка на выбранный документ, id вкладки и экземпляра.
3. Работа с документами: создание, открытие/выбор, подписка на изменения, операции модуля.
4. Настройки представления: чтение/запись состояния экземпляра.
5. События жизненного цикла: видимость, resize, сворачивание, закрытие.
6. Запрос дополнительного представления открытого документа.

Явно вне SDK v0: темы (использовать базовые токены приложения), межвиджетное взаимодействие, плагины из внешних пакетов.

### D7. Пользовательские уточнения (из карточки)

| Вопрос | Рекомендация | Альтернатива |
| --- | --- | --- |
| Раскладки режимов | Хранить отдельные раскладки тайлинга и каскада на каждую вкладку; возврат к режиму восстанавливает прежнюю раскладку (как предложено в 4.4) | Одна раскладка на оба режима — теряется состояние при переключении |
| Скрытые/свёрнутые окна | Приостанавливать тяжёлую отрисовку, сохранять состояние представления; экземпляр жив, документ остаётся общим (как предложено в 4.4) | Размонтировать экземпляр — потеря локального состояния |
| Удаление вкладки | Удалять вкладку и её экземпляры виджетов; **документы не удаляются** — остаются в каталоге | Каскадное удаление документов — опасная операция без явного запроса |
| Удаление документа | Отдельная операция каталога с подтверждением; открытые виджеты с этим документом переходят в состояние «документ отсутствует» с возможностью выбрать другой | Блокировать удаление открытого документа — менее предсказуемо |

### D8. Словарь сущностей

Закрепить за ADR: **модуль** — подключаемый при сборке пакет с типами виджетов; **тип виджета** — зарегистрированная разновидность содержимого (запись в каталоге); **экземпляр** — конкретное окно на вкладке со своими настройками и ссылкой на документ; **документ** — сохраняемые данные, независимые от окон; один документ — много экземпляров (согласовано в разделе 5 решений).

## Risks / Trade-offs

- [npm workspaces допускает фантомные зависимости и медленнее альтернативы] → линтер границ в PBT-005 проверяет импорты между пакетами; `packageManager` в корневом `package.json` и `package-lock.json` фиксируют окружение.
- [SDK v0 может оказаться неполным для Гантта] → ветка PBT-006–PBT-011 сознательно строится на этом минимуме; расширения оформляются новыми решениями, а не тихим ростом контракта.
- [Браузерные гарантии шире реального тестирования] → проверка вручную на Chromium-десктопах как основной сценарий; остальные — smoke при финальных проверках (PBT-057).

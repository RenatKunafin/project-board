# Design — PBT-040 Group editor

## Context

Ядро PBT-032 готово и протестировано: `createGroup(plan, {title, parentId?})`, `updateGroup(plan, id, {title?, parentId?})` (отсутствующее свойство не меняет поле, `parentId: undefined` — вынос на корень; перенос ставит группу в конец массива — D4), `deleteGroup` (вариант A владельца: прямые потомки к родителю удаляемой, содержимое сохраняется), коды `unknown-group`/`circular-group`. UI-паттерны заданы PBT-038: диалог-оверлей, `commitPlan` с ретраем при конфликте ревизии, remount чарта по `key={document.revision}`, возврат фокуса. SVAR строит дерево по `parent` из адаптера; строки `.wx-row[data-id=":g-…"/":t-…"]`. Раскрытие: стор SVAR применяет действие `open-task {id, mode}` (типы `@svar-ui/gantt-store`); после remount стор собирается заново из данных, где `open` приходит из адаптера.

## Goals / Non-Goals

- Goals: создание/переименование/перенос/удаление групп через форму; сообщение о цикле вложенности; раскрытие — состояние экземпляра (B4); сводная по дочерним без переноса дат; порядок и вложенность переживают reload.
- Non-Goals: см. proposal.

## Decisions

### D1. Одна форма группы — два режима

`GroupEditorDialog`: `plan`, `mode: 'create' | 'edit'`, `group?`, `onSubmit`, `onDelete`, `onClose`. Поля: название (текст) + родитель (селект «Корень» + группы плана, кроме редактируемой). Create: пустые поля (родитель — «Корень»). Edit: значения группы. Стили — существующие классы `task-editor__*` (единый визуальный язык диалогов v1, без дублирования CSS); клавиатура и фокус — как в PBT-038 (Esc/Enter, фокус в название, возврат на триггер).

### D2. Отправка — только команды ядра

- create → `createGroup(base, {title, parentId?})`;
- edit-название/родитель → `updateGroup(base, id, patch)`; патч родителя строится по правилу «отсутствующее свойство не меняет поле»: селект всегда содержит выбор → передаётся `{ title, parentId: selected === '' ? undefined : selected }` (выбор «Корень» = вынос на корень);
- delete → `deleteGroup(base, id)` с `window.confirm` (прецедент PBT-038).

Доменные ошибки (`circular-group`, `unknown-group`) показываются под полем родителя текстом из ядра — сообщение уже объясняет причину («не может быть перенесена в собственного потомка…»), отдельная карта текстов не строится. Селект сознательно **не исключает** подгруппы редактируемой группы: иначе сценарий «цикл объясняется пользователю» (DoD-2) недостижим в UI, а защита ядра всё равно обязательна (гонка с другим экземпляром).

### D3. Точки входа и идентификация строк

Кнопка «+ Группа» рядом с «+ Задача». `onChartDoubleClick` расширяется: `data-id` с префиксом `:g-…` проверяется по `plan.groups` → форма edit группы; задачи — как в PBT-038. Срез префикса `:` уже реализован.

### D4. Раскрытие групп — состояние экземпляра (B4)

- `initApi` добавляет перехватчик-наблюдатель `intercept('open-task', …)` (без блокировки): `mode === false` → id в множество свёрнутых, `true` → удаляется. Хранение — `useState`/ref в `PlanGanttWidget`: переживает remount чарта (`key={revision}`) и не попадает в документ.
- Адаптер: `planToGanttTasks(plan, collapsedGroups?)` → `open: !collapsedGroups?.has(group.id)` (умолчание — развёрнуто, текущее поведение PBT-037).
- Запись документа → remount → стор пересобирается из данных с учётом `collapsed` — раскрытие не сбрасывается (найденный бы баг «сброс к развёрнутым после каждого сохранения» закрыт этим же механизмом).
- Второй экземпляр имеет своё множество — B4. Начальное состояние после перезагрузки страницы — развёрнуто (сохранение раскрытия в настройках экземпляра — PBT-049, Non-Goal).

### D5. Сводная полоса и запрет переноса дат

Сводные не хранятся: SVAR вычисляет их по вложенным при сборке стора; любая команда (в т.ч. перенос группы) проходит через `commitPlan` → новая ревизия → remount → сводная пересчитана. Даты задач меняются только задачными командами — перенос/удаление групп их не трогают (контракт ядра PBT-032, тесты уже есть). E2E фиксирует видимый эффект: полоса группы и её строка следуют за родителем, даты в документе неизменны.

### D6. Попутная чистка

`console.info('[pbt039dbg] …')` в перехватчике `drag-task` удаляется (остаток отладки PBT-039 в f0b9c94); заявлено в proposal «What Changes».

## Risks / Trade-offs

- `open-task` в перехватчиках не проверялся спайком: если событие не срабатывает (стрелка дерева обрабатывается минуя bus), fallback — собственная колонка-тогл или клик-делегирование по DOM-строке; решение при отладке e2e, зафиксируется в Risks.
- Селект с подгруппами позволяет «ошибиться с циклом» — осознанный обмен в пользу DoD-2 (сообщение) и защиты от гонок; исключение потомков из селекта усложнило бы UI без надёжности (всё равно нужен показ ошибки ядра).
- Переиспользование классов `task-editor__*` формой группы — при появлении третьего диалога имеет смысл вынести общий CSS; сейчас объём не оправдывает.

## Migration Plan

Схема документа не меняется; группы уже в модели v1. Новая поверхность UI.

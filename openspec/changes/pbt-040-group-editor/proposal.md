# PBT-040 — Управление группами в интерфейсе

## Why

Ядро иерархии (PBT-032) не имеет UI: группы нельзя создать, переименовать, перенести или удалить из приложения. Форма задачи (PBT-038) умеет только выбирать существующую группу, поэтому из плоского плана структуру «направление → платформа → задачи» не построить. Это закрывает блок B правил ADR PBT-003 в интерфейсе (сводные полосы отображаются с PBT-037).

## What Changes

- Форма группы (единый диалог создания/редактирования по образцу формы задачи): название + родитель («Корень» или группа), удаление с подтверждением в режиме редактирования.
- Точки входа: кнопка «+ Группа» в тулбаре; двойной клик по строке группы открывает редактирование.
- Переносы командами ядра: подгруппа к другому родителю — селект родителя формы группы; задача в группу — уже существующий селект группы формы задачи (PBT-038). Порядок при переносах детерминирован («в конец» массива, D4 PBT-032); отдельное позиционное переупорядочивание — Non-Goal (см. ниже).
- Сворачивание/раскрытие групп (B4): перехватчик `open-task` SVAR → локальное состояние экземпляра виджета, передаётся адаптеру (`open`); документ и другие экземпляры не затрагиваются; состояние переживает remount чарта по ревизии.
- Отклонение ядра `circular-group` (перенос группы в собственную подгруппу) показывается сообщением под полем родителя — цикл вложенности объясняется пользователю (DoD-2).
- **Попутная чистка (вне исходных границ карточки):** удаляется отладочный `console.info('[pbt039dbg] …')` из перехватчика `drag-task` (остаток e2e-отладки PBT-039, попал в коммит f0b9c94). Поведение не меняется.

## Impact

- Новые файлы: `packages/gantt/src/GroupEditorDialog.tsx`, `packages/gantt/src/group-editor.ts` (валидация формы), unit-тесты; e2e `tests/e2e/plan-groups.spec.ts`.
- Изменённые: `packages/gantt/src/PlanGanttWidget.tsx` (кнопка тулбара, dblclick по группе, перехватчик `open-task`, состояние раскрытия, чистка console.info), `packages/gantt/src/svar-adapter.ts` (параметр раскрытости групп), `packages/gantt/src/index.ts` при необходимости.
- Ядро (`plan-hierarchy.ts`, `plan-commands.ts`) не расширяется: `createGroup`/`updateGroup`/`deleteGroup` готовы (PBT-032); delta spec — только `project-gantt`.
- Запись — существующий `commitPlan` с ретраем (PBT-038); второй экземпляр обновляется remount'ом по ревизии; сводная полоса пересчитывается SVAR по вложенным при пересоздании представления.

## Non-Goals

- Позиционное переупорядочивание строк (drag дерева SVAR, кнопки «выше/ниже»): действие `move-task`/`reorder-task` стора не проверено спайком PBT-014, а стратегия ADR-5 PBT-017 требует не верить стору без проверки; DoD карточки позиционный порядок не требует — порядок задаётся переносами (детерминированный «в конец»). Потребность оформляется отдельной задачей с проверкой поведения стора.
- Drag-создание зависимостей (PBT-045), ресурсы и назначения (PBT-041/042), отпуска (PBT-043).
- Сохранение раскрытия групп между сеансами (настройки представления — PBT-049 «фильтры и настройки представлений»); здесь раскрытие живёт в памяти экземпляра.

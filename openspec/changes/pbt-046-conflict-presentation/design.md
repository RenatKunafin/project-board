# Design — PBT-046 Conflict presentation

## Context

Диагностика чистая и типизированная: `dependencyViolations(plan)` — `expectedStart/actualStart/message` (формула рабочего лага, C5: даты не изменяются); `resourceConflicts(plan)` — union `parallel-work` (пары задач одного ресурса, обе непараллелизуемые, пересечение по рабочим дням) и `unavailability` (работа × отпуск ресурса, параллельность игнорируется — D6). Обе пересчитываются из документа мгновенно.

## Goals / Non-Goals

- Goals: единый список проблем с различением типов, полными сообщениями, переходом к задаче (включая свёрнутые группы), пересчётом без записи.
- Non-Goals: см. proposal.

## Decisions

### D1. Кнопка со счётчиком + диалог списка

Тулбар: «Проблемы (N)» — N = length(violations) + length(resourceConflicts); при N > 0 кнопка получает класс `has-issues` (опасный цвет границы). Диалог: список карточек: метка типа («Нарушение FS» / «Конфликт работ» / «Отпуск исполнителя»), текст диагностики как есть (содержит задачи/ресурс/даты/причину — DoD-2), кнопка «Показать» при наличии задачи перехода. Пустой список — «Проблем нет.».

### D2. Переход к задаче

`showTask(taskId)`: (1) цепочка `parentId` от задачи к корню — удаление всех предков из `collapsedGroups` (React-состояние) + `exec('open-task', {id, mode: true})` на каждого предка (стор раскрывает немедленно, intercept синхронизирует collapsed); (2) `exec('scroll-chart', {date: task.start})`; (3) `exec('select-task', {id})` (выделение строки). Свёрнутая группа: предок раскрыт действием стора до скролла — задача видна (DoD-5).

### D3. Пересчёт без записи

Список — `useMemo(plan)`: производное от документа; любые исправления (правка дат формой, жест, удаление отпуска) меняют документ → список пересчитывается во всех экземплярах (общий документ), записи не создаются (DoD-3).

### D4. Различение типов и отсутствие ложных срабатываний

Три источника мапятся в union-список с полем `kind`: `dependency` / `parallel-work` / `unavailability` — разные метки секций. Ложная подсветка «Разработка + ПСИ» исключена ядром (`isParallelAllowed`: хотя бы один разрешающий тип → пары нет — тесты PBT-036); e2e фиксирует отсутствие записи при Разработка+ПСИ и наличие при ПСИ-задаче в отпуске (DoD-4).

### D5. Подсветка полос на шкале — ограничение v1

taskTemplate переопределяет рендер полосы — зона хрупкости жестов (ADR-5). Переносится в отдельную задачу при потребности; в v1 визуальное выделение — в списке проблем (цветная метка типа). Зафиксировано как Non-Goal.

## Risks / Trade-offs

- `select-task`/`open-task` как exec-действия стора не проверялись спайком; при нестабильности fallback — только scroll-chart (раскрытие через collapsed+remount). Решение при отладке e2e.
- Диалог поверх чарта закрывает шкалу — список можно закрыть в любой момент; переходы выполняются из него поштучно.

## Migration Plan

Схема не меняется. Новая поверхность UI, производные значения.

## Open Questions

Нет — серия автономна (директива владельца).

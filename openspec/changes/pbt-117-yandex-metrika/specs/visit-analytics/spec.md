## Purpose

Публичное приложение собирает минимально необходимую аналитику посещений, не включая её в локальную работу и не добавляя содержимое личных документов в специально отправляемые цели, события или `dataLayer`. До отдельного отключения временный Вебвизор может записывать отображённый HTML и действия пользователя.

## ADDED Requirements

### Requirement: Аналитика только публичной сборки

Публичная сборка Project Board SHALL подключать счётчик Яндекс Метрики `113967203` только при явном release-флаге. Dev, локальный preview, тестовые сборки и production-сборки без флага MUST NOT загружать `mc.yandex.ru` или отправлять запросы Метрики.

#### Scenario: Публичная сборка с флагом

- **GIVEN** приложение собрано для публикации на GitHub Pages с включённым release-флагом
- **WHEN** пользователь открывает приложение
- **THEN** загружается счётчик `113967203` с согласованной временной конфигурацией Вебвизора и фиксируется просмотр

#### Scenario: Локальная или тестовая сборка

- **GIVEN** приложение запущено в dev, локальном preview или browser-тесте без release-флага
- **WHEN** пользователь открывает приложение и взаимодействует с ним
- **THEN** запросы к доменам Метрики не выполняются, а приложение продолжает работать

### Requirement: Один просмотр SPA

Счётчик SHALL фиксировать один просмотр при открытии SPA и MUST NOT создавать дополнительные просмотры из-за переключения вкладок, окон, виджетов, PWA-восстановления или изменения локального состояния. URL просмотра SHALL быть ограничен публичным адресом приложения без личного содержимого.

#### Scenario: Переключение интерфейса

- **GIVEN** счётчик уже зафиксировал открытие приложения
- **WHEN** пользователь переключает вкладки, окна и виджеты либо перезагружает локальное состояние PWA без навигации
- **THEN** новый просмотр не отправляется автоматически из-за этих действий

### Requirement: Временная конфигурация Вебвизора

При включённом release-флаге счётчик SHALL использовать временно согласованные параметры `webvisor: true`, `clickmap: true`, `trackLinks: true`, `ecommerce: "dataLayer"`, `referrer`, `url`, `accurateTrackBounce` и `ssr`. В приложение MUST NOT добавляться пользовательский `dataLayer`, цели или события, содержащие данные документов.

#### Scenario: Вебвизор включён владельцем

- **GIVEN** release-флаг включён
- **WHEN** пользователь открывает публичный PWA
- **THEN** Метрика получает разрешённые параметры просмотра и записи сессии согласно настройкам счётчика, но не получает специально отправленные данные документов или целей

#### Scenario: Вебвизор отключён переключением флага

- **GIVEN** release-флаг аналитики или параметр Вебвизора отключён перед публикацией
- **WHEN** публикуется новая сборка
- **THEN** запросы и записи Вебвизора прекращаются без изменения пользовательского кода приложения

### Requirement: Устойчивость и приватность

Недоступность скрипта Метрики, блокировщик, отказ сети и offline-режим MUST NOT блокировать запуск, работу, сохранение или восстановление PWA. Интеграция SHALL документировать временное включение Вебвизора и условие его отключения; проверка опубликованного сайта SHALL отделять локально проверяемые свойства от post-release проверки визита.

#### Scenario: Метрика недоступна

- **GIVEN** запрос к `mc.yandex.ru` заблокирован, завершился ошибкой или приложение работает offline
- **WHEN** пользователь запускает PWA и редактирует локальные данные
- **THEN** приложение работает без необработанных ошибок и не теряет локальные записи

#### Scenario: Проверка production

- **GIVEN** release опубликован на `/project-board/`
- **WHEN** владелец открывает опубликованный сайт и проверяет сетевой запрос/тестовый визит
- **THEN** один просмотр появляется в счётчике, а PR содержит отметку о проверках, выполненных локально и только после публикации

# Design — PBT-039 drag/resize

## Context

Спайк PBT-014 доказал схему: payload жестов SVAR ненадёжен; init-перехватчики переживают пересоздание bus; после mouseup стор читается несколько раз (задержки 80/450/1000 мс), расхождение краёв применяется правилами. Ядро PBT-031 уже реализует A2 (`moveTask`, с направлением привязки) и A3 (`setTaskDates` — отклонение перевёрнутого интервала вместо клампа спайка, решение design PBT-031). Специфика обёртки (design D6 PBT-037): пользовательский init вызывается вместо заливки props — перехватчики и ref api вешаются там же.

## Goals / Non-Goals

- Goals: drag/resize задач по дням; одна запись на жест; откат при отклонении; сводные неподвижны; второй экземпляр синхронен.
- Non-Goals: см. proposal.

## Decisions

### D1. Классификация факта (по спайку, на командах ядра)

После mouseup: для каждой задачи плана `api.getTask(id)` → `storeStart`, `storeEndInc` (end−1). Первое расхождение с документом → правило:
- `dStart === dEnd !== 0` → `moveTask(plan, id, storeStart)` (A2: длительность сохраняется, направление привязки внутри ядра);
- `dStart !== 0, dEnd === 0` → `setTaskDates(plan, id, {start: storeStart, end: task.end})` (A3-ввод начала как есть);
- иначе (правый край) → `setTaskDates(plan, id, {start: task.start, end: storeEndInc})`.
Одна задача за чтение (break), повторные чтения подхватят следующую — на практике жест меняет одну задачу.

### D2. Применение и откат

- ok → одна запись документа через `commitPlan` (ретрай при конфликте ревизии, PBT-038) → подписка → remount чарта по ревизии (стор пересоздаётся из документа). Точечные `update-task` для успешного случая не нужны.
- not-ok (например `inverted-interval` при сжатии левее начала — отличие от клампа спайка, решение PBT-031) → `api.exec('update-task', {id, task: {start, end: end+1}})` с датами из документа — полоса возвращается, документ не меняется. Это и есть «отмена жеста» (DoD-4).
- Стор может применить жест с задержкой — 3 чтения (80/450/1000) обязательны; после первой записи последующие чтения видят совпадение и ничего не делают.

### D3. Сводные неподвижны (B2)

`init`-перехватчик: `intercept('drag-task', (ev) => …)` — false, если строка сводная. Определение: `getTask(ev.id)?.type === 'summary'` либо id отсутствует в задачах документа. Проверка e2e — drag сводной не меняет документ.

### D4. Одна операция на жест

Запись — только в обработчике mouseup (сверка). Движения указателя не пишут документ и не ставят очередь: подряд идущие чтения идемпотентны (после записи стор равен документу).

### D5. Попутный фикс ядра: `moveTask` и особый случай `addWorkingDays(x, 0)`

Найдено зондом: перенос однодневной задачи (пн 12–пн 12, 1 раб. день) на пн 19 давал 19–20 (2 раб. дня). Причина: `addWorkingDays(start, workingDuration − 1)` при длительности 1 → `addWorkingDays(start, 0)` = следующий рабочий день. Фикс синхронен `setTaskDuration`: `workingDuration === 1 && isWorkingDay(start) → end = start`. Регрессионный тест в `plan-commands.test.ts`. Дополнение вне исходных границ карточки — заявлено в proposal What Changes.

### D6. E2E

- drag задачи через выходные (пн → пн+7): даты в обоих виджетах, ревизия +1;
- resize правого края через праздник: окончание сохранено как брошено (A3), рабочая длительность уменьшилась;
- сжатие левее начала (незавершимый жест): полоса вернулась, документ не изменился (ревизия та же) — отмена;
- drag сводной: документ не меняется;
- однодневная задача: drag сохраняет длительность 1 (регрессия D5 на e2e-уровне).

## Risks / Trade-offs

- `getTask(ev.id)` в перехватчике — API беты; при нестабильности fallback: блокировка всех сводных по префиксу id (`:g-`) из адаптера (id групп известны).
- Мигание чарта при remount после записи — осознанный компромисс v1 (см. Non-Goals).
- 3 чтения с задержками могут пропустить очень быстрые повторные жесты — окно 1 с; приемлемо (спайк PBT-014).
- **Найдено при реализации (e2e-отладка):**
  - SVAR останавливает всплытие `mouseup` внутри чарта — свертка вешается в capture-фазе на документ с фильтром по чарту (привязка к контейнеру через ref ненадёжна ещё и из-за ранних состояний виджета).
  - Стор применяет жест с анимацией: запись по первому чтению фиксировала промежуточное положение — запись только по последней сверке (120/500 → 250/700/1500 мс), промежуточные чтения лишь запоминают факт.
  - Курсор, вышедший за край панели, клампит жест — дальние переносы делаются несколькими жестами; для e2e перенос выбирается в пределах панели.
  - Клавишная отмена (Esc) беты не поддерживает; «отмена» = жест с возвратом полосы на место (нулевой факт). Ветка отката ядра (перевёрнутый интервал) остаётся защитой: сам стор беты клампит такие жесты и перевёрнутый факт не присылает.
  - Точки связи (wx-link) на краях полос перехватывают mousedown — тестовые захваты краёв смещены от крайних пикселей.

## Migration Plan

Схема документа не меняется. Поведение `moveTask` для однодневных задач исправляется до продуктового использования жестов — изменения существующих документов не требуются.

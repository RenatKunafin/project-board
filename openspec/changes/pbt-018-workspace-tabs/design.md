## Context

Вертикальный срез PBT-011: оболочка с фиксированными панелями чек-листа, модель документов в сервисе, автосохранение. Вкладки — первый блок платформы (решения 4.1: вкладка = именованное пространство с собственным названием и набором виджетов; лимита нет). Решения PBT-018 в ADR-002: React 18, dashboard-модель. Карточка PBT-066 (дизайн-токены) рекомендована перед 018 — решено владельцем выполнять отдельно; стили строго на токенах палитры.

## Goals / Non-Goals

**Goals:**

- Чистая модель вкладок в `dashboard` (unit-тестируемая) + панель вкладок в приложении по макету.
- Независимые наборы экземпляров per-вкладка; перенос среза PBT-011 в первую вкладку.
- Определённые правила удаления; клавиатурная доступность.

**Non-Goals:**

- Персистентность вкладок и наборов (PBT-024), drag-and-drop порядка (кнопки перемещения; DnD — при появлении окон PBT-020+), каталог/добавление виджетов (PBT-019), окна и рамки (PBT-020), дизайн-токены и тема (PBT-066).
- Ограничение количества вкладок (отсутствует по решениям 4.1).

## Decisions

- **Модель — чистые иммутабельные операции в `dashboard`.** `createWorkspaceState({ title })` → `{ tabs: [{ id, title }], activeId }`; операции `addTab(state, title)`, `renameTab(state, id, title)`, `moveTab(state, id, -1 | 1)`, `removeTab(state, id)`, `setActive(state, id)` — возвращают новое состояние или бросают `WorkspaceError` (последняя вкладка, пустое имя, неизвестный id). Без подписок: React держит состояние в `useReducer`, чистота упрощает unit-тесты. Подписочная модель не нужна — вкладки не меняются извне (нет second-window сценария для пространства).
- **id вкладок — `crypto.randomUUID()`**, имя операции задаёт пользователь; дефолт «Новая вкладка».
- **`moveTab(id, direction)`:** перемещение к соседней позиции; на границе — операция возвращает состояние без изменений (не ошибка: нажатие «←» у левой вкладки — штатное бездействие, в отличие от удаления последней).
- **Удаление активной:** активной становится соседняя справа; если удаляемая была крайней правой — соседняя слева. Последняя вкладка: `removeTab` бросает `WorkspaceError('last-tab')`, кнопка закрытия рендерится с `disabled` (видимое+доступное поведение).
- **Экземпляры per-вкладка в приложении:** `Record<tabId, PaneInstance[]>`, где `PaneInstance { instanceId, label, documentId }`. Инициализация: первая вкладка получает срез PBT-011 (`w-1`/`w-2` → список 1, `w-3` → список 2); новые вкладки — пустой массив → `EmptyWorkspace` (компонент dashboard: «Пространство пусто. Каталог виджетов появится в следующем обновлении.»). Удаление вкладки удаляет запись набора; документы остаются в сервисе (спецификация).
- **Панель вкладок — нативная доступность.** `role="tablist"` на контейнере, каждая вкладка — `role="tab"` + `aria-selected`, активация кнопкой. Переименование — двойной клик по названию → inline-инпут (Enter/blur — применить, Escape — отмена). Перемещение — кнопки «←/→» (с `aria-label`), создание — кнопка «+», закрытие — «×» с `disabled` на последней. Стрелочная навигация между вкладками: обработчик onKeyDown на tablist (←/→ двигают фокус и активируют — упрощённый «automatic activation»).
- **Содержимое активной вкладки:** наборы панелей чек-листа рендерятся как в PBT-011 (grid); пустая вкладка → `EmptyWorkspace`. Индикатор сохранения остаётся глобальным (по активному документу первой видимой панели списка 1 — сохранение привязано к документам, не вкладкам).

## Risks / Trade-offs

- [Кнопки перемещения вместо drag — менее привычно] → доступность и простота v1; drag появится вместе с окнами (PBT-020+) и не потребует изменения модели.
- [Сброс закрытых панелей при перезагрузке] → наборы в памяти (карточка: «состояние пока в памяти»); персистентность — PBT-024.
- [Automatic activation стрелками меняет вкладку на каждое нажатие] → стандартный ARIA-паттерн для небольшого числа вкладок; переключение по Enter добавит PBT-019 при росте панелей.

## Open Questions

- Владелец на ревью: подтверждение запрета удаления последней вкладки (альтернатива — замена на новую пустую) и порядка удаления активной (сосед справа).

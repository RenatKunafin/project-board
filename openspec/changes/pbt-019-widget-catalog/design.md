## Context

Реестр типов (PBT-006), вкладки с наборами панелей (PBT-018), `DocumentService` с `listByModule` (PBT-007/009) готовы. Иконка типа была отложена в PBT-006 («поле появится с каталогом» — теперь). Макет «Добавление виджета» (`​.context/layout/widget-adding.png`): выбор типа из сетки карточек.

## Goals / Non-Goals

**Goals:**

- Каталог из реестра (иконка + название), добавление экземпляра на активную вкладку.
- Документные типы: диалог «создать новый / открыть существующий», отмена без последствий.
- Второе представление одного документа (сценарий этапа 1).

**Non-Goals:**

- Рамки окон, перетаскивание, сворачивание (PBT-020), удаление экземпляров как отдельная операция (кнопка закрытия панели уже есть), каталог документов как самостоятельный UI (PBT-025), перетаскивание порядка вкладок, переупорядочивание панелей.

## Decisions

- **`icon: string` — текстовый символ (emoji).** Без иконочной библиотеки; замена на SVG-набор — решение при PBT-066/теме. Каталог и (позже) вкладка используют символ.
- **`documentSupport` — опциональный дескриптор в определении типа:** `{ moduleId, documentType, schemaVersion, createContent(title: string): DocumentContent }`. Платформа добавляет документные экземпляры через сервис (`create`/`listByModule`), не зная модуля. Модуль чек-листа предоставляет фабрику; типы без дескриптора добавляются без диалога.
- **Каталог — overlay-панель** поверх пространства (кнопка «Добавить виджет» в шапке; закрытие — «×»/Escape/клик вне). Выбор документного типа открывает второй шаг диалога: «Создать новый» (инпут названия) или список существующих документов (по убыванию `updatedAt`, заголовок = `content.title` или «Без названия»).
- **Идентификаторы экземпляров — `crypto.randomUUID()`** (гарантия уникальности DoD); подпись панели — «{тип} · {название документа}».
- **`ChecklistContent.title?: string`** — название списка живёт в содержимом; операции модели расширяются spread'ом (`{ ...content, items }`), чтобы сохранять title. Название документа для списка существующих берётся из `content.title` (приведение через `parseChecklistContent`).
- **Открытие существующего документа** не меняет его содержимое — экземпляр подписывается стандартным механизмом; повторное добавление = второе представление (сценарий решений 5).

## Risks / Trade-offs

- [Emoji-иконки неоднозначны кроссплатформенно] → временно до темы (PBT-066); каталог отображает символ в нейтральном стиле.
- [Список существующих документов без пагинации] → объёмы первой версии (десятки списков) приемлемы; полный каталог документов — PBT-025.
- [Диалог добавляет состояние в App] → локальное состояние диалога (шаг, тип), закрытие сбрасывает; бизнес-логика — в операциях сервиса/модели.

## Open Questions

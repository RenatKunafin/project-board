# PBT-055 — Генератор PlantUML

## Why

Публикация плана для команды (Confluence и т.п.) — согласованный сценарий (решения §1/§16). Ядро плана, группы, зависимости и календарь готовы (PBT-030–036). Владелец предоставил целевой образ — рабочий пример `.context/examples/plant-uml-example.plantuml` и референс-гайд его построения `.context/examples/SKILL (1).md` (референс для ознакомления, не процессный документ): экспорт должен выглядеть так же.

## What Changes

- **Новый модуль** `packages/gantt/src/plantuml-export.ts`: чистая функция `serializePlanToPlantUml(plan)` → `{ text, report }` — текст диаграммы PlantUML Gantt в стиле целевого примера и отчёт о непереносимой семантике. Без UI — потребитель PBT-056.
- **Состав экспорта по целевому образу:** `title` плана + `caption`-расшифровка (при наличии групп — их сокращения не выводятся автоматически; v1 — caption только при наличии title) и `language ru`; `Project starts` (минимальная дата задач, формат `YYYY/MM/DD`); закрытые дни недели и праздники (`is closed`) + **рабочие исключения (`is open` — поддержано форматом)**; группы — разделители `-- Имя --`; задачи **с алиасами** (`[Название] as [T3]`) в стиле `requires N days` + `starts D` (N — рабочая длительность ядра) с **цветом этапа по палитре примера** (АНЛ→LightSkyBlue, DEV→MediumPurple, ИФТ→Orange, ПСИ→Tomato, ТРЖ→LightGreen — по маркеру в названии); периоды недоступности — раздел «Отпуска», DarkGreen; FS-связи стрелками по алиасам; выходные — заливка `lightgray` диапазонами по всему горизонту; финал `printscale daily zoom 1`.
- **Отчёт экспорта** (непереносимое форматом): лаги связей (стрелка без задержки — проверено спайком), сводная полоса групп, типы работ/параллельность, загрузка `unit`, конфликты, задачи с датами на нерабочих днях (полоса может лечь иначе), вехи/выделенные даты (в модели нет — только упоминание при пустом плане? нет — не выводим вовсе).
- **Кодирование названий:** кириллица и «» переносятся как есть; `[`/`]` заменяются (ломают синтаксис — проверено); алиасы генерируются из id задач (стабильны, дубли названий не рвут связи).
- Генерация детерминирована, офлайн, документ не изменяется.

## Capabilities

### New Capabilities

- `plantuml-export`: публикация плана в PlantUML в стиле целевого примера владельца — состав, палитра этапов, алиасы, семантика дат, кодирование, отчёт о непереносимом.

### Modified Capabilities

(нет)

## Impact

- **Код:** только `packages/gantt` — новый модуль + тесты; ядро, SDK, платформа, UI не меняются.
- **Тесты:** unit на фиксированном выводе (контрольный план + факты референса); рендер-верификация на закреплённой версии PlantUML (живой прогон, скриншот в `change/screenshots/`).
- **Референсы:** `.context/examples/plant-uml-example.plantuml` (целевой вид) и `.context/examples/SKILL (1).md` (приёмы формата: алиасы, is open, requires/starts, цветовые конвенции).

## Non-Goals

- Экспорт из интерфейса — PBT-056; настройка профиля пользователем; конвертация в PNG/SVG; round-trip.
- Автоматическая расшифровка сокращений в `caption` (у владельца вручную; v1 — без caption-легенды, кроме случаев, где она берётся из данных).
- Вехи и выделенные даты релизов (в модели плана нет вех; пример владельца добавлял их вручную).
- Перенос ресурсных полос `on {Ресурс}` (рендер не моделирует занятость — скилл-референс прямо предупреждает; исполнители остаются в подписи задач).

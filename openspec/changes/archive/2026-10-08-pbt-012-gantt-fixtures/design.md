## Context

Прототипы PBT-014/015 будут сравниваться между собой и с целевой нагрузкой (раздел 20 решений: сотни задач, до 10 виджетов). Правила семантики зафиксированы [ADR PBT-003](../../../../docs/adr/PBT-003.md) — контрольный набор может иметь однозначные ожидания. Рабочий пример `docs/examples/diagramm.gantt` изучен (47 задач, 9 ресурсов, FS с лагами, отпуска-задачи, UTC-метки, Europe/Moscow) — сохраняется как эталон импорта.

## Goals / Non-Goals

**Goals:**

- Малый набор с ручными выписанными ожиданиями (каждая строка — будущий автотест PBT-013).
- Детерминированный генератор 500 задач (фиксированный seed, идентичность прогонов).
- Эталон рабочего примера + тестовый конвертер без претензий на продукт.
- Зафиксированные сценарии измерений для PBT-016.

**Non-Goals:**

- Продуктовый парсер `.gantt` (PBT-052), ядро планирования (PBT-030), вычисление длительностей/конфликтов (это проверяется прототипами на данных), UI.
- Поддержка почасового календаря исходного инструмента (исключено решениями).

## Decisions

- **Тестовый формат плана.** JSON: `{ meta: { title, calendar: { workingDays: [1..5], holidays: ['YYYY-MM-DD'] } }, resources: [{id, name, workTypes}], tasks: [{id, title, groupId?, start, end (inclusive), assigneeIds, workTypeIds, progress? }], groups: [{id, title, parentId?}], dependencies: [{fromTaskId, toTaskId, lagDays}] }`. Даты — `YYYY-MM-DD`, окончание включительно (ADR-003 A1). Формат сознательно минимален и помечен «fixtures-only».
- **Малый набор — фиксированные даты 2026 года.** Базовая неделя пн–пт. Состав: группа «Фаза 1» → задачи A/B/C; B после A с лагом 0; праздник ср 14.10 внутри A (пн–пт → 4 раб. дня); отпуск ресурса R1 21–22.10; пересечение «Разработка R1 + Разработка R1» → конфликт; «Разработка R1 + ПСИ R1» (ПСИ параллелизуемая) → допустимо. Ожидания — в `small-plan-expected.md` таблицей.
- **PRNG — mulberry32 с seed 42.** Компактный детерминированный генератор без зависимостей. Генерация: 500 задач, ~5% корневых групп, ~15% подгрупп, FS-связи между соседними задачами (лаг 0–2), 9 ресурсов (как в рабочем примере), назначения 1–2 ресурса на задачу, типы «Разработка»/«ПСИ».
- **Golden-файл в git.** `plan-500.json` коммитится; тест `generate-plan.test.ts` сравнивает свежую генерацию с golden построчно — регресс на неслучайность.
- **Эталон `.gantt` — копия без изменений** + конвертер `reference-gantt.ts` (парсит JSON рабочего примера в тестовый формат, метки UTC → даты Europe/Moscow — как в наблюдениях решений 17). Экспорт `convertReferenceGantt()` с JSDoc «fixtures-only: не полноценный импорт (PBT-052)».
- **Сценарии измерений** (зафиксировать, не выполнять): A — 1 план×500 задач, 10 представлений (6 проектных + 4 ресурсных) в одной вкладке; B — 10 планов×50 задач, по одному представлению. Операции: первичный рендер, скролл таймлайна 3 экрана, zoom ±2 шага, drag задачи, добавление задачи, пересчёт конфликтов. Окружение: Chromium (Playwright), macOS arm64, вкладка активна, DevTools закрыты. Повторы: 5 прогонов каждой операции, медиана и p95.

## Risks / Trade-offs

- [Тестовый формат разойдётся с будущей моделью ядра (PBT-030)] → формат помечен fixtures-only; миграция фикстур — механическая, ядру нужны те же поля.
- [Golden-файл 500 задач утяжелит репозиторий] → ~200–400KB JSON — приемлемо; при росте — сжатие или генерация в тесте с фиксацией hash.
- [Конвертер эталона может закрепить неверную интерпретацию `.gantt`] → помечен fixtures-only; продуктовый импорт (PBT-052) не наследует конвертер без отдельного ревью.

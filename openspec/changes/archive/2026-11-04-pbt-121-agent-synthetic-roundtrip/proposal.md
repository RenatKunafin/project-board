# PBT-121 — Синтетический сквозной эксперимент PWA → MCP → агент

## Why

PBT-120 подготовила профиль среды и протокол, но не доказала запуск нашего MCP-компонента, канал HTTPS → loopback и сохранение результата. Нужен один воспроизводимый синтетический обмен, чтобы принять решение о транспорте до разработки продуктовой интеграции PBT-122+.

## What Changes

- Создаётся изолированный исследовательский стенд: тестовая браузерная панель → локальный компонент с MCP → исполнитель → результат → реальный сервис документов и адаптер IndexedDB платформы → чтение после reload.
- Первым исследуется MCP через stdio и отдельный браузерный HTTP-канал на loopback. Короткий опрос ограничен временем; WebSocket, другие MCP-транспорты и постоянный цикл не реализуются заранее.
- Добавляются явное сопряжение, ограничения Host/Origin, проверка конверта результата и одной синтетической цели. Небольшая очередь в памяти процесса служит пробе, не обещает устойчивость после перезапуска.
- Готовятся отдельная статическая HTTPS-сборка без аналитики и переносимый локальный npm-артефакт. По выбору владельца HTTPS-проба планируется на временном GitHub Pages в отдельном репозитории; продуктовый сайт и его workflow публикации не меняются.
- Автоматические тесты используют MCP-имитатор и проверяют сохранение/reload, недоступность компонента, отказ persistence и неавторизованный доступ. Живой внутренний агент проверяется отдельно владельцем на рабочем Mac; текущая личная машина доступом к агенту не обладает.
- Готовятся инструкция одной обработки синтетического запроса и обезличенный отчёт `docs/research/PBT-121.md` с матрицей «проверено / отказ / не проверено», версиями, ограничениями и выводом для PBT-122.

## Capabilities

### New Capabilities

- Нет. Изолированное исследовательское tooling, `skip_specs: true`; продуктовый каталог не получает новый виджет или API.

### Modified Capabilities

- Нет. Сервис документов, SDK, сохранность продуктовых документов и штатный PWA lifecycle используются без изменения требований.

## Non-goals

- Реальные Jira/корпоративные данные, универсальное чтение/редактирование дашборда, изменение ручного плана.
- Долговечная очередь, lease/retry после падения, несколько рабочих пространств/агентов, полноценный продуктовый ACK-протокол и упаковка для всех ОС.
- Поддержка установленной PWA: первая заявленная среда — Chrome, обычная вкладка. Название серии не означает, что PWA уже проверена.
- Создание публичного npm-пакета, выпуск продукта или автоматическая публикация стенда при подготовке артефактов.

## Impact

- Планируемая область реализации: `tests/agent-integration/` (панель, изолированный серверный пакет, fixtures, тесты, сборка), отдельный Playwright config, целевые npm scripts и отчёт.
- Браузерная часть использует публичные экспорты `@project-board/dashboard` и `@project-board/widget-sdk`; изменений в продуктовых пакетах и `apps/project-board` не требуется.
- Сервер использует официальный MCP SDK за локальным адаптером. Новые зависимости закрепляются точными версиями в изолированном тестовом пакете с lockfile; перед установкой проверяется совместимость runtime и API.
- Временное размещение требует отдельного репозитория статических артефактов; его создание/публикация выполняются отдельным действием после подготовки проверяемого результата. Код стенда и единственный PR PBT-121 остаются в основном репозитории, цель PR — `develop`.
- PBT-120 завершена и заархивирована. Переход к основному контракту PBT-122 обосновывается результатом этой пробы; отсутствие живого результата не заменяется успехом имитатора.

# PBT-078 — Сетка каскада

## Context

Текущий CascadeLayout задаёт контролируемые position/size, bounds=parent, onDragStop/onResizeStop с clampCascadeArea. Фон — radial-gradient с шагом 16px. Стартовые области 600×420 и отступы 24+28n не кратны 16. Минимальная ширина чек-листа 280px также не кратна 16. Правило границ PBT-076 обязательно сохранить. Переносить жестовую демо-логику прототипа не нужно: у нас адаптер react-rnd.

## Референс поведения (уточнение владельца 2026-10-23)

Референс привязки — режим сетки прототипа, а не настройки его каскада. Проверены `WidgetFrame.tsx` и передача `snap={snap && tiled}` в `Dashboard.tsx`. В режиме сетки прототип округляет абсолютные координаты и размеры: `Math.round(value / gridSize) * gridSize`, по умолчанию gridSize=16. Во время pointermove вычисляется исходная геометрия + смещение указателя и сразу показывается дискретный preview; pointerup фиксирует последнее показанное значение. Это и есть целевое ощущение перемещения/ресайза для нашего каскада. Отсутствие snap в каскаде прототипа не является ограничением требований.

Сохранение только после жеста и дискретный preview переносим как поведение, без копирования обработчиков прототипа. В частности, штатные dragGrid/resizeGrid должны соответствовать округлению абсолютной геометрии, а не только прибавлять кратное смещение к несеточной исходной позиции.

## Decisions

1. Предложение: единый шаг 16px для x/y/width/height. Сетка отсчитывается от начала канваса. CSS-позиция точек должна совпадать с этой системой координат: центр текущего radial-gradient в середине тайла, поэтому требуется согласовать background-position. Шаг передать из одной платформенной константы через CSS custom property, чтобы CSS и жесты не расходились.
2. Дискретность видна во время жеста, а не только после отпускания: использовать штатные dragGrid/resizeGrid react-rnd (уточнить фактическую семантику в установленной версии до реализации) и итоговую нормализацию. Добавить эти поля в изолированный RndProps, библиотечные типы не выходят из адаптера.
3. По итогам ревью размер выбирается на ближайшем узле внутри ограничений типа, координаты неотрицательны. Видимый экран не задаёт максимум; канвас расширяется по окнам и preview с прокруткой по обеим осям. Например, minWidth 280 даёт сеточный минимум 288. Новое окно получает свободное место и показывается прокруткой.
4. При отсутствии узла внутри min/max типа приоритет имеют ограничения типа, шаг соответствующей оси — 1px. Viewport меньше минимума больше не сжимает окно: оно доступно через прокрутку. Чистая функция ограниченной геометрии сохраняет тесты тесных интервалов, адаптер расширяемого канваса использует нормализацию без лимита viewport.
5. Отображение новых и восстановленных областей проходит нормализацию snap + constraints. Старые записи не переписываются при загрузке или ResizeObserver. Итог жеста сохраняет показанную геометрию; переключение режимов сохраняет независимость раскладок. При добавлении в каскаде сохраняются и ранее не записанные стартовые области существующих окон: их позиции не должны зависеть от порядка записей IDB после перезапуска.
6. Для свёрнутого окна высота заголовка не округляется и сохранённая развёрнутая высота не затирается; перенос учитывает видимую высоту заголовка при границах. Разворачивание на весь дашборд не привязывается к сетке; возврат восстанавливает каскадную геометрию. Соседи могут перекрываться, активация меняет только порядок глубины.

## Validation

Содержательные unit-проверки чистой геометрии: округление, не кратные шагу минимумы/максимумы, тесный канвас, правая/нижняя границы, старые координаты и свёрнутое окно. Browser: реальный перенос и ресайз на не кратное 16 расстояние; геометрия во время движения и после отпускания, сохранение/reload, смена режима, границы, сворачивание/разворот. Проверить на 1024×778 и широком экране, снять до/после, проверить консоль MCP. Lint/typecheck/unit/build, полный test:browser в чистой среде и strict OpenSpec; dev-сервер предварительно остановить.

## Уточнения по реализации

- Проверены исходники установленных react-rnd/react-draggable/re-resizable: dragGrid округляет смещение, resizeGrid — абсолютный размер после min/max. Поэтому отображаемая исходная геометрия нормализуется, границы min/max ресайза выбираются по допустимым узлам; в интервале без узла шаг соответствующей оси — 1px.
- Штатный bounds у канваса с несеточным размером позволяет промежуточную несеточную координату у края. Каждое окно получает прозрачную плоскость границ с размером «размер окна + наибольшее допустимое кратное 16 смещение». Она не ловит указатель, не создаёт stacking context и не перемонтирует содержимое: z-index, keep-mounted и DOM-перенос максимизации сохраняются. Это избегает вмешательства во внутренний state библиотеки и исправлений позиции после кадра.
- Нашлось старое расхождение PBT-070/027: видимый свёрнутый заголовок с рамкой = 34px (32+2), CASCADE_COLLAPSED_HEIGHT оставался 44px, minHeight оболочки соответствовал развёрнутому окну. Исправлено в рамках требования о переносе свёрнутого окна: оболочка 34px с тем же min/maxHeight, развёрнутая высота при переносе сохраняется.
- Неприменимые бесконечные maxWidth/maxHeight до первого ResizeObserver не передаются в JSX/CSS. В промежуточной dev-проверке поймано предупреждение React об Infinity; исправлено, последующий свежий изолированный контекст — 0 ошибок.

## Изменение по ревью владельца: расширяемый каскад

Владелец сообщил, что ограничение видимым экраном не позволяет разнести новые окна без перекрытий. Предыдущее решение PBT-076 меняется: граница относится к логическому канвасу, который расширяется по окнам, а не к viewport. Каскад получает собственную прокрутку по обеим осям; сохранённые координаты не ужимаются при сжатии экрана. Новые окна размещаются на свободном месте с шагом 16px и автоматически показываются прокруткой. Существующие окна по-прежнему можно перекрывать вручную.

Рабочий канвас включает окна и текущий preview плюс небольшой отступ. Невидимая плоскость ограничений жеста имеет запас в один viewport сверх текущего канваса, поэтому движение внутри экрана не упирается в его рамку; во время жеста видимый канвас растёт по preview. Отрицательные координаты запрещены. Прокрутка каскада сохраняется на время максимизации и восстанавливается при возврате; overlay занимает viewport, а не весь увеличенный канвас. Формат БД/SDK не меняется.

Прежние проверки ограничения видимым экраном заменяются проверками достижимости окон через прокрутку. Это явное изменение поведения по текущему ревью, а не скрытый регресс PBT-076.

В проверке расширяемого канваса обнаружен и исправлен дефект стартовой геометрии: старые окна без явной cascadeArea сдвигались после появления UUID-окон и reload из-за порядка первичных ключей IndexedDB. При добавлении в каскаде эти исходные области теперь фиксируются по текущему порядку, без изменения прежних явных записей. Новый browser-сценарий сравнивает всю раскладку, проверяет отсутствие пересечений новых окон, автопрокрутку, возврат из максимизации и reload на меньшем экране.

Проверки после изменения по ревью: целевой browser — 17/17; полный `npm run test:browser` — 133/133 (27.9s), `npm test` — 492/492 (36 файлов), lint/typecheck/build/strict OpenSpec — успешно (19/19). Precache 85 файлов, 2057.06 KiB. MCP: четыре новых окна на 1024×778 занимают y=512/944/1376/1808 без перекрытий; высота канваса 2288px, прокрутка показывает новое окно, 0 ошибок. Снимок `screenshots/scroll-new-windows-1024.png`.

## Дополнение владельца: каскад по умолчанию

По запросу владельца каскад — режим первого запуска и новых вкладок, он показывается первым в переключателе. Сохранённый явный режим grid/cascade не меняется; записи без режима используют каскад. Миграция не требуется. Сценарии, зависящие от сеточной геометрии, выбирают сетку явно; отдельный browser-сценарий проверяет новое умолчание и сохранение сетки после reload.

Проверки нового умолчания: отдельный `default-layout.spec.ts` проверяет первый запуск, порядок «Каскад/Сетка», новую вкладку и сохранённую сетку после reload. Сценарии сеточной геометрии теперь выбирают её явно. Полный browser — 134/134 (28.4s), unit — 492/492, lint/typecheck/build/OpenSpec 19/19 успешны. В офлайн-сценарии добавлено ожидание записи режима в IndexedDB перед закрытием: сохранение документа не означает завершения отдельной очереди структуры workspace. В проверках нескольких вкладок селектор каскада ограничен активной вкладкой; две вкладки теперь могут иметь каскад одновременно. MCP подтвердил выбранный каскад в чистом профиле, снимок `screenshots/default-cascade-1024.png`.

Дополнительно `npm run test:pwa-updates` — 8/8 (32.5s), включая реальную сборку PBT-028, сохранение режимов и управляемое обновление.

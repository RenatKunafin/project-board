# Design — PBT-043 Resource absence editor

## Context

Ядро PBT-034: `createUnavailability` (проверка ресурса и интервала), `updateUnavailability` (итоговое состояние: неприсутствующие поля из текущей записи), `deleteUnavailability`; коды `unknown-resource`/`unknown-unavailability`/`inverted-interval`. Диалог справочников PBT-041 — точка входа (отпуск принадлежит ресурсу); паттерн applyCommand → switch → функции ядра готов.

## Goals / Non-Goals

- Goals: создание/изменение/удаление отпуска (ресурс + интервал), понятные ошибки, отдельность от задач.
- Non-Goals: см. proposal.

## Decisions

### D1. Третья секция диалога справочников

Секция «Отпуска» в ResourceCatalogDialog (после типов работ): отпуска принадлежат ресурсу — их место рядом со списком исполнителей. Форма добавления: select ресурса (плейсхолдер «Выберите ресурс», пустой = ошибка «Выберите ресурс.» — клиентская, до ядра), два `input[type=date]` (начало/окончание, умолчание — сегодня), кнопка «Добавить». Список: «{ресурс}: {дата}–{дата}», кнопки Изменить/Удалить.

Альтернатива «отдельный диалог» отклонена: лишний уровень навигации, а секция переиспользует applyCommand и стили.

### D2. Инлайн-редактирование строки периода

«Изменить» переводит строку в форму (select + две даты, как добавление): Enter/«✓» — сохранить (`updateUnavailability` с полным набором полей — итоговое состояние ядра покрывает), Esc/«×» — отмена. Подтверждение удаления — `window.confirm` (без перечисления последствий: отпуск ни на что не ссылается; конфликты — производные).

### D3. Ошибки

Пустой ресурс: клиентская проверка «Выберите ресурс.» у формы. Обратный интервал: текст ядра `inverted-interval` («Окончание раньше начала.») — alert секции. Гонка (удалён другим экземпляром): `unknown-unavailability` — alert списка. Документ при ошибках не меняется (атомарность ядра).

### D4. Отдельность от задач

Команды недоступностей не трогают `tasks` (контракт ядра PBT-034); рабочая длительность задач — производная календаря плана, персональных календарей нет — пересчёта при отпуске не существует. E2E фиксирует даты задач до/после создания/изменения/удаления отпуска.

## Risks / Trade-offs

- Диалог растёт по вертикали (3 секции) — прокрутка внутри `.task-editor` уже поддерживается (max-height + overflow).
- Отпуска не видны на шкале до PBT-046/047 — осознанный Non-Goal; проверка через редактор и документ.

## Migration Plan

Схема не меняется (`unavailability` в модели v1). Новая поверхность UI.

## Open Questions

Нет — серия автономна (директива владельца).

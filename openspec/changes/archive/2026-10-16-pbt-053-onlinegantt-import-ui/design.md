# Design — PBT-053 Предпросмотр и импорт `.gantt`

## Context

Парсер `parseOnlineGanttFile` (PBT-052) отдаёт `{ title, content, report }` с двухуровневой диагностикой и сводкой (`tasks/groups/resources/dependencies/unassignedTasks`). UI-механика импорта собственного формата (PBT-051, `PlanGanttWidget.tsx`): hidden `input[type=file]` → `file.text()` → валидация до создания → `documentService.create` → `switchDocument(created.id)`; отказ — inline-панель `importResult` под тулбаром. Диалоговые паттерны проекта: `TaskEditorDialog`, `GroupEditorDialog`, `ResourceCatalogDialog` (модалки с фокусом, Esc, токены).

## Goals / Non-Goals

Goals: довести `.gantt` до пользователя одной командой импорта с предпросмотром до создания документа; DoD карточки покрыть e2e.

Non-Goals (сверх proposal): правка данных в предпросмотре; автоматическое определение формата по содержимому (достаточно расширения); массовый импорт.

## Decisions

### D1. Одна команда импорта, роутинг по расширению

Кнопка 📥 (PBT-051) расширяется: `accept=".json,.gantt,application/json"`; выбранный файл с расширением `.gantt` (регистронезависимо) идёт в `parseOnlineGanttFile`, остальное — в `deserializePlanFile` как сейчас. Основание: пользователь думает «импортировать план», формат — свойство файла; отдельная кнопка дублирует команду и заставляет выбирать формат до выбора файла. Отказ обеих сторон не пересекается: `.json`-диагностика собственного формата не меняется, `.gantt`-файл никогда не попадает в `deserializePlanFile` (его `unknown-format` не заслоняет OnlineGantt-диагностику).

### D2. Состояние предпросмотра в виджете

`onlineganttPreview: { fileName: string; payload: OnlineGanttPayload } | undefined`. Фатальные issues парсера (`ok: false`) — переиспользуемая inline-панель `importResult` (тип ослабляется до `{ code: string; path: string; message: string }[]` — структурно совместимы `PlanFileIssue` и `OnlineGanttIssue`); диалог не открывается, документ не создаётся (DoD-2). Предпросмотр не мутирует результат парсера: `content` хранится в состоянии до применения.

### D3. Диалог `OnlineGanttImportDialog`

Props: `fileName`, `payload`, `onApply(title)`, `onCancel`. Разделы:

- **Название плана** — `input`, предзаполнен именем файла без расширения (`fileName.slice(0, lastIndexOf('.'))`, пустой результат — `ONLINEGANTT_DEFAULT_TITLE`); это `options.title`-слот парсера, применяемый при создании документа.
- **Сводка** — «Задач 47 · Групп 2 · Ресурсов 9 · Зависимостей 21 · Без исполнителя 16» (из `report.summary`).
- **Предупреждения** — `code (path): message` списком (паттерн inline-панели PBT-051); сворачиваемость не вводим — скролл области.
- **Требуют ручного решения** — задачи без `assigneeIds`: названием и текстом-пояснением «Назначьте исполнителя или преобразуйте в период недоступности (отпуск) после импорта». Пометка по отсутствию исполнителя, не по имени (D7); записи не удаляются (DoD-4).
- **Примечания** — задачи с `notes`: «название — текст примечания», текстом (DoD-5; HTML уже вырезан парсером PBT-052 — достигается по построению, React экранирует вывод).

Кнопки «Импортировать» (primary) и «Отмена»; Esc — отмена; фокус на поле названия (паттерн `TaskEditorDialog`). Скролл тела диалога при переполнении (`max-height` + `overflow`) — в узком окне тулбар и кнопки остаются видимыми.

### D4. Применение и отмена

`onApply(title)`: `title.trim()`, пустое — дефолт; `documentService.create({ moduleId: PLAN_MODULE_ID, documentType: PLAN_DOCUMENT_TYPE, schemaVersion: PLAN_SCHEMA_VERSION, title, content: payload.content })` → `switchDocument(created.id)` → inline-успех (`План «…» импортирован…`) → закрытие. Двойной импорт одного файла — два документа (идентичность по новой записи, прецедент PBT-051). `onCancel`/Esc — сброс `onlineganttPreview`, данные не тронуты.

### D5. E2E

Новый `tests/e2e/onlinegantt-import.spec.ts`, фикстура `tests/fixtures/gantt/onlinegantt-20261016.reference.gantt` (иерархический эталон — проверяются группы) + битый вход через `setInputFiles` с буфером. Сценарии:

1. **Полный импорт** (DoD-1, DoD-3): открыть предпросмотр, сверить сводку (47/2/9/21/16), предупреждения есть (`dropped-task-fields` color), применить → план в окне (группа «Отпуск» в дереве, полосы), каталог содержит документ; добавить виджет «Ресурсы» на тот же документ из каталога → дорожки с задачами.
2. **Отмена** (DoD-2): предпросмотр → отмена → каталог без нового документа, текущий план не изменился.
3. **Ошибочный вход** (DoD-2): буфер `not-a-json{` → inline-диагностика, диалог не открыт, документа нет.
4. **Повторный импорт**: два применения одного файла → два документа в каталоге, первый без изменений.

data-атрибуты: `data-onlinegantt-preview`, `data-onlinegantt-apply`, `data-onlinegantt-cancel`, `data-onlinegantt-summary` — по конвенции e2e проекта.

### D6. Стили и границы

Классы `plan-gantt__*`-диалога по образцу `TaskEditorDialog` (`task-editor.css`/`gantt.css`, секция диалогов); только токены, без хексов. Правки ограничены `packages/gantt` (компонент + виджет + css); SDK/платформа/ядро не трогаются.

## Risks / Trade-offs

- [Список «без исполнителя» из 16 записей перегружает диалог] → скроллируемая область, пояснение свернуто в один абзац; полный список не усекается (DoD-4 требует видимости ручных решений).
- [Предзаполненное имя файла может быть нерусским/некрасивым («Online Gantt 20261016»)] → поле редактируется до применения; дефолт парсера — fallback.
- [`.gantt` без расширения при `accept` фильтре] → пользователь может выбрать «все файлы»; такой вход уйдёт в `deserializePlanFile` и получит корректную диагностику `unknown-format` — поведение определено, молчаливых потерь нет.
- [Inline-панель ошибок соседствует с предпросмотром] → состояния взаимоисключающие: открытый диалог закрывает inline-панель.

## Попутные правки

- **Непрозрачный фон шкалы дат/месяцев** (находка владельца при приёмке, 2026-10-16): sticky-шкала SVAR `.wx-scale` прозрачна по умолчанию — при вертикальном скролле полосы задач просвечивали сквозь неё (заметны только залитые колонки выходных `.gantt-weekend`). Фикс: `background: var(--color-surface)` на `.plan-gantt__chart .wx-scale` (`gantt.css`); проверено DOM-инспекцией на прод-сборке (фон `rgb(255,255,255)`, sticky поверх потока строк) и скриншотом `screenshots/scale-solid-after-scroll.png`; e2e Гантта/импорта/переноса (14) зелёные. Дефект существовал с PBT-037, вне границ карточки — потому и оформлен здесь явно.

## Migration Plan

Новый UI без изменения контрактов; откат — удалить диалог и вернуть `accept`/роутинг PBT-051.

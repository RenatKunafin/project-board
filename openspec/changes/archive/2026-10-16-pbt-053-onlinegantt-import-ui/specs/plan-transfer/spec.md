## ADDED Requirements

### Requirement: Импорт файла OnlineGantt из интерфейса с предпросмотром

Команда импорта плана SHALL принимать файлы OnlineGantt `.gantt` наряду с файлами собственного формата: выбранный `.gantt` SHALL полностью разбираться до каких-либо изменений данных, а результат показываться в предпросмотре — создание документа выполняется только явным применением. Применение SHALL создавать новый независимый документ плана с названием из предпросмотра и переключать окно, из которого выполнен импорт, на новый план; ранее созданные планы MUST NOT изменяться. Критические ошибки разбора (некорректный JSON, отсутствие обязательных разделов) MUST блокировать применение: пользователю показывается перечень диагностик по месту команды, диалог предпросмотра не открывается, документ не создаётся. Отмена предпросмотра и неуспешный импорт MUST NOT изменять данные и каталог.

#### Scenario: Рабочий файл проходит предпросмотр и импортируется

- **GIVEN** пользователь выбрал в команде импорта эталонный файл `.gantt` с 47 задачами и 9 ресурсами
- **WHEN** предпросмотр открыт и пользователь применяет импорт
- **THEN** создаётся документ плана с задачами, группами, ресурсами и зависимостями из файла
- **AND** окно, из которого выполнен импорт, отображает импортированный план
- **AND** план доступен в каталоге документов и открывается в ресурсном представлении с теми же данными

#### Scenario: Отмена предпросмотра ничего не меняет

- **GIVEN** открыт диалог предпросмотра разобранного файла
- **WHEN** пользователь отменяет импорт или закрывает диалог
- **THEN** каталог и содержимое текущих планов остаются без изменений

#### Scenario: Критическая ошибка даёт диагностику без документа

- **GIVEN** пользователь выбрал файл, не являющийся корректным JSON
- **WHEN** выполняется разбор
- **THEN** пользователь видит перечень диагностик по месту команды импорта
- **AND** диалог предпросмотра не открывается и документ не создаётся

#### Scenario: Повторный импорт создаёт независимые планы

- **GIVEN** один файл `.gantt` импортирован дважды с применением
- **WHEN** пользователь просматривает каталог
- **THEN** каталог содержит два независимых документа, содержимое первого не изменилось

### Requirement: Состав предпросмотра импорта

Предпросмотр SHALL показывать до применения: сводку разбора (число задач, групп, ресурсов, зависимостей и задач без исполнителя), перечень предупреждений отчёта импорта с причинами (пропущенные записи и связи, неперенесённые поля и настройки) и редактируемое название создаваемого плана. Задачи без исполнителя SHALL быть помечены как требующие ручного решения (назначение исполнителя или преобразование в период недоступности) и MUST NOT удаляться или скрываться автоматически; пометка выставляется по отсутствию исполнителя, а не по названию записи. Примечания исходного файла SHALL отображаться как текст без исполнения HTML-разметки.

#### Scenario: Сводка и предупреждения видны до применения

- **GIVEN** файл с предупреждениями отчёта (неперенесённые настройки, поля записей)
- **WHEN** открывается предпросмотр
- **THEN** сводка показывает количества задач, групп, ресурсов и зависимостей
- **AND** предупреждения перечислены с указанием причины

#### Scenario: Задачи без исполнителя помечены как ручные решения

- **GIVEN** файл с задачами без назначенных ресурсов
- **WHEN** открывается предпросмотр
- **THEN** эти задачи перечислены с пометкой о ручном решении
- **AND** после применения они остаются в плане обычными задачами

#### Scenario: Примечание отображается текстом

- **GIVEN** файл с HTML-примечанием у задачи
- **WHEN** открывается предпросмотр
- **THEN** примечание показано как текст без тегов и не исполняется как разметка

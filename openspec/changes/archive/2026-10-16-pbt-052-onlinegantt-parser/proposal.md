# PBT-052 — Парсер OnlineGantt `.gantt`

## Why

Импорт рабочего формата `.gantt` — согласованная возможность первой версии (решения §16: «нужен импорт рабочего формата `.gantt` из предоставленного примера»). Ядро планирования (PBT-030–036), календарная арифметика (PBT-013) и образец диагностики (`parsePlanContent`, `deserializePlanFile` из PBT-050) готовы; для запуска цепочки импорта (PBT-053 — предпросмотр/применение, PBT-054 — преобразование отпусков) не хватает чистого преобразования «файл → документ плана + отчёт импорта».

## What Changes

- **Новый модуль разбора** `packages/gantt/src/onlinegantt-parser.ts`: чистая функция `parseOnlineGanttFile(text, options)` → результат `ok` с `PlanContent` (модель v1, без расширения схемы) и **отчётом импорта**, либо отказ с перечнем диагностик. Без UI — потребитель PBT-053.
- **Иерархия:** вложенность `subtasks` файла переносится в группы плана (контейнер с подзадачами → группа, рекурсивно; даты и длительность контейнера — производные исходника и не переносятся). Подтверждено вторым примером (`Online Gantt 20261016.gantt`: контейнеры «Отпуск» и «ОКАД», 47 листьев-задач, 9 ресурсов); плоский файл (первый пример) групп не содержит.
- **Конвертация дат:** UTC-метки файла → календарные даты `YYYY-MM-DD` по часовому поясу плана (`advanced.timezone`, резервно `timezoneOffset`); подтверждено примером: `EndDate` — включительный последний день (17:00 МСК), `Duration` исходника — производное и не переносится.
- **Календарь:** `advanced.workWeek` → `calendar.workingDays`; праздники `advanced.holidays` → `calendar.holidays` по той же конвертации дат; `workTime` (часы) и настройки отображения не переносятся — перечисляются в отчёте.
- **Зависимости:** строки `Predecessor` (`15FS`, `7FS+14 days`, несколько предшественников у записи) → `dependencies` с `lagDays`; неподдержанные типы связей (SS/FF/SF) и некорректные записи — диагностика, без молчаливого принятия.
- **Ресурсы и назначения:** `resources` → справочник ресурсов; `task.resources` → `assigneeIds`; загрузка `unit` сохраняется в данных доп. полем (ADR PBT-003 D3), на проверки не влияет.
- **Отпуск-строки** (задачи без назначений) остаются обычными задачами: автоматическое распознавание отпуска по имени не выполняется (D7 — преобразование с явным выбором ресурса в PBT-054).
- **Диагностика** по образцу `parsePlanContent`/`deserializePlanFile`: код/путь/сообщение; повреждённый вход не выдаётся за план; проблемы отдельных записей (невалидная дата, битая ссылка, дубль ID) — предупреждение в отчёте с пропуском записи, фатальные проблемы файла — отказ.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `plan-transfer`: ADDED — требования к разбору файла OnlineGantt `.gantt`: план и отчёт импорта, конвертация дат по таймзоне, FS-строки с лагом, календарь и рабочая неделя, политика дополнительных полей (`unit`, `info`, `color`, `Progress`, исходные ID), диагностика повреждённого входа.

## Impact

- **Код:** только `packages/gantt` — новый `onlinegantt-parser.ts` (+ типы отчёта); ядро, SDK, платформа и UI не меняются.
- **Тесты:** unit в `packages/gantt/src/onlinegantt-parser.test.ts` (малые входы: несколько предшественников, вложенность `subtasks`, повреждения, неподдержанные поля); тесты обоих рабочих файлов в `tests/fixtures/gantt/` по паттерну PBT-050 (плоский `diagramm.gantt` и иерархический второй пример — эталонные копии рядом с тестами, вне tsconfig пакетов).
- **Зависимости:** новые библиотеки не вводятся (конвертация дат — стандартный `Intl`/`Date`, прецедент `reference-gantt.ts`).
- **Границы карточки:** 47 записей / 9 ресурсов рабочего файла; `Europe/Moscow`; DoD карточки покрывается тестами.

## Non-Goals

- UI выбора файла, предпросмотра и применения импорта — PBT-053.
- Преобразование отпуск-строк в периоды недоступности и интерфейс выбора ресурса — PBT-054 (D7).
- Экспорт в формат `.gantt` (обмен с OnlineGantt однонаправленный: вход только).
- Воспроизведение почасового календаря `workTime` (модель — дни, ADR PBT-003), настроек отображения (`columns`, `zoomLevel`, `dateFormat`), правила `dependencyConflict` исходного инструмента.
- Автогруппировка плоского списка без `subtasks` (группы из иерархии файла переносятся; недостающие создаёт пользователь вручную — решения §10).
- Изменение модели `PlanContent`/`schemaVersion` — расширения только через доп. поля (passthrough PBT-050).

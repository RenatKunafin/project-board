## MODIFIED Requirements

### Requirement: Импорт файла с валидацией

Модуль SHALL десериализовать файл собственного формата с полной проверкой до выдачи плана: корректность JSON, наличие и типы полей конверта, совпадение маркера формата, поддержка версии формата и версии содержимого, валидность содержимого плана. Неизвестный идентификатор цвета задачи SHALL нормализоваться в автоматический цвет на шаге разбора; остальные проверки смягчения не имеют. Повреждённый или чужой файл MUST NOT выдаваться за план: результат SHALL содержать перечень диагностических сообщений с кодом, местом и причиной; входные данные MUST NOT изменяться. Проверка содержимого SHALL повторять полную валидацию плана при чтении, включая структуру, форматы дат, уникальность идентификаторов, внутренние ссылки и циклы групп.

#### Scenario: Повреждённый JSON даёт диагностику

- **GIVEN** текст файла обрезан и не является корректным JSON
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику синтаксической ошибки JSON
- **AND** план не создаётся

#### Scenario: Чужой формат распознаётся

- **GIVEN** файл с маркером формата, не совпадающим с маркером приложения
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику неизвестного формата
- **AND** содержимое файла не интерпретируется как план

#### Scenario: Невалидное содержимое даёт полный перечень проблем

- **GIVEN** файл формата приложения, содержимое которого ссылается на несуществующую группу и содержит цикл вложенности групп
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику обеих проблем с указанием места
- **AND** план не создаётся

#### Scenario: Валидный файл выдаёт план с названием

- **GIVEN** файл формата приложения с корректным содержимым и названием плана
- **WHEN** выполняется десериализация
- **THEN** результат содержит план, эквивалентный содержимому файла, и название для создаваемого документа

#### Scenario: Неизвестный цвет файла нормализуется в автоматический

- **GIVEN** файл формата приложения с задачей, цвет которой — неизвестный палитре идентификатор
- **WHEN** выполняется десериализация
- **THEN** план создаётся, задача без ручного цвета, остальное содержимое задачи сохранено
- **AND** файл с повреждённой датой в той же задаче по-прежнему отклоняется с диагностикой

### Requirement: Round-trip без потерь

Последовательные сериализация и десериализация плана SHALL восстанавливать название и все разделы содержимого без изменений, включая поддержанные дополнительные поля внутри сущностей содержимого и ручной цвет задач (идентификатор палитры либо его отсутствие). Повторный экспорт десериализованного плана SHALL давать эквивалентный файл без смены версии формата.

#### Scenario: Round-trip контрольного плана

- **GIVEN** план со всеми разделами модели
- **WHEN** план сериализуется в файл и десериализуется обратно
- **THEN** название и все разделы содержимого эквивалентны исходным

#### Scenario: Дополнительное поле сохраняется при переносе

- **GIVEN** файл, в содержимом которого у задачи присутствует неизвестное приложению поле
- **WHEN** файл десериализуется и результат сериализуется снова
- **THEN** дополнительное поле задачи сохраняется в полученном файле

#### Scenario: Ручной цвет сохраняется в round-trip

- **GIVEN** план с задачами, у части задан ручной цвет, у части он отсутствует
- **WHEN** план экспортируется в файл и импортируется обратно
- **THEN** идентификаторы цветов и отсутствие поля у неокрашенных задач сохраняются точно, версия формата не меняется

### Requirement: Политика дополнительных полей импорта

Разбор OnlineGantt SHALL документированно распоряжаться полями файла вне модели плана без молчаливой потери: процент загрузки назначения (`unit`) сохраняется в данных плана и не влияет на проверки; примечания (`info`) сохраняются как текст без HTML-разметки; цвет записи переносится в ручной цвет задачи только при точном совпадении его hex-значения (после нормализации регистра) со значением палитры цветов проекта, при отсутствии совпадения устанавливается автоматический цвет; прогресс и признак длительности не переносятся и перечисляются в отчёте; исходный идентификатор записи восстановим из идентификатора задачи.

#### Scenario: Загрузка назначения сохраняется без влияния на проверки

- **GIVEN** файл с назначением `unit: 100`
- **WHEN** выполняется разбор файла
- **THEN** назначение сохраняется в данных плана вместе с загрузкой
- **AND** проверки конфликтов не учитывают загрузку (правило ADR PBT-003 D3)

#### Scenario: Примечание сохраняется текстом

- **GIVEN** файл с примечанием записи в формате HTML
- **WHEN** выполняется разбор файла
- **THEN** примечание сохраняется как текст без тегов и не исполняется как разметка

#### Scenario: Цвет записи совпадает с палитрой и переносится

- **GIVEN** файл с цветом записи `#3186E9`
- **WHEN** выполняется разбор файла
- **THEN** задача получает ручной цвет `sapphire`

#### Scenario: Непереносимые поля перечислены

- **GIVEN** файл с цветом записи `#123456`, не входящим в палитру, и с полями прогресса у записей
- **WHEN** выполняется разбор файла
- **THEN** задача импортируется без ручного цвета (автоматический цвет), план не содержит прогресса
- **AND** отчёт импорта перечисляет неперенесённый прогресс и признак длительности

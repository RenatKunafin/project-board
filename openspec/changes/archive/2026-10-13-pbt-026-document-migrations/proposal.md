# PBT-026 — Версии БД и миграции документов

## Why

Двухуровневая версия согласована (решения §15.5): версия схемы БД (структура хранилищ) и `schemaVersion` содержимого документа — но миграции содержимого не реализованы. Документ с устаревшим `schemaVersion` восстановится как есть, а документ из более нового приложения будет восстановлен и молча перезаписан текущей схемой — данные пользователя разрушатся. Согласовано: миграции выполняются модулем-владельцем по `schemaVersion`; структура и содержимое — независимые уровни (§15.5), будущая версия не перезаписывается (DoD карточки).

## What Changes

- SDK: дескриптор документной поддержки дополняется списком миграций содержимого — шаги `from → to` с чистой функцией преобразования; `schemaVersion` дескриптора объявляет актуальную версию.
- Сервис документов: при восстановлении хранилища документы с устаревшей версией преобразуются цепочкой зарегистрированных миграций (от хранимой версии к актуальной), результат фиксируется в хранилище одной транзакцией. `schemaVersion` поднимается, `revision` сохраняется — миграция приводит формат, но не создаёт пользовательской редакции.
- Сбой на любом шаге цепочки оставляет документ нетронутым в хранилище: восстановление продолжается с остальными документами, проблема доступна приложению для отображения.
- Документ будущей неподдерживаемой версии: читается и отображается (с отметкой версии), но операции записи (обновление, переименование, удаление) отклоняются ошибкой — текущее приложение не перезаписывает и не уничтожает данные, которые написало более новое приложение.
- Миграция фиксируется один раз: повторное восстановление не трогает документы с актуальной версией.

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- `document-management` — ADDED: миграции содержимого при восстановлении (цепочка шагов модуля, однократность, разные функции `schemaVersion`/`revision`), обработка документа будущей версии (чтение без записи), диагностика сбоя преобразования.
- `local-persistence` — ADDED: атомарное применение миграций при восстановлении — сработавшая цепочка фиксируется одной транзакцией, сбой оставляет хранимый документ нетронутым.
- `widget-registry` — MODIFIED: дескриптор документной поддержки дополняется миграциями содержимого (шаги `from → to`); актуальная версия объявляется `schemaVersion` дескриптора.

## Non-goals

- Миграции структуры IndexedDB (хранилищ и индексов) — реализованы в PBT-024, поведение покрыто `local-persistence` («Расширение схемы сохраняет документы»).
- Откат документа к прошлой версии и история версий.
- Миграции по требованию при открытии одного документа — только пакетно при восстановлении хранилища.
- Перенос ленивого дополнения названия старым записям (PBT-025) в механизм миграций: название — метаданные оболочки, а не содержимое; компромисс остаётся как принят.
- Экспорт/бэкап документа будущей версии (PBT-064/065 — вне основного плана).

## Impact

- `packages/widget-sdk`: тип миграционного шага и дополнение `WidgetDocumentSupport` (опциональный список миграций).
- `packages/dashboard`: `document-service` — восстановление с миграциями, атомарная фиксация, реестр проблем, guard будущих версий в `update`/`rename`/`delete`; экспорт новых типов.
- `packages/checklist`, `packages/gantt`: регистрация пустых списков миграций (актуальные версии 1) — контракт вступает в силу без продуктовых миграций.
- Тесты: интеграционные — старая фикстура (реальная структура прошлой версии из тестового модуля), цепочка 0→1→2, сбой шага, будущая версия (реальная запись `schemaVersion` больше актуальной); кардинально — без mock-only проверок (DoD).
- Каталог документов: строка документа будущей версии с отметкой; операции блокируются (без молчаливого скрытия).

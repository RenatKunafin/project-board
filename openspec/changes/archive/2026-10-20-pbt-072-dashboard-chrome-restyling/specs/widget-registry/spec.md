## MODIFIED Requirements

### Requirement: Регистрация типа виджета при сборке

Платформа SHALL принимать типы виджетов только через список определений, переданный приложением при инициализации. Определение типа SHALL содержать непустой идентификатор, название, компонент содержимого, стартовые настройки и ограничения размеров окна, а также MAY содержать иконку, краткое описание назначения типа для каталога и дескриптор документной поддержки (модуль, тип документа, версия схемы, фабрика содержимого нового документа и опциональные миграции содержимого). Фабрика содержимого SHALL создавать начальное содержимое без названия: название документа задаётся пользователем и передаётся сервису документов при создании. Актуальная версия содержимого SHALL объявляться версией схемы дескриптора. Миграции содержимого SHALL задаваться упорядоченными шагами «от версии → к версии» с чистой функцией преобразования содержимого; шаги одного документа MUST NOT иметь разрывов между хранимой версией и актуальной при восстановлении. Повторная регистрация типа с уже существующим идентификатором SHALL отклоняться ошибкой регистрации с указанием конфликтующего идентификатора. Пропсы компонента виджета SHALL включать, помимо идентификатора экземпляра и настроек, опциональные ссылку на документ (`documentId`) и сервис документов (`documentService`), передаваемые платформой при создании экземпляра.

#### Scenario: Успешная регистрация типа

- **GIVEN** приложение инициализирует платформу списком из одного определения с идентификатором `demo`
- **WHEN** платформа создаёт реестр
- **THEN** реестр содержит тип `demo` с переданным названием, компонентом, стартовыми настройками и ограничениями размеров

#### Scenario: Дубликат идентификатора отклоняется

- **GIVEN** список определений содержит два типа с идентификатором `demo`
- **WHEN** платформа создаёт реестр
- **THEN** создание завершается ошибкой регистрации, сообщение содержит `demo`

#### Scenario: Экземпляр с документом получает ссылку и сервис

- **GIVEN** платформа создаёт экземпляр типа, работающего с документом, для документа `doc-1`
- **WHEN** компонент экземпляра рендерится
- **THEN** компонент получает `documentId = "doc-1"` и `documentService` через пропсы наряду с `widgetInstanceId` и настройками

#### Scenario: Каталог отображает иконку и название

- **GIVEN** зарегистрирован тип с иконкой и названием
- **WHEN** платформа открывает каталог типов
- **THEN** каталог отображает иконку и название зарегистрированного типа

#### Scenario: Каталог отображает карточку с описанием типа

- **GIVEN** зарегистрирован тип с описанием «Диаграмма Ганта: задачи, сроки, зависимости»
- **WHEN** пользователь открывает каталог виджетов
- **THEN** карточка типа показывает название и описание; поиск находит тип и по тексту описания

#### Scenario: Создание документа через фабрику и сервис

- **GIVEN** зарегистрирован тип с документной поддержкой (модуль `checklist`, тип `list`, схема 1)
- **WHEN** пользователь создаёт документ с названием «Покупки»
- **THEN** начальное содержимое создаётся фабрикой без названия, а название «Покупки» хранится в метаданных документа

#### Scenario: Дескриптор с миграциями принимается реестром

- **GIVEN** определение типа с дескриптором документной поддержки, содержащим миграции «0 → 1» и «1 → 2» и актуальной версией схемы 2
- **WHEN** платформа создаёт реестр
- **THEN** дескриптор доступен платформе с полным списком шагов и актуальной версией

# Design — PBT-015: спайк React Calendar Timeline (ресурсные дорожки)

## Context

Проектное представление проверено (PBT-014: SVAR — «подходит с ограничениями»). Ресурсное — компактные дорожки (решения 13.2): слева ресурс, справа — его назначенные задачи на шкале, пересечения укладываются по высоте внутри дорожки; отпуск — недоступность конкретного ресурса; планирование по дням, включительное окончание (ADR PBT-003). Кандидат — React Calendar Timeline (RCT), MIT; в решениях отмечено: ветки stable 0.28 и TS/React-18 0.30.0-beta, версию выбирать осознанно. Из спайка PBT-014 перенесены уроки: даты библиотеки могут быть в иной семантике (конвертация в адаптере, A1), payload жестов ненадёжен (сверка «стор → правила → стор»), колонки/шаблоны придётся кастомизировать.

## Goals / Non-Goals

**Goals:**

- Ответить на вопросы DoD карточки PBT-015 воспроизводимым прототипом на `small-plan.json`.
- Проверить React 18-совместимость конкретной версии и зафиксировать пин.
- Собрать факты для PBT-017: API жестов, укладка пересечений, ограничение точности до дня.

**Non-Goals:**

- Продуктовая интеграция, тесты продуктового поведения, проверка SVAR.
- Процентная загрузка, календари внутри библиотеки (D3: частичная занятость вне v1).

## Decisions

### D1. Место: отдельное приложение `apps/resource-timeline-spike`

Изоляция как в PBT-014: не в прод-сборке, своя команда `dev:resource-spike` (порт 5175), `typecheck` корня дополняется. Судьба после PBT-017 — удалить вместе с `apps/gantt-spike` или принять отдельным решением. Альтернатива «второй экран внутри gantt-spike» отвергнута: кандидаты независимы, сравнение должно быть по чистым стендам.

### D2. Версия: `react-calendar-timeline@0.30.0-beta.19` (пин в package.json)

Последняя TS/React-18/19 бета (обновление пакета — 2026-07-24), peer `react ^18||^19` — совместима с 18.3.1; без бета-прыжков внутри эксперимента. Stable-линия 0.28 не имеет React-18/19 поддержки в типах. Риск беты фиксируется в отчёте (open issues/known problems не исследуем глубже прототипа). Альтернатива «0.28 stable» отвергнута: без TS и React-18 гарантий.

### D3. Данные: фикстуры → groups/items адаптером

`small-plan.json` → RCT: ресурсы `r1`, `r2` → groups; задачи с `assigneeIds` → items **на дорожке каждого назначенного ресурса** (D1); неназначенные — не попадают в timeline (D2); отпуск R1 (26–27.10) → item в дорожке R1 с классом недоступности (D6-визуал); выходные/праздник 14.10 → фон всей шкалы. Дни: границы элемента — полночь дня начала и полночь дня **после** включительного окончания (конвертация A1, как в PBT-014).

### D4. Жесты: `onItemMove`/`onItemResize` → наши правила → стор RCT

Синхронизация по схеме PBT-014: после жеста читаем факт из стора RCT, применяем правила ADR PBT-003 и записываем обратно. Правила ресурсного спайка:

- drag задачи: рабочая длительность сохраняется, начало привязывается к рабочему дню в сторону переноса (A2);
- resize краёв: дата сохраняется как введена, даже нерабочая (A3); рабочая длительность пересчитывается (A4/A6);
- отпуск при перетаскивании задачи не двигается; пересечение задачи с отпуском визуально видно (проверка D6-визуала), подсветка конфликтов — не в этом спайке (PBT-036).

### D5. Точность до дня

RCT оперирует миллисекундами; при resize/drag снапим к границам суток (своим кодом при применении правил). Проверяется поведение при зуме: день ≥ 40px, чтобы drag в пределах дня был предсказуем. Пересечения: `stackItems` включён — укладка по высоте внутри дорожки (DoD-пункт 1).

### D6. Проверки спайка: ручной сценарий + typecheck/lint, без e2e

Как в PBT-014: research-задача, воспроизводимость — команды отчёта. В корень добавляются `dev:resource-spike`; `typecheck` дополняется проектом; ESLint — корневым прогоном. Автотесты не пишутся.

### D7. Референс OnlineGantt Resource View и консистентность стиля

Референс изучен (Resource View в сендвич-меню OnlineGantt): ресурс — сворачиваемая группа, под ним его задачи; у каждой группы ресурса — тёмная сводная полоса занятости; задачи раскрашены как в проектном виде; выходные — колонки темнее. Берётся **суть** (лента занятости ресурса: когда занят и где окна; единый стиль с проектным видом), а не иерархия «ресурс → подстроки» (отвергнута решением 13.2 — у нас компактная дорожка).

Стиль — консистентен с `apps/gantt-spike` (PBT-014): синие полосы задач `rgb(57,131,235)`, выходные `#e3e7ec`, праздник `#f8d3d3` на всю высоту, колонки «Задача / Начало / Раб. дни», легенда.

### D8. Лента занятости ресурса (union)

Назначение ресурсного вида — загрузка: когда ресурс занят и где окна. В дорожку ресурса добавляются тёмные элементы «занятость» — union непрерывных интервалов назначений ресурса (вычисляется адаптером из задач; отпуск не входит — он отдельный элемент недоступности). `stackItems` укладывает: ожидание — лента занятости верхним рядом, задачи под ней, окна видны разрывами ленты. Если RCT уложит иначе — фиксируется в отчёте; запасной вариант: отдельная группа «загрузка» над дорожкой задач.

## Risks / Trade-offs

- Бета-версия пакета: возможны баги RCT — фиксируются как ограничения; если блокируют DoD — вывод «не подходит» и поиск альтернативы (право владельца на PBT-017).
- API жестов RCT (interactjs) может отдавать время с дробными границами — снап решает; если снап нестабилен — фиксируется как блокер интеграции.
- Отпуск как item может визуально конфликтовать с укладкой задач (stackItems) — проверяется; при необходимости item в отдельной «дорожке отпусков» под ресурсом (запасной вариант, фиксируется в отчёте).
- Дублирование item'а задачи на дорожках нескольких ресурсов (D1) — при drag двигается задача на обеих дорожках; проверяется, что RCT обрабатывает это предсказуемо (items независимы — двигаем оба программно).

## Context

Готово: реестр типов (PBT-006), `DocumentService` с viewSettings (PBT-007), IndexedDB store (PBT-009), автосохранение и восстановление (PBT-010), модуль чек-листа (PBT-008). Оболочка уже показывает два экземпляра одного документа — исследование структурирует это в вертикальный срез и фиксирует наблюдения. Ключевой сценарий этапа 1 решений: подключить модуль при сборке, открыть один список в двух виджетах, проверить общие изменения и независимые настройки, перезапустить.

## Goals / Non-Goals

**Goals:**

- Демонстрация: два экземпляра одного списка + отдельный второй список; локальные настройки per-экземпляр; закрытие/повторное открытие; восстановление.
- E2E-защита синхронизации и восстановления (минимальный набор, не дублирующий unit).
- Research-отчёт с наблюдениями и выводом по достаточности SDK.

**Non-Goals:**

- Окна, вкладки, каталог, перетаскивание (PBT-018+), выбор документа из списка (PBT-025), второй тип представления списка (по смыслу PBT-011 это два виджета одного документа — таблица и «карточки» не требуются).
- Правки контракта SDK по итогам исследования — оформляются отдельными решениями/changes.
- Автоматизация представления «закрытие = unmount» как продуктового поведения жизненного цикла (PBT-027).

## Decisions

- **Два документа в bootstrap.** При старте гарантируются два документа чек-листа: «Список 1» и «Список 2» (если их меньше двух после `restoreAll` — досоздаются). Привязка экземпляров: `w-1`, `w-2` → первый документ; `w-3` → второй. Ключи viewSettings = id экземпляра (`w-1`…).
- **Локальная настройка — «Скрывать выполненные».** Чекбокс в шапке панели; хранится в `viewSettings[w-N]`; фильтрует отображение (пункты с `done` не рендерятся), документ не трогает. Проверяет: изоляция настроек (DoD-2) и то, что viewSettings не порождают уведомлений (PBT-007).
- **Закрытие экземпляра — локальный state оболочки.** `visible: {w1, w2, w3}`; закрытие = unmount компонента (подписка снимется в cleanup useEffect) + кнопка «Открыть» для возврата. Перезагрузка сбрасывает видимость (все панели видны) — документ при этом восстановлен (DoD-3).
- **E2E — минимальный набор из 4 проверок:** синхронизация 1↔2 при изоляции 3; локальная настройка изолирована; закрытие + перезагрузка сохраняют данные; повторное открытие показывает данные. Остальные сценарии уже покрыты unit (сервис) — не дублируем.
- **Research-отчёт — `.context/research/PBT-011.md`** (research переехал из `docs/research` вместе с документацией в PBT-006-периоде; путь фиксируется в config-контексте). Структура: окружение/запуск, сценарий с командами, наблюдения (что подтвердилось), ограничения (что не покрыто), вывод «подходит с ограничениями» + список уточнений для PBT-018+/SDK.

## Risks / Trade-offs

- [Демо-код в оболочке останется надолго] → сознательно: это вертикальный срез до PBT-018; при появлении вкладок переносится в оконный менеджер.
- [Локальная настройка на фильтре отображения не проверяет реальные «размеры окна»] → размеров окон ещё нет (PBT-020+); «изменение размера» из карточки интерпретируется как локальная настройка представления — зафиксировано в отчёте как ограничение.

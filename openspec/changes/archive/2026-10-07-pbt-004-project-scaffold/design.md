## Context

Решения приняты в [ADR PBT-002](../../.docs/adr/PBT-002.md): React + TypeScript + Vite (ADR-1), npm workspaces (ADR-2), структура и направления зависимостей (ADR-3), целевые браузеры ES2022 (ADR-4). Node v22.12.0, npm входит в поставку Node. Каркас — первый код в репозитории; ничего, кроме оболочки и заглушек пакетов, не создаётся.

## Goals / Non-Goals

**Goals:**

- Минимально запускаемое приложение: `npm install` → `npm run dev` → пустая оболочка в браузере.
- Четыре пакета-заглушки с корректными границами зависимостей, готовые к наполнению задачами PBT-006+.
- Воспроизводимая сборка: lockfile, `build` даёт статические ресурсы, `preview` их отдаёт.
- Единый `typecheck` по всем пакетам.

**Non-Goals:**

- Реестр виджетов и SDK API (PBT-006), состояние документов (PBT-007), тестовый раннер и линтер (PBT-005), CI (PBT-005), PWA-манифест и service worker (PBT-028).
- Выбор библиотек тайлинга/Гантта — они не устанавливаются.

## Decisions

**Итог ревью владельца (2026-10-07):** React 18.3 подтверждён; остальной состав каркаса — прямое воплощение ADR PBT-002 без новых решений.

- **Версия React — 18.3.x (не 19).** Кандидаты-библиотеки (React Grid Layout, react-rnd, React Calendar Timeline) исторически заявляют совместимость до React 18; 19 добавляет риск при их подключении в PBT-006+. ADR-002 допускает «React 18/19» — фиксируем нижнюю границу диапазона. Переход на 19 — отдельное решение при подтверждении совместимости.
- **TypeScript — strict**, ES2022 target/module (ADR-4). Схема конфигов: корневой `tsconfig.base.json` (общие флаги), в каждом пакете `tsconfig.json`, наследующий базу; `typecheck` = `tsc --noEmit` по всем пакетам через `npm run typecheck -ws` (workspaces) + корневой скрипт-агрегатор. Project references не вводим — оверкилл для каркаса, сборка пакетов первой версии остаётся в ответственности Vite.
- **Пакеты — `private: true`, ESM (`"type": "module"`).** Публикация в npm не планируется; монорепо собирается приложением. Экспорт каждой заглушки — минимальный `src/index.ts` с типом-маркером пакета (например, `export const PKG = 'dashboard' as const`), чтобы import работал и typecheck был содержательным.
- **Направления зависимостей (ADR-3):** `widget-sdk` — без зависимостей от пакетов проекта; `dashboard` — зависимость от `react`/`react-dom` только; `gantt`, `checklist` — зависимость от `widget-sdk` (`workspace:*`). Приложение зависит от всех четырёх. Проверка границы вручную на ревью; автоматизация — PBT-005.
- **Место подключения модулей:** в `apps/project-board/src` создаётся `widgets.ts` — единственная точка регистрации типов виджетов, пока возвращает пустой список; наполнение — PBT-006. Фиктивные реализации (добавление чек-листа в каталог) не делаются.
- **Оболочка:** компонент `App` рендерит заголовок «Project Board» и текст-заглушку; стили — один CSS-файл без фреймворков; тема и дизайн-система — вне каркаса.
- **Vite — актуальная стабильная мажорная версия на момент установки**; конкретная версия фиксируется `package-lock.json` и записывается в `.context/openspec-setup.md` и README. PWA-плагины не ставятся (PBT-028).
- **Node engines:** `"engines": { "node": ">=22" }` в корневом `package.json`; `packageManager` не указывается (npm берётся из Node 22; строгий pin через corepack нужен только при переходе на pnpm/yarn).

## Risks / Trade-offs

- [React 18 vs 19 — будущая миграция] → переход тривиален при отсутствии breaking usage; решается после проверки кандидатов.
- [`tsc --noEmit` по пакетам медленнее project references при росте числа пакетов] → на 5 конфигах незаметно; оптимизация — по мере необходимости, не в каркасе.
- [Версия Vite «на момент установки» не воспроизводится на другой машине] → воспроизводимость обеспечивает `npm ci` по lockfile; версия фиксируется в документации.

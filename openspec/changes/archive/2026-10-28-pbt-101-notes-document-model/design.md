## Context

См. `proposal.md` и `specs/notes/spec.md`. SDK задаёт оболочку `ManagedDocument` с `schemaVersion`, `revision` и `content`; `DocumentService.update` принимает ожидаемую редакцию и синхронно уведомляет подписчиков в памяти. При несовпадении редакций он выбрасывает `DocumentConflictError`. Платформа отдельно выполняет отложенную запись в хранилище.

## Goals / Non-Goals

**Goals:**
- Оставить доменную модель и операции внутри `packages/notes`, используя только публичный SDK.
- Применять операции к актуальному снимку, не теряя независимые изменения соседних заметок.
- Сохранить локальный черновик, когда приходит изменённая версия той же заметки.

**Non-Goals:**
- Изменять `DocumentService`, формат общей резервной копии или платформенную стратегию автосохранения.
- Хранить основной текст заметки в настройках отдельного окна.
- Сливать конкурентные изменения текста автоматически.

## Decisions

1. **Содержимое — `{ notes: Note[] }`, версия формата — оболочка `ManagedDocument.schemaVersion`.** Это следует существующему SDK и проектному решению PBT-101; не вводится параллельная версия внутри content. Каждая заметка содержит `id`, `title`, `body`, `tags`, `pinned`, `updatedAt`. Для даты используется ISO 8601 UTC строка, как у метаданных документа; исходный Markdown `body` сохраняется посимвольно, включая завершающие пробелы и пустые строки. Пустое тело разрешено, заголовок после trim обязателен и не обрезается молча; произвольные лимиты длины не вводятся. Рассматривался timestamp в миллисекундах из прототипа, но ISO строка согласуется с SDK и резервной копией.

2. **Создание новой модели начинается с пустого списка.** Парсер возвращает структурированный результат или диагностируемую ошибку; повреждённый снимок и будущая версия не превращаются в демо или пустой документ. Проверяются объектная форма, обязательные поля, типы, дата и уникальность ID. Схема версии равна текущему типу документа в регистрации миграций приложения; пакет не импортирует dashboard для её чтения.

3. **Изменения — чистые операции плюс тонкий адаптер SDK.** Чистые функции строят новый content, сохраняя неизвестные соседние поля документа на уровне оболочки и не меняя входные объекты. Адаптер передаёт `document.revision` в `DocumentService.update`. При конфликте он перечитывает актуальный документ через `get`; независимая операция над другой заметкой повторно применяется к актуальному снимку, а изменение той же заметки возвращает вызывающему коду состояние конфликта. No-op возвращает исходный снимок без вызова `update`, чтобы не создавать фиктивную редакцию.

4. **Входящее изменение не заменяет грязный редактор.** Подписка предоставляет новое содержимое. Если черновик редактора чистый, отображается новая версия. Если локальный текст изменён, держатель черновика сохраняет его отдельно от актуального документа и сообщает UI о конфликте. Разрешение: принять сохранённую версию или создать из черновика отдельную заметку; так пользователь сохраняет обе версии без автоматического merge. Попытка закрыть/переключить конфликтный черновик должна запросить явный выбор. Черновик остаётся состоянием окна в памяти до разрешения; его отдельное долговременное хранение не входит в этот change и не должно маскироваться под гарантированное сохранение.

5. **Удаление необратимо, подтверждение принадлежит UI.** Доменная операция удаляет одну заметку; вызывающая UI обязан получить подтверждение до вызова. Корзина и восстановление не добавляются.

## Risks / Trade-offs

- Локальный черновик конфликта пока не переживает закрытие/перезагрузку окна → до закрытия требовать явный выбор и сообщать, что вариант не сохранён; постоянные черновики можно рассмотреть отдельно.
- Сериализация ISO timestamp отличается от прототипа в миллисекундах → формат прототипа не является пользовательскими данными; преобразование включить в тесты и не молча принимать некорректные даты.
- SDK хранит синхронное состояние в памяти и асинхронно сохраняет его → ошибки постоянного хранилища продолжают отображаться платформенным save-state; пакет не объявляет такую запись подтверждённой.

## Migration Plan

Новый тип документа не имеет ранее сохранённых пользовательских документов для миграции. Зарегистрировать поддержку текущей schemaVersion в composition root следует в PBT-102. Универсальный экспорт/импорт PBT-064 сохраняет документ как обычное содержимое; проверка round-trip остаётся частью интеграции PBT-102. Откат пакета не изменяет документы, а неизвестный тип остаётся в общей резервной копии согласно существующему поведению.

## Why

Для проекта выбран SDD-фреймворк OpenSpec, и дальнейшие задачи бэклога (PBT-002 и далее) должны выполняться по процессу «одна задача PBT = один OpenSpec change = один PR». Пока версия CLI не закреплена, проект не инициализирован, а правила артефактов не записаны, процесс не воспроизводим. Это bootstrap-задача без зависимостей, поэтому выполняется первой.

## What Changes

- Закрепить инструментальную основу: Node.js v22.12.0 и OpenSpec CLI 1.11.0, способ установки и запуска (см. `docs/openspec-setup.md`).
- Заполнить `openspec/config.yaml`: контекст проекта (ссылки на `docs/project-decisions.md`, бэклог и workflow) и правила артефактов (русский язык, схема `spec-driven`, различие принятых решений и гипотез).
- Зафиксировать уже созданную интеграцию OpenCode: команды `/opsx-propose`, `/opsx-apply`, `/opsx-archive`, `/opsx-explore`, `/opsx-sync`, `/opsx-update` и skills в `.opencode/`.
- Проверить реальные имена команд, работу `openspec validate --strict` и поддержку изменения без spec deltas (`skip_specs: true` в `.openspec.yaml`).
- Сам change оформляется по процессу после появления структуры OpenSpec; продуктовые требования в этом change отсутствуют.

## Impact

- Затрагиваются только каталоги `openspec/`, `docs/` (новая инструкция настройки, статусы бэклога) и существующая интеграция `.opencode/`.

- Последующие задачи PBT получают воспроизводимый процесс: закреплённую версию CLI, заполненный конфиг и правила артефактов.

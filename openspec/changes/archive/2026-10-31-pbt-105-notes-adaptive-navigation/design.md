## Context

См. `proposal.md` и delta `specs/notes/spec.md`. `NotesWidget` уже использует CSS container query на ширине 560px, но `selectedNoteId` — единственная настройка экземпляра, передаваемая редактору; поиск, тег, режим и выбор панели остаются состоянием React. SDK предоставляет `updateSettings(patch)` для настроек конкретного окна. Общая резервная копия уже сохраняет настройки каждого экземпляра отдельно от содержимого документов. Тело заметки и конфликтный ввод принадлежат `NotesEditor` и общему документу, не настройкам окна.

## Goals / Non-Goals

**Goals:**
- Довести существующую адаптацию до единой политики при изменении размеров окна, сворачивании, разворачивании и восстановлении раскладки.
- Переносить настройки интерфейса каждого окна через уже существующий контракт SDK и формат общего бекапа.
- Сохранить текст и сценарии разрешения конфликтов по действующим требованиям notes/PBT-101.
- Проверить минимальный размер окна и основную клавиатурную навигацию в реальном production e2e.

**Non-Goals:**
- Менять схему общего документа заметок или формат резервных копий.
- Вводить автоматическое сохранение черновиков в настройки окна либо автоматическое слияние правок.
- Менять платформенный SDK, общую семантику раскладок или правила восстановления неизвестных данных.
- Перепроектировать редактор, Markdown, поиск и бекап за пределами поведения PBT-105.

## Decisions

### 1. Единственная ширина адаптации — содержимое окна заметок

Сохранить уже применённую границу: меньше 560 CSS px — одна панель, от 560 CSS px — список и редактор рядом. Единицей измерения остаётся content box `.notes-widget` с CSS `container-type`, поэтому окна разной ширины на одном viewport могут показывать разную компоновку. Не вводить media query по viewport или отдельную ширину дашборда.

**Альтернативы:** использовать ширину viewport или дополнительный запасной порог. Они расходятся с требованием по конкретному окну и ломают поведение при нескольких окнах; отдельный порог не нужен, пока production e2e подтверждает 560px на минимальных размерах платформы.

### 2. Настройки интерфейса принадлежат экземпляру, а текст — документу

Расширить существующие настройки окна для `selectedNoteId`, `query`, `activeTag`, `mode` и последней узкой панели (`list`/`note`). Локальные React-состояния остаются источником немедленного отображения в открытом экземпляре; при изменении значения вызывается `updateSettings` с частичным патчем. Не ждать нового значения prop `settings` в уже смонтированном окне: SDK не обещает его обновление. Компонент и редактор продолжают хранить ввод в памяти и передавать его в общий документ существующим синхронным механизмом.

При старом/невалидном значении использовать безопасные defaults. `NotesEditor` разрешает выбранный ID только против текущего документа; отсутствующую заметку не создавать. Активный тег валидировать против текущих тегов и очистить только локальный фильтр и настройку окна. Любая очистка ссылки меняет только per-window settings, не содержимое или revision документа.

**Альтернативы:** сохранить режим и фильтры в документе заметок — это синхронизировало бы личные настройки двух окон вопреки их независимости. Ввести отдельную схему или миграцию бекапа — излишне, потому что общий сериализатор уже переносит JSON-настройки экземпляров, а старые снимки допустимо читать через defaults.

### 3. Узкая панель не сбрасывается при временном широком виде

Хранить последнюю панель `list`/`note` отдельно от ширины. Выбор заметки или создание новой заметки задаёт `note`; кнопка «Назад к списку» задаёт `list`; новая/старая настройка без значения означает `list`. В широком виде обе панели остаются доступными, а сохранённый выбор применяется при следующем сужении. Такой выбор не зависит от того, вызвано ли изменение ширины resize, разворачиванием или восстановлением сетки/каскада.

**Альтернативы:** вычислять активную панель заново при каждом переходе через порог; это стирает осознанный выбор и даёт разные результаты при resize и maximize. Автоматически менять активную панель только из-за ширины не нужно.

### 4. CSS определяет видимость, наблюдатель нужен только для фокуса

Оставить CSS container query источником правды о видимости панелей. `ResizeObserver` отслеживает контейнер лишь для проверки, не оказался ли активный элемент скрытым правилом компоновки. Если фокусированный элемент теряет layout box внутри виджета, перенести фокус на видимый элемент текущей панели; при обратной навигации вернуть фокус на выбранную карточку. События размера не должны менять фокус, если он был вне окна.

**Альтернативы:** дублировать порог в JS и решать в нём видимость — порог может разойтись с CSS. Полностью полагаться на браузерный фокус после `display:none` — поведение непоследовательно и может оставить клавиатуру вне видимого содержимого.

### 5. Общий бекап остаётся без изменений

Проверить сценарий через штатный интерфейс создания/скачивания/восстановления копии. Сравнить документы, идентификаторы, ссылки окон, настройки и геометрию в чистом хранилище; отдельными fixtures проверить backup до появления Notes и непрозрачный неизвестный модуль. Изменение capability `workspace-backup` не требуется, пока тесты подтверждают существующий контракт без патча платформы.

**Альтернатива:** расширить общий format schema ради заметок — отвергается, так как заметки уже представлены документом, а настройки окна переносятся общим механизмом.

## Risks / Trade-offs

- `[Risk]` `updateSettings` вызывается при наборе строки поиска и других быстрых изменениях. → `[Mitigation]` Передавать компактные частичные настройки, не менять документ и не добавлять задержку, которая может потерять последнее значение; проверить рабочую область после набора и reload.
- `[Risk]` Порог 560px может оставлять мало места редактору при фактических минимальных размерах. → `[Mitigation]` Проверить 1024×778 и 1856×1269, а также окно уже и шире 560px; если порог или минимальный размер платформы конфликтуют, остановиться и согласовать изменение до реализации.
- `[Risk]` Восстановленная настройка указывает на удалённую заметку/тег. → `[Mitigation]` Валидировать ссылки при открытии против актуального документа; очищать только настройку экземпляра и проверять отсутствие записи в документ.
- `[Risk]` Скрытие панели теряет фокус или мешает IME. → `[Mitigation]` Перемещать фокус только при его фактическом скрытии; завершение IME и конфликты оставлять существующему `NotesEditor` и проверять реальными клавиатурными событиями.

## Migration Plan

Формат документа и резервной копии не меняется. Старые настройки и резервные копии читаются с defaults: пустой поиск, без тега, режим «Текст», список для узкого вида; существующий fallback выбора заметки остаётся безопасным. Откат интерфейса не требует преобразования данных и не удаляет новые ключи настроек; предыдущий код их игнорирует. Выполнить один PR PBT-105 в `develop`, принять PR, затем архивировать change с sync `notes` по процессу проекта.

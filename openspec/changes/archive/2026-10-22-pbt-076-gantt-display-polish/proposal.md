# PBT-076 — Гантт: доводка отображения (тулбар, зум-семантика, каскад)

## Why

Замечания владельца 2026-10-21, отложенные из ревью PBT-073/PBT-074 до завершения серии редизайна (решение зафиксировано в карточке и реестре):

1. **Строка 2 тулбара** не по прототипу: поиск ограничен `max-width: 260px` вместо растяжки на всю доступную ширину, счётчик задач вообще без стилей (шрифт выбивается из ряда строки). Референс — `flexi-dashboard-hub/src/components/dashboard/GanttPrototype.tsx` (строки 55–58): `flex-1` поиск слева, зум-сегмент и счётчик `text-xs text-muted-foreground` справа.
2. **Семантика зума «Недели»** неинтуитивна: сейчас «Дни/Недели» меняют только ширину клетки дня (48/33), подписи шкалы остаются дневными в обоих режимах. Решение владельца: «Недели» — одна колонка шкалы = одна неделя (продуктовое изменение против прототипа, прототип недельную семантику не реализует).
3. **Каскад: окно за краем канваса недоступно** (баг владельца 2026-10-21): drag/resize за границы и восстановление геометрии из БД без проверки границ оставляют окно за пределами канваса (`overflow: hidden` — осознанно, PBT-069); кнопки рамки и resize-уголок недостижимы. Воркэраунд «Сетка» неприемлем как постоянное решение.

Пункт 3 карточки (ресайз-контролы каскадного окна по прототипу) **исключён из объёма по решению владельца** (планирование 2026-10-21): SVG-уголок «M9 3 L3 9 M9 6 L6 9» уже доставлен PBT-075 (ревью PR#54, финальные итерации) в обоих режимах и совпадает с `WidgetFrame.tsx` прототипа. В этой задаче остаётся только контрольная визуальная сверка с референсом `12-cascade-mode.png`.

## What Changes

- **Строка 2 тулбара (по прототипу)**: поиск растягивается на всю доступную ширину (`flex: 1 1 auto`, снимается `max-width`); селект ресурса и зум-сегмент прижимаются вправо за ним; счётчик задач — общий стиль строки (12px, `muted-foreground`), текст и `data-task-count` без изменений.
- **Недельная семантика зума «Дни/Недели»** (решения владельца 2026-10-21: подпись-диапазон, ~100px/неделя):
  - «Дни» — одна колонка шкалы = один день (cellWidth 48, подпись дд.мм — текущее поведение);
  - «Недели» — одна колонка = одна неделя: нижняя строка шкалы агрегирует дни в недельные колонки, подпись — диапазон «12–18 окт» (на стыке месяцев «28 окт – 3 ноя»); ширина недельной колонки ~100px (точная цифра — живой сверкой на design-этапе);
  - полосы задач, связи и подсветка нерабочих дней сохраняют дневную точность внутри недельных колонок (подсветка — собственный слой: `highlightTime` SVAR не срабатывает для week-клеток);
  - сохранение позиции прокрутки при смене режима — конверсия через день (механизм PBT-073 D6.5, пересчёт на px/день); состояние экземпляра в settings переживает reload (без изменений).
- **Каскад: окно всегда в границах канваса**: клампинг позиции и размеров в границы области вкладки — при изменении размера (сейчас resize не ограничен канвасом: `bounds` react-rnd действует только на drag), при восстановлении геометрии из БД (сейчас без проверки) и при изменении размеров канваса. Перенос уже ограничен (`bounds="parent"`), сохраняется. Хранимая геометрия не перезаписывается на старте (клампинг отображения; валидная запись — при следующей пользовательской операции).

## Impact

- **Код**: `packages/gantt/src/zoom-utils.ts` (пиксели дня вместо ширины клетки, форматтер диапазона недели), `PlanGanttWidget.tsx` (scales для week-юнита, слой подсветки нерабочих дней недельного режима), `gantt.css` (строка 2 тулбара, слой подсветки), `packages/dashboard/src/cascade-layout.ts` + `CascadeLayout.tsx` (чистый клампинг + измерение канваса).
- **Тесты**: unit — `zoom-utils.test.ts` (конверсия на px/день, форматтер диапазона), `cascade-layout.test.ts` (клампинг); e2e — недельные колонки (подпись-диапазон, дневная точность подсветки, reload), каскадный клампинг (resize за край, восстановление за краем).
- **Скриншоты до/после**: строка 2 тулбара, недельный зум (1024×778 и широкое окно), каскад до/после клампинга — в `change/screenshots/`.

## Non-Goals

- Пункт 3 карточки (ресайз-контролы каскада по прототипу) — исключён решением владельца: доставлено PBT-075; остаётся контрольная сверка с `12-cascade-mode.png` без правок при совпадении.
- Хэндл ресайза сетки RGL — не трогаем (рассинхрон жестов, прецедент PBT-068).
- Зум колесом/плавный зум SVAR (`zoom-scale`) — вне задачи: только два дискретных режима сегментом.
- Ресурсный вид, светлая тема (PBT-066), переупорядочивание строк — вне задачи.
- Перезапись сохранённой геометрии каскада на старте приложения (без пользовательской операции) — сознательно не делаем: клампинг отображения достаточно, валидная геометрия фиксируется первым же переносом/ресайзом.

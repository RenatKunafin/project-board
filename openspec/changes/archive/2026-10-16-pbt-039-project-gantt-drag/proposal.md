# PBT-039 — Перетаскивание и изменение длины задач

## Why

Проектный Гантт (PBT-037) — просмотр; даты меняются только формой (PBT-038). Жесты drag/resize — основной способ планирования: переносят задачу и меняют длительность прямо на шкале. Механизм жестов SVAR ненадёжен (ADR PBT-017, ADR-5): payload событий нельзя считать источником данных, стор расходится с документом — нужен обмен «факт → правила ядра → применение» после завершения жеста.

## What Changes

- Разрешаются жесты drag полосы и resize краёв для строк задач; перехватчик PBT-037 `drag-task → false` снимается для задач и сохраняется для сводных (группы не двигаются — B2).
- По mouseup/touchend — сверка стора SVAR с документом (3 чтения с задержками 80/450/1000 мс, спайк PBT-014): расхождение краёв классифицируется и применяется командами ядра: одинаковый сдвиг краёв → `moveTask` (A2), сдвиг левого края → `setTaskDates` с прежним окончанием (A3), правого → `setTaskDates` с прежним началом (A3).
- Одно логическое действие на жест: одна запись документа (движения указателя не пишут ничего). Отклонение ядром (например, перевёрнутый интервал при сжатии левее начала) — откат полосы в стор исходных дат (`update-task`) без записи документа: «отмена жеста».
- **Попутный фикс ядра (дополнение, вне исходных границ карточки):** в `moveTask` не учтён особый случай `addWorkingDays(x, 0) = nextWorkingDay(x)` — перенос однодневной рабочей задачи давал окончание на следующий рабочий день (длительность 2 вместо 1). Исправляется синхронно с `setTaskDuration` (длительность 1 при рабочем начале → окончание = начало) + регрессионный тест. Без фикса drag активирует баг на каждой однодневной задаче.

## Impact

- Изменённые: `packages/gantt/src/PlanGanttWidget.tsx` (механизм жестов, сверка стора), `packages/gantt/src/plan-commands.ts` (фикс `moveTask`), `packages/gantt/src/plan-commands.test.ts` (регрессия), e2e `plan-gantt.spec.ts` (драг-сценарии); design D6 PBT-037 остаётся в силе: init-канал занят заливкой, перехватчики — в init.
- Запись документа — существующий `documentService.update` с ретраем (PBT-038); ревизия +1 на жест; второй экземпляр обновляется remount'ом по ревизии.
- Окно платформы не перемещается жестом чарта: платформа таскает окно только за заголовок (PBT-020, прецедент react-rnd).
- Разблокирует: PBT-046 (конфликты после жестов), PBT-048 (те же правила в ресурсном виде).

## Non-Goals

- Автоперенос зависимых (сверка ADR-5 — отдельная задача, следить за spec).
- Drag сводных полос и drag создания связей стрелками.
- Точечные `update-task` вместо remount при успешном применении (remount по ревизии остаётся; замена — при претензиях к миганию, PBT-049-соседство с view state).

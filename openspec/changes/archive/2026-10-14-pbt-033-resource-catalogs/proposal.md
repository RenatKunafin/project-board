# PBT-033 — Ресурсы и типы работ

## Why

Модель плана v1 (PBT-030) содержит справочники ресурсов и типов работ, но операции над ними отсутствуют: справочники нельзя наполнить, переименовать или почистить. Без них невозможны назначения и недоступности (PBT-034), проверки конфликтов по параллельности (PBT-036, правило D4 «задача без типа — непараллелизуемая» работает только при управляемом справочнике типов) и редакторы справочников в UI (PBT-041). Ссылки на ресурсы и типы уже живут в данных (`tasks[].assigneeIds`, `tasks[].workTypeIds`, `unavailability[].resourceId`), и валидатор чтения отклоняет ссылки на несуществующие записи — операции удаления обязаны поддерживать план валидным. Задача закрывает третий слой операций ядра: каталоги ресурсов и типов работ конкретного плана, где идентичность задаётся ID, а не отображаемым именем.

## What Changes

- В `packages/gantt` добавляется модуль `plan-catalogs.ts`: чистые операции — `createResource`, `updateResource`, `deleteResource`, `createWorkType`, `updateWorkType`, `deleteWorkType`.
- Команды включаются в объединение `PlanCommand`; диспетчер `applyPlanCommand` расширяется — единый путь команд сохраняется. Новый код отклонения `invalid-title` (пустое/пробельное название после trim — по прецеденту `assertDocumentTitle` SDK).
- `allowsParallel` хранится в документе (правило 11.2 решений); его изменение — только операция над справочником (D5: переопределения на уровне задачи нет).
- Удаление используемой записи — по контракту очищения ссылок D6 PBT-031: удаление ресурса вычищает его из `assigneeIds` всех задач и каскадно удаляет его недоступности; удаление типа вычищает его из `workTypeIds`. Задачи, их даты и зависимости не изменяются; опустевшие массивы ссылок убираются из задачи. Развилка design D2 — на утверждение владельца.
- Независимость планов (11.1): справочник принадлежит конкретному документу, одинаковые названия в разных планах не связывают записи — подтверждается тестом.
- Delta spec: новая capability `resource-planning` (справочники, параллельность, удаление с чисткой ссылок).

## Capabilities

### New Capabilities

- `resource-planning` — справочники ресурсов и типов работ плана: создание, переименование, удаление, признак параллельности, независимость планов, чистка ссылок при удалении.

### Modified Capabilities

- Нет.

## Non-goals

- Назначения ресурсов задачам и периоды недоступности как операции (PBT-034): здесь только очистка существующих ссылок при удалении.
- Проверки конфликтов ресурсов и отпусков (PBT-036): признак хранится, но не применяется.
- Редакторы справочников в UI (PBT-041), ресурсное представление (PBT-047+).
- Рабочий календарь плана (PBT-044): не входит.
- Изменения платформы и SDK.

## Impact

- Новые файлы: `packages/gantt/src/plan-catalogs.ts`, `packages/gantt/src/plan-catalogs.test.ts`.
- Изменённые: `packages/gantt/src/plan-commands.ts` (расширение `PlanCommand` и диспетчера, код `invalid-title`), `packages/gantt/src/index.ts` (экспорт).
- Прямых изменений приложения и платформы нет.
- Разблокирует: PBT-034 (назначения и недоступности поверх этих справочников), PBT-036 (проверки конфликтов по `allowsParallel`), PBT-041 (UI-редакторы).

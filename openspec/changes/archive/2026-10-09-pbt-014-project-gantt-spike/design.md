# Design — PBT-014: спайк SVAR React Gantt

## Context

Продуктовая платформа (вкладки, каталог, чек-лист, IndexedDB) работает; ядро Гантта (PBT-030+) не начато и ждёт решения PBT-017. Контрольные данные готовы (PBT-012): `small-plan.json` с ожиданиями E1–E10, генератор 500 задач. Первый кандидат проектного представления — SVAR React Gantt, открытая MIT-редакция; известные по документации границы: рабочие календари, ресурсные назначения и автопланирование относятся к коммерческой редакции, перехват действий — `api.intercept()`, подсветка областей — `highlightTime`, флаг `inclusiveEnd` переключает отображение/ввод окончания. Правила, которые обязан соблюдать эксперимент, зафиксированы в ADR PBT-003 (A1–A6, B1–B4, C1–C5).

## Goals / Non-Goals

**Goals:**

- Ответить на вопросы DoD карточки PBT-014 воспроизводимым прототипом на данных `small-plan`.
- Держать эксперимент изолированным от продуктовых пакетов и сборки.
- Собрать факты для PBT-017: использованные API, ограничения, лицензия, трудоёмкость адаптера.

**Non-Goals:**

- Production-качество адаптера, продуктовая интеграция, тесты продуктового поведения.
- Ресурсные дорожки (PBT-015), нагрузка (PBT-016), импорт `.gantt` (PBT-052+).
- Оценка коммерческой редакции SVAR.

## Decisions

### D1. Место спайка: отдельное приложение `apps/gantt-spike`

Изолированное Vite-приложение в workspaces (`apps/*`), не входящее в команды корня для `apps/project-board`. Альтернативы: кодировать сразу в `packages/gantt` — отвергнуто, прод-пакет должен остаться чистым до PBT-017; папка вне workspaces — отвергнута, теряются общий tooling/lint/typecheck. Судьба `apps/gantt-spike` после PBT-017 — удалить или принять отдельным решением.

### D2. Данные и модель: фикстуры как источник истины, адаптер в одну сторону

`small-plan.json` (включительное окончание, календарные даты `YYYY-MM-DD`) конвертируется в модель SVAR при старте спайка. Даты SVAR (исключительная внутренняя семантика) не сохраняются обратно как истина; источник истины — фикстурные данные в памяти спайка (следствие A1). Имя npm-пакета подтверждается при установке (кандидат `@svar-ui/react-gantt`); версия фиксируется в отчёте.

### D3. Редактирование — через `api.intercept()`, без доверия автопланированию

Все изменяющие действия (drag полосы, resize, правка в таблице/форме) перехватываются: спайк пересчитывает даты по правилам ADR PBT-003 (A2–A4), обновляет модель и отдаёт компоненту новые данные. Зависимые задачи библиотекой не двигаются (автопланирование — коммерческая функция; отсутствие автопереноса проверяется фактически). Цель — проверить, даёт ли открытая редакция полный контроль над датами без скрытых пересчётов; это ключевой критерий годности.

### D4. Календарь и рабочая длительность — собственный расчёт

Рабочая длительность и пересчёт по календарю считаются кодом спайка (переиспользуется арифметика PBT-013 из `packages/gantt` или локальная копия — по факту зависимостей пакета; предпочтительно импорт из пакета, он не зависит от UI). Нерабочие дни подсвечиваются `highlightTime`. В спайке — переключатель «сделать 14.10 праздником/рабочим», покрывающий A5/A6: границы задачи сохраняются, рабочая длительность пересчитывается.

### D5. Проверка включительного окончания по четырём поверхностям

Для задачи A (пн 12.10 – пт 16.10, включительно) сверяется: значение в таблице, покрытие полосы (пт окрашен), значение в форме редактирования, payload событий перехвата. С `inclusiveEnd: true` и без него. Расхождение любой поверхности фиксируется в отчёте как ограничение/блокер.

### D6. Проверки спайка: ручной сценарий + typecheck/lint, без e2e

Спайк — не продуктовый UI, e2e-провержение не требуется; воспроизводимость обеспечивают команды отчёта. В корневые скрипты добавляются `dev:spike`; `typecheck` корня дополняется проектом `apps/gantt-spike`, ESLint покрывает его корневым прогоном. Автотесты не пишутся (research-задача; golden-регресс фикстур уже есть).

## Risks / Trade-offs

- SVAR может незаметно пересчитывать данные (нарушение A1/A5) → фиксируется как блокер, вывод «не подходит» допустим и завершает исследование валидно.
- Несовпадение семантики `inclusiveEnd` с документацией → выявляется проверкой D5, отражается в отчёте.
- Дополнительная зависимость в lockfile даже при изоляции приложения — принимается; из прод-сборки не попадает.
- Время на адаптер может показать высокую стоимость интеграции — сам по себе факт для PBT-017, не сокращаем объём эксперимента.

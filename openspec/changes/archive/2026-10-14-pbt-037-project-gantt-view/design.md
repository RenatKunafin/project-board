# Design — PBT-037: проектный Гантт из документа плана

## Context

Ядро завершено (PBT-030–036): `PlanContent` v1, `groupSummaryBounds`, `taskWorkingDuration`-арифметика PBT-013, команды в `applyPlanCommand`. SDK-паттерн виджета — `ChecklistWidget`: `WidgetProps { widgetInstanceId, documentId, documentService, visible, onResize }`, подписка `subscribe` → parse → состояние. ADR PBT-017: ADR-1 (SVAR 2.8.0 — проектный вид), ADR-3 (ядро независимо, сводные и рабочая длительность — ядро), ADR-4 (адаптер с нуля: end+1 при передаче, `e2s`, колонка длительности своя), ADR-5 (стратегия жестов — props один раз, сверка стора после mouseup). Research PBT-014: SVAR внутри всегда исключителен (`inclusiveEnd: true` — только отображение); `duration` SVAR — календарный; перехватчики ненадёжны при жестах и пересоздании bus; StrictMode дважды вызывает init; сводная рисуется SVAR по вложенным; подсветка `highlightTime` по `unit === 'day'`; канал `update-task` ненадёжен.

## Goals / Non-Goals

**Goals:** production-адаптер план → SVAR (даты, дерево, FS); представление в каталоге вместо заглушки; включительные даты и рабочая длительность на поверхности; подсветка нерабочих дней; два экземпляра на общем документе; read-only без рассинхронизации.

**Non-Goals:** форма (PBT-038), drag/resize (PBT-039), управление группами (PBT-040), ресурсный вид (PBT-047), фильтры (PBT-049).

## Decisions

### D1. Адаптер `svar-adapter.ts`: чистое преобразование без типов SVAR в публичном контракте

`planToGanttTasks(plan): GanttTask[]` и `planToGanttLinks(plan): GanttLink[]` — чистые функции; локальные интерфейсы `GanttTask`/`GanttLink` (минимальный контракт: id, text, start, end, type, parent, duration; id, source, target, type, lag) вместо импорта `ITask`/`ILink` SVAR — типы библиотеки остаются внутри компонента (правило «минимальный локальный контракт без протекания», прецедент react-rnd/react-grid-layout). Совместимость структур проверяется компиляцией компонента.

Правила преобразования (ADR-4 + research PBT-014):
- группа → `{ id, text: title, type: 'summary', parent: parentId? }`; задача → `{ id, text: title, start, end: +1 календарный день, type: 'task', parent: groupId?, duration: календарная (end+1 − start) }`;
- зависимость → `{ id, source: fromTaskId, target: toTaskId, type: 'e2s', lag: lagDays }`;
- порядок: группы и задачи в порядке массивов документа; пустой план → пустые массивы.
Чтение (end−1) в этот PR не входит — операций редактирования нет (YAGNI; придёт с PBT-038/039 в адаптер же). Golden-тест на фикстуре PBT-012 `small-plan.json` (перенос в тесты пакета — design D1 PBT-030): группа «Фаза 1», задачи A–E, FS A→B, праздник 14.10.

### D2. Многотипные задачи подсветки: `nonWorkingDayKind(plan, date)`

Чистая функция → `'weekend' | 'holiday' | undefined`: `isWorkingDay` → undefined; дата в `holidays` → `'holiday'`; иначе → `'weekend'`. Рабочее исключение делает день рабочим → undefined (правила 8.2). Виджет передаёт в `highlightTime(date, unit)`: только `unit === 'day'`; классы `gantt__weekend` / `gantt__holiday` — цвета через var()-токены приложения (правило токенов до PBT-066), по образцу спайка (серый выходной, розовый праздник — референс OnlineGantt).

### D3. Read-only с блокировкой жестов: осознанное сужение ADR-5 до PBT-038/039

Полный механизм ADR-5 (props один раз, сверка стора 80/450/1000 мс, применение через ядро) нужен только при редактировании. В этом PR документ из представления не меняется, поэтому:
- `api.intercept('drag-task', () => false)` — жёсткая блокировка перетаскивания любых полос (включая сводные — B2): стор SVAR не расходится с документом, DoD-5 «не меняет документ при простом отображении» выполняется без сверок;
- форма `Editor` не подключается; `add-link` не блокируется дополнительно — связи создаются только редактором, которого нет;
- перехватчики вешаются в `init` с защитой от двойного вызова StrictMode (флаг на экземпляре api — прецедент research PBT-014);
- сворачивание групп не блокируется: это состояние виджета (B4), не данных.
Отклонённая альтернатива — позволить drag с рассинхронизацией стора: визуально полоса уезжает от документа и возвращается при первом обновлении props — хуже блокировки и против DoD-5. Правка design-плана ADR-5 не требуется: полная стратегия приходит с PBT-039.

### D4. `PlanGanttWidget`: подписка на документ, parse с диагностикой, видимость

По паттерну чек-листа: `subscribe` → `parsePlanContent` → `{ ok }` → состояние. Три состояния рендера:
- нет `documentId`/`documentService` → подсказка (как в чек-листе);
- `ok: false` → список диагностики `PlanIssue` (перенимает поведение заглушки; молчаливый fallback запрещён);
- `ok: true` → SVAR `Gantt` + `Willow` с данными адаптера, `inclusiveEnd: true`, `highlightTime`.
`visible === false` → SVAR не монтируется (тяжёлая отрисовка приостановлена), подписка жива — возврат показывает актуальный документ (контракт PBT-027). Два экземпляра: оба подписаны на один документ, оба рендерят из адаптера — копирования документа в стор нет; при внешнем изменении новые props приходят в Gantt (вне жестов — безопасно, жесты заблокированы D3; при PBT-039 обновление props координируется со стором по ADR-5). Resize контейнера — CSS `height: 100%` (подтверждено спайком), `onResize` не требуется.

### D5. Замена заглушки и регистрация

`createGanttModule().widgetTypes[0].component = PlanGanttWidget`; `PlanPlaceholderWidget` удаляется (его диагностическое состояние перенимает новый виджет). Реестр, каталог, восстановление пространства не меняются — платформа рендерит по реестру (design D7 PBT-030). `sizeConstraints.minWidth` поднят до 4 колонок: узкая панель скрывает бо́льшую часть шкалы (наблюдение PBT-037).

### D6. Специфика обёртки SVAR в прод-сборке (найдено при реализации)

Механика наполнения стора отличается от ожиданий «props → стор» и от dev-поведения:

1. При первом effect-запуске обёртка вызывает **пользовательский `init` вместо внутреннего заливания props в стор** (`Ke.current ? P.init(Ue) : F && F(Ge)` в бандле); заливка (`P.init(Ue)`) происходит только при **повторных** запусках эффекта.
2. Deps этого эффекта стабильны (useMemo-конфиг), поэтому в prod после монтирования второго запуска не наступает и таблица остаётся пустой; в dev его обеспечивает StrictMode (double-invoke) — в спайке PBT-014 (только dev) дефект не проявлялся.
3. Ранние `api.exec` (до первичного рендера шкалы) теряются без ошибок — заливка через exec сразу в `init` ненадёжна.

Решение в этом PR: после монтирования форсируется второй рендер виджета (`forceRerenderAfterMount`); `tasks`/`links` передаются новыми массивами (`[...tasks]`), deps эффекта меняются, внутренний `P.init(Ue)` заливает данные. Изменение документа отслеживается remount'ом по `key={document.revision}` (новый стор → новая заливка). Проверено в прод-сборке вручную (восстановление из IDB, подсветка, remount при записи) и e2e.

Для PBT-038/039: редактирование через `api.exec('update-task')` в этом режиме работает (проверено вручную); стратегия ADR-5 остаётся основой, но её перехватчики должны учитывать, что `init`-канал уже используется заливкой данных.

### D7. Зависимость и стили

`packages/gantt/package.json` += `@svar-ui/react-gantt` ровно `2.8.0` (ADR-8 PBT-017); react 18.3 — peer. Стили SVAR (`@svar-ui/react-gantt/style.css`) импортируются в модуле виджета; собственный `gantt.css` пакета — только `var(--…)` токены приложения (правило токенов до PBT-066). SVAR-импорты (включая типы и стили) не выходят за пределы `packages/gantt` — ESLint-границы ADR-3 не нарушаются (app импортирует только компонент модуля).

### D8. Проверки

Unit: адаптер (включительность +1, summary/parent на трёх уровнях, `e2s` с лагом, пустой план, golden small-plan.json), `nonWorkingDayKind` (weekend/holiday/исключение). E2E `plan-gantt.spec.ts`: каталог → план → запись контрольного контента через `window.__projectBoard` (фикстура small-plan) → автосохранение с паузой 1500 мс → reload → строки/полосы восстановлены; второй экземпляр того же документа; пустой план; скриншот в `openspec/changes/pbt-037-project-gantt-view/screenshots/`.

## Risks / Trade-offs

- **Блокировка drag до PBT-039** — пользователь может ожидать перетаскивание: представление помечается как «только просмотр» в подсказке состояния; операции приходят следующими карточками.
- **Обновление props вне жестов при внешнем изменении** — подтверждённый спайком канал; риск возникает только при активных жестах (заблокированы) — снимается в PBT-039 полным ADR-5.
- **Столбец рабочей длительности зависит от конфигурации колонок SVAR** — по спайку длительность показывается собственным вычислением; точная поверхность (колонка/подпись) уточняется при реализации по API спайка, контракт — «рабочая длительность видна на поверхности» (DoD).
- **`duration` в данных SVAR календарный** — не попадает в документ (ADR-3 PBT-017); ядро остаётся источником истины.

## Migration Plan

Заглушка удаляется; существующие сохранённые планы (созданные в PBT-030+) открываются новым виджетом без миграций — формат v1 не меняется.

# Design — PBT-045 Dependency editor

## Context

Ядро PBT-035: `createDependency` (самоссылка/косвенный цикл через BFS, дубли — идемпотентный ретрай того же лага vs `duplicate-dependency` при другом, `invalid-lag`), `updateDependency` (только лаг), `deleteDependency`; сообщения ядра человекочитаемы. Форма задачи (PBT-038) — карточка задачи; паттерн немедленных команд — applyCommand из PBT-041/043.

## Goals / Non-Goals

- Goals: список предшественников с лагами, добавление/изменение лага/удаление, отклонения с объяснениями, без изменения дат, reload/второй виджет.
- Non-Goals: см. proposal.

## Decisions

### D1. Секция в форме задачи, немедленные команды

Секция видна только в режиме редактирования (создаваемой задачи ещё нет в документе — связи требуют id). Каждое действие — отдельная запись документа через `applyDependencyCommand` (commitPlan + switch, как applyCatalogCommand). Форма «Сохранить» не участвует: зависимости — самостоятельные команды, отмена формы их не откатывает (инлайн-паттерн каталогов PBT-041).

### D2. Кандидаты не фильтруются — ядро объясняет

Селект добавления содержит все задачи плана, включая саму редактируемую и уже существующих предшественников. Попытка самоссылки/цикла/дубликата выполняется и отклоняется текстом ядра у строки («не может зависеть от самой себя», «создаёт цикл», «уже существует с лагом N; измените лаг») — DoD-3 требует именно объяснений, а ядро уже формулирует их; дублирующий фильтр в UI скрыл бы причину.

Альтернатива «фильтровать невозможных кандидатов» отклонена: скрывает семантику, оставляя пользователя без объяснения, и дублирует проверки ядра.

### D3. Лаг — целое ≥ 0, клиентская проверка

Поле лага: `input[type=number] min=0 step=1`; неположительное/дробное — клиентское сообщение «Лаг — целое число рабочих дней не меньше нуля.» (текст согласован с ядром), ядро остаётся защитой. Изменение лага — инлайн (кнопка «Изменить» → input + «✓», Enter/Esc) — паттерн каталогов.

### D4. Стрелки обновляются пересборкой

Записи зависимостей — записи формы (не жестов): remount по ревизии пересоздаёт стор с новыми `links` (адаптер уже мапит зависимости в стрелки e2s). Механизм стабилизации props (D7 PBT-039) не подавляет записи формы — стрелки обновляются без дополнительного кода.

### D5. Даты не меняются

`createDependency`/`updateDependency`/`deleteDependency` не трогают `tasks` (контракт ядра PBT-035, C5: нарушение — только диагностика). E2E фиксирует даты обеих задач до/после добавления связи, смены лага через праздник и удаления.

## Risks / Trade-offs

- Секция в форме растёт с числом предшественников — прокрутка диалога поддерживается; сотни предшественников вне целевого сценария.
- Отмена формы не откатывает зависимости — согласовано с инлайн-паттерном (как каталоги); отмечено в подсказке секции? Не требуется: действия явные и поштучные.

## Migration Plan

Схема не меняется (`dependencies` в модели v1). Новая поверхность UI.

## Open Questions

Нет — серия автономна (директива владельца).

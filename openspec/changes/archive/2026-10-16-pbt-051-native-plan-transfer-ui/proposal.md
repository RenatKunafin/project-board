# PBT-051 — Импорт и экспорт собственного формата в UI

## Why

Формат переноса готов (PBT-050: `serializePlanFile`/`deserializePlanFile`/`planFileName`), но создать или открыть файл плана в приложении нельзя — нет UI. Карточка PBT-051 закрывает это: скачивание файла плана и открытие файла через браузерный диалог, с готовым адаптером и каталогом документов.

## What Changes

- **Экспорт из тулбара плана:** кнопка «Экспорт» скачивает файл `pb-plan-YYYY-MM-DD_HH-mm-ss.json` (Blob + `a[download]`) с названием плана и актуальным содержимым документа. Чисто клиентский сценарий.
- **Импорт из тулбара плана:** кнопка «Импорт…» открывает браузерный диалог выбора файла (скрытый `input[type=file]`, `accept=".json"`); файл валидируется `deserializePlanFile` **до** создания документа; при успехе создаётся **новый независимый документ** (политика PBT-050) с названием из файла, при ошибке — перечень проблем показывается по месту, документ не создаётся; отмена выбора не меняет данные.
- **Открытие импортированного плана:** текущее окно плана переключается на импортированный документ (механизм платформы `replacePaneDocument` переиспользуется; прежний план остаётся в каталоге). Для этого SDK расширяется опциональным `WidgetProps.switchDocument(documentId)` — решение в design (прецедент расширения SDK опциональным хендлером: `updateSettings`, PBT-049).
- **Каталог документов:** созданный модулем документ появляется в каталоге (платформенная гарантия — delta `document-management`) и доступен в других виджетах обычным порядком.
- Повторный импорт того же файла — два независимых документа (текущее окно на последнем), существующие планы не перезаписываются (DoD-3).
- Попутная стабилизация существующих e2e (conflicts/plan-groups/resource-timeline): пауза 1500 мс после записи контрольных данных перед координатными жестами — SVAR пересобирает представление по ревизии, жест в переходный DOM попадает в соседнюю строку (причина в комментариях спек, факты — design Risks).

## Impact

- SDK: `WidgetProps.switchDocument?` — опциональный хендлер, платформа реализует через существующую перепривязку экземпляра.
- Dashboard (`App.tsx`/`WidgetPane`): прокидывание `switchDocument` в панели (строка кода через `PaneHandlers.replacePaneDocument`).
- Gantt (`PlanGanttWidget.tsx`): кнопки тулбара, файловый input, обработка результата импорта, скачивание экспорта; форматы — готовый `native-plan-format`.
- CSS: токены, без хексов (до PBT-066).
- E2E `tests/e2e/plan-transfer.spec.ts`: перенос между двумя изолированными контекстами, битый файл, двойной импорт.

## Non-Goals

- Замена содержимого существующего плана файлом — политика PBT-050 (вне v1).
- Drag&drop файла на окно, мультифайловый импорт, пакетные операции.
- Импорт OnlineGantt `.gantt` — PBT-052–054; экспорт PlantUML — PBT-055–056.
- Проверка DoD-5 «работает офлайн после подготовки PWA»: PWA ещё не реализована (PBT-028/029); используемые API (Blob, FileReader/download) клиентские и PWA-совместимы — проверка офлайн-сценария выполняется при задачах PWA.

# Design — PBT-021: тайлинг по сетке

## Context

Панели вкладки рендерятся через `WidgetWindow` (PBT-020) в фиксированной grid-раскладке приложения. Согласованное поведение тайлинга — решения §4.2 (сетка дашборда, сдвиг соседей, пустые места, прокрутка, предпросмотр). Кандидат библиотеки — React Grid Layout (MIT), зафиксирован в решениях §19 и подтверждён ADR PBT-002 как кандидат до прототипа; проверка прототипом не проводилась — эта задача и есть интеграционная проверка (при провале кандидата — новая PBT-задача с альтернативой, ядро рамки не страдает: адаптер изолирует библиотеку).

## Goals / Non-Goals

**Goals:** сетка с переносом за заголовок, resize по ограничениям типа, сдвиг соседей без перекрытия, placeholder, прокрутка, согласование сворачивания, сериализуемая раскладка в собственной структуре.

**Non-Goals:** каскад, режимы, персистентность, пауза отрисовки, стили под макеты.

## Decisions

### D1. React Grid Layout 1.4.4, изоляция в адаптере платформы

`react-grid-layout` (MIT) зафиксирован **точно: 1.4.4**. Свежий мажор 2.3.0 (переписан на хуки: `useGridLayout`/`useContainerWidth`, другой API, `WidthProvider` удалён) отброшен: молодой мажор с нестабильным API повторял бы риск беты RCT (PBT-015) без выигрыша; возврат к v2 — отдельное решение. Типы библиотеки изолированы: адаптер объявляет минимальный локальный контракт (`GridLayoutProps`/`GridLayoutItem`), `@types/react-grid-layout` — только devDep для разрешения модуля. Приложение использует только `TiledLayout`; базовые CSS RGL импортируются в адаптере (резолв относительно пакета независимо от hoisting workspaces). Если кандидат не вытянет сценарии DoD — замена через этот же адаптер без изменений приложения.

### D2. Параметры сетки

12 колонок, высота строки 72px, отступ 12px (gap), `compactType: 'vertical'` — соседи уплотняются вверх без перекрытия; контейнер пространства вкладки получает вертикальную прокрутку при нехватке высоты (DoD). Значения фиксируются константами адаптера; уточнение под макеты — PBT-066/PBT-023, не магия извне.

### D3. Ограничения размеров — из SDK

`sizeConstraints` типа (`minWidth/minHeight`, опциональные `maxWidth/maxHeight` — в «ячейках» сетки, семантика совпадает с RGL-колонками/рядами) передаются в `minW/minH/maxW/maxH` элемента. Нарушить минимум перетаскиванием невозможно. Стартовый размер нового окна: `w = clamp(6, minW..maxW)`, `h = clamp(4, minH..maxH)` — константа адаптера, не новое поле SDK (расширение контракта — отдельное решение при необходимости).

### D4. Перенос за заголовок, редактирование не мешает

`draggableHandle: '.widget-window__head'` — перенос только за рамку заголовка PBT-020; `draggableCancel` не требуется (кнопки заголовка — часть ручки; клик по кнопке не начинает drag). Placeholder RGL стилизуется классом адаптера (предпросмотр позиции, DoD). mousedown на заголовке по-прежнему активирует окно (PBT-020) — RGL начинает drag только после превышения порога движения.

### D5. Сворачивание согласовано с сеткой

Свёрнутое окно занимает **одну строку** (`h: 1`) — виден только заголовок; прежняя высота сохраняется в состоянии окна и возвращается при разворачивании (ADR-7 PBT-002: восстановление размера до сворачивания). Содержимое остаётся несмонтированным-но-живым (hidden, PBT-020). Кнопка сворачивания в заголовке-ручке не конфликтует с drag (клик без движения).

### D6. Сериализация в собственной структуре

Состояние раскладки вкладки: `Record<instanceId, { x, y, w, h }>` — обычные объекты платформы. `TiledLayout` принимает `items: { instanceId, node, constraints, collapsed }[]` + `layout`, отдаёт `onLayoutChange(next)` уже в собственной структуре (фильтр по известным instanceId, округление). Документы и экземпляры не ссылаются на библиотечные объекты (DoD); персистентность — PBT-024, формат записи тогда определится от этой структуры.

### D7. Совместимость с рамкой и существующими e2e

`WidgetWindow` не меняется; адаптер оборачивает окна и управляет их внешним размером (стретч по ячейке). Существующие e2e (вкладки, каталог, рамка, план) не используют координаты панелей — проходят без изменений. Новые e2e: перенос за заголовок (mouse-сценарий), resize, сворачивание в сетке, прокрутка, сериализация (состояние раскладки читается из рендера позиций).

### D8. Кнопки окна — не ручка переноса (найдено e2e)

Ручка переноса — весь заголовок `.widget-window__head`; mousedown на кнопках сворачивания/закрытия перехватывался drag-механикой RGL, и клики кнопок не доходили (e2e: `aria-expanded` не менялся). Контейнер кнопок `.widget-window__actions` прерывает всплытие `mousedown` (с активацией окна): кнопки кликабельны, перенос остаётся только за пустую часть заголовка. Проверено e2e.

### D9. Новые окна — поочерёдно в левую/правую половину

Стартовая область нового окна (`x = (число окон % 2) · 6 колонок`) заполняет сетку с чередованием колонок — иначе RGL складывает все окна в левую колонку, оставляя правую пустой. Дальнейшее уплотнение без перекрытий делает вертикальный компакт сетки.

## Risks / Trade-offs

- **RGL не проверен прототипом до этой задачи:** сценарии DoD и есть проверка; провал — отдельная задача с альтернативой (например, собственная раскладка), адаптер ограничивает зону замены.
- **Свёрнутое окно h:1 сжимает содержимое:** содержимое скрыто целиком (hidden) — высота ряда резервирует ровно заголовок; при разворачивании восстанавливается.
- **compactType vertical «подтягивает» окна вверх:** пустые места допустимы только в пределах уплотнения (согласовано §4.2 — сдвиг соседей обязателен, пустоты возникают по краям/между рядами, не поддерживаются искусственно в v1 раскладки).
- **resize+рамка:** уголок resize RGL поверх рамки окна — стилизуется в адаптере, минимальные размеры защищают контент.

## MODIFIED Requirements

### Requirement: Список проблем плана

Проектный Гантт SHALL отображать единый список проблем плана, различая типы: нарушение FS-зависимости, пересечение двух непараллелизуемых работ одного ресурса, пересечение работы с отпуском исполнителя. Записи SHALL группироваться по этим типам с счётчиком записей группы; список SHALL предоставлять фильтр типа («все» и каждый тип) со счётчиками по полному результату ядра и поиск по подстроке названия задачи или исполнителя назначений; фильтр и поиск SHALL комбинироваться. Каждая запись SHALL содержать название задачи-цели, понятную причину, структурированные рабочие даты (ожидание/факт для FS; интервал пересечения для конфликтов) и ресурс (когда применимо), полученные из полей ядра без разбора текста сообщений, и два явных действия: показ на диаграмме и редактирование задачи в общей форме с актуальными данными. Список SHALL пересчитываться из документа без создания записей документа; число и тексты проблем ядра MUST NOT изменяться представлением; похожие записи MUST NOT удаляться или объединяться. Отсутствие проблем вообще и отсутствие совпадений с фильтром или поиском SHALL различаться.

#### Scenario: Различение типов проблем

- **GIVEN** в плане нарушена FS-связь, у ресурса пересекаются две непараллелизуемые работы, а параллелизуемая работа пересекается с его отпуском
- **THEN** список проблем содержит три записи разных типов с задачами, ресурсом, датами и причинами

#### Scenario: Пересчёт без записи

- **WHEN** пользователь исправляет исходные данные (сдвигает задачу, удаляет отпуск)
- **THEN** соответствующая проблема исчезает из списка во всех экземплярах представления, а количество редакций документа соответствует только исправляющим операциям

#### Scenario: Группы, фильтры и счётчики полного ядра

- **GIVEN** план с проблемами трёх типов
- **WHEN** пользователь включает фильтр одного типа и вводит поисковый запрос
- **THEN** записи фильтруются по типу и запросу одновременно, счётчики групп отражают видимые записи, счётчики фильтров и кнопки тулбара — полный результат ядра
- **AND** ревизия документа не изменяется

#### Scenario: Структурированная строка без разбора текста

- **GIVEN** нарушение FS и конфликт работ с длинными названиями задач
- **WHEN** список открыт
- **THEN** строка показывает название задачи-цели, причину ядра, даты вида (ожидаемая/фактическая либо интервал пересечения) и ресурс при наличии, длинные строки переносятся, действия строки доступны и не перекрываются

#### Scenario: Различённые пустые состояния

- **WHEN** в плане нет проблем либо фильтр/поиск не дают совпадений
- **THEN** список показывает «Проблем нет» в первом случае и «Нет проблем по выбранному фильтру» либо «Ничего не найдено» — во втором, состояния различимы

#### Scenario: Редактирование из строки

- **GIVEN** запись проблемы с задачей
- **WHEN** пользователь активирует действие редактирования
- **THEN** модалка списка закрывается и открывается общая форма задачи в режиме редактирования с актуальными данными документа
- **AND** после сохранения исправления запись и счётчики обновляются без перезагрузки страницы

## Purpose

Публикация плана в текстовом формате PlantUML Gantt для встраивания на страницы (Confluence и т.п.): детерминированная офлайн-генерация текста диаграммы в стиле целевого примера владельца с точными датами и отчётом о семантике, которую целевой формат не выражает. UI экспорта — представления; эта capability определяет генерацию и её границы.

## ADDED Requirements

### Requirement: Генерация текста PlantUML из плана

Модуль SHALL генерировать из документа плана текст диаграммы PlantUML Gantt, включающий: русскую локаль шкалы, заголовок плана, дату старта проекта (минимальная дата начала задач), закрытые дни недели, праздники и рабочие исключения календаря, группы в виде разделителей, задачи с человекочитаемым названием, уникальным алиасом, явной датой начала и длительностью в рабочих днях, периоды недоступности отдельным разделом отпусков, FS-зависимости стрелками по алиасам, заливку выходных дней по горизонту плана. Задачи и отпуска SHALL окрашиваться по палитре этапов, определяемой маркерами в названии задачи. Генерация SHALL быть чистой функцией: без сети, без изменения документа, детерминированной для одного плана.

#### Scenario: Контрольный план переносится целиком

- **GIVEN** план с календарём (праздник, рабочее исключение, пн–пт), вложенными группами, задачами с исполнителями и FS-зависимостью, периодом недоступности
- **WHEN** выполняется генерация
- **THEN** текст содержит все перечисленные элементы и рендерится в валидную диаграмму закреплённой версии PlantUML
- **AND** отображаемые даты задач совпадают с планом: старт — исходный, длительность — в рабочих днях календаря плана

#### Scenario: Отпуск отображается тёмно-зелёной задачей в разделе отпусков

- **GIVEN** план с периодом недоступности ресурса
- **WHEN** выполняется генерация
- **THEN** текст содержит отдельный раздел отпусков с задачей периода, окрашенной в цвет отпуска палитры

#### Scenario: Этап задачи окрашивается по маркеру названия

- **GIVEN** задачи с маркерами этапов в названиях (например «-ПСИ-», «-DEV-»)
- **WHEN** выполняется генерация
- **THEN** каждая задача окрашена в цвет своего этапа по палитре; задача без известного маркера — без явного цвета

#### Scenario: Задача без рабочих дней выводится вехой

- **GIVEN** задача, чей интервал не содержит рабочих дней календаря плана
- **WHEN** выполняется генерация и рендер
- **THEN** задача отображается вехой-точкой на дате начала вместо полосы

#### Scenario: Рабочее исключение открыто на шкале

- **GIVEN** календарь с рабочим исключением (рабочая суббота)
- **WHEN** диаграмма рендерится
- **THEN** день исключения отмечен открытым и входит в длительность задач через него

### Requirement: Отчёт экспорта о непереносимой семантике

Результат генерации SHALL включать отчёт с перечнем семантики плана, не выражаемой целевым форматом: задержки FS-связей (стрелка без лага), сводная полоса групп (разделитель без полосы), типы работ и параллельность, загрузка назначений (`unit`), конфликты, задачи с полосой на границе нерабочего дня (полоса может лечь иначе; задачи без рабочих дней не входят — они выводятся вехами). Пункты отчёта появляются только при наличии соответствующих данных в плане. Календарь (праздники, рабочие исключения) переносится только в пределах горизонта дат плана.

#### Scenario: Лаг связи отражается в отчёте

- **GIVEN** план с FS-зависимостью с ненулевой задержкой
- **WHEN** выполняется генерация
- **THEN** связь отображается стрелкой без задержки
- **AND** отчёт содержит запись о невозможности отобразить лаг стрелкой

#### Scenario: План без непереносимой семантики даёт пустой отчёт

- **GIVEN** план только с задачами на рабочих днях, группами и связями с нулевым лагом
- **WHEN** выполняется генерация
- **THEN** отчёт экспорта пуст

### Requirement: Кодирование названий и стабильные алиасы

Генерация SHALL безопасно кодировать названия: кириллица и типографские кавычки переносятся как есть; символы, ломающие синтаксис (квадратные скобки), заменяются на близкие по начертанию. Каждая задача SHALL получать уникальный алиас, стабильный для документа; связи ссылаются на алиасы, поэтому повторяющиеся названия задач не нарушают сопоставление связей.

#### Scenario: Специальные символы не ломают диаграмму

- **GIVEN** задача с названием, содержащим квадратные скобки и кавычки
- **WHEN** выполняется генерация и рендер
- **THEN** диаграмма валидна, название читаемо с заменой скобок

#### Scenario: Дубли названий не рвут связи

- **GIVEN** две задачи с одинаковым названием, связанные зависимостями
- **WHEN** выполняется генерация и рендер
- **THEN** обе задачи отображаются, связи указывают на соответствующие задачи по алиасам

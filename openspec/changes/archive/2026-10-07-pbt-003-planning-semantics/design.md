## Context

Карточка PBT-003 требует закрыть неоднозначности модели до прототипов Гантта. Согласованная база: планирование по дням, включительные границы предложены (раздел 8.3), границы задач сохраняются при изменении календаря (8.1), полоса может проходить через выходные без добавления длительности (8.2), ручное перепланирование без автопереноса задач (7), правило конфликтов по параллельности типов работ (11.3), отпуск подсвечивается как конфликт всегда (12). Новая модель планирования использует дни, почасовой календарь исходного инструмента не воспроизводится.

## Goals / Non-Goals

**Goals:**

- Таблица правил с конкретными примерами дат — каждая строка пригодна для автоматического теста в PBT-013/PBT-030+.
- Решения по всем развилкам из карточки: даты/длительность, группы, зависимости, ресурсы/назначения/отпуска.
- Явное исключение неподдерживаемого из первой версии (не молчаливое умолчание).

**Non-Goals:**

- Реализация движка и тестов; дизайн UI-редакторов (PBT-038+); почасовая точность (исключена); автоматическое выравнивание ресурсов (отменено).
- Правила импорта формата `.gantt` в целом (PBT-052) — здесь только семантика загружаемых значений (процент загрузки, отпуск-задачи).

## Decisions

**Итог ревью владельца (2026-10-07):** все 24 развилки блоков A–D утверждены по рекомендациям, без изменений. Блок C принят после детального раскрытия примеров (лаг 0, запрет отрицательного лага, зависимости только задача→задача, отклонение циклов, подсветка нарушений).

Формат: развилка → варианты → рекомендация. Итог фиксирует владелец на ревью; в ADR попадают принятые правила с примерами. Базовая неделя по умолчанию: пн–пт рабочие, сб–вс нет.

| A3 | Ручной ввод дат в нерабочие дни | (a) даты хранятся как введены, полоса проходит через выходные; (b) сдвиг на рабочий день | (a) — согласовано в 8.2 «полоса может проходить через выходные»; длительность считается только по рабочим дням |

## Risks / Trade-offs

- [Часть исключений (отрицательный лаг, FS на группы, дорожка «Без ресурса») сузит первую версию] → все решения явно перечислены в ADR как «исключено»; возврат — отдельная задача-решение, не тихое расширение.
- [Правило A2 (drag привязывает к рабочим дням) может расходиться с ожиданиями пользователей, привыкших к календарному сдвигу] → проверка на прототипе PBT-014; расхождение фиксируется как замечание прототипа.
- [Хранение дат как введённых (A3) даст полосы с нулевой рабочей длительностью] → отображение длительности 0 согласовано; подсветка не вводится в первой версии.

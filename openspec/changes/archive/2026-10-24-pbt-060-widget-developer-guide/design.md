# PBT-060 — Руководство и уборка репозитория

## Context

По поручению владельца задача расширена 2026-10-24. База develop73f48c9, ветка feature/pbt-060-widget-developer-guide. Исходный результат руководства сохраняется; инвентаризация — audit.md. Общий объём уборки одобрен владельцем 2026-10-24 («Все ок»). Выбор унификации агентов вынесен в agent-options.md; вариант2 с .agents/rules и общим .agents/skills одобрен владельцем («Отлично, делаем»).

## Decisions

### D1. Документация и пример

Каноническая директория — docs/. Руководство docs/widget-development.md опирается на фактические экспорты widget-sdk: регистрация в apps/project-board/src/widgets.ts, documentSupport и миграции, documentService, updateSettings, видимость/размеры и освобождение подписок. Небольшой пример хранить отдельно от штатного каталога продукта; проверить его подключение в изолированном чистом checkout и приложить diff. Два окна одного документа показывают общие данные и независимые настройки. Пример не добавляет новую предметную зависимость в dashboard/SDK.

### D2. Удаляемые материалы

Удалить весь apps/load-demo и одноразовый __shot.cjs; удалить125 архивных изображений по явному списку из git ls-files, не затрагивая продуктовые ассеты. Сохранить текстовые архивы, ADR, fixtures и численные доказательства производительности. Исправить ссылки на удалённые изображения и пути их будущей генерации. История git остаётся прежней; уменьшение текущего дерева не объявлять уменьшением уже накопленной истории git.

Удалить неиспользуемую запись __ganttApiRegistry после повторной проверки потребителей. Используемые тестовые hooks __projectBoard и storage-selftest сохраняются. Никаких массовых обновлений/удалений общих зависимостей; lockfile пересобирается под оставшиеся workspaces.

### D3. AGENTS и rules

Корневой AGENTS — компактный навигатор с критическими неизменными ограничениями. Детали процесса, кода и проверок — .agents/rules/workflow.md, .agents/rules/code.md, .agents/rules/testing.md; явно указать обязательное чтение соответствующих файлов. Удалить хронологию, повторения и завершённые исключения, сохранить язык, источники истины, границы SDK/платформы, нормальный цикл ревью/merge и требование честных проверок. Правило обновлять «Стадию» AGENTS при каждом merge заменяется обновлением реестра. .agents/rules/*.md не заменяют системные разрешения команд и не зависят от предполагаемой автозагрузки произвольной папки.

README — инструкция входа разработчика: описание, команды, карта и ссылки docs. Игнорируемая .context не должна быть необходима для понимания SDK и запуска на чистом checkout; локальный реестр задач остаётся рабочим источником статусов владельца. OpenSpec-конфиг ссылается на актуальные правила и стабильный стек, без выдуманного раннего статуса.

### D4. Переименование docs

Переместить директорию и обновить Markdown-ссылки и действующие пути в отслеживаемых файлах; отдельно обновить локальные .context. Архивные факты/числа и принятые решения не переписывать; исправление адресов ссылок не считается новым ADR. Проверить отсутствие рабочих ссылок на .docs и относительных ссылок на удалённые изображения. Исторические fingerprints и raw не редактировать ради косметики.

### D5. Материалы UI и инструменты

Новые скриншоты/записи — test-results/ или поддерживаемые вложения PR, не OpenSpec. Сохранить живую проверку UI с консолью и текстовый отчёт. Убрать тестовую запись в архив. Владелец использует разных агентов: нужен общий источник инструкций и проверенные адаптеры загрузки. Варианты — agent-options.md; одобрен вариант2 (.agents/rules + .agents/skills), реализованы тонкие адаптеры; не создавать независимые копии правил и не удалять нужные OpenSpec-интеграции.

## Risks / Validation

Удаление картинок требует проверки ссылок, переименование docs — отдельной проверки путей. Удаление workspace не гарантирует, что все его зависимости стали ненужными: сверять оставшиеся импорты/peer dependencies. Скрытые локальные .context не публикуются автоматически; публичные правила/руководство должны быть самодостаточны.

Нужны чистый checkout/npm ci, проверка подключения примера с diff, линт границ пакетов, typecheck/unit/build/browser/OpenSpec, discovery вспомогательных наборов и проверка отсутствия записей тестов в архив. Сохранение бюджета/форматов/календарной семантики — неизменные ограничения. Архивация change только после принятия отдельного PR PBT-060.

### D6. Проверка примера и интеграций

Пример examples/counter-widget находится вне workspaces продукта. Скрипт verify:widget-example создаёт detached worktree текущего HEAD, подключает копию примера в packages/ и composition root, выполняет чистую установку/проверки и записывает diff подключения в test-results. Две browser-проверки охватывают общий документ, отдельные настройки, hidden/reload/отписки, миграцию v1 и сохранение будущей версии. Платформа и SDK в diff не меняются.

OpenSpec-сценарии перенесены из .opencode/skills в .agents/skills. Сохранены license/author/version/generatedBy; совместимость Requires openspec CLI перенесена в metadata.requires для валидатора Codex. Claude получает относительные симлинки отдельных навыков и импорты правил из CLAUDE.md; OpenCode — instructions и короткие opsx-команды. Общие правила имеют trigger: always_on. Проверка путей/метаданных не выдаётся за запуск моделей всех редакторов.

### D7. Уборка тестов (одобрена владельцем 2026-10-24)

Удалить moveTab и3 его теста, clampCascadeArea и7 его тестов: tracked-вызовов приложения нет, порядок вкладок и расширяемый каскад проверяются действующими сценариями. Удалить fixtures-only reference-gantt.ts с3 тестами: единственный потребитель — собственный тест, реальные файлы импорта и продуктовый парсер сохраняются.

Убрать отдельный screenshot-only каскадный тест; геометрия/доступность проверяются оставшимися e2e. Объединить второй smoke плана с первым сценарием создания/reload/повторного открытия, усилить его сохранёнными ID/данными. Проверки заголовка/default-вкладки из двух shell-smoke перенести в существующие сценарии каркаса/переключения.

Фикстуры: пустой цикл заменяется реальными assigneeIds, самопроверка ID — проверкой уникальности. E5/E6 вызывают resourceConflicts; E2/E7/E8 проверяют реальные зависимости/конфликты, а не повторяют правило тестовым кодом. Сохранить эталоны JSON и golden500 без изменений.

Заменить фиксированные ожидания сохранения в затронутых shell/plan/window/catalog/default-layout сценариях на polling IndexedDB: документ, окна, вкладки, настройки. Исправить старую проверку, которая после закрытия окна ожидала его появления при reload. Паузы жестов, измерений и защиты от позднего отката сохраняются; массовое удаление124 пауз не входит в решение. Границы/бюджеты/проверки потери данных и миграций не ослабляются.

В изолированном verify:widget-example unit запускается с --exclude examples/**: копия уже находится в packages/counter-widget. Это исключает повтор тех же3 тестов без потери проверки подключённого пакета.

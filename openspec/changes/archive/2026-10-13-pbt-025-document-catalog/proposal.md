# PBT-025 — Каталог документов и повторное открытие

## Why

Рабочее пространство полноценно (PBT-018–024), но жизненный цикл документов ограничен: закрытый документ можно найти и открыть только через диалог «добавить виджет», переименование и удаление не реализованы, а выбор документов и подписи окон в приложении проверяют поля содержимого конкретных модулей (`checklistTitle`/`planTitle`) — каталог не опирается на метаданные, что требовал DoD карточки. Согласовано: «Каталог планов — создание, переименование, удаление, повторное открытие и несколько представлений одного плана» (решения §2); правило удаления — ADR-7 PBT-002. Попутно исправляется дрейф от ADR-5 PBT-002: название документа предусмотрено в оболочке записи, но реализация его не завела.

## What Changes

- Название документа переносится в метаданные: `ManagedDocument.title`, название передаётся при создании, новая операция сервиса `rename` (новая редакция, автосохранение, уведомление подписчиков). Для хранимых записей без названия — ленивое дополнение при старте силами приложения; полная миграция — PBT-026.
- Новый каталог документов («Документы» в шапке): список по метаданным, фильтр по типам из регистрации модулей, создание через фабрику модуля, переименование, удаление с подтверждением, открытие в виджете — в том числе сразу вторым экземпляром. Каталог не проверяет поля содержимого модулей.
- Сервис документов: операция `delete` — отмена отложенной записи, удаление из памяти и хранилища (контракт хранилища дополняется `delete`), очистка состояния сохранения и подписок.
- Удаление документа при открытых окнах: окна переходят в состояние «документ недоступен» с возможностью выбрать другой документ того же типа (ADR-7 PBT-002).
- Оба каталога — виджетов и документов — переводятся на выпадающие панели от кнопок в шапке по макету 04 (вместо модального диалога PBT-019). Попутное расширение границ карточки: дополнение зафиксировано в design.md.
- Подписи окон вычисляются из названия документа при рендере — снимает известный trade-off устаревания `label` (design PBT-024 D2).

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- `document-management` — ADDED: каталог документов (список, фильтр по типу, раздельные состояния «пусто / нет по фильтру / ошибка загрузки»), переименование, удаление с согласованным поведением открытых окон, открытие документа из каталога в экземпляре виджета; название — обязательное поле оболочки документа.
- `widget-registry` — MODIFIED: фабрика содержимого дескриптора документной поддержки не принимает название — название документа передаётся сервису документов при создании.
- `widget-windows` — ADDED: состояние «документ недоступен» у открытого экземпляра и замена недоступного документа выбором другого документа того же типа.

## Non-goals

- Полные миграции и версии документов (PBT-026) — здесь только ленивое дополнение названия старым записям.
- Жизненный цикл скрытых/свёрнутых окон: пауза отрисовки, подписки, ошибки рендера (PBT-027).
- Дизайн-токены и темы (PBT-066) — dropdown-панели стилизуются текущими токенами.
- Межоконные конфликты рабочего пространства (локальный сценарий одного окна, как в PBT-024).
- Поиск по содержимому документов; удаление вкладки каскадом удаляет экземпляры — вне этого change.

## Impact

- `packages/widget-sdk`: `ManagedDocument` + `title`, `DocumentCreateInput` + `title`, `DocumentService` + `rename`/`delete`, `WidgetDocumentSupport.createContent` без параметра названия.
- `packages/dashboard`: `document-service` (title при создании, rename, delete с очисткой очереди и состояний), новые dropdown-панели каталогов, `App` (кнопка «Документы», перепривязка окон, подписи из title), `main.tsx` (безопасный restore, ленивое дополнение названия старым записям), `index.css`.
- `packages/checklist`, `packages/gantt`: фабрики содержимого без параметра названия.
- E2E: новый сквозной сценарий каталога; правки существующих сценариев, завязанных на модальный диалог выбора документа.

# Design — PBT-144

## D1. Механизм дефекта

`download(row)` диалога резервных копий: `URL.createObjectURL(blob)` → `anchor.download = имя` → `anchor.click()` → **синхронно** `URL.revokeObjectURL(url)` → статус «Файл передан браузеру для скачивания».

`anchor.click()` лишь инициирует скачивание: браузерный процесс Chromium разыменовывает blob-URL асинхронно. Немедленный отзыв в том же таске JS оставляет браузеру окно, в котором URL уже недействителен — скачивание отменяется без ошибки на странице. Исход гонки зависит от нагрузки/планировщика, поэтому дефект перемежающийся: в споко­йной изоляции тест проходил, под нагрузкой полного набора — падал 2/2, повтор одиночного теста дал 1/8.

## D2. Решение

Отложенный отзыв: `window.setTimeout(() => URL.revokeObjectURL(url), 1000)` — прецедент `PlanGanttWidget` (экспорт PlantUML, два вызова, работает с момента внедрения). Тысяча миллисекунд на много порядков превышает обычное время разыменования; blob копии — килобайты JSON, удержание на секунду неощутимо. Таймер одноразовый, утечки нет.

Отвергнутое: отзыв по событию завершения скачивания — страница из JS не получает такого события; отзыв «через 40 с» по образцу FileSaver.js — избыточно для KB-объёмов и расходится с прецедентом проекта.

Смежное: `notes/export.ts` уже откладывает отзыв (`setTimeout 0`, отзыв в `catch`) — сбоев не зафиксировано, не меняется (Non-goal); повышение задержки при будущих флейках — отдельное решение.

## D4. Тестовая гонка, вскрытая фиксом

После отложенного отзыва 2/8 повторов calendar-теста упали с «Execution context was destroyed»: `expect.poll(page.evaluate)` стартует сразу после клика «Заменить пространство», а `restore()` после `replace` выполняет `window.location.reload()` — evaluate попадает в навигацию. Класс ошибки уже встречался в диагностике проекта (`.context/diagnostics/pbt-139/browser-final-2.log`); до фикса скачивания тест до этого места не доходил (вис на `waitForEvent('download')`).

Решение: ошибки навигации внутри poll возвращаются как `undefined` («ещё не готово», повтор), итоговое `toMatchObject` без изменений. Это не маскировка дефекта: проверяемое поведение то же, ретрай устраняет только гонку теста с перезагрузкой. `waitForFunction` SW-контроллера стоит после успешного poll — к этому моменту навигаций нет.

## D5. Проверки

- Регресс: `calendar.spec.ts:188` с `--repeat-each=8` — до фикса скачивания 1/8 красный (зависание `download`), после отложенного отзыва вскрылась тестовая гонка (2/8), после стабилизации poll — 8/8 зелёные.
- Прогон `workspace-backups.spec.ts` (родная специфика диалога) и calendar-спеки целиком.
- Полный набор testing.md — включая ожидающий PBT-143, которому нужен детерминированный набор.
- Живой контроль: скачивание копии владельцем в реальном браузере (по желанию).

## D6. Риски

- Остаточная теоретическая гонка при экстремальной задержке браузера (>1 c) до разыменования — на практике не наблюдалась даже под нагрузкой набора; при повторении — увеличить задержку отдельным решением.
- `blocked`-таймер при закрытии вкладки до 1 с — отзыв не критичен, сборщик мусора контекста освобождает blob.

# PBT-058 — Итоговая проверка производительности

Дата: 2026-10-23. Production-код: develop `65aba99` после PBT-057. Изменения этой задачи — benchmark и документация. **Приёмка заблокирована:** добавление задачи превышает утверждённые 400 мс (PBT-080); при изменении сроков жестом в общем плане обнаружен откат (PBT-081). Бюджеты не пересматриваются, оптимизации и исправления — отдельными PR.

## Окружение и данные

Apple M4 Pro, 24 ГБ RAM, macOS 26.6.2 (25G83), Node 22.12.0, npm 11.2.0, Playwright 1.63.0, установленный Google Chrome 155.0.8059.86. Окно headed 1400×1000, активная вкладка, DevTools закрыты, без настроенного CPU/network throttling. Перед прогоном остановлены dev/preview/MCP-страницы. Калибровка видимости/фокуса/rAF сохраняется в raw; headless не используется для окончательных чисел.

A: golden PBT-012 `plan-500.json`, seed42, **500 задач, 100 групп, 425 FS-связей**, 9 ресурсов. Числа взяты из фактического golden, прежнее описание «~25 групп» не подменяет данные. **6 проектных +4 ресурсных представления одного плана на одной вкладке**, режим сетки. Десять окон смонтированы и получают данные, часть физически ниже viewport; это не десять больших таймлайнов, одновременно помещённых в экран.

B: 10 независимых планов по 50 задач, seeds42–51, по одному проектному виду на 10 вкладках. Дополнительный тест переключения наборов: вкладка A (6+4, общий500) ↔ вкладка B (10 проектных, независимые50), всего 20 keep-mounted окон; это отдельный случай от исходного B.

Данные преобразуются из fixtures-only в текущий native JSON с сохранением ID/дат/связей и проверяются `parsePlanContent`. Подготовка через штатный UI-импорт и каталог виджетов, без подмены продуктового адаптера и без записи fixture прямо в IDB. Seeds/хеши/версии/состав — в [raw](..). Fixture и lockfile не менялись, новых зависимостей нет.

## Методика

Один разогрев и пять измеряемых повторов; исходные выборки, медиана и p95 nearest-rank (при n=5 максимум). Сравнение с бюджетом — медиана, p95 раскрыт. При переключении направлений каждый имеет пять измерений; объединённая выборка приведена только дополнительно. Измерения последовательны, контексты независимы; состояние перед повтором восстанавливается через UI.

Монтирование: первый внешний init-script нового документа до bootstrap → фактический контент всех 10 окон и два rAF. Включено восстановление IDB/адаптеры, исключена сеть до первого JS. Повторная загрузка — на прогретом браузерном кэше после разогрева. Это консервативнее компонентного mount PBT-016; не чистое время React.

Переключение: событие клика в странице → активный набор с содержимым и два rAF; keep-mounted не объявляется новым mount. Добавление: click Submit подготовленной формы → обновлённые счётчики/готовые чарты всех 10 видов и два rAF. Подготовка полей и время RPC Playwright исключены. Контрольная добавленная задача удаляется до следующего повтора; исходные 500 не накапливаются.

Запись: начало реальной транзакции документов → complete; внешние обёртки IDB-прототипов сохраняют оригинальные аргументы и результаты. Это wall time транзакции, включая ожидание callback в занятом главном потоке, а не чистая дисковая стоимость. Полное Submit→persisted с debounce приводится отдельно. Сырая запись напрямую в IDB вместо автосохранения не используется.

Прокрутка: реальное горизонтальное колесо на три ширины шкалы за 120 шагов; независимые rAF-интервалы и фактическое перемещение сохраняются. Один проектный вид максимизирован, девять соседей скрыты keep-mounted — это явно отдельная нагрузка от добавления при 10 открытых видах. Численный FPS ресурсного вида этим прогоном не доказан. Zoom измеряет Дни↔Недели; штатный UI имеет две позиции, «±2 шага» неприменимы буквально, поэтому выполнены полные циклы двух состояний.

Жесты: отдельные реальные mouse events; время первой реакции после mouseup и стабильность дат после всех сверок проверяются раздельно. Фикстура уходит до 2037 года: перед жестом прокрутить фактический `.wx-chart` к полосе после 2-секундного окна восстановления, проверить elementFromPoint. Попытки, где мышь промахнулась по полосе вне viewport, не засчитываются в доказательства. Пять измеряемых drag прошли; серия resize не завершена (нет устойчивого наблюдаемого изменения в первом прогоне). Полную проверку жестов нельзя объявить прошедшей.

## Жизненный цикл и память

Два независимых случая: план-50 на десяти вкладках и общий план-500 в десяти представлениях. Один разогревочный цикл, затем 20 повторов открыть→свернуть/развернуть→закрыть. После каждого закрытия число подписок возвращается к 10; точки heap/DOM — 0/5/10/15/20, после завершения 2,2-секундного окна callbacks и принудительного GC. GC выполняется вне времен отклика.

| Случай | JS heap после GC, 0→20 | DOM nodes, 0/5/10/15/20 | Обработчики, 0/5/10/15/20 | Подписки |
| --- | --- | --- | --- | --- |
| B, план50 | 12.00→12.94 МБ | 6860, 6860, 6860, 6860, 6860 | 751, 751, 751, 751, 751 | 10 во всех точках |
| A, план500 | 51.66→52.67 МБ | 58307, 58316, 58316, 58316, 58316 | 3120, 3120, 3120, 3120, 3120 | 10 во всех точках |

DOM/обработчики не растут от пачки к пачке после разогрева; JS heap вырос примерно на 0,9–1 МБ за 20 циклов. Удержание удалённого документа сервисом/IDB не обнаружено; к памяти применяется качественная оценка, без выдуманного численного бюджета.

Сохранённые документы намеренно остаются в каталоге при закрытии окон. Временный импортированный документ и его пустой подготовительный документ удаляются через каталог; проверены отсутствие целевого документа в каталоге, IDB и кеше сервиса. Reload независимых вкладок восстанавливает 10 проектных окон и 10 подписок. Умеренный рост JS heap раскрыт; эти наблюдения не доказывают отсутствие любых утечек в длительных сессиях.

## Находки и воспроизведение MCP

- **PBT-079:** закрытие первой активной вкладки из двух выбирает ID удалённой вкладки; также остаются orphan instances в snapshot. В подготовке benchmark стартовые окна сначала закрываются, затем после удаления вкладки явно выбирается оставшаяся. Эти действия вне измеряемой операции; продукт не исправлялся.
- **PBT-080:** добавление в общий план с 10 представлениями медленнее 400 мс. Источник нужно установить профилем, не назначать причиной по догадке. Кандидаты — повторные расчёты и пересоздание представлений при ревизии.
- **PBT-081:** срок, уже изменённый жестом, возвращается к исходному с несколькими ревизиями при нескольких проектных видах общего документа. Benchmark оставляет проверку красной; retry/skip не добавлены.

Отдельный MCP на production: 6 проектных видов общего плана500, один максимизирован, фильтр «Задача 500», Дни. Hit-testing подтвердил попадание в полосу `:t-500`. После движения мыши на 96px документ наблюдался в ревизии5 с датами 05–20.03.2037, затем примерно через 1,5 с в ревизии9 с исходными 05–18.03.2037. Это подтверждение отката, а не успешное выполнение корректного drag/resize. Заключительная отдельная MCP-проверка в новом контексте также дала ревизию1→4 с исходными датами в финале; hit-testing был корректным, ошибок страницы/console.error не обнаружено. ## Проверки и DoD

- Данные/методика/окружение воспроизводимы; исходные значения приложены.
- Численное сравнение основных метрик собрано; корректный полный набор жестов пока блокирован PBT-081.
- 20 циклов на двух нагрузках проверены с подписками/DOM/heap/удалением документа; ограничения памяти раскрыты.
- **Бюджет добавления не выполнен, итоговый DoD остаётся открытым.** Никакой оптимизации production-кода в этом PR нет.
- Отчёт позволяет повторить замеры; PBT-058 нельзя считать завершённой до исправлений и повторной проверки.

Стандартные проверки: lint/typecheck — успешно, unit **492/492**, build — успешно (85 precache entries), общий browser **134/134** за 28,5 с, OpenSpec strict **19/19**. Полный benchmark: **2 сценария выполнены, 1 красный** (resize); отдельный budget checker возвращает exit1 из-за добавления и незавершённого жеста. Это не зелёная приёмка производительности. PWA-обновления и планировочный набор PBT-057 не менялись и в этой задаче повторно не запускались.

## Команды

Перед автоматикой остановить dev, старые preview и живые MCP-страницы, освободить 4173. Production-сборка обязательна; окна Chrome должны оставаться активными. Результаты относятся к согласованному устройству.

```bash
npm ci
npm run build
npm run bench:release
```

`bench:release` сохраняет результаты даже при красном критерии; ненулевой exit code — ожидаемый сигнал невыполненного бюджета/стабильности, а не успешная приёмка. Команда с фильтром предназначена для диагностики; общий бюджет по частичному запуску не вычисляется:

```bash
npm run bench:release -- --grep 'A-interactions'
node tests/performance/check-budgets.mjs
```

Raw: `openspec/changes/pbt-058-release-performance/results/{environment,A,B,A-interactions}.json`; общий runId защищает от смешивания старых выборок. UI/failure-снимки — `test-results/performance/`; общий browser-набор очищает `test-results`, нужные артефакты сохранять заранее.

Общие проверки отдельно, после завершения benchmark и остановки preview/MCP:

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run test:browser
openspec validate --all --strict
```

Скрипты benchmark выполняются Playwright как TypeScript; штатный `typecheck` проверяет приложения/пакеты и не является отдельной статической проверкой browser-скриптов. Ранний `load-demo` не используется вместо production-приложения и остаётся до отдельной релизной зачистки по ADR-6.

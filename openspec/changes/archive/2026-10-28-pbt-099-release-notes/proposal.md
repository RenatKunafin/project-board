## Why

Пользователям и команде нужен единый журнал изменений, который можно обновлять вместе с каждым выпуском и читать внутри приложения. Сейчас описание выпуска не является частью пользовательского сценария PWA, поэтому пользователю сложно понять, что изменилось после обновления.

## What Changes

- Добавить поддерживаемый в репозитории формат release notes, сгруппированный по версиям и обновляемый при подготовке выпуска.
- При первом наполнении подготовить заметки для уже опубликованных версий, восстановив пользовательски значимые изменения по GitHub Releases, тегам и истории проекта.
- Показывать журнал изменений в PWA через пункт «Что нового» в настройках рядом с резервными копиями.
- При обнаружении новой версии приложения предлагать открыть изменения этого выпуска; просмотр журнала также доступен позднее из настроек.
- Обеспечить доступность актуального журнала в установленной и offline PWA.

## Capabilities

### New Capabilities
- `release-notes`: ведение версионного журнала и его представление пользователю в PWA.

### Modified Capabilities
- `pwa-lifecycle`: предложение пользователю ознакомиться с изменениями при доступности новой версии.

## Impact

- Репозиторная документация релизов и сборка `apps/project-board`.
- Настройки PWA, интерфейс просмотра release notes и интеграция с существующим сценарием обнаружения обновлений.
- Процесс подготовки выпуска дополняется обязательным обновлением журнала и проверкой записи для публикуемого тега в release workflow; триггер публикации сохраняется.
- Не меняются формат данных документов и резервное копирование.

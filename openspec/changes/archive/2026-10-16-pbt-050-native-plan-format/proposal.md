# PBT-050 — Собственный формат плана

## Why

План существует только внутри локальной БД браузера: очистка данных сайта уничтожает его, а передать редактируемые данные другому человеку нельзя (§16 решений: «собственный формат для полного переноса редактируемого плана» — согласовано). Первая задача раздела «Обмен файлами»: версионированный файловый формат одного плана — сериализация, валидация и десериализация. Файл должен переносить план целиком (задачи, группы, связи, назначения, типы работ, календарь, отпуска) и давать структурированную диагностику вместо молчаливого fallback.

## What Changes

- Новый модуль `native-plan-format.ts` в `packages/gantt`: чистые функции `serializePlanFile` / `deserializePlanFile` (строка JSON ↔ план с названием).
- Конверт файла: `format: "project-board-plan"`, `formatVersion` (версия формата файла, отдельная от `schemaVersion` содержимого), название плана (каноническое место — метаданные документа, PBT-025), `schemaVersion`, `content` (модель плана v1 без изменений).
- Политика переноса (закрепляется в design и тестах): импорт файла всегда создаёт **новый независимый документ**; идентификаторы сущностей внутри плана сохраняются из файла, ссылки остаются внутренними — случайное связывание ресурсов разных планов исключено по построению (независимость планов — действующий spec).
- Диагностика по образцу `parsePlanContent`: повреждённый JSON, чужой формат, будущая версия формата, невалидное содержимое — результат с перечнем проблем (код, место, сообщение), без подмены данных.
- Утилита имени файла экспорта `planFileName(now: Date)`: шаблон `pb-plan-YYYY-MM-DD_HH-mm-ss.json` (решение владельца 2026-10-16; двоеточия заменены дефисами — `:` недопустим в именах файлов Windows, целевой платформе ADR-4). Имя файла — конвенция генерации, парсер его не проверяет.
- Эталонный файл формата и описание формата для другого пользователя/разработчика (DoD-5).
- Round-trip: экспорт → импорт восстанавливает все разделы плана и поддержанные дополнительные поля (passthrough неизвестных полей содержимого).

## Impact

- `packages/gantt`: новый модуль + экспорт из `index.ts`; ядро (`plan-document`, команды) не расширяется.
- `tests/`: unit-тесты сериализации, валидации, десериализации и round-trip; эталонная фикстура.
- `packages/gantt/NATIVE-PLAN-FORMAT.md` — описание формата.
- Delta spec `plan-transfer` (capability заявлена в workflow, действующего spec нет — создастся при архивации).

## Non-Goals

- UI импорта/экспорта (кнопки, диалоги, выбор файла) — PBT-051.
- Импорт OnlineGantt `.gantt` — PBT-052–054; экспорт PlantUML — PBT-055–056.
- Замена содержимого существующего плана из файла — вне v1 (потребность закрывается связкой «новый план + удаление старого»; при реальной потребности — отдельная задача: требует развилки целостности ссылок и открытых представлений).
- Резервная копия всего приложения (вкладки, экземпляры, раскладки) — PBT-064+.
- Миграции устаревших версий формата файла: v1 — первая версия, миграционный механизм появится отдельным решением при первой смене `formatVersion`.

# Design — PBT-041 Resource catalog editors

## Context

Команды справочников готовы (PBT-033): `createResource`/`updateResource`/`deleteResource`/`createWorkType`/`updateWorkType`/`deleteWorkType` — чистые, с кодами `invalid-title`/`unknown-resource`/`unknown-work-type`; удаление — вариант A владельца (чистка ссылок задач и недоступностей без удаления задач). UI-паттерны диалогов отработаны (PBT-038/040): оверлей внутри контейнера виджета, `commitPlan` с ретраем, клавиатура Esc/Enter, возврат фокуса. Dropdown-панели платформы (PBT-025) недоступны модулю (границы ADR-3 — модуль не импортирует dashboard), поэтому диалог собственный.

## Goals / Non-Goals

- Goals: создание/переименование/удаление ресурсов; создание типов с параллельностью, её переключение, переименование/удаление; понятные подтверждения и ошибки; независимость планов.
- Non-Goals: см. proposal.

## Decisions

### D1. Один диалог, две секции

`ResourceCatalogDialog`: секция «Исполнители» + секция «Типы работ» друг под другом (без вкладок — всё видно сразу, записей немного). Секция: список строк (название [+ флажок параллельности у типа] + кнопки «изменить»/«удалить»), внизу поле добавления с кнопкой. Пустой справочник — плейсхолдер «Нет исполнителей — добавьте первого».

Альтернатива «две вкладки» отклонена: вкладки скрывают содержимое, а объём записей (единицы–десятки) позволяет вертикальный список.

### D2. Инлайн-редактирование названий

Кнопка «изменить» переводит строку в режим ввода (input с текущим значением): Enter — сохранить, Esc — отмена, «✓»/«×» — мышью. Причина против отдельной формы: правка однострочная, лишний диалог — лишние клики; паттерн подтверждения window.confirm для удаления сохранён (прецедент PBT-038/040).

### D3. Параллельность — флажок в строке + правило с примерами

Тип работы: флажок «можно параллельно» в строке, переключение — сразу команда `updateWorkType({allowsParallel})` (одно изменение — одна запись). В шапке секции — статичное пояснение: «Разработка — нельзя параллельно; ПСИ — можно: пересечение непараллелизуемых работ одного ресурса — конфликт» (правило 11.3 решений, D4 ADR PBT-003). При создании типа — флажок в форме добавления (умолчание: не параллельно — консервативно, D4).

### D4. Удаление с объяснением последствий

`window.confirm` с текстом по типу записи: ресурс — «Задачи потеряют назначение «{title}», его периоды недоступности будут удалены. Удалить?»; тип — «Задачи потеряют тип «{title}» (станут непараллелизуемыми по умолчанию). Удалить?». Пояснение соответствует контракту ядра (вариант A PBT-033); отклонений удаления ядро не производит — объяснение «или отклоняется» (DoD-3) покрывается случаем гонки: ошибка `unknown-resource/work-type` показывается как alert строки (запись уже удалена вторым экземпляром).

### D5. Ошибки домена — по месту

`invalid-title` (пустое/пробельное название) — alert под полем добавления или под редактируемой строкой; `unknown-*` (гонка) — alert строки. Форма не закрывается при ошибке; документ не меняется (атомарность ядра).

### D6. Независимость планов

Бесплатно из архитектуры: команды применяются к документу конкретного плана (`commitPlan` по `documentId`), идентичность по id. E2E проверяет два плана с одинаковыми названиями ресурсов и переименование в одном без влияния на другой (DoD-4).

### D7. UI без ёмкости пула (DoD-5)

Никаких полей процента/ёмкости в редакторах; загруженность — предмет ресурсного представления (PBT-047), не справочника. Зафиксировано как Non-Goal (альтернатива «QA = 300%» отклонена в решениях §11.1).

### D8. Клавиатура и фокус

Esc закрывает диалог (вне режима редактирования строки), Enter в поле добавления — добавить, в поле переименования — сохранить; при закрытии диалога фокус возвращается на кнопку тулбара (прецедент PBT-038/040).

## Risks / Trade-offs

- Инлайн-редактирование без отдельной формы — при будущих полях ресурса (например, описание) потребует рефакторинга на форму; принято ради компактности v1.
- Флажок параллельности переключается одной записью без подтверждения — осознанно (обратимое действие, один флаг).
- Переиспользование классов `task-editor__*` — при третьем диалоге серии (PBT-043 отпуска) стоит вынести общий CSS диалогов; пока объём не оправдывает.

## Migration Plan

Схема документа не меняется; справочники уже в модели v1. Новая поверхность UI.

## Open Questions

Нет — развилок, требующих владельца, не выявлено; серия делается автономно (директива владельца 2026-10-14/15).

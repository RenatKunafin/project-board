# PBT-030 — Документ плана и регистрация модуля

## Why

Ядро планирования разблокировано решением PBT-017 (ADR, PR#20), но начинать его с операций (PBT-031) нельзя: нет типа документа плана, который операции изменяют. Модуль Гантта (`packages/gantt`) содержит только арифметику календаря (PBT-013); каталог приложения не предлагает планы, а fixtures-формат PBT-012 — тестовый и не годится как продуктовый контракт. Эта задача вводит типизированный, версионируемый и валидируемый документ плана v1 и регистрирует модуль через SDK — фундамент для операций (PBT-031+), представлений (PBT-037, PBT-047) и импорта (PBT-050+).

## What Changes

- В `packages/gantt` появляется продуктовая модель документа плана v1: задачи, вложенные группы, рабочий календарь, ресурсы, назначения, типы работ, периоды недоступности, FS-зависимости — иммутабельные структуры, без зависимостей от UI-библиотек (следствие ADR PBT-017 ADR-3).
- Фабрика пустого плана: календарь пн–пт по умолчанию, пустые коллекции; дата формата — ISO `YYYY-MM-DD`, окончание включительно (A1), лаг зависимостей ≥ 0 (C2).
- Валидатор чтения: повреждённые данные возвращают список диагностики (код, путь, причина) и НЕ становятся рабочим документом — в отличие от молчаливого fallback чек-листа, здесь DoD требует явную диагностику.
- Регистрация модуля `createGanttModule()` по образцу чек-листа: тип виджета «План» с `documentSupport {moduleId: 'gantt', documentType: 'plan', schemaVersion: 1}`; компонент — временная заглушка до продуктового представления (PBT-037), указанная в design как осознанное временное решение.
- Модуль подключается в комплектацию приложения (`apps/project-board/src/widgets.ts`): каталог предлагает создание плана; создание/сохранение/открытие идут через существующие сервисы платформы без нового кода платформы.
- Delta spec: новая capability `planning-documents` (формат, фабрика, валидация, независимость планов, регистрация).
- Зависимость PBT-030 ← PBT-026 снята владельцем 2026-10-10: `schemaVersion` закладывается сразу, механизм миграций — при появлении v2.

## Capabilities

### New Capabilities

- `planning-documents` — формат документа плана, фабрика пустого плана, валидация при чтении, независимость планов, регистрация модуля плана.

### Modified Capabilities

- Нет.

## Non-goals

- Операции над задачами и датами (PBT-031), иерархия/сводные сроки (PBT-032), ресурсы и конфликты (PBT-033–036).
- Продуктовые представления Гантта (PBT-037+, PBT-047+): заглушка-компонент не отображает план.
- UI-каталог документов (PBT-025), миграции документов (PBT-026): «создание через общий каталог» проверяется сервисом и регистрацией модуля.
- Импорт `.gantt` (PBT-052+): формат v1 проектируется совместимым по смыслу, адаптер — отдельная задача.
- Изменения платформы (`packages/dashboard`, `widget-sdk`): используются как есть.

## Impact

- Новые файлы: `packages/gantt/src/plan-document.ts`, `packages/gantt/src/PlanPlaceholderWidget.tsx`, тесты; `openspec/changes/pbt-030-plan-document/specs/planning-documents/spec.md`.
- Изменённые: `packages/gantt/src/index.ts` (экспорт модуля), `apps/project-board/src/widgets.ts` (комплектация), `apps/project-board/src/App.tsx` (обобщение рендера панелей по реестру — см. design D7), `tests/e2e/shell.spec.ts` (уточнение локаторов двух флаки-тестов).
- Разблокирует: PBT-031 (операции), далее PBT-032+; для PBT-052+ фиксирует целевой формат импорта.

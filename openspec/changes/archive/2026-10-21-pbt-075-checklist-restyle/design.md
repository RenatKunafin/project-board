# Design — PBT-075 Чек-лист: оформление, прогресс и скрытие выполненных

Референс: `flexi-dashboard-hub/src/components/dashboard/widgets.tsx` (`TodoWidget`, строки 61–121), скриншот `screenshots/redesign-ref/01-dashboard-overview.png` (правое окно). Переносим визуальный язык, не код (принцип серии).

## D1. Шапка: производный прогресс + кнопка-чип скрытия

- **Прогресс** — чистая производная документа: `done = items.filter(done).length`; подпись «{done}/{total} выполнено ({pct}%)» — 12px `muted-foreground`, процент — `--font-mono` `--foreground` (по прототипу); полоса 4px: фон `--muted`, заполнение `--success`, радиус полный, `transition: width`. Пустой список — «0/0 выполнено (0%)», полоса пустая (деления нет, прототип показывает то же).
- **Кнопка-чип «Скрыть выполненные»**: `aria-pressed` (toggle), текст 12px; активна — `border-color: color-mix(primary 50%)`, фон `color-mix(primary 10%)`, текст `--foreground`; неактивна — рамка `--border`, текст `--muted-foreground`, hover — текст `--foreground`. Прецедент чипов: `.doc-catalog__chip` (PBT-025/069).
- Раскладка шапки: `flex` между прогрессом (flex:1, min-width 0) и чипом (`flex: none`), отступ 8px, нижний отступ перед списком.

## D2. Скрытие — persisted-состояние экземпляра (механизм PBT-049)

- Сегодня: `documentService.setViewSettings(instanceId, { hideDone })` — **in-memory Map сервиса** (document-service.ts:465–477), reload теряет флаг; карточка требует переживание.
- Переход на SDK `WidgetProps.updateSettings?.({ hideDone })` (PBT-049: запись в settings БД `view:<instanceId>`, дебаунс на стороне платформы); чтение — `settings.hideDone === true` при монтировании (нестрогое — отсутствующее/unknown → false).
- `visible === false` (PBT-027): пересчёт фильтра не выполняется — логика `visibleItemsRef` сохраняется без изменений.
- In-memory флаг исчезает бесследно: он и сегодня не живёт дольше сессии — миграция не нужна. `setViewSettings/getViewSettings` из SDK не удаляем (платформенный API вне границ задачи).
- Изоляция экземпляров — по ключу `view:<instanceId>` (прецедент PBT-049), существующий e2e «локальная настройка экземпляра изолирована» остаётся зелёным (правка только на кнопку).

## D3. Пункты списка

- Строка (`li`): `padding: 4px 6px`, радиус `--radius-sm`, hover `--accent` (по прототипу `bg-accent/50` — принимаем полную заливку токеном, half-mix на тёмном фоне почти неотличим и дешевле по слоям).
- Чекбокс: 16×16, `accent-color: var(--primary)` (нативный чекбокс окрашивается токеном — прототип `accent-primary`).
- Выполненный текст: `line-through` + `--muted-foreground` (уже есть).
- Удаление: иконка `Trash2` (lucide, 14px) вместо «×»; `opacity: 0`, на hover строки — 1 (фокус с клавиатуры — `:focus-visible` тоже показывает); hover иконки — `--destructive`; `aria-label="Удалить: <текст>"` и локатор `.checklist__remove` сохраняются (e2e).
- Инлайн-переименование (dblclick, Enter/Esc) — без изменений; `.checklist__edit` вписывается в строку.
- Пустые состояния («Список пуст…», «Все пункты выполнены.») — текст и поведение сохраняются.

## D4. Ввод

- Форма: поле `flex: 1` (рамка `--input`, фон `--background`, фокус — рамка `--primary`), placeholder «Новая задача…» (по прототипу; сейчас «Новый пункт» — e2e используют placeholder, правим локаторы) + кнопка 32×32 `--primary`/`--primary-foreground` с иконкой `Plus` 16px, `aria-label="Добавить"` (сохраняется для e2e), `type="submit"` (Enter уже работает через форму).
- `lucide-react` в зависимостях `packages/checklist` (пин `0.575.0`, прецеденты PBT-069/072/073).

## D5. Стили пакета и чистка приложения

- Новый `packages/checklist/src/checklist.css` (импорт в виджете); из `apps/project-board/src/index.css` блок `.checklist__*` (строки ~343–415) удаляется. Только токены `:root` (правило до PBT-066), значения по прототипу.
- Корень `.checklist`: `flex column, height: 100%, padding: 12px, box-sizing: border-box` — вписывается в `widget-window__body` (прецедент растяжки PBT-073: body без flex:1, height:100% от окна). Скролл — только список (`overflow: auto`, шапка и форма закреплены).

## D6. Тесты и проверки

- **E2e (обновление `shell.spec.ts`):** «Скрывать выполненные» — с чекбокса на кнопку (`getByRole('button', { name: 'Скрыть выполненные' })` + `aria-pressed`), 2 существующих теста; placeholder «Новый пункт» → «Новая задача…» (3 вхождения).
- **Новые e2e:** (1) прогресс — добавить 3 пункта, отметить 2 → подпись «2/3 выполнено (67%)», полоса `width` ≈ 66.7% (атрибут style); (2) скрытие переживает reload — включить, отметить выполненный, reload → фильтр активен (до ката настройка терялась); (3) кнопка-«+» добавляет (aria-label «Добавить»).
- **Живые проверки (MCP):** консоль, 1024×778 и широкое окно, скриншоты до/после; сценарий карточки «добавить 3 → отметить 2 → скрыть → reload».
- **Полный набор:** lint → typecheck → test → build → чистая среда → test:browser → `openspec validate --all --strict`.

## D7. Риски и меры

- `updateSettings` опционален (`WidgetProps.updateSettings?`) — виджет может получить окружение без платформенной поддержки (unit-стенды): все вызовы через `?.`, UI не зависит.
- Нативный чекбокс с `accent-color` — рендер отличается между ОС; на macOS/Chromium (e2e) предсказуем, визуально сверяется скриншотом.
- Перенос css из приложения в пакет меняет порядок каскада (специфичность не меняется — селекторы те же) — регресс e2e чек-листа и платформы (стили приложения рядом) покрывает полный прогон.

## D8. Правки ревью PR#54

- **Форма ввода прибита к низу** (замечание 1): пустые состояния не растягивались (hint-параграф вместо `ul flex:1`), форма шла за текстом — `.checklist__hint` теперь `flex: 1 1 auto` (margin 0; отступ даёт `margin-top` формы) — при пустом и «Все пункты выполнены» форма у нижнего края при любой высоте окна.
- **Двухстатусная кнопка скрытия** (замечание 2, решение владельца поверх прототипа — там текст неизменен): не нажата — «Скрыть выполненные», нажата — «Показать выполненные»; `aria-pressed` сохранён. Текст нажатого состояния — UI-деталь, delta spec не меняется (требование описывает переключатель, не подписи).
- **Хэндл ресайза тайлинга — по прототипу** (замечание 3, попутная правка вне карточки — платформенный css): дефолтный L-уголок RGL (`::after` border-right/bottom) заменён на два диагональных штриха 8×2px rotate(-45deg) через `::before`/`::after`, `muted-foreground/70` (color-mix), хэндл 14→16px — как SVG-уголок прототипа (`WidgetFrame.tsx` «M9 3 L3 9 M9 6 L6 9») и как каскад (PBT-070). Только визуал псевдоэлементов: геометрия и жесты RGL не тронуты (прецеденты PBT-068/070).
- **Финальная реализация уголка (после двух итераций ревью)**: два одинаковых штриха → НЕ прототип; сжатие маски 14×14 укорачивало штрихи; viewBox-сдвиг не применился. Итог: SVG-маска с точным путём прототипа, фиксированные 16×16, прижатые к углу **окна** с отступом 1px (`mask-position: calc(100% − 1px)` у RGL; у каскада `right/bottom: 11px` — хэндл react-rnd с inline `20×20, right/bottom −10px` центрирован на углу и наполовину за окном, привязка к хэндлу выводила штрихи за край). Отдельная находка: при замене блока у RGL-`::after` потерялись `width/height: 100%` — дефолтные 5×5 обрезали маску в «огрызок» (диагностика живьём по computed).
- **Активное окно без акцентной рамки** (решение владельца): `.widget-window--active` — `border-color: var(--border)` + `--shadow-float`; спека app-theme «рамка + тень» корректируется дельтой (тень при обычной границе).
- **Флаки widget-maximize (попутная находка)**: до-замер геометрии ловил автоскролл канваса `.instances` — фокус поля соседа при возросшей высоте контента (шапка чек-листа) заставлял браузер проскроллить 21px, а возврат из разворота (PBT-071 D4) нормализует scrollTop в 0 — координаты сравнивались в разных системах отсчёта (91 против 112; при одиночном прогоне поле было видно без скролла — маскировка). Фикс: нормализация `scrollTop=0` перед обоими замерами. Два отвергнутых подхода зафиксированы: poll ширины сетки (WidthProvider был ни при чём — ранняя укладка той же ширины) и цикл стабильности бокса (устойчивое, но прокрученное состояние).

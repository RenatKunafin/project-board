## Why

Владельцу нужно визуально отмечать произвольные даты на проектном Гантте (дедлайны, вехи, внешние события) цветом — так же, как сегодня выглядят нерабочие дни и дни-исключения. Сейчас единственная фоновая подсветка шкалы — календарь плана (выходные/праздники), который по смыслу привязан к рабочей арифметике; чисто декоративного выделения дат в продукте нет.

## What Changes

- Модель документа плана дополняется опциональным разделом «цветовые метки дат»: дата (ISO `YYYY-MM-DD`) → идентификатор цвета из конечной палитры — шести цветов существующей палитры задач (`coral`, `pumpkin`, `ochre`, `jade`, `sapphire`, `plum`). В приложении метки притушены прозрачностью (смешение с поверхностью), чтобы не конфликтовать с полосами задач (решение владельца 2026-11-11). Поле опционально, схема остаётся версии 1 — прецедент расширения без миграции PBT-084 (`tasks[].color`).
- Метки полностью декоративны: не влияют на определение рабочего дня, рабочую длительность, проверки зависимостей и конфликтов, подсветку нерабочих дней.
- Ядро: новая чистая команда атомарной замены набора меток с валидацией (ISO, существующая дата, уникальность даты, известный идентификатор цвета) — отдельно от `updateCalendar`, чтобы не смешивать декоративные данные с рабочей семантикой календаря.
- Управление: секция «Календарь» диалога «Настройки плана» получает список «Особые даты» (название владельца, 2026-11-11) — добавление дня/диапазона с выбором цвета из палитры, перекрашивание повторным добавлением, удаление; общий черновик настроек и одна запись при сохранении (механизм PBT-044/PBT-086).
- Отображение: только проектный Гантт (решение владельца 2026-11-11). Метка заливает колонку дня выбранным цветом в обоих масштабах («Дни» через `highlightTime`, «Недели» через собственный слой) с дневной точностью; при совпадении с нерабочим днём метка перекрывает фон (приоритет: метка > праздник > выходной; решение владельца 2026-11-11).
- Обмен: собственный формат плана сохраняет метки в round-trip; при импорте файла с неизвестным идентификатором цвета метки эта метка получает случайный известный цвет палитры (решение владельца 2026-11-11 об отказе от удаления), файл не отклоняется — по образцу нормализации цвета задач PBT-084.
- Экспорт PlantUML: особые даты переносятся заливкой дня по образцу эталонного примера владельца (`<дата> is colored in <цвет>`, соседние даты одного цвета — диапазоном `to`); цвет — осветлённое к белу представление hex палитры меток (эмуляция прозрачности на светлом фоне, без конфликтa с полосами задач); строки идут после серых выходных и перекрывают их; день метки не закрывается (`is closed` отсутствует) и не влияет на длительности; метки за пределами горизонта плана не выводятся и попадают в отчёт экспорта.

### Non-goals

- Ресурсный вид: метки не отображаются (данные в документе есть, отрисовка не вводится).
- Импорт `.gantt` OnlineGantt: метки не создаются (в формате нет соответствующего понятия).
- Произвольные цвета вне палитры, подписи/названия меток, автоправила раскраски дат.

## Capabilities

### New Capabilities

(нет — изменения укладываются в существующие возможности)

### Modified Capabilities

- `planning-documents`: новый раздел модели «цветовые метки дат» — хранение, декоративность, валидация при чтении и командная операция редактирования.
- `project-gantt`: отображение меток на шкале проектного Гантта с приоритетом над подсветкой нерабочих дней и управление метками в настройках плана.
- `plantuml-export`: особые даты переносятся заливкой дня hex-цветом палитры меток с приоритетом над выходными; метки вне горизонта — отчёт.
- `plan-transfer`: round-trip собственного формата сохраняет метки; нормализация неизвестного цвета метки при импорте.

## Impact

- `packages/gantt/src/plan-document.ts` — тип `PlanDateMark`, поле `dateMarks`, валидация в `parsePlanContent`.
- `packages/gantt/src/plan-commands.ts` — команда `updateDateMarks` (коды ошибок, атомарность).
- Новый `packages/gantt/src/date-mark-colors.ts` — палитра из 6 идентификаторов `task-colors.ts` (coral/pumpkin/ochre/jade/sapphire/plum, hex не дублируется); классы заливки генерируются из палитры по образцу `ganttBarColorRules`.
- `packages/gantt/src/PlanGanttWidget.tsx`, `svar-adapter.ts` / `calendar-view.ts` — определение цвета метки даты, рендер в режимах «Дни» и «Недели»; проверить сохранение `dateMarks` в `filterPlanForView`.
- `packages/gantt/src/PlanCalendarSection.tsx`, `plan-settings-draft.ts` — список «Особые даты» в общем черновике настроек.
- `packages/gantt/src/native-plan-format.ts` — нормализация неизвестных цветов меток при импорте.
- `packages/gantt/src/plantuml-export.ts` — заливка особых дат после блока выходных (механизм эталонного примера `is colored in`), диапазоны соседних дат, отчёт по меткам вне горизонта.
- `packages/gantt/src/gantt.css`, `apps/project-board/src/tokens.css` — производные заливки меток (новых литеральных цветов не появляется).
- Схема данных: версия 1 сохраняется, миграция не требуется; `PLAN_SCHEMA_VERSION` не меняется.
- Затрагиваемые представления по данным: ресурсный вид читает тот же документ, но поле игнорирует (без изменений кода ресурсного вида, кроме возможной необходимости не потерять поле при копиях плана).

## MODIFIED Requirements

### Requirement: Импорт файла с валидацией

Модуль SHALL десериализовать файл собственного формата с полной проверкой до выдачи плана: корректность JSON, наличие и типы полей конверта, совпадение маркера формата, поддержка версии формата и версии содержимого, валидность содержимого плана. Неизвестный идентификатор цвета задачи SHALL нормализоваться в автоматический цвет на шаге разбора; метка даты с неизвестным идентификатором цвета SHALL получать случайный известный цвет палитры меток на шаге разбора (решение владельца 2026-11-11); остальные проверки смягчения не имеют. Повреждённый или чужой файл MUST NOT выдаваться за план: результат SHALL содержать перечень диагностических сообщений с кодом, местом и причиной; входные данные MUST NOT изменяться. Проверка содержимого SHALL повторять полную валидацию плана при чтении, включая структуру, форматы дат, уникальность идентификаторов, внутренние ссылки и циклы групп.

#### Scenario: Повреждённый JSON даёт диагностику

- **GIVEN** текст файла обрезан и не является корректным JSON
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику синтаксической ошибки JSON
- **AND** план не создаётся

#### Scenario: Чужой формат распознаётся

- **GIVEN** файл с маркером формата, не совпадающим с маркером приложения
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику неизвестного формата
- **AND** содержимое файла не интерпретируется как план

#### Scenario: Невалидное содержимое даёт полный перечень проблем

- **GIVEN** файл формата приложения, содержимое которого ссылается на несуществующую группу и содержит цикл вложенности групп
- **WHEN** выполняется десериализация
- **THEN** результат содержит диагностику обеих проблем с указанием места
- **AND** план не создаётся

#### Scenario: Валидный файл выдаёт план с названием

- **GIVEN** файл формата приложения с корректным содержимым и названием плана
- **WHEN** выполняется десериализация
- **THEN** результат содержит план, эквивалентный содержимому файла, и название для создаваемого документа

#### Scenario: Неизвестный цвет файла нормализуется в автоматический

- **GIVEN** файл формата приложения с задачей, цвет которой — неизвестный палитре идентификатор
- **WHEN** выполняется десериализация
- **THEN** план создаётся, задача без ручного цвета, остальное содержимое задачи сохранено
- **AND** файл с повреждённой датой в той же задаче по-прежнему отклоняется с диагностикой

#### Scenario: Метка с неизвестным цветом получает случайный цвет палитры

- **GIVEN** файл формата приложения с двумя метками дат, у одной цвет — неизвестный палитре меток идентификатор
- **WHEN** выполняется десериализация
- **THEN** план создаётся с обеими метками, метка неизвестного цвета сохранена с одним из цветов палитры меток
- **AND** несколько меток с одним и тем же неизвестным цветом получают одинаковый цвет в пределах одного импорта
- **AND** файл с повреждённой датой метки в том же разделе по-прежнему отклоняется с диагностикой

### Requirement: Round-trip без потерь

Последовательные сериализация и десериализация плана SHALL восстанавливать название и все разделы содержимого без изменений, включая поддержанные дополнительные поля внутри сущностей содержимого, ручной цвет задач (идентификатор палитры либо его отсутствие) и цветовые метки дат. Повторный экспорт десериализованного плана SHALL давать эквивалентный файл без смены версии формата.

#### Scenario: Round-trip контрольного плана

- **GIVEN** план со всеми разделами модели
- **WHEN** план сериализуется в файл и десериализуется обратно
- **THEN** название и все разделы содержимого эквивалентны исходным

#### Scenario: Дополнительное поле сохраняется при переносе

- **GIVEN** файл, в содержимом которого у задачи присутствует неизвестное приложению поле
- **WHEN** файл десериализуется и результат сериализуется снова
- **THEN** дополнительное поле задачи сохраняется в полученном файле

#### Scenario: Ручной цвет сохраняется в round-trip

- **GIVEN** план с задачами, у части задан ручной цвет, у части он отсутствует
- **WHEN** план экспортируется в файл и импортируется обратно
- **THEN** идентификаторы цветов и отсутствие поля у неокрашенных задач сохраняются точно, версия формата не меняется

#### Scenario: Цветовые метки сохраняются в round-trip

- **GIVEN** план с метками дат разных цветов и план без меток
- **WHEN** оба плана экспортируются в файл и импортируются обратно
- **THEN** даты и цвета меток первого плана сохраняются точно, у второго раздел меток отсутствует, версия формата не меняется

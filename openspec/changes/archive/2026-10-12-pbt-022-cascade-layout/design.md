# Design — PBT-022: каскадное размещение окон

## Context

`TiledLayout` (PBT-021) даёт сетку; согласованное поведение каскада — решения §4.3: свободные позиции, перекрытие допустимо, активное окно поверх. Кандидат react-rnd (MIT) зафиксирован решениями §19 для «управляемых позиции и размеров». Активация окон (PBT-020: `activeInstanceId`) уже есть — глубина строится поверх неё. Сериализация должна оставаться в собственной структуре (прецедент `TiledLayoutState`).

## Goals / Non-Goals

**Goals:** `CascadeLayout`-адаптер (перенос/resize/границы/глубина), собственная сериализация, сворачивание, временный переключатель режимов для проверки.

**Non-Goals:** продуктовое переключение режимов (PBT-023), персистентность (PBT-024), пауза отрисовки (PBT-027), стилизация (PBT-066).

## Decisions

### D1. react-rnd 10.5.3, точный пин, изоляция в адаптере

`react-rnd` (MIT; тянет re-resizable + react-draggable) ставится в `packages/dashboard` с точным пином. Адаптер объявляет минимальный локальный контракт props (как в `TiledLayout` D1 PBT-021) — типы библиотеки не протекают в приложение. Библиотека даёт единый примитив «позиция+размер+drag+resize» — в отличие от RGL, без сеточной семантики.

### D2. Собственная структура каскадной раскладки

```text
CascadeLayoutState {
  areas: Record<instanceId, { x, y, width, height }>   // пиксели области вкладки
  order: instanceId[]                                   // порядок глубины, последний — верхний
}
```

Запись — после завершённых операций: `onDragStop`, `onResizeStop`, при активации (изменение порядка). Промежуточные движения в структуру не пишутся (решения §15.4). Библиотечные объекты, ссылки на DOM и узлы не сохраняются (DoD).

### D3. Глубина по активации

При активации окна его `instanceId` переносится в конец `order`; `zIndex = 1 + позиция в order`. Новые окна — наверх стека. Это даёт DoD «активация заднего окна поднимает его поверх» и сохраняемый порядок без UI-ссылок.

### D4. Ограничения размеров и правило границ

`sizeConstraints` (ячейки) → пиксели константой адаптера: `CASCADE_CELL = { width: 140, height: 96 }`; `minWidth = minWidth·140`, `minHeight = minHeight·96`, максимумы аналогично (если заданы). Стартовый размер нового окна — 600×420, зажатый ограничениями. Правило границ (DoD «заголовок остаётся доступным»): перенос ограничен областью вкладки так, что в видимой области остаётся минимум 120px ширины и полная высота заголовка окна (`bounds="parent"` + `dragHandleClassName=".widget-window__head"`); resize не выводит окно за область.

### D5. Сворачивание — как в тайлинге

Свёрнутое окно: `height = 44px` (высота заголовка), прежняя высота хранится в приложении (`collapsedHeights`), разворачивание возвращает (ADR-7 PBT-002). Позиция при сворачивании не меняется.

### D6. Новые окна — каскадный стек

Стартовая позиция нового окна: смещение по диагонали от левого верхнего угла: `x = 24 + (n mod 8) · 28`, `y = 24 + (n mod 8) · 28`, где `n` — число окон в раскладке; размер — стартовый из D4. Окно добавляется наверх стека.

### D7. Временный переключатель режимов

Минимальное управление в приложении: пара кнопок «Сетка / Каскад» (`aria-pressed`) рядом с «+ Виджет». Состояние — в памяти, одно на приложение; раскладки режимов не разделяются (переход на каскад и обратно пересобирает вид из соответствующего состояния: тайловое — своё, каскадное — своё, но без раздельного сохранения «последнего вида режима» — это PBT-023). Обозначено временным: PBT-023 заменит его продуктовым переключением с раздельными раскладками per вкладка.

### D8. Совместимость с рамкой и виджетами

`WidgetWindow` не меняется; `CascadeLayout` оборачивает окна, задаёт абсолютную позицию и zIndex. Drag — только за заголовок (`dragHandleClassName`), кнопки окна прерывают mousedown (решение D8 PBT-021), редактирование содержимого перенос не запускает. Активация окна — mousedown на рамке (PBT-020) плюс перенос/resize тоже активируют.

## Risks / Trade-offs

- **react-rnd не проверялся спайком** (как и RGL до PBT-021): сценарии DoD — проверка кандидата; замена — через тот же адаптер.
- **Пиксельная раскладка при узком окне:** стартовые 600×420 могут не влезть — зажимаются ограничениями области при первом переносе; допустимо, в PBT-024 раскладка сохраняется как есть.
- **Перекрытые окна и клики:** клик по видимой части окна активирует его — стандартное поведение каскада; скрытые под стеком части недостижимы до подъёма (по определению каскада).
- **Переключатель-времянка:** пользовательский сценарий переходов будет заменён в PBT-023 без миграции состояний (раскладки в памяти).

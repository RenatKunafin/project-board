# Design — PBT-023: переключение режимов размещения

## Context

Временный переключатель PBT-022: `layoutMode` — глобальное состояние приложения; сеточная (`areasByTab`) и каскадная (`cascadeByTab`) раскладки уже хранятся **per вкладка**, но режим общий и раскладки режимов не разделены семантически (переход на каскад начинал стек заново). Согласовано: режим у каждой вкладки (§4.1), отдельные раскладки режимов с восстановлением (§4.4, ADR-7 PBT-002).

## Goals / Non-Goals

**Goals:** режим — свойство вкладки; раздельные раскладки с восстановлением; корректное отражение добавления/закрытия окон в обеих раскладках; сохранение сворачивания и настроек содержимого; замена временного тумблера.

**Non-Goals:** персистентность (PBT-024), пауза отрисовки (PBT-027), анимации, стилизация.

## Decisions

### D1. Режим — свойство вкладки в состоянии приложения

`modeByTab: Record<tabId, 'grid' | 'cascade'>`; вкладка без записи — сетка (умолчание). Читается только для активной вкладки; переключатель в шапке меняет режим активной вкладки, остальные вкладки не затрагиваются. В `packages/dashboard/workspace.ts` режим не переносится: это состояние представления вкладки уровня приложения (как panesByTab), персистентность придёт в PBT-024 в `tabs`/`settings` (ADR-5).

### D2. Раздельные раскладки уже per вкладка — политика достраивается

Сетка: `areasByTab[tabId]`; каскад: `cascadeByTab[tabId] = { areas, order }`. Режим определяет, какой слот рендерится. Возврат к режиму показывает его слот как есть — это и есть «восстановление прежней раскладки». Для вкладки, никогда не бывшей в каскаде, слот пуст — окна размещаются стартовыми областями (каскадный стек / стартовые области сетки): «определённо размещать новые окна при первом переключении».

### D3. Изменение состава окон отражается в обеих раскладках

При добавлении окна area записывается в **обе** раскладки вкладки: сеточная — стартовая область поочерёдной половины (PBT-021 D9), каскадная — окно наверх стека (пустые areas посчитает адаптер). При закрытии — удаление id из обеих раскладок и из порядка глубины (устраняет накопление мёртвых записей, заметку готовит PBT-024). Активация окон обновляет только каскадный порядок (в сетке глубина не имеет смысла).

### D4. Смена режима не трогает содержимое

`collapsed` живёт в `PaneInstance` — переживает смену режима; свёрнутое окно в сетке разворачивается в прежнюю строку (`collapsedHeights`), в каскаде — прежний пиксельный размер. Настройки содержимого — в документах и view-settings (PBT-007) — режимом не затрагиваются. ID экземпляров и ссылки на документы не пересоздаются.

### D5. Переключатель активной вкладки

Существующие кнопки «Сетка/Каскад» (`aria-pressed`) остаются, читают режим активной вкладки и меняют его. Скрытие/показ — без изменений разметки; переключатель остаётся в шапке (финальное место и вид — PBT-066/макеты).

## Risks / Trade-offs

- **Две раскладки на вкладку — объём состояния растёт:** осознано (ADR-7); чистка закрытых окон в D3 удерживает состояние актуальным.
- **Окно, добавленное в одном режиме, незнакомо другому:** стартовые области обоих адаптеров корректны без пересчёта (сетка — свободная половина, каскад — верх стека).
- **`modeByTab` не в workspace-модуле:** состояние представления, живёт рядом с panesByTab; перенос в workspace-операции не даёт выгоды и усложняет чистый модуль.

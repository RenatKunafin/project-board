## Why

Документы чек-листа переживают только жизнь страницы: сервис держит их в памяти, store записывает лишь в тестах — между ними нет связи. Пользователь должен получать автосохранение после операций (согласовано в решениях 15.4: запись после завершённой операции, защита от затирания более новой редакции) и видеть состояние «сохранено/сохраняется/ошибка». Границы гарантий — локальная защита целостности, не совместное редактирование (15.4).

## What Changes

- `createDocumentService({ store?, saveDelayMs? })` — опциональное подключение хранилища: каждая зафиксированная операция ставит документ в очередь автосохранения (debounce), flush сохраняет **последнюю** корректную редакцию с `expectedStoredRevision` последнего успешного сохранения; несколько быстрых операций — одна запись, в правильном порядке.
- Состояние сохранения по документу: `saved / saving / error / conflict` + подписка `subscribeSaveState`; технический сбой записи — до 3 повторов с нарастающей задержкой, затем `error`; повтор по следующей операции не теряет изменения (очередь хранит последнюю редакцию).
- **Разрешение конфликта двух окон** (выбранный сценарий): при `DocumentConflictError` от store сервис перечитывает документ из хранилища, обновляет память и уведомляет подписчиков, выставляя состояние `conflict` — хранилище является истиной, несохранённые правки проигравшего окна отбрасываются видимым образом (индикатор), без молчаливой перезаписи.
- Восстановление при старте: `restoreAll()` читает документы из store в память; приложение при инициализации создаёт документ чек-листа только если его ещё нет — список переживает перезагрузку.
- Индикатор состояния сохранения в оболочке приложения (один на активный документ).
- `DocumentStore` расширяется `listAll()` для восстановления.

### Modified Capabilities

- `document-management`: ADDED — автосохранение (очередь, состояние сохранения, повтор при сбое), разрешение конфликта двух окон (перечитывание из хранилища), восстановление при старте; существующие требования редакций/подписок не меняются.
- `local-persistence`: ADDED — полная выборка документов (`listAll`) для восстановления состояния при старте; существующие требования не меняются.

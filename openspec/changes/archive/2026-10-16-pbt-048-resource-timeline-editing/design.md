# Design — PBT-048 Resource timeline editing

## Context

Ядро даёт все команды: `moveTask` (A2: рабочая длительность, привязка начала к рабочему дню), `setTaskDates` (A3: даты как введены). Бета RCT: `onItemMove/onItemResize` при жестах не эмитятся, работает `onItemDrag` (`{eventType: 'move'|'resize', itemId, time, edge?}`) на каждый кадр; interactjs включается только у выделенного элемента (клик-выделение обязателен). Спайк PBT-015 проверил схему: факт в ref → mouseup → правила → запись.

## Goals / Non-Goals

- Goals: drag/resize на дорожках к командам ядра, форма задачи по dblclick, одна запись на жест, переназначение ресурса исключено.
- Non-Goals: см. proposal.

## Decisions

### D1. Включение жестов на элементах

Адаптер: задачи — `canMove: true`, `canResize: 'both'`; недоступности — `false`/`false` (D6-визуал PBT-047). Timeline: `canChangeGroup: false` (переназначение ресурса жестом исключено — DoD-5), `useResizeHandle: true` (видимые ручки — resize требует выделения, ручки упрощают попадание), `canResize: 'both'`. Глобальные `canMove: true`. Отпуск не выделяется жестами, но клик-выделение RCT допускает — безвредно (двигать нельзя).

### D2. Схема жеста (ADR-5, адаптация PBT-039)

`onItemDrag` только запоминает факт. `mouseup`/`touchend` на `document` в capture (жест может закончиться вне чарта — прецедент PBT-039) — применение через 60 мс (interactjs завершает жест после mouseup, прецедент спайка):
1. Перенос: дата из `time` события (проверено: точное время указателя), классификация относительно **expected-базы** (даты документа на старте жеста — ref, очищается первым фактом жеста): `dStart ≠ 0` → `moveTask(plan, taskId, snapIso)`; снап к ближайшей локальной полночи (полуденное правило спайка).
2. Resize: **сырой `time` ресайза беты масштабно врёт** (находка отладки 2026-10-15: мышь +2 дня → `time` +45 дней); дата края считается по пиксельной дельте указателя от старта жеста (`mousemove/touchmove` в capture пишут `clientX`): день = ширина полосы / календарная длительность задачи; `left` → `setTaskDates({start: base.start + N, end: base.end})`, `right` → `{start: base.start, end: base.end + N}` (A3: дата как введена).
3. Правила вернули те же даты — холостая ревизия исключена; отклонение ядром (перевёрнутый интервал) — без записи, полоса вернётся из props.
4. Одна запись через `commitPlan` (ретрай конфликта ревизии), `localRevisionRef` запоминает свою ревизию.

Промежуточных сверток нет (отличие от SVAR-версии PBT-039): источник отрисовки RCT — props, немедленная коррекция без записи невозможна; полоса до отпускания двигается как есть (preview interactjs), после записи встаёт по правилам. Принятая схема ADR-5.

### D3. Несколько назначений — одна задача

itemId = `taskId:resourceId`: жест на любом элементе извлекает `taskId` и правит исходную задачу один раз; после записи items пересчитываются из документа — обновляются все элементы задачи (DoD-2).

### D4. Форма задачи — общий хук

`useTaskForm.ts` — вынос из `PlanGanttWidget` без изменения поведения: `commitPlan` (запись с ретраем ревизии), `submitTaskForm` (validateTaskForm + buildTaskDates + create/update + setTaskDates + назначения целиком), `deleteCurrentTask`, `applyDependencyCommand`. Оба виджета используют хук и `TaskEditorDialog`; ресурсный вид открывает форму по `onItemDoubleClick` (taskId до «:»). Focus-возврат после закрытия — как в проектном виде.

### D5. Подавление ремоунта собственной записи

Remount по ревизии (D7 PBT-047) сбрасывал бы прокрутку после каждого жеста. Как в SVAR-версии (D7 PBT-039): `localRevisionRef`; key не меняется при собственной записи — данные обновляются через props (items/groups от нового документа), внешние записи ремоунтят как прежде.

### D6. Ограничения коротких полос и ручек

Ручки resize (`useResizeHandle`) занимают до 20% ширины полосы (внутренние стили беты) — на полосах 1–2 дня ручки съедают значительную часть. v1 принимается (полоса остаётся кликабельной в центре); minResizeWidth не переопределяется.

## Risks / Trade-offs

- Запись на mouseup с setTimeout-задержкой (60 мс, прецедент спайка) — interactjs завершает жест после mouseup; применение до завершения может собрать неполный факт. Задержка сохранена из спайка.
- Клик-выделение перед жестом — требование беты; пользователь может не знать: e2e фиксирует сценарий «клик → drag».
- Наложение подписей вплотную стоящих полос (Risks PBT-047) при drag рядом с соседом — вне v1. Находка отладки 2026-10-15: содержимое узкой полосы (`.rct-item-content`, inline-block) вылезает за её границы и перехватывает клики соседней полосы — ограничено `max-width: 100%; overflow: hidden` в `resource-timeline.css` (подпись обрезается, полный текст в `title`).

## Migration Plan

Схема не меняется; команды ядра существующие.

## Open Questions

Нет — серия автономна (директива владельца).

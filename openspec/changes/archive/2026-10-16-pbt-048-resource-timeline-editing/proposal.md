# PBT-048 — Редактирование сроков в ресурсном виде

## Why

Ресурсные дорожки (PBT-047) только читают документ. Согласованная роль вида — анализ загрузки (§13.2), но перенос отдельной задачи прямо на дорожке — естественное продолжение анализа «когда занят»; ADR-5 PBT-017 предусматривает жесты RCT по схеме «факт после mouseup». Сейчас для правки сроков нужно переключаться в проектный вид.

## What Changes

- Жесты на дорожках: drag (перенос, A2 — рабочая длительность сохраняется, начало привязывается к рабочему дню) и resize краёв (A3 — дата как введена) подключаются к существующим командам ядра (`moveTask`/`setTaskDates`). Схема ADR-5: жест после клика-выделения, факт применяется после mouseup («факт → правила ядра → применение»), payload библиотеки источником данных не используется. Специфика беты: `onItemMove/onItemResize` не эмитятся — работает `onItemDrag` (спайк PBT-015).
- Двойной клик по элементу открывает общую форму задачи (PBT-038) — редактирование из ресурсного вида тем же диалогом, что и в проектном.
- Переназначение ресурса жестом не поддерживается v1 (`canChangeGroup: false`): вертикальное движение не меняет `assigneeIds` (DoD-5 — поведение явно задано).
- Запись — одна на жест; холостая ревизия (правила вернули те же даты) исключена; отклонение ядром — без записи, полоса возвращается из документа.
- Попутный рефакторинг без изменения поведения: общий хук `useTaskForm` (запись документа с ретраем ревизии, submit/удаление задачи, команды зависимостей) вынесен из `PlanGanttWidget` — ресурсный вид переиспользует форму, дублирования нет (заявлено по правилам серии).

## Impact

- Новый файл: `packages/gantt/src/use-task-form.ts` (хук).
- Изменённые: `packages/gantt/src/ResourceTimelineWidget.tsx` (жесты, форма, подавление ремоунта своей записи), `packages/gantt/src/resource-timeline-adapter.ts` (`canMove`/`canResize` задач), `packages/gantt/src/PlanGanttWidget.tsx` (использование хука), index.ts (экспорт).
- E2E `tests/e2e/resource-timeline-editing.spec.ts`.
- Delta spec — `resource-timeline` (ADDED Requirements).

## Non-Goals

- Переназначение ресурса перетаскиванием между дорожками (§13.2 — детализация вне v1); создание задач жестом по канве.
- Undo/redo жеста (PBT-062–063 — вне основного плана).
- Подсветка «призрака» правил во время жеста: полоса до отпускания двигается как есть, правила применяются после mouseup (принятая схема ADR-5; в SVAR-виде немедленная коррекция возможна через точечный `update-task` стора, у RCT источник отрисовки — props).

# Design — PBT-044 Plan calendar editor

## Context

Календарь — данные плана (`plan.calendar`: `workingDays`/`holidays`/`workingExceptions`), читается всеми расчётами через `createWorkingCalendar` (PBT-013) и подсветкой (`nonWorkingDayKind`, PBT-037). Команды календаря в ядре нет. Валидатор чтения уже отклоняет пустой календарь (`empty-calendar`: нет рабочих дней И нет исключений) и не-ISO даты.

## Goals / Non-Goals

- Goals: настройка недели, добавление/удаление праздников (день/диапазон) и рабочих исключений, атомарная команда ядра, регрессия A5 в e2e, независимость планов.
- Non-Goals: см. proposal.

## Decisions

### D1. Команда полной замены календаря

`updateCalendar(plan, definition)` — одна команда с валидацией: даты ISO и существующие; `workingDays` — подмножество 1–7 без дублей; пересечение `holidays ∩ workingExceptions` отклоняется (`invalid-calendar`, детерминированнее нормализации — прямые записи через dev-хук с пересечением ловятся явно; при чтении пересечение допускается, приоритет исключения сохранён — `nonWorkingDayKind` не меняется); пустой календарь (без рабочих дней и без исключений) отклоняется. Замена атомарна. Код `invalid-calendar` добавлен в `PlanCommandErrorCode`.

Альтернатива «гранулярные команды (addHoliday/setWeekday…)» отклонена: UI всё равно собирает полное состояние (чекбоксы недели, списки), полная замена атомарна и не оставляет промежуточных состояний.

### D2. Секция «Календарь» в диалоге настроек плана

Четвёртая секция диалога; кнопка тулбара переименована «Справочники» → «Настройки плана» (диалог теперь охватывает справочники и календарь; aria-label «Настройки плана»). Секция: 7 чекбоксов (Пн–Вс, checked = рабочий); праздники — список дат (сортированный) + добавление двумя датами («с» обязательна, «по» опциональна → диапазон раскладывается на отдельные дни, существующие не дублируются); исключения — аналогично («сделать рабочим»). Политика конфликтов: добавление праздника удаляет дату из исключений и наоборот (дата не в обоих списках; ядро всё равно отклонит пересечение — UI не доводит).

### D3. Регрессия A5 через колонку «Раб. дни»

Праздник 14.10 внутри задачи 12–16: колонка «Раб. дни» (производная календаря) меняется 5 → 4, даты полосы неизменны — A5 виден пользователю без пересчёта хранения (длительность не хранится). Возврат — рабочее исключение на 14.10 → 5. E2E использует колонку таблицы и документ.

### D4. Независимость планов и пустой календарь

Диапазон применяется к документу конкретного плана (commitPlan); e2e проверяет второй план не тронут. Снятие последнего рабочего дня без исключений: ядро отклоняет `invalid-calendar`, UI показывает alert секции, чекбокс возвращается ререндером (план не изменился). Снятие последнего рабочего дня при наличии исключений — валидно (все дни нерабочие, кроме отмеченных).

## Risks / Trade-offs

- Полная замена календаря одной командой: одно изменение пользователя = одна ревизия — ок для v1 (undo нет).
- Годовой запас праздников не хранится — UI не ограничивает даты добавления (любой год), шкала чарта расширяется диапазоном задач (фикс. диапазон PBT-039 D7 не зависит от праздников).
- Переименование кнопки меняет aria-label — тесты PBT-041/043 обновлены на «Настройки плана».

## Migration Plan

Схема не меняется. Команда новая, документов не касается.

## Open Questions

# PBT-054 — Преобразование импортированных отпусков

## Why

После импорта `.gantt` отпуск-строки исходника остаются обычными задачами без исполнителей (PBT-052/053, пометка «Требуют ручного решения» в предпросмотре). Правило D7 ADR PBT-003 требует их явного преобразования в периоды недоступности с выбором ресурса пользователем — сейчас механизм отсутствует: 16 строк эталона не становятся отпусками, конфликты «работа × отпуск» (D6) и отпуск-элементы дорожек не работают для них.

## What Changes

- **Команда в форме задачи:** кнопка «Преобразовать в отпуск…» в режиме редактирования любой задачи (решение владельца 2026-10-16: без ограничения «только без исполнителей» — операция явная, потери показываются в пояснении), открывающая диалог преобразования.
- **Диалог преобразования:** выбор ресурса из справочника плана (**без предвыбора и угадывания по названию задачи** — D7), даты начала/окончания предзаполнены датами задачи и редактируемы, пояснение последствий («задача будет удалена вместе с назначениями и зависимостями; будет создан один период недоступности»), ошибки по месту (ресурс не выбран, перевёрнутый интервал — тексты ядра), кнопки «Преобразовать»/«Отмена», Esc — отмена.
- **Атомарная замена без расширения ядра:** композиция готовых команд в одной записи документа — `deleteTask` (чистит зависимости, контракт D6 PBT-031) + `createUnavailability` (валидация ресурса/интервала); одна ревизия, частичное состояние невозможно.
- **Отмена** диалога ничего не меняет; после применения исходной строки больше нет — повторное преобразование той же строки исключено, дублей не возникает.
- После преобразования работают штатные механизмы: отпуск на дорожке ресурса (PBT-047) и конфликт «работа × отпуск» в списке проблем (PBT-036, D6) — без переноса других задач.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `resource-planning`: ADDED — «Преобразование задачи в период недоступности»: атомарная замена (один период с датами из диалога и выбранным ресурсом; исходная задача с назначениями и зависимостями удаляется), отмена без изменений, невозможность повторного преобразования той же строки.
- `plan-transfer`: ADDED — «Явный выбор ресурса при преобразовании импортированных строк»: ресурс определяется выбором пользователя из справочника плана, а не названием записи; неоднозначные имена не влияют.

## Impact

- **Код:** `packages/gantt` — новый `AbsenceConvertDialog`, кнопка в `TaskEditorDialog` (edit, без назначений), применение — композиция команд в `use-task-form`/виджете; ядро, SDK и платформа не меняются.
- **Тесты:** unit на чистую логику (если выделится), e2e на эталоне: импорт → преобразование двух строк (включая неоднозначную «ОТПУСК-DEV-iOS» при двух iOS-ресурсах), отмена, конфликт и дорожка после.
- **CSS:** токены, без хексов.

## Non-Goals

- Массовое преобразование всех строк без исполнителей разом (каждая — явное решение с выбором ресурса).
- Изменение справочника ресурсов в диалоге (нет ресурсов — подсказка открыть «Настройки плана»).
- Автосоздание ресурсов по именам из названий строк.
- Отдельная точка входа создания отпуска вне «Настроек плана» — вопрос навигации отложен до редизайна (решение владельца 2026-10-16).

# Design — PBT-054 Преобразование импортированных отпусков

## Context

После импорта (PBT-052/053) отпуск-строки — задачи без назначений, помеченные в предпросмотре как «требуют ручного решения». Ядро готово к композиции: `deleteTask` (`plan-commands`) удаляет задачу и каскадно чистит только зависимости (контракт очистки ссылок D6 PBT-031); `createUnavailability` (`plan-assignments`) валидирует ресурс (`unknown-resource`) и интервал (`inverted-interval`, ISO) и генерирует id. Запись документа — одна операция на действие (`commitPlan` в `use-task-form`, прецеденты PBT-040/044). Форма задачи (`TaskEditorDialog`) уже имеет footer с «Удалить» в edit-режиме; отпуск-редактор PBT-043 (секция «Отпуска» в «Настройках плана») — образец полей «ресурс + даты».

## Goals / Non-Goals

Goals: явное преобразование строки без исполнителя в один период недоступности (выбор ресурса пользователем, D7); атомарность без расширения ядра; DoD покрыт e2e на эталоне.

Non-Goals (сверх proposal): массовое преобразование; преобразование задач с исполнителями; правка справочника ресурсов из диалога.

## Decisions

### D1. Точка входа — форма задачи

Кнопка «Преобразовать в отпуск…» в footer `TaskEditorDialog` — в `edit`-режиме **любой** задачи (решение владельца 2026-10-16; первоначальное ограничение «только без исполнителей» снято: операция явная, потери показываются в пояснении, автоматического выбора ресурса нет в любом случае — D7 соблюдён). Открытие — поверх формы отдельным диалогом `AbsenceConvertDialog` (форма остаётся под ним; после применения закрываются оба). Альтернатива «список кандидатов из тулбара» отклонена: лишняя сущность при живом сценарии «двойной клик по строке → форма» (PBT-038).

### D2. Диалог `AbsenceConvertDialog`

Props: `task` (title, start, end), `resources`, `onApply({resourceId, start, end}) => string | undefined` (ошибка по месту), `onClose`. Поля: селект ресурса (**пустой по умолчанию** — D7, никакой предвыборки по названию), даты `start`/`end` (type=date, предзаполнены из задачи, редактируемые — DoD-1 «проверяет даты»). Пояснение последствий: «Задача будет удалена вместе с назначениями и зависимостями; будет создан один период недоступности». Ошибки по месту: ресурс не выбран («Выберите ресурс.» — образец PBT-043), перевёрнутый интервал (`inverted-interval`, текст ядра). `resources.length === 0` — сообщение «В плане нет ресурсов — создайте их в „Настройках плана“», кнопка применения скрыта (спека plan-transfer). Esc/«Отмена» — закрытие без изменений. Паттерн — `OnlineGanttImportDialog`/`GroupEditorDialog` (overlay, role=dialog, Esc, токены).

### D3. Применение — композиция команд ядра в одной записи

В `use-task-form`/виджете (по образцу `submitGroupForm`): `commitPlan((latest) => ...)`: `parsePlanContent` → `deleteTask(plan, taskId)` → при отказе `undefined` (без записи) → `createUnavailability(afterDelete, { resourceId, start, end })` → при отказе текст ошибки возвращается диалогу (без записи, план не тронут). Успех — один новый `plan` (одна ревизия): атомарность гарантируется самим `commitPlan` (запись только при ненулевом результате). Ядро не расширяется; идемпотентность повторного применения обеспечена исчезновением задачи (DoD-4).

### D4. Закрытие и фокус

После применения: закрыть `AbsenceConvertDialog` и форму задачи (задача больше не существует — форма с ней висеть не должна). Фокус — в чарт (существующая механика закрытия формы). Отмена — закрыть только диалог преобразования, форма остаётся открытой с прежними значениями.

### D5. E2E (`tests/e2e/absence-mapping.spec.ts`)

Фикстура — импорт эталона `onlinegantt-20261016.reference.gantt` (команда 📥 + apply, приёмы PBT-053), затем:

1. **Два преобразования** (DoD-проверка «несколько отпусков, включая неоднозначное имя»): «ОТПУСК-QA» → QA; «ОТПУСК-DEV-iOS» → «iOS-разработчик 2» (в плане два iOS-ресурса — выбор пользователя, не имени). Проверки: счётчик задач −2, обе исходные строки исчезли, у QA назначенная работа «ОКАД-ПСИ-iOS» (21.09–28.09) пересекается с отпуском QA 21.09–02.10 → «Проблемы» содержит unavailability-конфликт; дорожка QA в ресурсном виде содержит отпуск-элемент (`data-rt-unavailability`).
2. **Отмена**: открыт диалог → отмена → задача на месте, периодов столько же.
3. **Перевёрнутые даты** → ошибка по месту, план не изменился.
4. **Пустой справочник**: план без ресурсов (native-импорт пустого/ручной) → сообщение, применения нет. (Сценарий малый — допускаю unit-форму через e2e на встроенном малом плане.)

data-атрибуты: `data-absence-convert`, `data-absence-resource`, `data-absence-start/end`, `data-absence-apply/cancel`, `data-absence-error`.

## Risks / Trade-offs

- [Задача с исполнителями превращается в отпуск одного ресурса — прочие назначения теряются] → пояснение в диалоге говорит прямо «вместе с назначениями и зависимостями»; сценарий закреплён спекой; операция явная и отменяемая до применения.
- [Диалог поверх формы — два оверлея] → z-index/вложенность по образцу stacked-диалогов проекта (PBT-045: предшественники внутри формы); Esc перехватывается внутренним диалогом (stopPropagation, образец `TaskEditorDialog.handleKeyDown`).
- [Даты редактируются — можно изменить интервал при преобразовании] → это осознанно (DoD-1 «проверяет даты»); исходные даты не сохраняются дополнительно.

## Migration Plan

Новый UI-слой, без изменения контрактов и схемы; откат — удалить диалог и кнопку.

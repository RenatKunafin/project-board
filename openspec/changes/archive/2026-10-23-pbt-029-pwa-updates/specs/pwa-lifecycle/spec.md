## ADDED Requirements

### Requirement: Обнаружение и откладывание обновления

Приложение SHALL сообщать пользователю о полностью подготовленной новой версии и предоставлять действие обновления. Обнаружение обновления MUST NOT автоматически перезагружать текущую сессию. Пользователь SHALL иметь возможность отложить обновление и вернуться к нему позже.

#### Scenario: Подготовлена новая версия

- **GIVEN** пользователь работает в текущей версии приложения
- **WHEN** новая версия полностью подготовлена к применению
- **THEN** приложение показывает «Доступна новая версия» и действие «Обновить»
- **AND** документы, открытые формы и рабочее пространство продолжают работать без перезагрузки

#### Scenario: Пользователь откладывает обновление

- **GIVEN** приложение предлагает доступную новую версию
- **WHEN** пользователь выбирает «Позже»
- **THEN** текущая сессия продолжает работать
- **AND** пользователь может снова вызвать действие обновления

### Requirement: Подтверждение и сохранение перед обновлением

Приложение SHALL запрашивать подтверждение перезапуска и напоминать о сохранении правок открытых форм. После подтверждения оно SHALL блокировать новые пользовательские изменения на время подготовки и применять обновление только после подтверждения записи документов, рабочего пространства и настроек представлений. Отмена подтверждения MUST NOT применять обновление.

#### Scenario: Правка непосредственно перед обновлением

- **GIVEN** новая версия доступна, пользователь только что изменил документ и расположение окна
- **WHEN** пользователь подтверждает обновление
- **THEN** приложение дожидается подтверждённой записи актуального документа, расположения и настроек представлений
- **AND** только затем применяет новую версию и перезапускает текущую страницу

#### Scenario: Отмена подтверждения

- **GIVEN** пользователь открыл подтверждение обновления
- **WHEN** он выбирает «Отмена»
- **THEN** приложение не перезагружается и позволяет продолжить работу

### Requirement: Ошибка сохранения откладывает обновление

При ошибке, конфликте или превышении времени ожидания сохранения приложение MUST NOT применять обновление или перезагружать страницу. Оно SHALL сообщать причину, сохранять доступ к текущей сессии и позволять повторить попытку после устранения проблемы.

#### Scenario: Хранилище отклоняет запись

- **GIVEN** пользователь подтвердил обновление с ещё не записанной правкой
- **WHEN** сохранение завершается ошибкой
- **THEN** приложение остаётся в текущей версии с доступным состоянием сессии и сообщением об ошибке
- **AND** новая версия не применяется

#### Scenario: Повтор после устранения ошибки

- **GIVEN** обновление было отложено из-за сбоя записи, хранилище снова доступно
- **WHEN** пользователь повторяет обновление
- **THEN** приложение сохраняет актуальные данные и применяет новую версию после подтверждения записи

### Requirement: Применение обновления при одном открытом окне

Для применения обновления пользователь SHALL оставить одно окно или вкладку Project Board на текущем адресе. Если открыты другие окна приложения, система SHALL попросить их закрыть и повторить попытку; она MUST NOT принудительно закрывать или перезагружать эти окна.

#### Scenario: Открыта другая вкладка приложения

- **GIVEN** Project Board открыт в двух вкладках или в обычной вкладке и установленном окне
- **WHEN** пользователь пытается применить обновление
- **THEN** приложение просит закрыть другие окна Project Board
- **AND** обе сессии остаются открытыми без принудительного применения обновления

#### Scenario: Пользователь оставил одно окно

- **GIVEN** обновление ранее было отложено из-за других окон, пользователь их закрыл
- **WHEN** он повторяет обновление в оставшемся окне
- **THEN** после подтверждения записи приложение применяет подготовленную версию

### Requirement: Восстановление данных и автономная работа после обновления

Обновлённое приложение SHALL восстанавливать сохранённые документы, вкладки, окна, раскладки и настройки представлений. Зарегистрированные миграции SHALL выполняться по существующим правилам восстановления. После успешного применения новой версии подготовленное приложение SHALL повторно запускаться без сети с ресурсами этой версии.

#### Scenario: Данные и миграции после перезапуска

- **GIVEN** перед обновлением сохранены документы, рабочее пространство и настройки, для старого документа зарегистрирована миграция
- **WHEN** приложение запускается обновлённой версией
- **THEN** документы и рабочее пространство восстановлены, документ приведён к поддерживаемой версии существующим механизмом миграций

#### Scenario: Обновлённая версия запускается без сети

- **GIVEN** новая версия успешно применена и все окна приложения закрыты
- **WHEN** пользователь повторно запускает приложение без сети
- **THEN** открывается обновлённая версия с сохранёнными данными
- **AND** её скрипты, стили, шрифты и иконки доступны без подмешивания несовместимых ресурсов прежней сборки

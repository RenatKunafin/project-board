## Context

Дизайн одобрен владельцем до кода (2026-10-23, «Делаем»). База — свежий develop. Методика и исходное наблюдение сохранены в материалах PBT-058; исправление выполняется отдельным PR PBT-081.

В текущем PlanGanttWidget captureHandler каждого экземпляра обрабатывает любой mouseup/touchend документа, очищает gestureExpectedRef и запускает сверки через 250/700/1500 мс. Сверка перебирает задачи до первого расхождения стора и документа. Таймеры при cleanup не отменяются. Эти свойства проверены чтением кода; причинная связь с откатом пока является гипотезой.

### Подтверждение регресса

На неизменённом develop 65aba99 минимальный план из двух задач, два проектных вида, один максимизирован. Drag переводит задачу с 12–16.10 на 14–20.10 (rev2→3). Клик в поле поиска, пока сосед скрыт, приводит к 12–20.10 (rev4). Доказательство — `results/baseline-regression.md`. Обычные drag/resize без последующего клика прошли; этот клик запускает глобальные сверки скрытого экземпляра, чей apiRef ещё указывает на старый стор размонтированного чарта.

## Goals / Non-Goals

Цель — стабильный результат одного drag/resize в нескольких видах общего документа, включая hidden keep-mounted и максимизацию. Non-goals перечислены в proposal; правила ядра и стратегия чтения факта из стора по ADR-5 сохраняются.

## Decisions

### D1. Сначала красный регресс

После ревью воспроизвести дефект на неизменённом production-коде. Начать с двух видов и небольшого плана; при необходимости вернуться к шести видам и plan-500. Использовать реальные mouse events, проверять hit-testing полосы и конкретное изменение дат. Снимать стартовую ревизию, даты сразу после записи и после завершения всех сверок (не менее 2 с после mouseup). Если дефект не воспроизведён, не объявлять гипотезу причиной и не вносить профилактический фикс вместо доказательства.

### D2. Владелец жеста — экземпляр и задача

Предпочтительный подход после подтверждения D1: начало взаимодействия на полосе своего экземпляра фиксирует ID задачи. Окончание отслеживается глобально в capture-фазе, чтобы отпускание за пределами чарта продолжало работать. Сверяется только задача этого жеста; случайное расхождение другой задачи не считается пользовательским вводом. Клик по обычному UI и mouseup соседнего экземпляра не дают права записывать документ. Конкретные DOM-селекторы полос и краёв проверить на установленном SVAR; payload update-task не использовать как источник дат.

### D3. Жизненный цикл сверок

Каждая серия таймеров принадлежит поколению жеста и документу. При начале нового жеста предыдущий уже завершённый ввод фиксируется по наблюдаемому факту, затем его серия отменяется (иначе быстрые жесты по разным задачам теряли бы первую операцию); cleanup при unmount/смене documentId отменяет таймеры и сбрасывает ожидаемые даты. Перед действием callback проверяет актуальность владельца. Промежуточные сверки корректируют только стор, финальная фиксирует результат не более одного раза. Сохранить существующее исключение холостых ревизий.

Внешнее изменение документа во время ожидающей сверки требует проверки в регрессе: устаревшая серия не должна возвращать уже заменённые даты. При необходимости сбрасывать серию при внешней ревизии, отличая собственную финальную запись. Одновременные конкурирующие жесты не получают новую политику разрешения конфликтов в этой задаче.

Скрытие вкладки само по себе не отменяет уже завершённый жест: виджет остаётся смонтированным, его API сохраняет факт ввода и может завершить запись при неизменной ревизии. Видимость читается через ref для запрета нового взаимодействия со скрытым видом, без перезапуска серии при hide/show. Для скрытого чарта не подавляется обновление props по собственной ревизии: его следующий mount должен получить актуальные даты, а не прежний source. Размонтирование или смена документа по-прежнему отменяют серию.

### D4. Проверки

Browser-регресс: два и шесть проектных видов, два видимых соседа, hidden keep-mounted при максимизации, сетка и каскад. Проверить drag, оба края resize, отпускание снаружи чарта, обычный клик после жеста, неизменность чужих задач, одну ревизию и reload. Для таймеров — новый жест, смена документа и unmount до завершения серии. Покрыть эти измерения небольшим набором сценариев, без полного декартова произведения.

После исправления — отдельный живой browser-проход, стандартные проверки и доступный жестовый сценарий PBT-058. Полный повтор итоговых бюджетов выполняется в PBT-058 после PBT-080; результаты не смешиваются с прежними raw.

## Alternatives

- Фильтровать только target mouseup: отвергнуто, теряется отпускание вне чарта.
- Проверять только visible: недостаточно при двух видимых соседях.
- Убрать capture: SVAR может остановить всплытие события.
- Перевести SVAR на полностью контролируемые props или изменить ядро: расширяет границы и противоречит принятой стратегии без доказанной необходимости.

## Risks

SVAR применяет факт с задержкой; отмена старой серии при быстром следующем жесте требует отдельной проверки. DOM-разметка полос принадлежит библиотеке и проверяется на закреплённой версии. Обнаружение иной причины в D1 требует обновления дизайна до расширения реализации. Воспроизведение жестов не должно маскироваться retry/skip.

## Migration / Rollback

Миграций нет. Откат — возврат к предыдущей сборке с совместимыми данными; он возвращает известный дефект. Публикация и merge не входят в подготовку артефактов.

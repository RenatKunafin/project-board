# Design — PBT-020: рамка окна, сворачивание и закрытие

## Context

После PBT-030 `PaneInstance { instanceId, typeId, label, documentId }` рендерится по реестру, но рамки нет: заголовок — строка label + кнопка «Закрыть», закрытие лишь прячет панель в `closed`-множестве (экземпляр не удаляется), сворачивания и активного состояния нет. Макеты: заголовок = иконка типа + название, справа кнопки −/□/✕; свёрнутый виджет — только заголовок; активное окно — подсвеченная рамка. Правила ADR-7 (PBT-002): отдельные раскладки режимов — вне границ; скрытые/свёрнутые окна не размонтируются, состояние представления сохраняется; закрытие удаляет экземпляр, документ жив.

## Goals / Non-Goals

**Goals:** общий chrome в платформе; сворачивание без размонтирования; закрытие = удаление экземпляра; активное окно; доступность; сквозной e2e.

**Non-Goals:** drag/resize, каскад, персистентность, пауза отрисовки, тема.

## Decisions

### D1. Рамка — компонент платформы `packages/dashboard`

`WidgetWindow({ title, icon?, collapsed?, active?, onToggleCollapse?, onClose?, onActivate?, children })` — чистый презентационный компонент в `packages/dashboard` (экспорт из index). Рамка владеет: заголовком (иконка + название), кнопками «Свернуть»/«Развернуть»/«Закрыть», подсветкой активности, обработчиком активации (mousedown на рамке). Виджеты получают только `children`-слот и не знают о chrome — соответствие «тема и поведение рамки принадлежат платформе» (карточка). Кнопки: символы −/□/✕ как в макете, каждый с `aria-label="{Действие} {label}"`.

### D2. Состояние окна — в приложении, в памяти

`PaneInstance` расширяется `collapsed?: boolean`; активность — `activeInstanceId` в состоянии App (переключение по mousedown на рамке). Ни SDK, ни хранилище не затрагиваются: сворачивание — настройка представления экземпляра; персистентность — PBT-024 (`widgetInstances`), активность активной вкладки — `settings` (ADR-5). Разворачивание «восстанавливает размер по правилам PBT-002»: в текущей сетке размеры задаются контейнером, поэтому разворачивание автоматически возвращает прежний размер; отдельное хранение размеров появится с сеткой PBT-021.

### D3. Свёрнутое окно — скрытие без размонтирования

Контейнер содержимого получает `hidden`-атрибут/CSS `display:none` при `collapsed`. Компонент остаётся смонтированным: React-состояние (черновики чек-листа, настройки вида) и подписки на документ живут (ADR-7). Свёрнутая панель — одна строка заголовка по макету; соседние панели сетки вытягиваются (гибкая раскладка приложения). Доступность: содержимое скрывается целиком, кнопка превращается в «Развернуть» (`aria-expanded` на кнопке).

### D4. Закрытие — удаление экземпляра

`closed`-множество удаляется; кнопка «Закрыть» убирает `PaneInstance` из `panesByTab` активной вкладки. Документ не трогается (остаётся в сервисе/хранилище), другие представления того же документа продолжают работать — сценарий spec. Повторное открытие — через каталог (уже реализовано PBT-019).

### D5. Активное окно

`activeInstanceId` по умолчанию — первая панель вкладки; mousedown на рамке окна делает его активным. Подсветка — CSS-класс (`accent`-рамка по токенам приложения, без хардкода хексов вне файла токенов — по духу PBT-066, токены `:root` пока временные). Активность чисто визуальная до PBT-021 (сдвиг фокуса ввода не навязывается — не перехватываем фокус у содержимого).

### D6. Доступность и границы перехвата

Кнопки — нативные `<button>` с `aria-label` («Свернуть План · ОКАД», «Развернуть …», «Закрыть …»), на кнопке сворачивания — `aria-expanded`. Фокус видим (стандартный outline). Активация окна — `onMouseDown` на корне рамки, кнопки — `onClick`: редактирование текста внутри виджета не перехватывается (клики по содержимому не всплывают в обработчики chrome, кроме безвредной установки активности). Клавиатура: все кнопки достигаются Tab, активируются Enter/Space.

### D7. Стабильное сопоставление панелей и документов (найдено живым воспроизведением через Playwright MCP)

Флаки-тесты «документ переживает перезагрузку» падали из-за предрамочной проблемы вертикального среза PBT-011: bootstrap создавал два чек-листа в одну миллисекунду (равные `createdAt`), панели при первом запуске получали документы **в порядке создания**, а после перезагрузки — **в порядке сортировки** (createdAt → id). Привязка «панель → документ» менялась между загрузками: пункт «исчезал» из окна (данные в IDB были целы — подтверждено чтением IndexedDB в браузере). Фикс `main.tsx`: сортировка выполняется и после создания недостающих документов, сопоставление стабильно. Попутно в e2e усилены паузы подтверждения записи перед reload (дебаунс + запись IDB) и локаторы сужены до конкретных панелей.

## Risks / Trade-offs

- **`display:none` против условного рендера:** скрытие дороже по DOM, но сохраняет состояние (требование ADR-7); условный рендер размонтировал бы виджеты.
- **Активность без переноса фокуса:** клик по заголовку не двигает фокус внутрь виджета — иначе ломалось бы редактирование; подсветка — информационная.
- **`aria-label` на group-панели остаётся** («План · ОКАД») — существующие e2e не ломаются; кнопки получают развёрнутые подписи.
- **Свёрнутая панель в flex-раскладке:** соседи вытягиваются; после PBT-021 сворачивание будет согласовано с сеткой (пункт DoD PBT-021).

## Context

Дизайн одобрен владельцем 2026-10-24 («Делаем»). Ветка создана от свежего develop после merge PBT-081. Дополнение владельца от 2026-10-24: стрелки в заголовках вкладок не нужны.

Чтением кода подтверждено: removeTab выбирает соседа из state.tabs по индексу, ограниченному длиной уже отфильтрованного массива. Для двух вкладок при закрытии первой возвращается её же ID. Кнопка закрытия вызывает только dispatch/remove; panesByTab и остальные карты состояния не очищаются. Снапшот перебирает Object.entries(panesByTab), поэтому включает окна удалённой вкладки.

Подтверждение на исходном коде: два unit-кейса красные (первая из двух активных и средняя из трёх); browser показывает отсутствие выбранной вкладки после удаления первой и три orphan instance после удаления неактивной исходной вкладки. Выводы сохранены в `results/baseline-unit.txt` и `results/baseline-browser.txt`.

## Goals / Non-Goals

Корректное закрытие вкладки, освобождение её состояния и компактная шапка без кнопок ←/→. Документы продолжают жить независимо от окон. Non-goals — в proposal.

## Decisions

### D1. Выбор соседа

Выбирать соседа в результирующем массиве tabs по Math.min(index, tabs.length - 1). Неактивное удаление сохраняет activeId, единственная вкладка остаётся защищена на уровне модели и UI. Проверить первую, среднюю и последнюю позиции параметризованными unit-регрессиями, включая два элемента — пропущенный ранее случай.

### D2. Один обработчик закрытия вкладки

Сначала проверить существование вкладки и запрет последней. В обработчике выполнить dispatch/remove и удалить ключ tabId из panesByTab, areasByTab, cascadeByTab, modeByTab и maximizedByTab. Очистить collapsedHeights для её окон, сбросить activeInstanceId/renamingTabId, если они принадлежат закрываемому контексту. React 18 объединяет обновления обработчика; не вводить общий рефакторинг всех состояний App ради одной операции.

Построение снапшота дополнительно ограничить workspace.tabs: вкладка определяет принадлежность окна, старый ключ в карте не должен порождать ссылку на несуществующий tabId. Документы и их содержимое не удалять; при размонтировании окон освобождаются их подписки.

### D3. Настройки экземпляров и очередь записи

Удалить настройки закрытых экземпляров из viewStatesRef и persisted ключей view:<instanceId>. Если необходим метод удаления в WorkspaceStore, он внутренний и использует ту же enqueue-очередь, что saveViewSetting/save/flush: ранее начатая запись не должна возвращать удалённый ключ. Защитить обновление настроек от запоздалого callback уже закрытого экземпляра и проверить flush после закрытия. Настройки других экземпляров и общие settings не менять.

Это явно включённая часть очистки состояния окон. Глобальная сборка мусора для всех исторических записей и переработка закрытия отдельных окон в эту задачу не входят. Схема БД и публичный SDK не меняются.

### D4. Удаление стрелок

Удалить оба tab__move, action move и неиспользуемый импорт moveTab из App; убрать CSS только для удалённых кнопок, сохранив стили закрытия. Новый способ перестановки вкладок не добавлять. Сохранённый порядок и добавление в конец остаются действующими правилами. Внутреннюю экспортируемую операцию moveTab не требуется удалять: её наличие не создаёт кнопок в интерфейсе и не требует изменения контрактов платформы.

ArrowLeft/ArrowRight на клавиатуре по-прежнему переключают вкладку и фокус: дополнение относится к видимым кнопкам. Кнопка закрытия останавливает всплытие keydown: Enter/пробел должны выполнять её стандартное действие, а не перехватываться родительским обработчиком активации вкладки. Это проверяется закрытием с клавиатуры. Удалить требование изменения порядка из delta spec; общий порядок записей при восстановлении сохраняется. При архивации убрать упоминание пользовательского изменения порядка из Purpose workspace-tabs.

### D4.1. Крестик вкладки по прототипу (ревью владельца 2026-10-24)

По прямому поручению владельца оформление кнопки сверено с Dashboard.tsx прототипа flexi-dashboard-hub: Lucide X 14×14 вместо символа ×, нулевой padding кнопки, промежуток 8px от названия, горизонтальные отступы вкладки 16px. Цвет muted, hover destructive; кнопка появляется на hover/focus для доступности. Для единственной вкладки кнопка не рендерится, как в прототипе; защита последней вкладки в модели и обработчике сохраняется. Проверки прежнего disabled обновляются на отсутствие кнопки.

### D5. Проверки

Перед исправлением подтвердить регресс первой активной вкладки (модель и browser). Unit: первая/средняя/последняя, активная/неактивная, единственная; очередь удаления настроек после ранее запущенной записи. Browser: закрытие активной первой и средней/последней, неактивной, единственной; оба режима раскладки, максимизированное окно, повторное создание вкладок, сохранение и reload. Читать фактические таблицы tabs/widgetInstances/settings и проверять отсутствие удалённых tabId/instanceId; документы остаются и открываются через каталог.

Прежний shell-тест закрывает неактивную исходную вкладку и после reload ищет окно удалённой вкладки; он не доказывает сохранение документа и зависит от orphan instances. Заменить ожидание явным повторным открытием документа из каталога. Тест перемещения заменить проверкой отсутствия стрелок, порядка создания и восстановления. Отдельно проверить клавиатурное переключение.

Полный набор перед PR: lint, typecheck, unit, build, browser на чистой production-среде, OpenSpec strict, живой browser-проход с консолью.

## Alternatives

- Только клик по оставшейся вкладке после удаления: обход дефекта, не исправляет модель или orphan instances.
- Только фильтрация снапшота: не освобождает состояние и настройки закрытой вкладки в памяти.
- Только очистка карт: не защищает сохранение от других устаревших ключей; ограничение снапшота живыми вкладками поддерживает инвариант.
- Замена стрелок перетаскиванием: новая функция, не входит в поручение владельца.

## Risks / Migration

Очередь настроек и flush обновления PWA не должны возвращать старые view-ключи. Очистка не должна затронуть документ, открытый в другом окне. Миграций нет: восстановление уже игнорирует записи окон без живой вкладки, новый снапшот записывает только актуальные вкладки. Возможность изменить порядок кнопками снимается по прямому поручению владельца; прежний порядок не сбрасывается.

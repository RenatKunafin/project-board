# PBT-079 — проверка закрытия вкладок

## Исходный дефект

Baseline: develop `3bf7c0f`, production build, 2026-10-24. В модели два новых unit-кейса падают: закрытие первой из двух активных вкладок и средней из трёх оставляет activeId удалённой вкладки. В browser-регрессе после закрытия первой активной вкладки нет выбранной вкладки; после закрытия неактивной исходной вкладки в widgetInstances остаются три её окна. Выводы: `baseline-unit.txt`, `baseline-browser.txt`.

## Изменения и проверки

Сосед выбирается из оставшихся вкладок. Один обработчик закрытия очищает экземпляры, сетку/каскад, режим, максимизацию, сохранённые высоты и настройки закрытых экземпляров. Снапшот строится по живым вкладкам. Удаление view-ключей использует общую очередь WorkspaceStore; поздний SDK callback проверяет существование владельца. Документы и настройки оставшихся окон не удаляются.

Кнопки ←/→, их UI action и CSS удалены по поручению владельца. Порядок создания/восстановления и клавиатурное переключение сохранены. Keydown кнопки закрытия не всплывает к обработчику активации вкладки, поэтому Enter закрывает её стандартным действием.

- `workspace.test.ts`: матрица из шести случаев (первая/средняя/последняя, активная/неактивная), прежний запрет последней вкладки.
- `workspace-store.test.ts`: ранее запущенная запись, удаление нескольких view-ключей, последующий flush оставшегося пространства; сохранность настроек другого экземпляра.
- `close-tab.test.tsx`: реальный App и WorkspaceStore; поздний callback размонтированного виджета и PWA prepareForUpdate не возвращают настройки; восстановленный старый ключ panesByTab без вкладки не попадает в снапшот.
- `close-tabs.spec.ts`: пять сценариев закрытия, включая обе раскладки, максимизацию, общий документ, сохранность соседнего вида, подписки, повторное создание вкладок, закрытие Enter, чтение настоящей IDB и reload.
- `shell.spec.ts`: отсутствие стрелок, сохранённый порядок, клавиатурное переключение и повторное открытие документа закрытой вкладки из каталога.

Первый целевой прогон: 20/22. Два падения относились к подготовке/ожиданиям тестов: исходные документы ещё не попали в IDB при снятии baseline, а shell делал reload до отложенной записи рабочего пространства. Ожидания заменены проверкой фактических записей IDB, без retry/skip. Исправленный целевой прогон: 22/22. Старое ожидание shell, что после закрытия вкладки возвращается её окно, заменено явным повторным открытием документа из каталога.

## Живой Chrome

Проверены клавиатурное переключение вкладок, удаление исходной вкладки с максимизированным каскадным окном, выбор соседней, удаление средней/последней, Enter на кнопке закрытия, запрет последней вкладки и повторное создание. После reload одна вкладка и одно нужное окно, одна подписка документа, 0 ошибок консоли. Стрелок нет. Raw: `live-chrome.json`; снимки: `tabs-after-close.png`, `tabs-reloaded.png`.

## Ревью крестика (2026-10-24)

По поручению владельца крестик приведён к Dashboard.tsx прототипа: Lucide X 14×14, отступ 8px от названия, padding вкладки 16px. Кнопка проявляется на hover/focus, у единственной вкладки отсутствует. После правки повторены lint/typecheck/build, unit 500/500, полный browser 149/149 и OpenSpec 19/19. PWA 8/8 относятся к проверке основной логики до этой визуальной правки; механика обновления не менялась. Повторный живой Chrome подтвердил SVG и кнопку 14×14, gap 8px, padding кнопки 0, токен destructive при hover; все сценарии закрытия и reload проходят, ошибок консоли нет. Raw и снимки обновлены.

Следующее визуальное уточнение: крестик опущен на 3px. Живая проверка на dev: computed transform `matrix(1, 0, 0, 1, 0, 3)`, центр кнопки на 3px ниже центра вкладки; снимок `tab-close-offset.png`. `git diff --check` пройден. Полные тесты повторно не запускались для этой CSS-правки.

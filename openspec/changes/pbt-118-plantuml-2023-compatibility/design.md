## Context

PlantUML 1.2023.9 сопоставляет задачи также по подписи; см. proposal.md. Согласована минимальная адаптация экспорта после локального сравнения с целевым файлом.

## Goals / Non-Goals

Обеспечить различимость строк без изменения документа, порядка вывода, алиасов и графа связей.

## Decisions

- Сначала кодировать все названия задач и отпусков и подсчитать совпадения в общем пространстве подписей.
- Для совпадений добавлять `(Tn)`/`(Un)`. Это меньшее изменение, чем добавление путей групп и периодов; существующие алиасы уже детерминированы.
- Резервировать исходные кодированные подписи и алиасы; при совпадении с готовым суффиксом добавлять номер. Уникальная исходная подпись не должна изменяться из-за ранее выданного суффикса.
- Проверять рендер локальным JAR 1.2023.9, без отправки данных плана внешнему серверу. JAR не включать в репозиторий.

## Risks / Trade-offs

- Суффикс содержит технический алиас → добавлять его только при коллизии.
- Коллизии после кодирования и между задачей/отпуском → общий генератор уникальных подписей.
- Нельзя считать отсутствие синтаксической ошибки успешным рендером → сравнивать количество подписей и стрелок в SVG.

## Migration Plan

Изменяется только следующая выгрузка; миграции документов нет. Откат — возврат прежнего генератора.

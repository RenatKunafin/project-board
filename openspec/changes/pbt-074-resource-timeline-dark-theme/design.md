# Design — PBT-074 Ресурсный вид: тёмная тема и легенда

Референс: `flexi-dashboard-hub/src/styles.css` (блок `.resource-timeline-chart`, строки 162–190), `ResourceTimelineChart.tsx` (`TimelineHeaders`, `groupRenderer`, `lineHeight 42`), `ResourcePrototype.tsx` (тулбар, легенда, футер); скриншот `screenshots/redesign-ref/01-dashboard-overview.png` (нижнее окно). Версия RCT в прототипе и проекте совпадает (`0.30.0-beta.19`) — переопределения и пропорции переносимы без пересчёта.

## D1. Токены полос и слоя дней (закрытие регресса PBT-069)

- **Находка (регресс PBT-069, подтверждён живой проверкой 2026-10-21):** стилевые константы `resource-timeline-adapter.ts` ссылаются на `--color-accent`/`--color-on-accent`/`--color-danger`; эти токены были удалены из `index.css` при переходе на `tokens.css` (4a484c5) — переименование затронуло CSS-файлы, инлайны `.ts` не были обновлены. Вычисленное следствие (getComputedStyle на прод-состоянии develop): фон обычных полос задач **прозрачный** `rgba(0,0,0,0)` (видна только primary-рамка через валидный `--color-rt-task-border`); у конфликтных полос фон валиден (`--color-rt-conflict-bg`), но рамка и текст через висячий `--color-danger` вырождаются в унаследованный foreground — destructive-акцента нет; у полос недоступности текст так же не warning. Юнит-тесты ассертят строки-имена токенов, а не вычисленные значения — регресс невидим для проверок. Фикс — часть перекраски по прототипу (не отдельная задача: те же файлы, что и задача).
- **Новые токены** (`tokens.css`, продолжение блока спец-токенов представлений):

  ```css
  --color-rt-task-bg: color-mix(in oklch, var(--primary) 35%, var(--surface));
  --color-rt-conflict-border: var(--destructive);
  --color-rt-weekend: color-mix(in oklch, var(--muted) 60%, transparent);
  --color-rt-holiday: color-mix(in oklch, var(--warning) 12%, transparent);
  ```

- **Полосы** (стилевые константы адаптера; жесты, `data-*`, контракт — не трогаем; `itemProps.style` — единственный путь стилей дефолтного itemRenderer беты, находка PBT-047):
  - задача: фон `--color-rt-task-bg`, рамка `--color-rt-task-border` (уже `primary`), текст `--foreground`, 13px sans (прототип `.resource-bar`);
  - конфликт: фон `--color-rt-conflict-bg` (уже destructive 18%), рамка `--color-rt-conflict-border`, текст `--foreground` (прототип текст конфликтов не красит — цвет наследуется от полосы);
  - недоступность: фон/рамка `--color-rt-unavailability-*` (уже warning 14% / warning), текст `--warning` (прототип: `.resource-bar-absence { color: var(--warning) }`), 12px (подпись «Недоступен» длинная — ellipsis уже стоит; вживую сверить с 13px).
- **Слой нерабочих дней:** `rt-day--weekend` → `--color-rt-weekend`, `rt-day--holiday` → `--color-rt-holiday` (полупрозрачные, по прототипу `.resource-day`). Общие `--color-gantt-weekend/holiday` НЕ трогаем — они используются проектным Гантом (`gantt.css:187/191`); значения ресурсного вида теперь расходятся с Гантом сознательно (прототип задаёт их раздельно: `.demo-weekend` у Гантта непрозрачный `--muted`, `.resource-day` — 60% transparent).
- Юнит-тесты адаптера обновляются на новые имена токенов.

## D2. Оформление RCT: шапка, сайдбар, границы

По прототипу (`styles.css` 163–171, 183–190), скоуп `.resource-timeline` (существующие усиленные селекторы — прецедент спайка PBT-015):

- `.rct-header-root` → `surface-raised` + нижняя граница `--border`;
- `.rct-dateHeader-primary` → `chrome`, текст `--foreground` (primary-строка месяца);
- `.rct-dateHeader` → `surface-raised`, `muted-foreground`, **mono 12px** (`--font-mono`);
- сайдбар и строки зебры: `.rct-sidebar-row-odd/even`, `.rct-hl-even/odd` → `--surface`; `.rct-sidebar-row { padding: 0 }` (свой `groupRenderer`);
- границы `.rct-sidebar`, `.rct-vl`, `.rct-hl-*`, `.rct-calendar-header` → `--border`;
- линия курсора `.rct-cursor-line` → `--primary`;
- текущая нейтральная заливка шапки (`--surface`) и снятие кремовой краски выходных RCT (`rct-day-0/6 → transparent`) — сохраняются/заменяются прототипными значениями.

`min-width: 460px` чарта из прототипа не переносим: у RCT собственный горизонтальный скролл канвы, окно виджета уже обеспечивает скролл; если живая проверка на 1024×778 покажет артефакты — добавим (фиксация в Risks).

## D3. Сайдбар: аватары, шапки TimelineHeaders, плотность

- **`groupRenderer`** (по прототипу): строка `flex h-full items-center gap-2 px-2` — аватар `24px` круг `--secondary`, инициалы `text-xs muted-foreground`; имя `text-sm` (14px), `truncate`. Инициалы — первые буквы слов имени (прототип: `split(' ').map(w => w[0]).join('')`, точки отбрасываются: «Иванов И.И.» → «ИИ»). Чистая функция в виджете; текст аватара покрывается e2e-ассертом (юнит не нужен — презентационная логика без доменных правил).
- **`TimelineHeaders`** (сейчас дефолтные шапки RCT): `SidebarHeader` — «Исполнитель» (muted, по нижнему краю, как в прототипе); `DateHeader unit="primaryHeader"` — «месяц год» (`ru-RU`, month long + year numeric), высота 28; вторичная `DateHeader` — день, высота 28 (формат дефолтный беты, mono — из CSS D2). Прототип использует те же пропсы на той же версии — перенос 1-в-1.
- **Плотность** (решение владельца 2026-10-21): `lineHeight 34 → 42`, `itemHeightRatio 0.72 → 0.7`, `sidebarWidth 150` (без изменений). e2e-укладка пересечений сравнивает `top` полос относительно друг друга, абсолютные пиксели не проверяются; «пиксель дня» жестовых спек берётся из ширины полосы (прецедент PBT-068) — смена плотности жесты не ломает.
- **Риск:** контролируемая шкала (`visibleTimeStart/End` + `onTimeChange`, PBT-049) вместе с `TimelineHeaders` — шапки беты рендерятся из того же канваса; при рассинхроне (дублирование строк, «замершие» подписи при зуме) — зафиксировать в Risks, откат TimelineHeaders отдельно от остального (граница изменения чистая).

## D4. Тулбар, легенда, футер

- **Тулбар** (одна строка — в ресурсном виде нет команд создания/экспорта): поиск `type="search"` с иконкой `Search` lucide внутри поля (absolute слева, `pl-8`), растягивается (`flex: 1`, `min-width: 144px`); селект ресурса (`max-width: 192px`); зум — пара ghost-кнопок 28×28 с `ZoomIn`/`ZoomOut`. Локаторы `data-rt-filter-query` / `data-rt-filter-resource` / `data-rt-zoom-in` / `data-rt-zoom-out` и aria-label/title сохраняются. `border-bottom: 1px solid var(--border)` у тулбара (по прототипу).
- **Легенда** (низ, над футером): свотчи 8×12px — «Задачи» (фон `--primary`), «Отсутствия» (фон `warning 20%` + рамка `--warning`), «Конфликты» (фон `destructive 20%` + рамка `--destructive`); справа — mono-диапазон видимой области `YYYY-MM-DD — YYYY-MM-DD` из `effectiveVisible` (уже вычисляется для контролируемого зума; ISO — `timelineDayIso`). Производное: обновляется при зуме/скролле, записей не создаёт; без `aria-live` (меняется при каждом скролле — шум для скринридеров).
- **Футер:** 24px, слева название документа (`ellipsis`), паттерн PBT-073 (`plan-gantt__footer`); без `role="status"` — в ресурсном виде нет действий, порождающих статусы (жесты статусов не пишут; демо-надпись прототипа не переносим).
- Итоговый порядок: тулбар → чарт → легенда → футер; легенда и футер `flex: none`.

## D5. Тесты и проверки

- **Unit:** `resource-timeline-adapter.test.ts` — обновление ассертов имён токенов (фон задач, рамка конфликтов, текст недоступности).
- **E2e (`resource-timeline.spec.ts`):** обновление `toHaveText(['QA','QA2'])` на `.rct-sidebar-row` — аватары добавляют инициалы в текст строки («QA» → «QAQA»); ассерт заменить на проверку по имени ресурса (подстрока/отдельный элемент). Новые: аватар присутствует с инициалами; легенда — три свотча + mono-диапазон, диапазон меняется после зума; конфликтные полосы — класс `rtl-item--conflict` (цвет полос — computed style по CSS-переменным в e2e не проверяем надёжно, визуально — скриншот). Жестовые спеки `resource-timeline-editing.spec.ts` — без правок, регресс.
- **Живые проверки (MCP):** консоль на React-предупреждения после добавления `TimelineHeaders`; зум/скролл/жесты drag/resize; 1024×778 и широкое окно; конфликтный план подсвечивается destructive.
- **Полный набор:** lint → typecheck → test → build → чистая среда → test:browser → `openspec validate --all --strict`.

## D6. Риски и меры

- **TimelineHeaders × контролируемая шкала** (D3) — живая проверка до фиксации; fallback: откат шапок, остальное остаётся.
- **Прозрачный фон полос с PBT-069** — до ката в этой задаче заметен только на живом UI; «до»-скриншот фиксирует состояние для PR.
- **42px строка в узком окне** — минимальная высота виджета 220px остаётся; при артефактах — `min-width` контейнера по прототипу (D2).

## D7. Находки ревью PR#52 (2026-10-21) и их закрытие

- **Подсветка нерабочих дней при зуме (замечание 1).** Корней два. (а) `onBoundsChange` беты врёт по концу канвы: коллбэк отдаёт `canvasTimeStart + 3×visibleSpan`, а фактическая ширина канвы зависит от `clientWidth` хоста — слой делил `scrollWidth` на завышенный диапазон и растягивался. (б) `clientWidth`/`scrollWidth` хоста — DOM-свойства: useMemo слоя не пересчитывался при развороте/ресайзе окна (замороженное значение с первого рендера, воспроизведено: 1000px при фактических 562). Фикс: масштаб = `hostWidth / visibleSpan` (фактическая видимая ширина ↔ контролируемый видимый диапазон — подтверждено с точностью до сотых: слой 14.41 = полосы 14.41 px/день при трёх зумах), `hostWidth` — через ResizeObserver; начало канвы — `canvasTimeStart` из onBoundsChange (гистерезис беты меняет только видимую область, канва стабильна), до первого события — формула беты (`visibleStart − span`, buffer 3); колонки — на всю канву (`scrollWidth`), чтобы подсветка не обрывалась при скролле внутри буфера. Сверка позиций: колонка воскресенья = расчётная позиция дня (218.3 = 218.3 px).
- **«Сдвигается, но возвращается» (замечание 2).** Механика PBT-048 подтверждена живьём во всех сценариях (прод и dev, конфликтные/стек-полосы, развёрнутое окно): без дневного снапа визуального слоя бета тащит полосу суб-дневно, а ядро снапит к полуночи — микро-сдвиг (< полудня) визуально «уезжает» и откатывается. Фикс: `dragSnap={DAY_MS}` (как в прототипе `ResourceTimelineChart.tsx`) — полоса прыгает по дням при перетаскивании, снап виден сразу, согласован с `snapToDayIso` (полуденное правило). Живая проверка: сдвиг 0.4 дня — холостая без записи, 1.4 дня — применился (rev +1).
- **Курсор канвы (замечание 3, опционально).** `.rct-scroll`/`.rct-canvas` — `grab`, при `:active` — `grabbing`; полосы сохраняют собственный курсор беты (инлайн pointer/move приоритетнее).
- Ложные следы диагностики зафиксированы: жесты по координатам полос **скрытого** окна (keep-mounted неактивной вкладки, PBT-027) не доходят до беты — при живых проверках обязателен контроль, что окно видимо («Просмотр приостановлен»).

# Design — PBT-073 Проектный Гантт: тёмная тема, тулбар и зум

Референс: `flexi-dashboard-hub/src/styles.css` (блок `.svar-gantt .wx-willow-dark-theme`, строки 100–160), `SvarGanttChart.tsx` (колонки, scales, `WillowDark fonts={false}`), `GanttPrototype.tsx` (тулбар в две строки, футер, Dialog max-w-xl); скриншоты `screenshots/redesign-ref/01`, `07`–`10`. Исследование пакета: `node_modules/@svar-ui/react-gantt/dist/index.es.js`, `@svar-ui/react-core/dist/index.es.js` (строки 3016–3082 — механика CDN-запроса иконок).

## D1. Тема: WillowDark + переопределения `--wx-*` на токены

- Обёртка `Willow` → **`WillowDark`**: рендерит контейнер `.wx-theme.wx-willow-dark-theme` — на него вешается полный набор `--wx-*` переопределений из прототипа (переносим визуальный язык, значения уже совпадают с нашими токенами PBT-069: `--surface`, `--primary`, `--success`, …). Существующие селекторы `.plan-gantt__chart .wx-*` от переименования темы не зависят.
- Состав переопределений (по прототипу, блок переносится в `gantt.css` под скоуп `.plan-gantt .wx-willow-dark-theme`): фон `surface`/`surface-raised`, hover `accent`, шрифт `--font-sans` 14/12px, задачи `primary` (заливка mix 50% + заливка полосы `primary` + бордер `primary`), сводные `success` (mix 35%), связи `muted-foreground` → `primary` при наведении, выделение `accent`, праздники/выходные шкалы — базовые `--wx-gantt-holiday-*` (фактическая заливка колонок — наш слой `gantt-weekend`/`gantt-holiday`, см. D2), радиус полос 3px, тени полос нет, сетка: заголовок `surface-raised` без тени, границы `--border`, mono-шкала `--wx-timescale-font: 12px var(--font-mono)`.
- Sticky-шкала: фикс PBT-053 (непрозрачный `.wx-scale`) сохраняется; фон по прототипу — `surface-raised`.
- Подсветка нерабочих дней: классы `gantt-weekend`/`gantt-holiday` и растяжка слоя `.wx-gantt-holidays` — без изменений (PBT-037/053); значения уже на токенах (`--color-gantt-weekend: var(--muted)`, `--color-gantt-holiday: warning 15%` — совпадают с прототипом `.demo-weekend`/`.demo-holiday`).

Отклонено: писать собственную тему с нуля без обёртки WillowDark (теряем базовые шрифтовые размеры/отступы SVAR); CSS-переопределение светлой Willow (прототип эталонирует именно WillowDark).

## D2. Иконки wx локально (закрытие находки PBT-069)

- Механика нарушения (react-core, строки 3016–3082): каждая тема (`Willow`, `WillowDark`, …) при `fonts !== false` рендерит `<link rel="preconnect" href="https://cdn.svar.dev">` и `<link rel="stylesheet" href="https://cdn.svar.dev/fonts/wxi/wx-icons.css">`.
- Решение: `WillowDark fonts={false}` (как в прототипе) + **вендоринг** `wx-icons.css`, `wx-icons.woff`, `wx-icons.woff2` в `packages/gantt/src/vendor/wx-icons/` (источник — тот же CDN, версия фиксируется хешем в query `?5c1d2b451b95eb4894fd97b9270b27ad`, сохранённом в комментарии файла); `import './vendor/wx-icons/wx-icons.css'` в `PlanGanttWidget.tsx`. Vite обрабатывает относительные `url()` в CSS — шрифты попадают в assets сборки (прецедент: @fontsource в PBT-069).
- Иконки останутся штатными wxi-глифами SVAR (тогглы раскрытия групп, стрелки) — CSS-обходы прототипа (`.wx-toggle-icon::before` и `.wxi-menu-down::before` рисуют стрелки вручную именно потому, что прототип отключил шрифт) **не переносим**: у нас шрифт локальный и полный.
- Проверка офлайна: после сборки — Network-панель на пустых запросах внешних хостов (методика PBT-069).

Отклонено: убрать иконки совсем (прототип без шрифта теряет часть глифов); тянуть CSS через `<link>` из public (лишний ручной файл-манифест, вне графа сборки).

## D3. Зум «Дни/Недели» (включён решением владельца 2026-10-19)

- Сегмент-контрол (паттерн `.layout-mode-switch` платформы): «Дни» → `cellWidth=48`, «Недели» → `cellWidth=33`. **Дефолт — «Недели» (33)**: сохраняет требование PBT-068 «компактная плотность по умолчанию»; 48px — осознанный выбор пользователя (delta spec — MODIFIED с уточнением).
- `scales` (сейчас не задаются, дефолт SVAR) — по прототипу: верхняя строка `{ unit: 'month', step: 1, format: «октябрь 2026 г.» (ru-RU, month long + year numeric) }`, нижняя `{ unit: 'day', step: 1, format: «Дни» → дд.мм (ru-RU day 2-digit + month 2-digit), «Недели» → только число дня }`.
- Состояние — settings экземпляра (`updateSettings({ ganttZoom })`), переживает перезапуск; начальное значение из `settings` (нестрого: неизвестное/отсутствующее → `'weeks'`).
- Смена зума не меняет документ; пересборка представления SVAR (новые cellWidth/scales) — то есть зум меняет `chartRemountKey` (доп. компонент `zoom` в ключе). Позиция взгляда — конверсия через дни, см. D6.
- Прототип (48↔28) не копируем: наша компактная плотность 33 (PBT-068, замер по OnlineGantt) остаётся базовым масштабом.

## D4. Колонки таблицы: дд.мм моно

- «Начало»/«Конец»: `template` по прототипу — ISO-строка SVAR `slice(5)` → реверс → «дд.мм». Для «Конец» — сверка с фактическим отображением при `inclusiveEnd: true` вживую (прототип делает `shift(-1)` от внутреннего значения; наши e2e текстовый формат колонок сегодня не проверяют — только полосы/подсветка, поэтому правка безопасна, но живая проверка обязательна: включительность окончания — семантика A1).
- Моно-шрифт ячеек: CSS `.plan-gantt .wx-cell[data-col-id='start'/'end'] { font-family: var(--font-mono); }` (по прототипу).
- Состав колонок не меняется: «Задача», «Начало», «Окончание», «Раб. дни», «Исполнители», «Типы» (карточка: «Исполнители» — как есть).

## D5. Тулбар в две строки + футер + lucide

- **Строка 1:** [«+ Задача» primary (Plus)] [«Группа» ghost (FolderPlus)] | разделитель | [«Импорт» ghost (Upload)] [«Экспорт» ghost (Download)] [«PlantUML» ghost (BarChart3)] [иконка настроек ghost (Settings2, aria-label «Настройки плана»)] … справа [«⚠ Проблемы N» (AlertTriangle): `warning` при N>0, `muted-foreground` при N=0 — сейчас destructive; прототип использует warning].
- **Строка 2:** поиск с иконкой Search слева в поле (input `type="search"`, aria-label «Поиск задач»), селект ресурса (оба — фильтры PBT-049), сегмент «Дни/Недели», справа счётчик «N задач».
- **Футер** (h-24px, верхняя граница): слева — название документа плана; справа — служебный статус последнего действия виджета (`role="status"`, например «План обновлён»/«Импортировано…»/«Экспортировано…»), в покое — пусто. Существующая панель `importResult` (ошибки импорта с деталями) остаётся под тулбаром без изменений: это диагностическая панель, а не статус.
- `lucide-react@0.575.0` — точный пин в `packages/gantt/package.json` (прецеденты: PBT-069 dashboard, PBT-072 apps/project-board; лицензия ISC... точнее MIT — та же версия, что уже в репозитории).
- **Совместимость e2e (критично):** сохраняются все `data-*`-атрибуты (`data-add-task`, `data-add-group`, `data-catalogs`, `data-issues`, `data-export-plan`, `data-export-plantuml`, `data-import-plan`, `data-import-plan-input`, `data-gantt-filter-query`, `data-gantt-filter-resource`, `data-task-count`), aria-labels команд импорта/экспорта и текст «Проблемы (N)» → «Проблемы N» сверяется со спеками (при необходимости спеки точечно правятся на новый вид подписи, жестовые — нет).
- Стили тулбара переезжают из `task-editor.css` в `gantt.css` (унификация: кнопки primary/ghost по прототипу, высота 28px, иконки 14px).

## D6. Техдолг D8 (PBT-071): сохранение прокрутки шкалы при ресайзе

Корень (design D8 PBT-071): SVAR 2.8 при скачке ширины контейнера пересобирает шкалу и сбрасывает прокрутку; отвергнуты поллинг-удержание (гонки), перемонтирование (пустая шкала), якорный старт (уход к началу плана).

Механизм (отличается от всех трёх отвергнутых):

1. **Пассивный трекинг:** слушатель `scroll` (capture, passive) на `.plan-gantt__chart` записывает последний известный `scrollLeft` скролл-контейнера SVAR в ref. Никаких таймеров — только событие.
2. **Восстановление:** на `onResize` из SDK (платформа уже троттлит кадром) — debounce ~150 мс после последнего изменения → `api.exec('scroll-chart', { left })`. Дистрибутив SVAR подтверждает поддержку `{ left }` (внутренняя синхронизация скролла таблицы и чарта диспатчит ровно это; наш `showTask` уже использует `{ date }`).
3. **Асинхронность пересборки:** после дебаунса — восстановление на следующий rAF + одна повторная попытка через 150 мс (ограниченная серия из двух, не поллинг: без бесконечного цикла).
4. **Кламп:** браузер сам ограничит `scrollLeft` при сузившемся контенте; SVAR `{ left }` дополнительно не клампится (проверить вживую, при необходимости — `Math.min(left, scrollWidth - clientWidth)`).
5. **Смена зума (D3):** пиксельная позиция невалидна (cellWidth меняется) → конверсия через дни: до пересборки `daysFloat = scrollLeft / cellWidthOld`, после — `scrollLeft' = daysFloat * cellWidthNew` тем же `scroll-chart { left }`. Чистая функция конверсии — unit-тест.

Fallback при нестабильности `{ left }` вживую: `scroll-chart { date }` к левой видимой дате (`chartRange.start + daysFloat`), точность до дня. Оба варианта проверяются живой проверкой (разворот длинного плана, прокрутка к концу, разворот → позиция взгляда сохранена).

Отклонено повторно: поллинг-удержание позиции (гонки — D8 PBT-071); подавление пересборки шкалы (фикс autoScale уже стоит, проблема в другом слое); перенос SVAR в собственный скролл-контейнер (масштабная правка жестов).

## D7. Единый стиль диалогов модуля

- Все 7 диалогов уже на общем паттерне (`__overlay` absolute + `surface` + радиус + `shadow-float`, все `role="dialog"`). Унификация до прототипа: **max-width 576px** (`max-w-xl`; сейчас task-editor 440px, catalog 600px), в шапке — заголовок + **строка описания** (по образцу `DialogDescription`: назначение диалога, 13px, `muted-foreground`); недостающие описания добавляются, существующие тексты сохраняются.
- Структура форм, поля, валидация, клавиатура, фокус — без изменений (спеки PBT-038/040–046/051–056).
- Ширины текстов в css-файлах диалогов (`task-editor.css`, `absence-convert.css`, `onlinegantt-import.css`, `plantuml-export-dialog.css`) правятся точечно; общие классы шапки выносятся в `gantt.css` (`.plan-gantt-dialog__*`), файлы диалогов продолжают держать свою специфику.

## D8. Риски и меры

| Риск | Мера |
| --- | --- |
| `scroll-chart { left }` ведёт себя иначе, чем внутренний диспатч (кламп/единицы) | Живая проверка на длинном плане до фиксации подхода; fallback `{ date }` (D6.5) |
| Переход Willow→WillowDark меняет каскад SVAR (не только переменные) | Полный набор жестовых e2e + живая проверка drag/resize/даблклика после смены; сравнение с референс-скриншотами |
| Вендоринг шрифта — дрейф версии иконок SVAR при будущем обновлении `@svar-ui/react-gantt` | Хеш версии в комментарии `wx-icons.css` + проверка `wxi-` глифов при обновлении (заметка в design — обновление SVAR и так отдельное решение по ADR PBT-017) |
| Тулбар в две строки съедает высоту чарта в узких окнах (1024×778) | Проверки на 1024×778 и широком экране (DoD); футер 24px, строки тулбара компактные (28px) |
| Даты в колонках: включительность «Окончания» при `inclusiveEnd` | Живая проверка дд.мм против полосы (пн–пт → 12.10/16.10); сверка с существующим отображением до правки |
| lucide-react в packages/gantt — новая зависимость модуля | Точный пин 0.575.0 (та же версия, что в dashboard/app), изоляция импортами в файлах модуля |

## Тесты

- **e2e новые:** (1) зум: переключение «Дни/Недели» меняет ширину клетки дня (замер DOM полосы/шкалы), reload → состояние сохранено; (2) разворот окна с прокруткой к концу длинного плана → позиция взгляда сохранена (сравнение левой видимой даты до/после), возврат из разворота — тоже; (3) скриншот-сверка темы не автоматизируется — глазами по референсу (прецедент PBT-069/070).
- **e2e регресс:** жестовые спеки plan-gantt (drag/resize/откаты), plan-editor, gantt-view-state, widget-maximize; при правке подписи «Проблемы» — точечная правка локаторов.
- **unit:** конверсия позиции прокрутки при зуме (D6.5) — чистая функция; чтение `settings.ganttZoom` с защитой от мусора.
- **Скриншоты до/после:** `change/screenshots/` — оба зума, диалоги, 1024×778 и широкое окно.

# PBT-142 — Глубина ротации файловых аварийных копий

## Why

Инцидент владельца 23.11.2026: после перезагрузки рабочего MacBook база Chrome пересоздана (механизм 2 из PBT-138 — пересоздание БД браузером); восстановить актуальную версию из двух резервных файлов не удалось, причина пока не установлена. Текущая ротация PBT-140 хранит всего два файла: история ограничена одной предыдущей копией, а повреждение одного файла оставляет единственную точку восстановления.

## What Changes

- Количество слотов файловых аварийных копий увеличивается с 2 до 10: `project-board-recovery-a.json` … `project-board-recovery-j.json`.
- Новый снимок публикуется в первый свободный (отсутствующий или негодный) слот; при отсутствии свободных — перезаписывает слот с наименьшей генерацией, то есть копии перезаписываются по очереди, старейшая первой.
- Существующие файлы прежней версии остаются читаемыми без миграции: старые слоты a/b включаются в новый набор, поколения продолжают существующую нумерацию.
- Обновляются тексты диагностики повреждений (store, координатор, стартовый диалог) с «двух файлов» на набор из десяти.
- Delta spec `recovery-snapshots` — ADDED «Глубина ротации копий».
- Проверки: unit-тесты ротации/миграции/повреждений, e2e на реальной файловой системе браузера.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `recovery-snapshots`: новое требование «Глубина ротации копий» фиксирует количество слотов, правило перезаписи по очереди и миграцию существующих файлов без удаления.

## Non-goals

- Выбор произвольной (не самой свежей) версии копии в UI восстановления.
- Изменение триггеров и частоты снимков (пауза 30 секунд после подтверждённых изменений).
- Диагностика потери актуальности в инциденте владельца: причина, почему два файла не дали восстановить актуальную версию, устанавливается отдельно по фактическим данным папки и браузера.
- Изменение диалога восстановления, хранилища настроек и схемы БД.

## Impact

- `packages/dashboard/src/recovery-snapshot-store.ts` — набор слотов и обобщённый выбор целевого слота.
- `packages/dashboard/src/recovery-snapshot-coordinator.ts` — regex распознавания блокировки «все файлы повреждены».
- `apps/project-board/src/RecoveryStartup.tsx` — текст о повреждённой части файлов.
- Unit-тесты `recovery-snapshot-store.test.ts`, e2e `tests/e2e/recovery-snapshots.spec.ts`.
- Частота и содержимое снимков не меняются; рост объёма чтения на сохранение оценивается в design и приемлем для фоновых операций.

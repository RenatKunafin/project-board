# PBT-120 — Профиль среды и протокол проверки внутреннего MCP-клиента

## Why

Серия PBT-120–136 строит интеграцию дашборда с внутренним агентом через локальный MCP. Поддержка MCP внутренним клиентом подтверждена владельцем (используется Playwright MCP), но не установлены свойства среды, от которых зависит жизнеспособность всей схемы: способ запуска именно нашего компонента, браузерный канал из разрешённого окружения, установка скилла/инструкций, длительный цикл и ограничения компании. Дорожная карта прямо требует: не строить стенд PBT-121 и дальнейший контракт на непроверенном транспорте и предположениях о внутреннем клиенте. PBT-120 закрывает этот пробел минимальным профилем среды и протоколом проверки, которую выполняет владелец во внутреннем клиенте.

## What Changes

- Фиксируется таблица знаний о среде со статусами «подтверждено владельцем / проверено / неизвестно / не поддерживается» по каждому свойству, необходимому для пробы PBT-121; поддержка MCP фиксируется как уже подтверждённая, без повторного доказательства.
- Готовится минимальная анкета среды для владельца: ОС клиента агента, браузер/режим дашборда, способ конфигурации MCP-серверов, поддержка инструкций/скилла, цикл/расписание и таймауты, доступность инструментов чтения источника, ограничения компании (установка ПО, источник пакетов, loopback, размещение дашборда).
- Готовится протокол пробы PBT-121 и форма обезличенного ответа владельца (без названий клиента, токенов и корпоративных данных).
- В 120 выполняется только часть, не требующая нашего MCP-сервера: ответы анкеты и тривиальные наблюдения владельца в клиенте (поля конфигурации MCP, имена уже доступных инструментов). Подключение нового сервера и сквозной обмен — PBT-121 и здесь не объявляются доказанными.
- Формулируются критерии перехода к стенду PBT-121, включая правило «один ручной запуск обработки допустим; отсутствие бесконечного цикла не блокирует интеграцию».
- Результат — обезличенный отчёт `docs/research/PBT-120.md`; продуктовый код не изменяется, delta specs отсутствуют (`skip_specs: true`).

### Modified Capabilities

- Нет.

## Non-goals

- Разработка моста, MCP-сервера, очереди и любых продуктовых схем (PBT-121+).
- Исследование внутреннего клиента по публичной документации или выяснение его названия/версии.
- Корпоративные токены, payload и любые неанонимизированные данные в репозитории.
- Проверка подключения нового MCP-сервера и браузерного канала (область пробы PBT-121).
- Выбор формата очереди, транспорта и библиотек (кандидаты фиксируются, решение — PBT-121/122).

## Impact

- Новые файлы: `openspec/changes/pbt-120-agent-environment-probe/**`, отчёт `docs/research/PBT-120.md`.
- Зависимости: без новых; продуктовый код и тесты не затрагиваются.
- Данные для отчёта собирает владелец по анкете и протоколу; репозиторий получает только обезличенный результат.

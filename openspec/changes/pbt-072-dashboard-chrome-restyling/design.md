# Design — PBT-072 Каркас дашборда

Референс: `flexi-dashboard-hub/src/components/dashboard/Dashboard.tsx` (header/nav/Popover/пустое состояние), скриншоты `screenshots/redesign-ref/01-dashboard-overview.png`, `03`–`06`, `11-empty-tab-state.png`.

## D1. Топ-бар

Новый `<header className="app-topbar">` над панелью вкладок (первый дочерний `.shell`):

- высота 44px (`h-11` прототипа), `background: var(--chrome)`, нижняя граница `--border`.
- слева: `LayoutDashboard` (lucide, 16px, `--primary`) + «Project Board» (semibold). Заголовок `h1` из потока убирается (название живёт в топ-баре; `h1` сохраняется внутри топ-бара для семантики — компактный, без потоковых отступов).
- справа: индикатор `save-state` (существующий компонент/статусы переносятся как есть: подписи, `role="status"`, классы `is-*` уже на токенах с PBT-069). Из `.tabs-header__right` удаляется.
- высота канваса уменьшается на ~44px: проверка на 1024×778 обязательна (DoD).

## D2. Панель вкладок

- Полоса `--chrome` высотой 40px; вкладки растягиваются от левого края с разделителями (`border-right` у прототипа).
- Активная вкладка: `background: var(--background)`, верхняя полоса `--primary` 2px, текст `--foreground`; неактивная: прозрачная, текст `--muted-foreground`, hover — `--surface` + текст `--foreground`. Существующие радиус-«язычки» убираются.
- Управляющие кнопки вкладки (перемещение ←/→, закрытие ×) — `opacity: 0`, проявление по `:hover`/`:focus-within` вкладки (прототип: закрытие по hover). Aria-label, `disabled`-логика и клавиатурный доступ (требование «Доступность управления с клавиатурой») не меняются.
- «+» — компактная ghost-кнопка в конце полосы.
- Переименование по двойному клику — как есть (инлайн-инпут в стиле темы).

## D3. Сегмент-контрол раскладки

`.layout-mode-switch` становится сегментом: общий контейнер `border: 1px solid var(--border)`, `border-radius: var(--radius-md)`, сегменты 28px высотой; активный — `background: var(--accent)`, текст `--foreground`; неактивный — `--muted-foreground`. `role="group"`, `aria-pressed` и обработчики — без изменений.

## D4. Панели каталогов

Общий язык (уже частично с PBT-069): фон `--popover`, `shadow-float`, паддинги прототипа.

- **Каталог виджетов** (`WidgetCatalogPanel`): карточка типа — иконка-плитка 32×32 (`border`, `--surface-raised`, содержимое — emoji-иконка типа цветом `--primary`), справа название (14px) и описание (12px, `--muted-foreground`, обрезка). Поиск и пустой результат — как есть. Описание — новое поле SDK.
- **Каталог документов** (`DocumentCatalogPanel`): строка документа — иконка-плитка типа документа, название (inline-переименование как есть), подстрока `{Название типа} · открыт в {N} окн{е/ах}` (N — сумма по `panesByTab`), кнопки действий — `opacity: 0` → hover строки (aria сохраняются). Фильтры-чипы и confirm удаления — как есть, на токенах.
- **Пикер документов** (`DocumentPickerPanel`): карточки выбора и dashed-кнопка нового документа — стиль прототипа (`border-dashed`, hover `--primary`).

## D5. SDK: описание типа

`WidgetTypeDefinition.description?: string` — опционально, каталог показывает при наличии (иначе без второй строки). Тексты по прототипу: План — «Диаграмма Ганта: задачи, сроки, зависимости»; Ресурсы — «Загрузка и отсутствия команды»; Чек-лист — «Списки задач с отметкой выполнения». Расширение контракта заявлено (обратимосовместимо; поиски каталога ищут и по описанию).

## D6. Пустое состояние

`EmptyWorkspace`: круг 56px `--surface-raised` с иконкой `LayoutGrid` (24px, muted), заголовок «Пустой дашборд», подсказка «Добавьте виджеты, чтобы собрать рабочее пространство», кнопка primary «Добавить виджет» → открывает панель каталога виджетов (callback из App: `setHeaderPanel({kind:'widgets'})`... фактический вид состояния — по коду App на реализации). Прежний текст «каталог появится в следующем обновлении» уходит.

## D7. Тесты и риски

- e2e: (1) топ-бар показывает название и индикатор «Сохранено»; (2) каталог виджетов содержит описания; (3) каталог документов показывает «открыт в N окнах»; (4) пустая вкладка — кнопка «Добавить виджет» открывает каталог. Существующие спеки не меняются: все aria-локаторы сохраняются (клики «Документы», «Добавить виджет», чипы фильтров).
- Риски: (а) высота хрома — контроль 1024×778; (б) hover-проявление кнопок — не сломать playwight-клики по aria (клики работают и на прозрачных элементах — `opacity` не блокирует hit-testing; кнопки не `display:none`); (в) `h1` в топ-баре — проверить тесты, ищущие heading (grep `getByRole('heading')` в tests/).
- Скриншоты до/после в `change/screenshots/`.

## D8. Отклонения от прототипа (зафиксировано)

Без демо-метрик («Спринт 24…»), пользователя/аватара, часов и wifi; переименование вкладок — двойной клик (у нас) вместо отсутствия у прототипа; кнопки перемещения вкладок ←/→ сохраняются (функциональность, которой нет в прототипе).

## Context

Мотивация и границы — [proposal.md](proposal.md), наблюдаемое поведение — [дельта notes](specs/notes/spec.md). PBT-101–103 уже в `develop`: `NotesEditor` синхронно держит исходный ввод, завершает IME-композицию перед записью и защищает локальный вариант при внешних изменениях. Виджет использует `DocumentService`, подписка живёт при `visible=false`. Отдельная схема представления Markdown сейчас отсутствует.

Подтверждено владельцем: начальный режим «Текст»; счётчик по отображаемому телу без Markdown-маркеров, отдельного заголовка карточки и тегов; файл включает заголовок и теги. Остальные решения ниже — предлагаемый технический дизайн для согласования до кода.

Визуальная композиция следует `flexi-dashboard-hub/src/components/dashboard/NotesPrototype.tsx` и `MarkdownView.tsx`: переключатель с пиктограммами слева в верхней панели, закрепление/скачивание/удаление справа, заголовок и теги над телом, нижний футер с «N слов · Markdown» и временем изменения. Заголовок редактируется прямо в строке и сохраняется по Enter или потере фокуса; Escape отменяет ввод. Поле добавления тега остаётся без линии фокуса. Значок закреплённой заметки в списке использует основной акцентный цвет, а кнопка закрепления в панели действий остаётся серой. Принятые владельцем правила текста и офлайн-сохранности имеют приоритет над деталями прототипа.

## Goals / Non-Goals

**Goals:**

- Один путь разбора для просмотра и извлечения отображаемого текста; независимое исходное тело остаётся источником истины.
- Ограниченная поверхность рендера: только известные React-элементы и проверенные атрибуты.
- Все изменения внутри модуля `notes`, его зависимостей и тестов; существующие контракты платформы и SDK достаточны.

**Non-Goals:**

- Нормализация сохранённого Markdown, миграции модели, новый механизм записи, HTML-редактор или автоматическое слияние конфликтов.
- Общая служба экспорта либо общие SDK-контракты ради потребностей заметок.
- Хранение режима через `updateSettings` и восстановление узкого мобильного состояния после повторного открытия: PBT-105. В PBT-104 входит только локальное переключение списка/заметки по действию пользователя, как в прототипе.

## Decisions

### 1. Парсер: предложен `markdown-it@15.0.3`

Сравнение выполнено 29.10.2026 по опубликованным npm-пакетам. Размеры измерены одинаковым `esbuild@0.25.12`: `bundle`, `minify`, browser ESM, target `es2022`, production, React и `react/*` внешние; затем Node `gzipSync`. Для первых двух кандидатов вход экспортирует функцию получения токенов, для третьего — компонент с GFM. Это размер библиотечного входа с транзитивными зависимостями, без будущего адаптера, CSS и уже имеющегося React; это не измерение прироста production-сборки приложения.

| --- | --- | --- | --- | --- |
| `marked@18.1.2` | Вложенные токены, GFM содержит зачёркивание, но также таблицы, задачи и автоматические ссылки | Не зависит от React, работает локально; встроенные TS-типы | 47 767 / 14 329 | Самый компактный; нужен дополнительный контроль GFM и преобразование текстовых токенов с HTML-сущностями для React |
| `markdown-it@15.0.3` | `commonmark`, `html:false`, отдельно включён `strikethrough`; без таблиц, задач и linkify | Не зависит от React, работает локально; опубликованы собственные TS-типы | 99 709 / 41 724 | Больше Marked, зато правила синтаксиса включаются независимо, а текстовые токены уже содержат декодированные символьные ссылки |
| `react-markdown@10.1.0` + `remark-gfm@4.0.1` | Готовые React-узлы; GFM добавляет зачёркивание вместе с расширениями | Peer `react >=18`, локальная сборка без CDN | 164 274 / 50 492 | Меньше собственного рендера, но более широкая цепочка unified/remark/rehype и отдельная работа для общего подсчёта текста и ограничения GFM |

Рекомендуется `markdown-it`: дополнительный размер оправдан точным выбором правил и единым потоком декодированных токенов. Добавить только точный пин `15.0.3` в `packages/notes/package.json`, обновить lockfile штатным npm; дополнительный `@types/markdown-it` для этой версии не требуется. Типы библиотеки не экспортировать из пакета notes. Окончательный прирост оценить в production build без изменения действующих бюджетов.

Источники: [настройки markdown-it](https://markdown-it.github.io/markdown-it/interfaces/MarkdownItOptions.html), [API и поддержка правил](https://markdown-it.github.io/markdown-it/), [опубликованная конфигурация пакета](https://github.com/markdown-it/markdown-it/blob/master/package.json); альтернативы — [токены Marked](https://marked.js.org/using_pro), [настройки Marked](https://marked.js.org/using_advanced), [react-markdown](https://github.com/remarkjs/react-markdown), [его peer-зависимости](https://github.com/remarkjs/react-markdown/blob/main/package.json). Версии и зависимости дополнительно сверены через npm registry. Временный эксперимент изолирован от репозитория; не добавляет код или зависимости в продукт.

Самописный regex-парсер прототипа отвергнут: вложенные структуры, смешанное форматирование и незавершённый ввод требуют полноценного разбора. Генерация HTML с последующим `dangerouslySetInnerHTML` отвергнута: модель React-узлов исключает необходимость вставки HTML и отдельного санитайзера.

### 2. Адаптер и точные границы синтаксиса

Адаптер внутри `packages/notes` создаёт единственный закрытый экземпляр `MarkdownIt('commonmark', { html:false, linkify:false, typographer:false, breaks:false })` и включает только встроенное правило `strikethrough`. Плагины, `.use()` и изменение глобальных правил другими модулями не используются. Разбор через `.parse()`; `.render()` не вызывается.

Токены переводятся в небольшое внутреннее дерево блоков и строчных узлов; из него строятся React-узлы и строковая проекция для счётчика. Список допустимых элементов закрыт: абзацы, `h1`–`h3`, списки/пункты, цитаты, `hr`, `pre/code`, `strong`, `em`, зачёркивание, переносы и проверенные ссылки. Тип элемента не берётся произвольно из `token.tag`, атрибуты не копируются целиком. Для нумерованного списка разрешён проверенный числовой `start`; язык ограждения кода не превращается в произвольный HTML/атрибут или загрузку подсветки.

Поведение за пределами обязательного минимума фиксируется явно:

- Заголовки уровней 4–6 показываются обычным абзацем с текстом заголовка; setext-заголовки уровней 1–2 допустимы как стандартный синтаксис парсера.
- Отступные блоки кода, ссылки со ссылочными определениями и явные `<https://...>` допустимы. Голые адреса без Markdown-разметки не превращаются в ссылки.
- `image`-токен показывает только альтернативный текст без `img`, запроса URL или интерактивной ссылки на изображение. Правило разбора изображения сохраняется, иначе `![alt](https://example.com/image.png)` может частично превратиться в обычную ссылку.
- `[ ]` / `[x]` остаются текстом пункта списка; таблицы, сноски, математика, расширения и интерактивные элементы не добавляются.
- HTML запрещён в парсере; текстовые токены выводятся строками React. Например, `<script>` виден буквально, а `&lt;b&gt;` становится видимым текстом `<b>`, не DOM-тегом.
- Неполные строчные маркеры видны как текст; незакрытое ограждение кода продолжается до конца тела. Мягкие переводы строк следуют CommonMark, жёсткие дают перенос. Исходные окончания строк при этом не меняются в документе или экспорте.

Неизвестный тип токена или ошибка адаптера дают диагностируемый безопасный просмотр исходника целиком как обычного текста. Редактор и скачивание остаются доступны; документ не перезаписывается. Для этого случая счётчик использует фактически показанный исходный текст. Не требуется строить собственный синтаксический движок ради редких неподдержанных конструкций.

### 3. Политика ссылок и безопасности

Проверка адреса принадлежит адаптеру notes и действует поверх штатной проверки парсера. Использовать полученный адрес, отклонять управляющие символы C0/DEL и их процентное кодирование, разбирать `new URL(value)` без base. Разрешить только `http:`/`https:` с явным `://` и непустым hostname либо `mailto:` с непустым адресным содержимым. Схемы сравнивать после разбора без учёта регистра; относительные и `//host` не разрешать.

Разрешённые ссылки получают только проверенный `href`, текстовую подпись, `target="_blank"`, `rel="noopener noreferrer"`. Непринятый URL никогда не даёт `<a href="">`: если парсер создал link-токен, показывается его подпись без ссылки; если сам парсер оставил конструкцию текстом, она остаётся текстом. Указанный пользователем `title` не нужен для поведения MVP и не переносится в атрибуты. HTML, события, стили и пользовательские ID не становятся атрибутами DOM.

Проверки включают `javascript:`, `data:`, `file:`, относительные адреса, смешанный регистр, символьные ссылки в схеме и управляющие символы. Отдельно проверяются отсутствие вызовов обработчиков, диалогов, навигации и сетевых запросов изображений. Обычные разрешённые ссылки остаются рабочими.

### 4. Режим — локальное состояние окна, редактор остаётся владельцем ввода

Хранить режим рядом с `NotesEditor` в компоненте окна, начальное значение `text`. Выбор существующей заметки сохраняет режим окна, успешное создание открывает `text`. `NotesEditor` не пересоздаётся при переключении; существующий выбор, поиск, тег и подписка сохраняются. Пока нет заметки, действия режима/скачивания не показываются. Постоянное сохранение режима отложено в PBT-105 и не меняет схему settings в этом PR.

Переход к просмотру и скачивание сначала завершают композицию из актуального DOM-значения textarea обычным `endComposition`. После этого обработчик читает свежий синхронный `editor.getSnapshot()`, а не снимок замыкания предыдущего render. Конфликт, `writeFailed` или открытое переименование блокируют действие существующим локальным диалогом. При ошибке перехода режим остаётся `text`; после разрешения диалога действие требуется повторить, отложенного автоматического переключения/скачивания нет. Это не новый механизм flush и не обещание физической записи на диск: диск по-прежнему обслуживает платформа.

Просмотр использует текущее тело выбранного draft после успешного перехода. Внешняя правка чистой заметки обновляет его через прежнюю подписку. При конфликте первичен существующий диалог с обоими вариантами, просмотр не принимает решение за пользователя. Скачивание берёт свежие заголовок, тело и теги из согласованного состояния после завершения ввода, а не из устаревшего `draft.base`.

Кнопки имеют доступные названия и `aria-pressed`; при переходе к тексту фокус получает textarea, при переходе к просмотру — его именованная область с `tabIndex=-1`. Двойной клик игнорирует ссылки и другие интерактивные потомки. Обычная кнопка «Текст» обеспечивает тот же сценарий с клавиатуры без собственного нестандартного сочетания клавиш.

### 5. Футер, вычисления и размещение

Счётчик работает по проекции того же внутреннего дерева, из которого строится просмотр. Текстовые листья внутри одного строчного блока соединяются без добавочных пробелов, чтобы `од**но**` осталось одним словом; границы блоков и переносы разделяют слова. Учитываются подписи ссылок, альтернативный текст изображения, код и буквально показанный HTML; URL скрытой ссылки, маркеры списка/заголовка и ограждения кода не учитываются. Явно видимые `[x]` остаются частью видимого текста и учитываются по общему правилу.

Слово — буквы/цифры, допускающие последующие диакритические знаки и внутренние `-`, `'`, `’` между буквенно-цифровыми частями. Использовать Unicode property escapes, без зависимости от DOM, ICU и размеров окна. Пунктуация/эмодзи отдельно дают ноль; `по-русски`, `don't`, `42` — по одному; `# План` — одно, `[два слова](https://example.com)` — два. Отдельный заголовок и теги не подаются в счётчик.

«Изменено: ДД.ММ, ЧЧ:ММ» использует `updatedAt` самой заметки, локальную зону устройства и имеющийся формат `noteDate` без года; `<time dateTime>` сохраняет исходный timestamp. Нет относительного таймера и ложной даты последнего переключения. При неподтверждённом вводе дата остаётся датой сохранённого состояния.

Результат разбора и счётчик мемоизируются по телу и пересчитываются только у `visible=true`; скрытое окно хранит последний результат, но подписка продолжает получать документы. При возврате вычисляется актуальный текст до показа просмотра. Не добавлять debounce в сохранение текста и не создавать кеш всех исторических версий заметок. React-поддерево просмотра также мемоизируется, чтобы скрытое окно не перестраивало его на каждое уведомление.

Композиция следует прототипу `NotesPrototype.tsx`: поиск, создание и сгруппированный список расположены слева, выбранная заметка и её редактор — справа. На ширине контейнера менее 560px список и заметка поочерёдно занимают панель целиком; кнопка «Назад к списку» возвращает к списку. Режим заметки остаётся независимым от этого локального переключения. Содержимое имеет `min-width:0`, обычные слова/ссылки — `overflow-wrap:anywhere`, код — `white-space:pre` и локальную горизонтальную прокрутку. Существующая вертикальная прокрутка минимального окна сохраняется. Используются семантические токены и локальные шрифты. Сохранение мобильного состояния и расширенные возможности навигации остаются в PBT-105.

### 6. `.md` — чистая сериализация и локальное скачивание

Чистая функция получает выбранную заметку, возвращает имя и содержимое файла. Формула содержимого:

```text
"# " + title + "\n\n" + body
+ (tags.length ? "\n\n" + tags.map(tag => "#" + tag).join(" ") : "")
+ "\n"
```

`body` вставляется посимвольно, без trim, переформатирования, нормализации CRLF/LF или HTML-экранирования. Название и теги берутся из актуальной заметки; порядок тегов сохраняется. Служебные переводы строк добавляются вокруг тела, даже если оно уже заканчивается переводом строки. UTF-8 без BOM. Импорт и возможность восстановить документ из этого файла не обещаются: полная модель переносится общим бекапом.

Безопасное имя: заменить C0/DEL и `\\/:*?"<>|` на `_`, убрать краевые точки/пробелы, ограничить основу 180 байтами UTF-8 без разрезания Unicode code point, снова убрать краевые точки/пробелы; при пустой основе — `note`. Для Windows-имён `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9` (в том числе с суффиксом после точки, без учёта регистра) добавить префикс `_`. Затем добавить `.md`. Ограничение касается только имени файла и не меняет название или тело внутри файла/документа.

Обёртка скачивания создаёт `Blob` типа `text/markdown;charset=utf-8`, object URL и временный `<a download>`, инициирует штатное скачивание. Anchor удаляется и URL освобождается в гарантированном cleanup; после успешного click освобождение планируется на следующую задачу event loop, чтобы не отозвать URL до обработки скачивания. Ошибка показывает локальную диагностику без изменения документа и не оставляет URL.

### 7. Проверки и след решения

Модульные тесты проверяют проекцию дерева, комбинации/вложенность Markdown, неполные конструкции, HTML/URL-политику, границы Unicode-слов, точные байты сериализации, сохранение CRLF/пробелов и безопасные имена. Компонентные проверки покрывают актуальный snapshot после IME, отсутствие повторного действия после конфликта, независимость режимов и пропуск тяжёлых вычислений при hidden с возобновлением при visible.

Production e2e используют реальные два окна, фактически скачанный файл, прямую проверку отсутствия исполнения/запросов и неизменности revision/updatedAt при view-only действиях. Сценарий восстановления загружает настоящий файл общего бекапа в чистом хранилище и сравнивает тело/теги, после чего проверяет просмотр и повторный экспорт offline. Дополнительно живой осмотр минимального окна, длинного содержимого и консоли. Выполнить обязательный набор из `.agents/rules/testing.md`; не считать этот план заменой проверок реализации.

Отдельный ADR для выбора рендера не нужен: формат данных и архитектурные границы не меняются; решение сохраняется в design и затем в архиве change. Если реализация потребует изменения этих границ, это новая существенная развилка для владельца.

## Risks / Trade-offs

- Больший размер `markdown-it` относительно Marked → принять осознанно ради выбора правил; проверить фактическую production-сборку с сохранением бюджетов.
- Парсер имеет защитный предел вложенности → тестировать глубокие/неполные структуры; текст всегда остаётся доступен в редакторе, исходник не обрезается.
- Очень большое тело требует синхронного разбора даже в режиме «Текст» ради счётчика → один разбор на версию видимого тела, мемоизация, отсутствие вычислений hidden; при выявленной проблеме производительности обсуждать отдельное решение, не менять сохранение текста скрытно.
- Изменение формата токенов при будущем обновлении зависимости → точный пин, закрытый адаптер и поведенческие тесты.
- Переход по ссылке открывает внешний ресурс → только явное действие пользователя и разрешённые схемы; сам просмотр не загружает ресурсы заметки.
- `.md` не является полной резервной копией → не смешивать одиночный экспорт и существующий перенос полной модели.

## Context

Карточка PBT-090 (зависимости PBT-019/025/085 — Done). Текущее: `DropdownPanel` (dashboard) — `role=dialog`, закрытие по Escape/клику вне уже есть; позиционирование `absolute` под кнопкой в `.header-anchor` без клампа к viewport; фокус при открытии/закрытии не управляется. Подтверждение удаления (`DocumentCatalogPanel`) — inline «Удалить …?» без объяснения последствий; счётчик открытых окон уже вычисляется и передаётся (`openWindowCount`). Модальный редактор — нативный верхний слой: фоновые панели недоступны по построению. UX-правила размещении/клавиатуры согласованы в PBT-085/PBT-089 (диалоги Гантта, меню «⋯»).

## Goals / Non-Goals

Goals: единообразное поведение трёх панелей платформы (каталог виджетов, каталог документов, выбор документа) — clamp-размещение, прокрутка, Escape/клик-вне, возврат фокуса, фокус первого поля; объяснение последствий при удалении документа.

Non-Goals: `role=menu`/перехват стрелок (панели интерактивные), общий SDK-сервис или UI-пакет, изменения модели и состояний каталога.

## Decisions

### D1. Размещение DropdownPanel: fixed по якорю с clamp

Панель позиционируется `position: fixed` по `getBoundingClientRect()` кнопки-якоря: выравнивание по правому краю кнопки, clamp левой/правой границы к viewport, разворот вверх от нижнего края при нехватке высоты; `max-height` сохраняется (прокрутка длинного содержимого уже есть). Позиция пересчитывается при открытии; resize окна закрывает панель. Реализация платформенная, без портала (панель остаётся в поддереве шапки).

### D2. Фокус: первое поле при открытии, якорь при закрытии

При открытии фокус переходит первому полю ввода панели (поиск каталога/выбора), иначе первому интерактивному элементу. Escape и клик вне закрывают панель и возвращают фокус на кнопку-якорь (клик по самой кнопке — переключение, фокус на ней естественно). Стрелки не перехватываются: панели содержат поля и списки со своей навигацией.

### D3. Семантика панелей

Панели остаются `role=dialog` с доступным названием: они интерактивны (поиск, поля, множественные действия), а не списки команд — `role=menu` и перехват стрелок не вводятся (правило карточки).

### D4. Удаление документа: подтверждение с последствиями

Inline-подтверждение удаления показывает: документ «название», счётчик открытых представлений и последствие — «все его окна перейдут в состояние недоступного документа» (для 0 окон — формулировка без счётчика). Закрытие окна виджета и удаление документа — по-прежнему разные действия; удаление остаётся отдельной операцией каталога с подтверждением, отмена ничего не меняет.

### D5. Границы платформы

Реализация целиком в `packages/dashboard` (+CSS приложения): модули не получают новых импортов, SDK не расширяется, меню модулей (PlanMoreMenu и др.) не переиспользуются платформой — раздельные реализации по карточке.

## Risks / Trade-offs

- Fixed-позиционирование панели в поддереве шапки: корректно, пока шапка не создаёт `transform`-контекст; проверено кейсами максимизации/узкого экрана в e2e.
- Правила фокуса добавляются к действующим панелям — регресс проверяется существующими e2e каталога и новыми кейсами.

## Test Strategy

E2E: панель у правого/левого края и на малой высоте экрана целиком в viewport; длинный список (30 документов) прокручивается; Escape/клик вне закрывают с возвратом фокуса на кнопку; при открытии фокус в поле поиска; подтверждение удаления показывает счётчик окон и последствие, отмена/подтверждение работают (существующие сценарии удаления зелёные); при открытом модальном редакторе панели шапки недоступны. Unit: вычисление позиции (clamp/разворот) — чистая функция. Обязательный набор: lint/typecheck/unit/build/browser, verify:repository, openspec strict; скриншоты 1024×778 и 1856×1269.

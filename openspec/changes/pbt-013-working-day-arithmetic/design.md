## Context

Правила семантики — [ADR PBT-003](../../.docs/adr/PBT-003.md) (по дням, включительное окончание, лаг ≥ 0, пн–пт по умолчанию, праздники, рабочие исключения 8.2). Ожидания E1–E10 выписаны в фикстурах PBT-012 (`tests/fixtures/gantt/small-plan-expected.md`). Расположение: календарь — предмет Гантта (ADR-3), код в `packages/gantt` (первый настоящий код пакета). Паттерн чистых функций без React/IDB — как модель чек-листа (PBT-008).

## Goals / Non-Goals

**Goals:**

- Чистое иммутабельное ядро арифметики: `isWorkingDay / nextWorkingDay / addWorkingDays / workingDaysBetween`.
- Прогон ожиданий E1–E8 из фикстур PBT-012 как unit-тестов.
- Календарные границы: месяц/год, високосный день, DST, однодневный и перевёрнутый интервалы.

**Non-Goals:**

- Валидация зависимостей и циклов (E9/E10 → PBT-035), конфликты ресурсов (PBT-036), редактор календаря в UI (PBT-044), часовые пояса пользователя (планирование по календарным датам; TZ-сдвиги нейтрализуются UTC-внутренностями — и это тестируется).
- Хранение календаря в документе плана (PBT-030 связывает календарь с `DocumentService`).

## Decisions

- **Даты — строки `YYYY-MM-DD`; внутренняя арифметика — `Date` на `T00:00:00Z` (UTC).** UTC не имеет DST-переходов, поэтому календарная дата не смещается при переходах летнего времени (сценарий DoD). Конвертация UTC-меток исходного `.gantt` остаётся в адаптерах (PBT-052).
- **Календарь — фабрика `createWorkingCalendar({ workingDays, holidays, workingExceptions })`.** Возвращает иммутабельный объект с методами; списки нормализуются и валидируются при создании: `workingDays` — непустой массив чисел 1–7 без дублей, даты — в формате `YYYY-MM-DD`. Пустой `workingDays` без рабочих исключений → `WorkingCalendarError` (DoD «конечный результат»: циклы невозможны по построению).
- **Приоритет дня:** рабочее исключение (день рабочий) > праздник (день нерабочий) > день недели. Рабочее исключение применимо и к празднику (перенос праздника сделан рабочим — решения 8.2 «отметить отдельный обычный выходной рабочим»).
- **`addWorkingDays(date, 0)` = `nextWorkingDay(date)`** — ближайший рабочий день ПОСЛЕ указанной даты (ADR-003 C1: лаг 0 — начало в ближайший рабочий день после окончания предшественника). Отрицательный лаг — `WorkingCalendarError` (валидация входа; E10).
- **`workingDaysBetween` с `end < start` → 0** без ошибки (DoD «определённый результат»; спецификация PBT-013).
- **Иммутабельность:** методы не мутируют календарь и аргументы; календарь заморожен (`Object.freeze`).

## Risks / Trade-offs

- [Строковый формат дат допускает невалидные значения] → фабрика валидирует формат по регулярному выражению и реальному календарю (`Date` round-trip); ошибки — `WorkingCalendarError('invalid-date')`.
- [O(n) циклы по дням в больших интервалах] → для сотен задач и интервалов в годы — незаметно; при необходимости (десятилетия) добавляется замкнутая формула, не сейчас.
- [`backendDB`-независимость: dexie не импортируется] → гарантировано отсутствием зависимостей пакета; lint-граница dexie уже запрещает.

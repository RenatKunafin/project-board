## Context

Цель и границы описаны в `proposal.md`, наблюдаемое поведение — в `specs/notes/spec.md`. Основа — PBT-102 из `develop` (`725ff4f`): `NotesEditor` держит базовую заметку и локальный ввод, адаптер notes работает через синхронный DocumentService, текст передаётся в общий документ при вводе, конфликты разрешаются модальным диалогом модуля. Поля tags, pinned и updatedAt уже существуют; updatedAt хранится как ISO 8601 UTC.

Прототип использует числовой timestamp, демонстрационные данные при ошибке чтения, обрезание тегов до 32 символов и вычисление недели вычитанием фиксированных суток. Эти механизмы не переносятся: рабочая модель уже определена PBT-101, а локальный день может иметь продолжительность, отличную от 24 часов.

Владелец подтвердил три решения: последние семь локальных календарных дней; очистка поиска с сохранением активного тега при успешном создании; сброс исчезнувшего тега на «Все». Ниже приведена предлагаемая техническая детализация для общего рассмотрения design перед кодом.

## Goals / Non-Goals

**Goals:**

- Держать поиск, группировку, управление метаданными и состояние фильтров внутри `packages/notes`.
- Разделить производный список и открытый редактор: изменение списка не должно менять идентичность редактируемой заметки.
- Сохранять актуальные соседние данные при изменении тегов и закрепления через существующую проверку revision.
- Проверять календарные границы, порядок и счётчики чистыми функциями с заданным временем.

**Non-Goals:**

- Менять schemaVersion, SDK, платформенную очередь сохранения, backup и политику конфликтов.
- Вводить парсер Markdown, стороннюю библиотеку дат или постоянное хранилище фильтров.
- Завершать переход между одно- и двухколоночным режимами PBT-105; текущая базовая компоновка должна оставаться доступной с прокруткой.

## Decisions

### 1. Чистые селекторы организации заметок

Добавить внутренний модуль чистых функций для нормализации тега, сбора счётчиков, фильтрации, сортировки, группировки и предварительной строки. Он получает readonly заметки и явный now, возвращает производные данные и не меняет входные массивы. Поиск — буквальное вхождение обрезанного по краям запроса после приведения к нижнему регистру в каждом из полей title, body и tags. Регулярные выражения, нечёткий поиск, транслитерация и специальный синтаксис запроса не вводятся. Ё и е различаются.

Тег-фильтр сравнивается с нормализованным представлением тегов. Счётчики считаются по всему блокноту, по одному вхождению на заметку; фильтры не влияют на них. Чипы фильтра упорядочиваются по убыванию счётчика, затем по названию в русском порядке с дополнительным сравнением строк для разрешения равенства. Чип «Все» доступен и при отсутствии тегов. Повторное нажатие активного тега выключает его; «Все» сбрасывает только тег, а явная команда сброса фильтров очищает и запрос.

Альтернатива — смешать фильтрацию с записью состояния документа — создаёт лишние редакции и связывает окна между собой. Вычисления в JSX труднее проверять на границах календаря и повторно использовать при выборе после удаления.

### 2. Нормализация тегов и операции по актуальному документу

При принятии удалить краевые пробелы, все ведущие #, снова краевые пробелы, привести строку к нижнему регистру. Повторяющиеся # и пробелы в начале обрабатывать как единый префикс, чтобы нормализация была идемпотентной. Пустой результат игнорировать, произвольный лимит длины не вводить. Пробелы внутри тега допустимы; запятая разделяет теги. Enter принимает текущий ввод, запятая принимает завершённые части, вставка нескольких частей через запятую обрабатывается последовательно; потеря фокуса принимает оставшуюся непустую часть. Незавершённая IME-композиция не принимается по Enter или промежуточной запятой до её завершения.

Ввод тега принадлежит ID заметки, для которой начат: переход и blur не могут назначить его другой заметке. Очищать принятый ввод после успешной операции; при ошибке держать сырой ввод привязанным к прежнему ID и показывать ошибку. Это временное состояние модуля, без обещания восстановления после закрытия.

Существующий парсер допускает произвольные строки в tags, поэтому при чтении не переписывать ранее сохранённые данные. Для отображения, поиска, сравнения и счётчиков использовать уникальную нормализованную проекцию. Добавление существующего нормализованного тега — no-op, без записи и изменения времени. При удалении чипа удалять все сохранённые варианты этого нормализованного тега; остальные значения сохранять. Чипы самой заметки сохраняют порядок первого появления.

Текущий `setTags` принимает готовый массив: построение такого массива из старого UI-снимка может потерять добавление другого окна. Для UI добавить внутри адаптера notes относительные операции добавления/удаления тега, которые читают актуальную заметку внутри существующего commit и повторно применяются при DocumentConflictError. Закрепление задаёт желаемое значение через существующую операцию setPinned. Изменяются только запрошенные метаданные; прежняя защита body/title остаётся в NotesEditor. Подписка не выполняет обратную запись в документ.

Альтернативы: перенос ограничения 32 символа из прототипа молча меняет пользовательский ввод; нормализация всей базы при чтении меняет данные без действия пользователя; запись полного снимка заметки теряет независимые правки.

### 3. Локальные календарные группы и стабильный порядок

Сначала применить поиск и тег. Затем выделить закреплённые; прочие заметки разделить по локальным границам суток. Для todayStart использовать начало текущего локального дня, для weekStart — начало дня на шесть календарных дат раньше. Вычислять границы календарными операциями Date, а не вычитанием `6 * 24 часа`: это сохраняет смысл на переходах часового пояса. Интервалы: updatedAt >= todayStart — «Сегодня»; weekStart <= updatedAt < todayStart — «За неделю»; меньше weekStart — «Раньше». Как в референсе, отметки позже текущего дня из-за неверных часов также попадают в верхнюю незакреплённую группу; исходный timestamp не исправляется автоматически.

Порядок групп фиксирован; пустые группы не рендерятся. В каждой группе — время по убыванию, затем ID по возрастанию обычным сравнением строк. Чтение и сортировка массива не меняют документ. Нажатие закрепления меняет updatedAt только при фактической смене pinned, в соответствии с существующей операцией модели.

Для видимого экземпляра пересчитывать now при показе и планировать таймер до следующей локальной полуночи. На window focus и document visibilitychange пересчитывать дату и планировать таймер заново: фоновые таймеры могут запаздывать, а локальный часовой пояс — меняться. При visible=false остановить календарный таймер и тяжёлые расчёты; подписка и черновик продолжают жить. При возврате вычислить актуальный список по последнему документу. Все listeners и таймеры освобождаются при размонтировании.

Альтернативы: календарная неделя отвергнута владельцем; фиксированные интервалы по миллисекундам расходятся с локальными датами; сортировка только по времени оставляет порядок зависимым от массива при равных timestamp.

### 4. Фильтры и жизненный цикл выбора

Query и activeTag остаются в состоянии конкретного окна и не попадают в content. Их постоянное восстановление и backup настроек входят в PBT-105; в этом change после нового открытия окна они начинаются пустыми. Существующее сохранение выбранного noteId PBT-102 остаётся.

На входящем снимке проверять существование активного тега по нормализованным тегам всего блокнота. Если он исчез, очистить только activeTag, оставив запрос. Сброс не вызывает запись документа. Создание сначала выполняет операцию с активным тегом; только после успеха очищает query в текущем окне, сохраняет тег и явно выбирает новую заметку. При ошибке не менять фильтры и редактор. Создаваемому заголовку не присваивается поисковый запрос.

Открытый ID существует независимо от видимых карточек. Даже если правка текста, тегов или query исключила заметку из списка, сохранять её редактор и показать пояснение, что открытая заметка вне текущего фильтра. Редактор не размонтируется из-за пустой выдачи; key зависит от идентичности окна/документа, а не позиции в списке, группы или updatedAt. Закрепление, поле запроса и редактор должны удерживать фокус при перестановке карточек.

При удалении выбранной заметки без локального ввода выбрать первую по актуальным фильтрам, группам и сортировке. Если выдача пуста, очистить выбор и показать предложение выбрать заметку или сбросить фильтры; это не сообщение о пустом блокноте, если документ содержит другие заметки. Для решения использовать тот же чистый селектор с текущими значениями фильтров, а не старую React-замкнутую переменную. Само изменение фильтра не выбирает другую заметку автоматически. Если есть локальный конфликтный ввод, приоритет имеет существующий диалог PBT-102, включая удалённую заметку и скрытое окно.

Альтернативы: принудительный переход к первой карточке при каждом фильтре или изменении updatedAt сбрасывает рабочий контекст и фокус; сохранение исчезнувшего тега оставляет несуществующий фильтр, что владелец отклонил.

### 5. Карточки без внедрения Markdown-просмотра

Группированный список карточек добавляется к текущей базовой компоновке. Карточка содержит заголовок, моноширинную локальную дату/время в формате ru-RU и предварительный текст первой содержательной строки. Подпись действия выбора должна по-прежнему однозначно называть заметку; дата и предварительный текст доступны как описание, а не меняют идентичность кнопки. Длинные значения обрезаются только визуально, исходные строки не изменяются.

Предварительная строка — небольшой текстовый helper: пропустить пустые строки и отдельные разделители/ограждения блока кода; удалить распознанные префиксы заголовка, списка и цитаты, простые маркеры inline-оформления. Не удалять обычные начальные числа, например в «2026: планы». Если содержательной строки нет — «Нет текста». Это plain text в React, без HTML и Markdown-рендера; исходный body остаётся неизменным. Полноценный синтаксис и режим просмотра принадлежат PBT-104.

Альтернатива — импортировать парсер ради одной строки — добавляет зависимость и расширяет PBT-103 до следующего этапа.

## Risks / Trade-offs

- Изменение времени переносит карточку между группами при каждом вводе → сохранять редактор отдельным стабильным узлом, проверять caret и фокус реальным вводом.
- Перевод часов и задержка фонового таймера → календарные границы, пересчёт при показе/focus, unit на полуночь и переходы часового пояса.
- Старые варианты записи тегов → нормализованная проекция без записи при чтении; счётчик по уникальному тегу заметки, относительные операции по свежему документу.
- Ошибка принятия тега при переключении заметки → привязка сырого ввода к ID, очистка только при успехе и явная диагностика.
- Дополнительные элементы при минимальном размере → прокрутка и перенос длинных чипов, живая проверка базовой доступности; полный адаптивный режим остаётся в PBT-105.
- Фильтры пока не восстанавливаются после reload → хранить отдельно от общих данных; постоянное восстановление явно отнесено к PBT-105.

## Migration Plan

1. Добавить селекторы и относительные операции внутри notes, затем подключить UI к существующей модели и NotesEditor.
2. Проверить unit на нормализацию, даты, поиск, сортировку и относительные операции; production e2e на два окна, сохранность ввода, reload/offline и backup с непустыми метаданными.
3. Выпустить одним PR в develop. После одобрения PR синхронизировать notes spec и архивировать change заключительным коммитом, дождаться CI и выполнить merge.
4. Миграция документа и backup не нужна. При откате интерфейса ранее сохранённые tags/pinned/updatedAt остаются совместимы с PBT-101/102.

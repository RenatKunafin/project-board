# PBT-078 — Сетка каскада

## Context

Текущий CascadeLayout задаёт контролируемые position/size, bounds=parent, onDragStop/onResizeStop с clampCascadeArea. Фон — radial-gradient с шагом 16px. Стартовые области 600×420 и отступы 24+28n не кратны 16. Минимальная ширина чек-листа 280px также не кратна 16. Правило границ PBT-076 обязательно сохранить. Переносить жестовую демо-логику прототипа не нужно: у нас адаптер react-rnd.

## Референс поведения (уточнение владельца 2026-10-23)

Референс привязки — режим сетки прототипа, а не настройки его каскада. Проверены `WidgetFrame.tsx` и передача `snap={snap && tiled}` в `Dashboard.tsx`. В режиме сетки прототип округляет абсолютные координаты и размеры: `Math.round(value / gridSize) * gridSize`, по умолчанию gridSize=16. Во время pointermove вычисляется исходная геометрия + смещение указателя и сразу показывается дискретный preview; pointerup фиксирует последнее показанное значение. Это и есть целевое ощущение перемещения/ресайза для нашего каскада. Отсутствие snap в каскаде прототипа не является ограничением требований.

Сохранение только после жеста и дискретный preview переносим как поведение, без копирования обработчиков прототипа. В частности, штатные dragGrid/resizeGrid должны соответствовать округлению абсолютной геометрии, а не только прибавлять кратное смещение к несеточной исходной позиции.

## Decisions

1. Предложение: единый шаг 16px для x/y/width/height. Сетка отсчитывается от начала канваса. CSS-позиция точек должна совпадать с этой системой координат: центр текущего radial-gradient в середине тайла, поэтому требуется согласовать background-position. Шаг передать из одной платформенной константы через CSS custom property, чтобы CSS и жесты не расходились.
2. Дискретность видна во время жеста, а не только после отпускания: использовать штатные dragGrid/resizeGrid react-rnd (уточнить фактическую семантику в установленной версии до реализации) и итоговую нормализацию. Добавить эти поля в изолированный RndProps, библиотечные типы не выходят из адаптера.
3. Размер выбирать ближайшим узлом сетки внутри допустимого интервала типа и канваса; позиции — ближайшим узлом в интервале [0, canvas-size]. Например, minWidth 280 даёт минимальный сеточный размер 288, если он помещается. Возле края выбирать последний допустимый узел внутри, а не выталкивать окно за канвас ради округления.
4. При отсутствии допустимого узла ограничения размера/достижимость важнее кратности: например, canvas 283px и minWidth 280px требуют допустимый несеточный размер. Для канваса меньше минимума действует прежнее исключение PBT-076: минимальный размер, позиция 0. Эти случаи проверяются отдельно.
5. Отображение новых и восстановленных областей проходит одну нормализацию (snap + constraints + canvas). Старые записи не переписываются при загрузке или ResizeObserver. Итог жеста сохраняет показанную допустимую геометрию; переключение режимов сохраняет независимость раскладок. Стартовые окна выравниваются тем же правилом.
6. Для свёрнутого окна высота заголовка не округляется и сохранённая развёрнутая высота не затирается; перенос учитывает видимую высоту заголовка при границах. Разворачивание на весь дашборд не привязывается к сетке; возврат восстанавливает каскадную геометрию. Соседи могут перекрываться, активация меняет только порядок глубины.

## Validation

Содержательные unit-проверки чистой геометрии: округление, не кратные шагу минимумы/максимумы, тесный канвас, правая/нижняя границы, старые координаты и свёрнутое окно. Browser: реальный перенос и ресайз на не кратное 16 расстояние; геометрия во время движения и после отпускания, сохранение/reload, смена режима, границы, сворачивание/разворот. Проверить на 1024×778 и широком экране, снять до/после, проверить консоль MCP. Lint/typecheck/unit/build, полный test:browser в чистой среде и strict OpenSpec; dev-сервер предварительно остановить.

## Уточнения по реализации

- Проверены исходники установленных react-rnd/react-draggable/re-resizable: dragGrid округляет смещение, resizeGrid — абсолютный размер после min/max. Поэтому отображаемая исходная геометрия нормализуется, границы min/max ресайза выбираются по допустимым узлам; в интервале без узла шаг соответствующей оси — 1px.
- Штатный bounds у канваса с несеточным размером позволяет промежуточную несеточную координату у края. Каждое окно получает прозрачную плоскость границ с размером «размер окна + наибольшее допустимое кратное 16 смещение». Она не ловит указатель, не создаёт stacking context и не перемонтирует содержимое: z-index, keep-mounted и DOM-перенос максимизации сохраняются. Это избегает вмешательства во внутренний state библиотеки и исправлений позиции после кадра.
- Нашлось старое расхождение PBT-070/027: видимый свёрнутый заголовок с рамкой = 34px (32+2), CASCADE_COLLAPSED_HEIGHT оставался 44px, minHeight оболочки соответствовал развёрнутому окну. Исправлено в рамках требования о переносе свёрнутого окна: оболочка 34px с тем же min/maxHeight, развёрнутая высота при переносе сохраняется.
- Неприменимые бесконечные maxWidth/maxHeight до первого ResizeObserver не передаются в JSX/CSS. В промежуточной dev-проверке поймано предупреждение React об Infinity; исправлено, последующий свежий изолированный контекст — 0 ошибок.

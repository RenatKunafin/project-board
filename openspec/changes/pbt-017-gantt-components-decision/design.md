# Design — PBT-017: решение по компонентам Гантта

## Context

Три исследования закрыли открытый вопрос ADR PBT-002 «компоненты Гантта — кандидаты»:

- **PBT-014** (`apps/gantt-spike`, SVAR `@svar-ui/react-gantt@2.8.0`, MIT): ручной режим без автопереноса подтверждён; включительное окончание реализуется адаптером (+1 день) по всем поверхностям; дерево со сводными и сворачиванием; FS-связи; подсветка нерабочих дней (`highlightTime`); форма `Editor`. Ограничения: ненадёжный payload `update-task` при мышиных жестах; календарная `duration` (рабочую считаем сами); сводные пересчитываются библиотекой некорректно при подмене дат (считаем сами); перехватчики, навешанные в `init`, перестают ловить жесты после пересоздания bus; несимметрия `getTask` для сводных.
- **PBT-015** (`apps/resource-timeline-spike`, `react-calendar-timeline@0.30.0-beta.19`, MIT): компактные дорожки с укладкой пересечений (`stackItems`); лента занятости как union-интервалы; отпуск — элемент дорожки; день-точность собственным снапом; drag/resize с семантикой A2/A3. Риски: бета-линия с нестабильным API жестов (`onItemDrag` вместо `onItemMove/onItemResize`, в жести не эмитятся); жесты только после клика-выделения; дефолтную тему надо переопределять.
- **PBT-016** (`apps/load-demo`): обе библиотеки в одном бандле конфликтов не показали; 10 виджетов на плане-500 — монтирование 145 мс, редактирование ≤300 мс (верхняя оценка), запись плана-500 ~470 мс, восстановление полное. Пороги-кандидаты для PBT-058 предложены.

Требования к компонентам — решения §13 (проектное и ресурсное представления), правила ADR PBT-003 (A1–D7), ручной режим §7, нагрузка §20.

## Goals / Non-Goals

**Goals:**

- Зафиксировать компоненты обоих представлений, версии, лицензии и границы ответственности «ядро ↔ библиотека ↔ адаптер».
- Перевести ограничения библиотек из «рисков» в явный контракт адаптеров.
- Закрыть судьбу исследовательских стендов и утвердить пороги PBT-058.

**Non-Goals:**

- Код адаптеров и ядра; выбор layout-библиотек; PWA; файловые форматы.

## Decisions (черновик — на ревью владельца)

### D1. Проектное представление: SVAR React Gantt 2.8.0 (MIT)

Альтернативы: Frappe Gantt (отклонён ещё на отборе: слабее по произвольной вложенности); собственный рендер (дорог: дерево, связи, форма, масштабирование — всё проверено SVAR «из коробки»); коммерческие редакции (против предпочтения open-source). Принимается с ограничениями, которые становятся контрактом адаптера (см. D4–D5).

### D2. Стратегия жестов SVAR: стор-ориентированная сверка

Данные передаются в `Gantt` один раз; источник отображения — стор SVAR; после `mouseup`/`touchend` план сверяется со стором (серия 80/450/1000 мс), к факту применяются правила ядра (A2 — drag с привязкой начала к рабочему дню в сторону переноса; A3/A4 — ручной ввод границ), исправленные даты пишутся `api.exec('update-task')`. Режим жеста определяется дельтами дат (оба края — drag, один край — ручной ввод). Альтернатива «блокировать (`return false`) и применять самому» — резервный вариант, если сверка даст сбои на продуктовых сценариях (нестабильные тайминги стора). Контролируемые props не смешивать с жестами.

### D3. Ресурсное представление: React Calendar Timeline 0.30.0-beta.19 (MIT, точный пин версии)

Альтернативы: стабильная ветка 0.28.0 (нет TS/React 18 линии — не подходит стеку); собственный рендер дорожек (укладка + виртуализация + лента занятости — всё уже решено RCT; оценка дороже и без выигрыша в первой версии). Принимается бета с мерами: точный пин `0.30.0-beta.19` в `package.json`; API жестов изолируется в единственном модуле адаптера; план Б при поломке беты — собственный рендер, оформляется новой PBT-задачей до PBT-047. Жесты в ресурсном виде вторичны (примечание владельца в PBT-015: основное редактирование — проектный Гантт, вид — анализ загрузки).

### D4. Независимость ядра от внутренних моделей библиотек

Источник истины — документ плана нашего ядра (PBT-030+): календарные даты с включительным окончанием (A1), рабочая длительность, сводные полосы (B2 — min/max вложенных), FS-проверки (C1–C5), конфликты ресурсов и отпусков (D1–D7), рабочий календарь (арифметика PBT-013). Библиотеки — только отображение и первичный ввод жестов. Адаптеры: `plan ↔ SVAR ITask/ILink` и `plan ↔ RCT groups/items`; конвертация включительного окончания (+1/−1 день) локализована в адаптерах. Колонку «Длительность» SVAR заменить своей (рабочие дни); `getTask` нормализовать при чтении.

### D5. Судьба исследовательских стендов

- `apps/gantt-spike`, `apps/resource-timeline-spike` — удалить после merge PBT-017 отдельным хаускипинг-PR (решение принято, стенды своё отработали; отчёты PBT-014/015 и git-история сохраняют схемы адаптеров; держать мёртвый код до PBT-037 — риск рассинхронизации).
- `apps/load-demo` — сохранить до PBT-058 (итоговая проверка производительности по утверждённым порогам), удалить в релизной зачистке.

### D6. Пороги производительности PBT-058

Принять кандидатов из отчёта PBT-016 (окружение: активная вкладка Chromium, macOS): монтирование 10 виджетов на плане-500 ≤ 1000 мс; переключение набора 10 панелей ≤ 500 мс; добавление задачи (план-500) ≤ 400 мс; запись плана-500 в IndexedDB ≤ 700 мс; прокрутка таймлайна ≥ 30 FPS (ручная проверка на видимой вкладке).

### D7. Матрица обязательных сценариев этапа 2

| Сценарий (решения §21) | Подтверждение |
| --- | --- |
| Группа задач и сводная полоса | PBT-014: иерархия, сводная рисуется, сворачивание; расчёт сводных — наше ядро (B2) |
| FS-зависимость с лагом | PBT-014: `e2s`, отрисовка; лаг и проверки — ядро (C1–C5) |
| Выходной, праздник, рабочая длительность | PBT-014: `highlightTime`, арифметика PBT-013, E1–E8 |
| Ресурсная дорожка с пересечениями и отпуском | PBT-015: `stackItems`, отпуск-элемент, лента занятости, E7 |
| Ручное изменение без переноса других | PBT-014/015: зависимые неподвижны (E2), изоляция элементов |
| Два согласованных представления одного документа | PBT-016 сценарий A: SVAR+RCT на одном плане-500 одновременно |
| Размещение в окне с изменяемыми размерами | PBT-014 (resize контейнера), PBT-015 (974→1374) |

Блокеров нет; риски беты RCT и перехватчиков SVAR зафиксированы с мерами (D2, D3).

## Risks / Trade-offs

- **SVAR-перехватчики нестабильны как канал** (перестают ловить после пересоздания bus): сверка по стору после mouseup не зависит от перехватчиков; перехватчики используются только для служебных запретов (drag сводной) с защитой от дублей и переустановкой при `init`.
- **Бета RCT может сломаться при обновлении**: пин версии; обновления — осознанная отдельная операция; план Б зафиксирован (D3).
- **Стор SVAR и props React конфликтуют**: данные в компонент — один раз при монтировании и после зафиксированных операций; никаких обновлений props в окне жеста.
- **Пороги сняты на одной машине с троттлинг-накладной**: значения заданы с запасом; PBT-058 перепроверяет на продуктовых сборках.

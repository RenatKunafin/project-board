## Why

PWA уже проверена локально, но у приложения нет постоянного опубликованного адреса. Владелец выбрал GitHub Pages и выпуск после merge в main и публикации GitHub Release; репозиторий он переводит в публичный самостоятельно.

## What Changes

- Публикация на `https://renatkunafin.github.io/project-board/` через GitHub Actions по событию `release: published`.
- Сборка именно коммита тега опубликованного релиза; проверка его принадлежности истории main и успешные проверки перед deployment.
- Поддержка пути `/project-board/` для HTML/JS/CSS/шрифтов/иконок, manifest и Service Worker, проверенная на production-артефакте.
- Установка, сохранение, reload, холодный offline-запуск и управляемое обновление между двумя опубликованными версиями.
- Инструкция включения Pages, выпуска/повторного запуска и совместимого возврата через новый Release.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `pwa-lifecycle`: постоянный HTTPS-адрес приложения, согласованность путей и управляемый переход опубликованных версий.

## Impact

Workflow публикации/CI, параметры сборки apps/project-board, документация и проверки размещения в подпути. Публичный SDK, IndexedDB и формат документов не меняются. Публикуется только apps/project-board/dist.

## Non-Goals

Backend, передача пользовательских документов на сервер, перенос данных между origin, резервное копирование, смена видимости репозитория агентом, автоматический выпуск от push/merge/tag без опубликованного Release, новый GitHub Release без отдельного поручения владельца.

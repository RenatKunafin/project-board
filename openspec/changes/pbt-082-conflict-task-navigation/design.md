# PBT-082 — Переход от конфликта к задаче

## Context

База — свежий develop bcab82d, задача перед PBT-060 по поручению владельца. Артефакты подготовлены до реализации; дизайн одобрен владельцем 2026-10-24 («Делаем»).

PlanIssuesDialog показывает текст в span и отдельную кнопку «Показать», вызывающую onShowTask без onClose. showTask в PlanGanttWidget раскрывает предков, сбрасывает фильтры и сразу вызывает scroll-chart/select-task. Снятие фильтров обновляет source через React, поэтому немедленная команда может обращаться к прежнему набору строк. В PBT-073 есть ограниченное восстановление прокрутки после resize/zoom; его нужно согласовать с явным переходом пользователя.

## Decisions

### D1. Действие по всей записи

Запись с taskId содержит одну нативную кнопку на всю ширину: текст конфликта и визуальное действие «Показать». Клик по тексту и по действию ведёт к той же задаче; Enter/Space выполняют то же действие. Список сохраняет семантику ul/li, вложенных кнопок нет. Записи без цели остаются обычным текстом. Для пары работ сохраняется существующий выбор первой задачи.

### D2. Порядок перехода

Проверить цель в актуальном документе; закрыть модалку, снять фильтры текущего экземпляра и раскрыть цепочку предков. После применения нового набора строк прокрутить таблицу и шкалу к цели, выделить задачу и вернуть фокус в диаграмму. Не открывать форму редактирования. Не создавать ревизию документа; изменения фильтров/групп остаются настройками экземпляра, как прежде.

### D3. Согласованность с жизненным циклом

Ожидающий переход относится к текущему экземпляру, документу и taskId. Не использовать прежний API после пересборки; при смене документа/закрытии отменять переход. Согласовать явную навигацию с таймерами восстановления прокрутки, чтобы они не возвращали старую позицию. Использовать актуальную геометрию дней/недель и штатный API SVAR; проверять фактическую видимость строки и полосы после стабилизации, а не только вызов exec. Без произвольной длительной паузы и постоянного поллинга.

### D4. Проверки

Browser: клик по тексту и Enter/Space; модалка исчезла; далёкая по дате и строке задача видна и выделена; свёрнутые вложенные группы раскрыты; скрывающие фильтры сняты; переход работает в Днях/Неделях и не откатывает прокрутку после окна восстановления. Ревизия и сроки документа не меняются; настройки/прокрутка второго экземпляра сохраняются. Существующий тест conflicts проверяет уже видимую строку и не доказывает горизонтальную прокрутку — усилить его реальным положением полосы.

Перед PR — lint/typecheck/unit/build/browser/OpenSpec и живая проверка с консолью. До автоматических browser-проверок остановить dev/preview/MCP; после вернуть dev на 5173.

## Risks

SVAR виртуализирует строки и шкалу; задача может отсутствовать в DOM до снятия фильтра/раскрытия группы. Отдельно проверить навигацию после resize и zoom: прежнее восстановление прокрутки не должно отменять новый выбор пользователя. Если задача удалена до перехода, не изменять документ и не обращаться к устаревшему API.

## Уточнения реализации

В установленном SVAR 2.8.0 select-task поддерживает show/focus и прокручивает таблицу; для горизонтальной позиции используется фактическая координата $x задачи в текущем масштабе с отступом24px и существующий applyChartScrollLeft. Это показывает начало длинной полосы, а не только её центр. Два requestAnimationFrame после обновления props дают примениться дереву/фильтрам и заливке стора; callbacks отменяются cleanup при смене цели/документа/видимости/размонтировании. Предыдущие повторы восстановления scroll отменяются, pendingRestore сбрасывается.

При собственной ревизии жеста source прежде удерживался независимо от смены фильтров/групп. Удержание теперь допускается только при прежних ссылках viewFilter/collapsed: явное изменение представления обновляет props, а обычная собственная запись по-прежнему не пересобирает данные. Отдельный e2e проверяет переход после собственной записи drag.

Прежний conflicts.spec.ts проверял t-d, которая была видима до перехода, хотя целью пары является t-c в свёрнутой группе. Проверка исправлена на t-c и закрытие модалки. Первые четыре запуска нового e2e остановились на ошибке фикстуры: фоновые задачи без типа считались непараллельными и создавали1770 лишних конфликтов. Фоновым задачам задан разрешающий параллельность тип; продуктовые правила не менялись.

Живой скриншот выявил дополнительную причину недоступности строки: style.css Гантта задаёт виртуальной .wx-body top через --wx-body-offset, но не включает базовый position:relative из react-grid/style.css. В production CSS этого правила нет: top:-52px игнорируется, подпись цели находится на y1059–1095 при нижней границе окна1043, хотя полоса видна. Узкое правило `.plan-gantt .wx-table .wx-body { position:relative }` включает штатное смещение виртуальных строк без импорта всей темы grid и без изменения библиотек. Попытка доводить scrollTop внешнего .wx-gantt отвергнута: штатный API его ограничивает, это не устраняет игнорируемый CSS-offset; дополнительный DOM-scroll и четыре rAF удалены.

E2e усилены проверкой подписи задачи в viewport браузера и вертикальных границ фактической .wx-table-container. Полная .wx-grid имеет виртуальную высоту и не подходит как видимая граница. Подпись, а не вся строка всех колонок, проверяется целиком: в узком окне остальные колонки могут штатно уходить в горизонтальный скролл.

Локальная совместимость CSS также восстанавливает position:sticky/top/z-index и непрозрачный токеновый фон .wx-header-wrapper: виртуальные строки с отрицательным offset должны уходить под шапку, сохраняя её доступность для клика. E2e проверяет elementFromPoint в шапке после перехода, чтобы строки не перекрывали заголовки.

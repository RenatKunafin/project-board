# Design — PBT-027: жизненный цикл скрытых виджетов

## Context

`App` рендерит панели только активной вкладки: переключение размонтирует скрытые — локальное состояние (`draft`, `editingId` чек-листа) теряется, вопреки ADR-7 PBT-002 («экземпляр остаётся жив»). Свёрнутое окно не размонтируется (PBT-020), но видимость в модули не передаётся (ADR-6.5 SDK v0 не реализован). Ошибка в содержимом окна поднимается до корня — нет границы. Подписки виджетов чистятся в unmount-эффектах, но количественной проверки «не умножаются» нет.

## Goals / Non-Goals

**Goals:** keep-mounted скрытые вкладки с memo-границей перерисовок; `visible` и `onResize` в SDK-пропсах; локальный boundary ошибки в рамке; счётчик активных подписок для DoD-проверки «×20».

**Non-Goals:** виртуализация списков, персистентность черновиков в БД, viewSettings для scroll/размеров, профилирование PBT-058.

## Decisions

### D1. Скрытые вкладки — смонтированы, но невидимы

`App` рендерит поверхности всех вкладок; неактивные — в контейнере с атрибутом `hidden` (выводит из tab-порядка и a11y-дерева, события ввода не доставляются). Поверхность вкладки выносится в `TabSurface` — `React.memo` по данным этой вкладки (панели, области, режим, состав окон): взаимодействия на активной вкладке меняют только её срез состояния → скрытые пропускают рендер (измеримо счётчиком в unit-тесте). Изменения их собственных документов по-прежнему доставляются подписками виджетов → возврат показывает актуальное (spec). `visible` окон скрытой вкладки = `false`.

### D2. SDK: `visible` — пропс, размеры — колбэк с троттлингом

`WidgetProps` += обязательный `visible: boolean` и опциональный `onResize?: (size: WidgetSize) => void` (`{width, height}`). Видимость меняется редко (вкладка/сворачивание) — пропс уместен; размеры меняются непрерывно при drag — колбэк из `ResizeObserver` рамки с `requestAnimationFrame`-троттлингом (одно значение на кадр, spec «без серии промежуточных»). Нулевые размеры (скрытое окно) не доставляются. Контракт виджета: при `visible: false` — не запускать таймеры/тяжёлые пересчёты; подписки на документ сохранять. Альтернатива «размеры пропсом» отклонена: ре-рендер виджета на каждый кадр drag угрожает порогам PBT-058.

### D3. Boundary ошибки в рамке окна

`WidgetWindow` оборачивает содержимое в локальный класс-границу (getDerivedStateFromError + сброс по «Повторить» с перемонтированием): падение содержимого показывает состояние ошибки на токенах с кнопками «Повторить» и штатным закрытием рамки; соседние окна и вкладки не затронуты. Ошибка логируется в консоль (диагностика). Проверка — unit на тестовом падающем компоненте (прод-комплектация без виджетов-ломателей; e2e не требуется — DoD говорит «демонстрационный компонент», им служит тестовый).

### D4. Подписки: счётчик сервиса + e2e-цикл ×20

`AutosavingDocumentService.activeSubscriptionCount(): number` — сумма обработчиков по документам (диагностика, дешёвая). Для DoD-проверки сервис экспонируется тестам: `main.tsx` устанавливает `window.__projectBoard = { activeSubscriptionCount: () => n }` (локальный инструмент, назначение — e2e; задокументировано). E2E: цикл ×20 «добавить окно с документом → свернуть/развернуть → закрыть» — счётчик до и после цикла равен базовому; попутно черновик переживает переключение вкладок.

### D5. Checklist: уважение видимости

`ChecklistWidget` сохраняет подписку всегда (актуальность при возврате), но тяжёлые пересчёты (`visibleItems` — useMemo) и таймеры не выполняет при `visible: false`: ранний стабилизированный возврат последнего результата `useMemo` (зависимость от `visible` в массиве пересчёта). Паттерн для будущих модулей — в PBT-060 (руководство разработчика виджета).

## Risks / Trade-offs

- **Все вкладки в дереве React**: объём смонтированных компонентов растёт (вкладки × окна ≤ лимитов §20 — 10 виджетов/вкладка); memo-граница удерживает перерисовки скрытых; при превышении порогов — пересмотреть (отложено к PBT-058).
- **`visible` обязателен в пропсах**: существующие виджеты и тесты правятся (checklist, demo) — в том же PR.
- **ResizeObserver в каждом окне**: наблюдателей немного (10), отсоединение — в cleanup; утечки проверяются циклом ×20.
- **`window.__projectBoard`**: диагностическая глобальная переменная в прод-сборке; поверхность — только чтение счётчика, риск принят для проверяемости DoD.

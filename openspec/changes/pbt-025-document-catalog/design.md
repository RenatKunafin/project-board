# Design — PBT-025: каталог документов и повторное открытие

## Context

Оболочка документа (`ManagedDocument`) не содержит названия: ADR-5 PBT-002 предусматривал `title` в списке полей записи, но реализация PBT-007 завела документ без него, а название «ушло» в содержимое модулей (`content.title` у чек-листа и плана). Выбор документа и подписи окон в `App.tsx` ветвятся по `moduleId` (`checklistTitle`/`planTitle`) — каталог зависит от конкретных модулей, что DoD запрещает. Операций `rename` и `delete` у сервиса нет; у хранилища `IndexedDbDocumentStore.delete` уже есть и покрыт spec `local-persistence` («удаление отсутствующего документа не ошибка»). Решения владельца (2026-10-13): название — в метаданных; оба каталога и пикер выбора документа переводятся на dropdown-панели по макету 04.

## Goals / Non-Goals

**Goals:** название как метаданные + `rename`; каталог документов (список/фильтр/создание/переименование/удаление/открытие); `delete` сервиса с согласованным поведением открытых окон; dropdown-панели каталогов; раздельные состояния каталога (пусто / нет по фильтру / ошибка загрузки); ленивое дополнение названия старым записям.

**Non-Goals:** полные миграции и версии документов (PBT-026), жизненный цикл скрытых окон (PBT-027), темы/токены (PBT-066), межоконные конфликты, поиск по содержимому.

## Decisions

### D1. Название — обязательное поле метаданных (исправление дрейфа ADR-5)

`ManagedDocument` + `readonly title: string`; `DocumentCreateInput` + `title` (непустая строка после trim, иначе ошибка). Новая операция `rename(documentId, expectedRevision, title)`: проверка редакции как у `update`, новая редакция и `updatedAt`, `content` не изменяется, отложенная запись и уведомления подписчиков — как у обычной операции. Конфликт редакции при переименовании — `DocumentConflictError`.

Альтернатива «хелперы `getTitle`/`renameTitle` в SDK» отклонена владельцем: это расширение SDK-контракта, которое ADR-6 PBT-002 разрешает только «новыми решениями», и дальнейший уход от ADR-5. Правило «название живёт только в оболочке»: фабрики `createContent()` теряют параметр названия (правка `WidgetDocumentSupport`, MODIFIED spec `widget-registry`), `content.title` у новых документов не записывается; хранящиеся в старых записях значения не интерпретируются платформой. Функции `checklistTitle`/`planTitle` остаются в модулях для D2, из каталога и подписей убираются.

### D2. Ленивое дополнение названия старым записям — на границе приложения

Сервис не знает модулей (ADR-3, содержимое непрозрачно), поэтому починка хранимых записей без `title` выполняется в `main.tsx` после `restoreAll`: приложение (composition root, знает комплектацию) вычисляет название зарегистрированными функциями модулей (`checklistTitle`/`planTitle`, fallback «Без названия») и вызывает `rename(doc.id, doc.revision, title)`. Запись уходит в хранилище штатным автосохранением; для уже починенных записей операция не повторяется. Одноразовая массовая запись ограничена числом старых документов (сейчас — единицы). Полная миграция с версиями — PBT-026.

### D3. Удаление: синхронно в памяти, сразу в хранилище

`DocumentService.delete(documentId)`: снятие отложенной записи (очистка таймера и очереди документа — иначе `pagehide` воскресит документ), удаление из памяти, `store.delete` (контракт `DocumentStoreLike` дополняется `delete`; адаптер уже реализует), очистка состояния сохранения и обработчиков. Уведомления подписчикам об удалении не доставляются (контракта нет): окна узнают через слой приложения (D6). Двухоконные гонки удаления — non-goal, как в PBT-024.

### D4. Dropdown-панели каталогов (попутное расширение — решение владельца)

Обе панели — dropdown от кнопок в шапке, позиционируется под кнопкой, закрытие по клику вне и Escape, стили на текущих токенах (макет 04):

- **Каталог виджетов** (перевод модала PBT-019): список типов — иконка, название, поиск по подстроке названия; поведение выбора без изменений (документный тип → пикер документа).
- **Пикер документа** (замена модала «выбор документа»): список документов модуля/типа с названиями из метаданных, форма создания нового.
- **Каталог документов** (новый, кнопка «Документы»): список всех документов по метаданным, фильтр-чипы по зарегистрированным типам документов (уникальные `moduleId`+`documentType` из дескрипторов реестра), действия по документу: открыть, переименовать (инлайн), удалить (подтверждение отдельным диалогом), форма создания выбранного типа.

Согласованность паттернов важнее минимального объёма — решение владельца от 2026-10-13; расширение границ карточки зафиксировано здесь и в PR.

### D5. Открытие из каталога и состояния каталога

Подбор типа для документа: зарегистрированные типы с дескриптором, равным по `moduleId`+`documentType`; один — открыть сразу, несколько — выбор в панели (сейчас 1:1; задел под PBT-037). Состояния каталога раздельные: «нет документов» (подсказка создать), «нет документов выбранного типа» (текст при непустом полном списке), «ошибка загрузки» — `main.tsx` оборачивает `restoreAll` в try/catch и передаёт флаг в `App`; каталог показывает плашку ошибки вместо «пусто» (DoD). Рабочее пространство при ошибке документов восстанавливается независимо; окна с несуществующими документами показывают состояние D6.

### D6. Недоступный документ и замена

`WidgetPane` уже показывает «Документ недоступен» (PBT-024) — расширяется до состояния с действием «Выбрать документ…» (пикер D4, отфильтрованный по `moduleId`+`documentType` удалённого документа; пусто → предложение создать). Выбор обновляет `pane.documentId` (новая операция `App` — перепривязка, без пересоздания окна и раскладки). Реактивность: delete не рассылает уведомлений, поэтому `App` держит счётчик версий документов, инкрементируемый после `delete`/перепривязки, — перерендер панелей перечитывает `documentService.get`. Подписи окон — из `document.title` при рендере (`documentService.get(documentId)?.title`), хранимый `label` записи остаётся fallback для окна без документа; снимает trade-off устаревания подписи (design PBT-024 D2).

## Risks / Trade-offs

- **Разовая запись при первом старте после обновления** (D2): объём — по одному сохранению на старую запись; после закрепления `title` не повторяется.
- **`title` обязателен в контракте**: фабрики и тесты модулей правятся; старые записи в памяти до починки показываются каталогом как «Без названия» (короткое окно внутри bootstrap — пользователь его не видит).
- **Уведомлений об удалении нет**: виджеты, кэширующие документ, обновятся при следующем рендере; для первой версии достаточно (содержимое недоступно сразу — `get` возвращает `undefined`).
- **Dropdown поверх раскладки**: панели рендерятся в шапке вне области раскладки; риск перехвата событий react-grid-layout низкий, проверяется e2e и MCP-консолью.
- **Три панели на одном компоненте-списке**: риск перегрузить компонент флагами режимов; держим поведение режимов в пропсах-колбэках, без ветвлений по «типу страницы».

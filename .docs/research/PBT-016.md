# PBT-016 — Замеры 500 задач и 10 виджетов (нагрузочный прототип)

- **Дата:** 2026-10-10
- **Тип:** Исследование
- **Change:** `pbt-016-prototype-performance` (skip_specs — новых продуктовых требований нет)
- **Ветвь:** `feature/pbt-016-prototype-performance` → PR в `develop`

## Вопросы

1. Какова стоимость сборки из готовых прототипов при целевой нагрузке (сценарии A/B PBT-012): монтирование 10 виджетов, редактирование, прокрутка?
2. Какова стоимость записи документа (IndexedDB) — имитация автосохранения ядра?
3. Восстанавливаются ли панели и данные после нагрузки (перезагрузка)?
4. Какие пороги предложить владельцу для итоговой проверки PBT-058?

## Окружение и воспроизведение

- Node v22.12.0, npm 11.2.0; Chromium (Playwright MCP и `bench/run-bench.mjs`); macOS arm64; окно 1400×1000.
- Стенд: `apps/load-demo` (`npm run dev:load-demo` → `http://localhost:5176`), сценарии A/B по PBT-012; данные — golden `plan-500.json` и генератор (seeds 42–51).
- Автоматический прогон: `node apps/load-demo/bench/run-bench.mjs` → `apps/load-demo/bench/results.json`.
- Проверки: `npm run lint`, `npm run typecheck` (8 проектов), `npm test` — зелёные.

**Ограничение среды:** замер выполнялся в MCP-управляемом окне браузера, где rAF троттлится (кадр ~205 мс — калибровка ниже). FPS-метрики через rAF в этом окружении **недостоверны**; численные значения редактирования/записи (performance.now, IndexedDB) достоверны, но получены с троттлинг-накладной — считать верхней оценкой. Ручная проверка плавности на видимой вкладке обязательна (см. «Пороги»).

## Результаты замеров

### Калибровка rAF (среда)

| Метрика | Значение |
| --- | --- |
| Средний кадр | 204.7 мс (~5 FPS) |
| Максимальный кадр | 292 мс |

### Сценарий A — план-500, 10 виджетов

| Операция | Результат |
| --- | --- |
| Монтирование 10 панелей | **145 мс** параллельно (все панели ≤145 мс) |
| Добавление задачи (SVAR, exec + 2 кадра) | медиана **300 мс**, разброс 235–464 (включая троттлинг-накладную ~400 мс на 2 кадра — верхняя оценка) |
| Переключение на сценарий B (10 панелей × 50 задач) | **118 мс** |

### Запись в IndexedDB (полный цикл open+put+complete)

| Документ | Прогоны | Медиана |
| --- | --- | --- |
| план-500 (98 КБ) | 469 / 469 / 470 мс | **469 мс** |
| план-50 (10 КБ) ×10 подряд | 1.3–3.5 с | растёт из-за очереди серии (см. риски) |

### Восстановление

| Проверка | Результат |
| --- | --- |
| Перезагрузка после нагрузки | 10/10 панелей отрисовались; видимых элементов дорожек 44 до/44 после (виртуализация RCT), план-500 на месте |
| Закрытие/открытие панелей | монтирование панелей повторно 118–145 мс |

## Узкие места и наблюдения

1. **Прокрутка/FPS в среде замера недостоверны** (троттлинг rAF фонового окна: средний кадр 205 мс). Единичный авто-прогон дал avgFps 7–10 — не интерпретировать как производительность; ручная проверка на видимой вкладке показала плавный скролл гантт-панелей.
2. **Записи IDB в очереди накапливают задержку** (серия мгновенных saveAll: 1.3→3.5 с) — транзакции сериализуются. Для ядра (PBT-010: debounce-очередь) это аргумент сохранять после завершения операций, не чаще.
3. **Полный цикл записи включает открытие БД** (~0.5 с при паузах). В ядре Dexie-соединение постоянное — фактическая стоимость записи ниже; замер — верхняя оценка.
4. SVAR и RCT в одном бандле конфликтов не показали; 10 инстансов план-500 памяти не исчерпали (страница стабильна).
5. Drag на плане-500 не автоматизирован (плотные полосы) — задержка редактирования измерена операцией «добавление задачи»; в спайках PBT-014/015 применение правил на планах до 500 задач происходило в пределах кадра.

## Предложенные пороги для PBT-058 (кандидаты — на согласование)

Окружение: активная вкладка Chromium, macOS. Замеры получены с троттлинг-накладной, поэтому пороги заданы с запасом; фактические значения ниже.

| Метрика | Порог-предложение | Факт (верхняя оценка) |
| --- | --- | --- |
| Монтирование 10 виджетов (план-500) | ≤ 1000 мс | 145 мс |
| Переключение набора из 10 панелей | ≤ 500 мс | 118 мс |
| Добавление задачи (план-500) | ≤ 400 мс | 300 мс (медиана, с накладной) |
| Запись плана-500 в IndexedDB | ≤ 700 мс | 469 мс |
| Прокрутка таймлайна | ≥ 30 FPS (видимая вкладка, ручная проверка) | в среде замера недостоверно |

## Вывод

**Прототипы выдерживают целевую нагрузку** (сценарии A/B) на зафиксированном окружении: монтирование 10 виджетов ~145 мс, редактирование ≤300 мс (верхняя оценка), запись плана-500 ~470 мс, восстановление полное. Узкие места — не производительность компонентов, а среда замера (rAF-троттлинг MCP-окна) и сериализация IDB-очереди. Пороги-кандидаты выше — на утверждение владельцем для PBT-058; массовая оптимизация не потребовалась.

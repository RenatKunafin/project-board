# PBT-014 — Проверка компонента проектного Гантта (спайк SVAR)

- **Дата:** 2026-10-09
- **Тип:** Исследование
- **Change:** `pbt-014-project-gantt-spike` (skip_specs — продуктового поведения нет)
- **Ветвь:** `feature/pbt-014-project-gantt-spike`

## Вопросы

1. Даёт ли открытая редакция SVAR React Gantt полный контроль над датами: ручное редактирование без автопереноса зависимых и без скрытых пересчётов?
2. Как реализуются согласованные правила ADR PBT-003: включительное окончание (A1), рабочая длительность (A4–A6), праздник внутри задачи (A5), drag с сохранением рабочей длительности (A2)?
3. Что доступно из коробки: дерево со сводными, FS-связи, подсветка нерабочих дней, форма редактирования, resize контейнера?
4. Каковы ограничения и риски для решения PBT-017?

## Наблюдения

### 1. Даты и семантика (ключевое)

- **Внутренняя семантика SVAR всегда исключительная.** `inclusiveEnd: true` меняет только отображение и ввод (совпадает с документацией из решений, раздел 8.3). Адаптер обязан передавать `end + 1 день`; входящие из компонента даты окончания уменьшать на день.
- Проверка включительного окончания по четырём поверхностям для A (12–16 вкл, праздник 14.10): таблица — Start 12-10-2026, Duration 5; полоса — покрывает день 16 (ширина 5 ячеек, `cellWidth=100`, `$w=500`); форма (`Editor`) — end `16-10-2026`, Duration 5; события — `update-task` несёт исключительное окончание (17.10). До исправления адаптера (передавали включительный end) полоса была короче на день, Duration=4.
- **`duration` SVAR — календарные дни (`end − start`).** Рабочая длительность считается только своим кодом: в спайке — арифметика PBT-013 (A: 4 раб. дня при 5 календарных — E1 ✓; C: 5 — E3; D: 2 — E4).
- **`calendar` и `schedule` — PRO Edition only.** В открытой редакции нет ни рабочих календарей, ни автопланирования — это соответствует нашему ручному режиму (раздел 7 решений): даты не пересчитываются скрыто, зависимые не двигаются.
- `highlightTime(date, unit) => cssClass` — открытая функция, работает: выходные 11/17.10 и праздник 14.10 подсвечены.

### 2. Drag/resize и зависимые задачи

- Drag полосы A на 2 дня: SVAR предложил 14–18; перехватчик по A2 привязал начало к рабочему дню (14.10 — праздник → 15.10) и сохранил рабочую длительность 4 (15,16,19,20 → окончание 20.10). Даты B (19–20.10) не изменились ни в одном прогоне — подтверждено и по таблице спайка, и по `api.getTask('t-b')`. Автопереноса нет (E2 ✓).
- Resize за правый край: SVAR эмитит `update-task` только с изменённым окончанием — отличимо от drag (пришло начало).
- **Главный риск: канал `update-task` ненадёжен как источник данных.** В части прогонов payload содержал старые даты, тогда как стор уже применил жест (проверено `getTask`), в других — новые. Причины видны в минифицированном коде: эмиты зависят от порядка событий мыши.

**Уточнение по результатам ревью владельца (2026-10-09, вторая итерация спайка).** Симптомы «полоска не переносится / схлопывается до одного дня» воспроизведены и объяснены; БД тут ни при чём (в спайке IndexedDB не участвует):

1. **init-перехватчики `api.intercept()` перестают ловить мышиные жесты** после пересоздания внутреннего bus SVAR (программный `api.exec()` при этом перехватывается). Поэтому перехват как канал ненадёжен в принципе.
2. **Два источника истины (props React и стор SVAR) конфликтуют**: стор применяет жест с нестабильной задержкой; если props обновляются в этом окне, DOM показывает одно, стор — другое; следующий жест интерпретируется по стору при визуально другой полосе («попал не туда»), а рассинхронизированный payload с окончанием раньше начала даёт схлопывание задачи до одного дня.
3. **Решение в спайке**: данные передаются в `Gantt` один раз; источник отображения — стор; после `mouseup`/`touchend` в чарте план сверяется со стором три раза (80/450/1000 мс), к факту применяются правила ADR PBT-003 (A2 с привязкой начала к рабочему дню **в сторону переноса**, A3/A4 без правки введённого окончания), и исправленные даты записываются обратно `api.exec('update-task')`. Серия из 7 жестов (drag вперёд/назад, resize за оба края, сжатие) дала полное согласование плана и стора на каждом шаге, зависимые задачи неподвижны.
4. Следствие для PBT-017: в продуктовом адаптере не смешивать контролируемые props с жестами; либо полностью стор-ориентированная модель с нормализацией по правилам (как в спайке), либо блокировка действий (`return false`) с собственным применением — решение за PBT-017.
- `schedule-tasks` не эмитился ни разу (ожидаемо — PRO).

### 3. Дерево, сводные, прочее

- Иерархия через `parent`, тип `summary`: сводная полоса «Фаза 1» (12–28.10, Duration 17) рисуется автоматически; сворачивание/разворачивание группы — 6 полос → 1 → 6.
- **Несогласованность сводных при перехвате**: после подмены дат в `update-task` пересчитанная SVAR сводная не всегда равна min/max вложенных (наблюдался старт 17.10 при ожидаемом 15.10). Для продукта: сводные считаем своим ядром (правила B2, ADR PBT-003), а не библиотекой.
- **Запрет drag сводной (B2)**: в открытой редакции сводная получает режим "move" — запрет потребует перехвата (`drag-task` → `return false` для summary).
- FS-связь A→B (lag 0) отрисовывается от края полосы; редактор формы подключается компонентом `<Editor api={api}/>`; контейнер: SVAR растягивается по высоте контейнера при `height: 100%` у обёрток (в спайке — CSS-правило для `.wx-theme`).
- Мелочи: колонка Duration в таблице SVAR показывает календарную длительность — в продукте заменить своей (рабочей); `getTask` возвращает для пересчитанных сводных включительную полночь, а для обычных задач — переданное исключительное значение (несимметрия — нормализовать при чтении); спам предупреждений `Writable _progressLinePoints is not defined` из `lib-state` без функциональных последствий; React StrictMode дважды вызывает `init` — перехватчики вешать с защитой от дублей.

## Использованные API

`Gantt` (props: `tasks`, `links`, `inclusiveEnd`, `init`, `highlightTime`), `Willow` (тема), `Editor`, `api.intercept(action, handler)`, `api.getTask(id)`, `api.getState()`, `api.exec('show-editor')`, действия `update-task` / `drag-task` / `add-link` / `select-task` / `schedule-tasks`; стили `@svar-ui/react-gantt/style.css`.

**Лицензия:** MIT (пакет и зависимости @svar-ui/* — MIT). Платные возможности (рабочие календари, автопланирование, ресурсная нагрузка) не использовались и не считались доступными.

## Вывод

**Подходит с ограничениями** — как кандидат проектного представления для решения PBT-017.

- Подтверждено: ручной режим без автопереноса, включительное окончание через адаптер (+1 день) по всем поверхностям, дерево со сводными и сворачиванием, FS, подсветка нерабочих дней, форма, resize контейнера, MIT.
- Ограничения/риски: ненадёжный payload `update-task` при мышиных жестах (требуется выбранная стратегия перехвата — см. выше); сводные и рабочая длительность — только своим кодом (у нас уже есть арифметика PBT-013); несимметрия `getTask` для сводных; запрет drag сводной — дополнительным перехватом.
- Отказ от кандидата не требуется; сравнение с React Calendar Timeline (ресурсные дорожки) — задача PBT-015, сводное решение — PBT-017.

# ADR PBT-003 — Семантика редактирования плана

- **Дата:** 2026-10-07
- **Статус:** Принято (ревью владельца 2026-10-07; все 24 развилки блоков A–D change `pbt-003-planning-semantics`)
- **Затрагивает:** PBT-013 (арифметика дней), PBT-030–PBT-036 (ядро планирования), PBT-052–PBT-054 (импорт `.gantt`)
- **Связанные решения:** [ADR PBT-002](PBT-002.md) (стек и границы), `.context/project-decisions.md` разделы 7–12

## Контекст

Планирование ведётся по дням, вручную, без автопереноса задач; нарушения подсвечиваются (раздел 7 решений). Прототипы Гантта и ядро требуют однозначных правил редактирования. Каждое правило ниже сформулировано так, чтобы проверяться одним автотестом. Базовая неделя: пн–пт рабочие, сб–вс нерабочие (настраивается).

## Правила: даты и длительность

| # | Правило | Пример (ожидаемый результат) |
| --- | --- | --- |
| A1 | Даты хранятся как календарные; окончание — **включительно**. Конвертация в исключительную семантику UI-библиотеки — в адаптере представления | Задача «пн 12.10 – пт 16.10» включает пт; длительность 5 рабочих дней |
| A2 | Перетаскивание задачи сохраняет **рабочую длительность**; окончание сдвигается по календарю; начало привязывается к ближайшему рабочему дню в сторону переноса | Задача пн 12.10 – пт 16.10 (5 р.д.) перетащена вперёд на неделю → пн 19.10 – пт 23.10, 5 р.д.; перетаскивание начала на вс 18.10 → фактическое начало пн 19.10 |
| A3 | Ручной ввод дат сохраняется как введён, даже в нерабочие дни; полоса проходит через выходные, они не добавляют рабочую длительность | Пользователь ввёл сб 17.10 – вс 18.10 → даты хранятся; рабочая длительность 0 |
| A4 | Длительность вводится в рабочих днях; окончание = отсчёт вперёд от начала по календарю; минимум 1 при создании | Задача с пн 12.10, длительность 7 → окончание вт 20.10 |
| A5 | Добавление праздника/выходного внутри задачи сохраняет границы и уменьшает рабочую длительность | Задача пн 12.10 – пт 16.10; ср 14.10 объявлен праздником → границы те же, длительность 4 |
| A6 | Задача без рабочих дней в интервале допустима; рабочая длительность 0; отдельного статуса нет | Задача сб 17.10 – вс 18.10 → 0 р.д.; пн–пт, у которого все дни стали праздниками → 0 р.д. |

## Правила: группы

| # | Правило | Пример / следствие |
| --- | --- | --- |
| B1 | Пустые группы разрешены; сводная полоса отсутствует | Создана группа «ОКАД» без задач → строка в дереве без полосы |
| B2 | Сводная полоса группы **не перетаскивается** — только вычисляемое отображение (min начала … max окончания вложенных) | Попытка drag полосы группы не сдвигает задачи; группировка пересчитывается при любом изменении вложенных |
| B3 | Задачи и подгруппы переносятся между группами (drag в дереве); сводная полоса пересчитывается | Задача перенесена из «iOS» в «Android» → полосы обеих групп пересчитаны |
| B4 | Состояние раскрытия групп хранится отдельно у каждого виджета | Сворачивание группы в проектном Гантте не влияет на другой виджет того же плана |

## Правила: зависимости (только FS, задача → задача)

| # | Правило | Пример (ожидаемый результат) |
| --- | --- | --- |
| C1 | Лаг 0: последователь может начаться в **ближайший рабочий день** после окончания предшественника | A пн 12.10 – пт 16.10; B с лагом 0 → B может начаться пн 19.10; начало в сб не требуется и не ожидается |
| C2 | Лаг — целое ≥ 0 рабочих дней; отрицательный ввод отклоняется валидацией | Ввод «−3» → ошибка валидации, зависимость не создаётся |
| C3 | Зависимости только между задачами; группы в графе зависимостей не участвуют | Связь «группа → задача» не моделируется; ограничение на группу выражается зависимостью от последней задачи группы |
| C4 | Циклы (включая A→A и косвенные A→B→A) отклоняются при создании/изменении зависимости с сообщением | Попытка C→A при A→B→C → операция отклонена |
| C5 | Нарушение FS (перекрытие или несоблюдение лага) — только подсветка; даты не изменяются | B поставлена раньше допустимого начала → индикатор нарушения у связи, даты сохранены |

## Правила: ресурсы, назначения, отпуска

| # | Правило | Пример / следствие |
| --- | --- | --- |
| D1 | Задача может иметь несколько назначений; работа отображается на дорожке каждого ресурса; конфликт проверяется по каждому | Задача назначена QA и QA2 → видна на обеих дорожках; пересечение двух непараллелизуемых работ у QA — конфликт, у QA2 — по её работам |
| D2 | Задачи без ресурса допустимы; в ресурсном представлении первой версии не отображаются | Задача без назначения видна в проектном Гантте, отсутствует в дорожках |
| D3 | Процент загрузки импорта (`unit`) сохраняется в данных, но **не влияет** на проверки первой версии | Назначение `unit: 50` ведёт себя как 100%: конфликты определяются только параллельностью типов работ (правило 11.3) |
| D4 | Задача без типа работы считается **непараллелизуемой** | Две одновременные задачи без типов у одного ресурса → конфликт |
| D5 | Переопределение параллельности у отдельной задачи не поддерживается; тип назначается только из справочника | У задачи нет флага «исключение»; поменять параллельность можно только сменой/правкой типа в справочнике |
| D6 | Пересечение работы с отпуском считается по рабочим дням; отпуск, целиком лежащий на нерабочих днях, конфликта не даёт | Работа пн–пт, отпуск сб–вс → конфликта нет; отпуск ср–чт той же недели → конфликт; правило действует и для параллелизуемых работ |
| D7 | Отпуск-«задачи» импорта `.gantt` преобразуются в периоды недоступности с явным выбором ресурса пользователем | Запись «Отпуск QA» без назначения при импорте помечается как требующая преобразования; детали UI — PBT-054 |

## Явно исключено из первой версии

Отрицательный лаг; зависимости на группы; условная дорожка «Без ресурса» в ресурсном виде; частичная занятость как фактор конфликтов; переопределение параллельности отдельной задачей; автоперенос задач при любом редактировании. Возврат к любому пункту — отдельная задача-решение.

## Сверка с согласованными принципами

- «Редактирование задачи не переносит другие задачи» (7): A2 двигает только перетаскиваемую задачу; B2 запрещает групповой drag; C5 не меняет даты. Противоречий нет.
- «Полоса может проходить через выходные» (8.2): A3 сохраняет введённые даты; A6 допускает нулевую длительность. Противоречий нет.
- Правило конфликтов «обе непараллелизуемые» (11.3): D3 не добавляет частичную занятость; D4 закрывает дыру «задача без типа»; D6 добавляет отпуска по рабочим дням. Противоречий нет.
- «Отпуск подсвечивается как конфликт всегда» (12): D6 уточняет меру пересечения (рабочие дни), не ослабляя правило. Противоречий нет.

## Последствия

- Каждая строка таблиц — кандидат автотеста в PBT-013 (календарная арифметика) и PBT-030–PBT-036 (ядро).
- Адаптер представления обязан конвертировать включительное окончание в семантику библиотеки (следствие A1; критично для SVAR).
- Импорт `.gantt` (PBT-052–PBT-054) сохраняет `unit` в данные и помечает отпуск-задачи для преобразования.
- `.context/project-decisions.md` обновлён: разделы 8, 9, 10, 11, 12 ссылаются на этот ADR; спорное помечено «исключено из первой версии».

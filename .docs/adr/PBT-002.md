# ADR PBT-002 — Технические границы платформы

- **Дата:** 2026-10-07
- **Статус:** Принято (ревью владельца 2026-10-07, развилки D1–D8 change `pbt-002-platform-boundaries`)
- **Затрагивает:** PBT-004 (каркас), PBT-005 (проверки), PBT-006–PBT-011 (платформа и первый сквозной сценарий)
- **Источник деталей:** `openspec/changes/archive/` после завершения change; решения уточняют [project-decisions.md](../../.context/project-decisions.md)

## Контекст

Каркас пакетов и первая продуктовая ветка требуют зафиксированного стека, менеджера пакетов, направлений зависимостей, схемы хранения и минимального SDK. До этого решения соответствующие позиции `.context/project-decisions.md` были кандидатами и предложениями. Модули подключаются при сборке, установка плагинов пользователем отменена; платформа должна быть независима от сущностей Гантта.

## Решения

### ADR-1. Стек: React + TypeScript + Vite

Утверждено как решение (ранее кандидат). Единый стек платформы и модулей, статическая сборка PWA, все отобранные кандидаты-библиотеки рассчитаны на React. Отклонено: SolidJS/Svelte/Vue — потребовали бы переотбора кандидатов Гантта и тайлинга без выигрыша по требованиям.

### ADR-2. Менеджер пакетов: npm workspaces

Выбрано владельцем. Основание: без сторонних инструментов; Node 22 уже зафиксирован. Отклонено: pnpm (рекомендация ревью) — сильнее изоляция и быстрее, но требует установки инструмента. Последствия: риск фантомных зависимостей компенсируется линтером границ (PBT-005) и ревью `package.json` пакетов; `packageManager` и `package-lock.json` фиксируют окружение.

### ADR-3. Структура пакетов и направления зависимостей

```text
apps/project-board → packages/{dashboard, widget-sdk, gantt, checklist}
packages/gantt, packages/checklist → packages/widget-sdk
packages/widget-sdk → (не зависит от других пакетов проекта)
```

Запреты, проверяемые линтером границ с PBT-005: `dashboard` не импортирует `gantt`/`checklist`; модули не импортируют внутренности `dashboard`; `widget-sdk` не зависит от UI-библиотек виджетов. Приложение `project-board` собирает комплектацию и регистрирует типы модулей в платформе.

### ADR-4. Целевые браузеры и платформы

Десктоп: две последние мажорные версии Chrome, Edge, Firefox, Safari. PWA-установка гарантируется на Chromium-десктопах; Safari/macOS — по возможностям платформы. Мобильные браузеры вне гарантий первой версии. Базовый язык: ES2022; `browserslist` закрепляется в каркасе PBT-004. Основное ручное тестирование — Chromium-десктопы; остальные — smoke при PBT-057.

### ADR-5. Схема хранения: IndexedDB через Dexie

Утверждено как стартовое для первой версии (ранее предложение): библиотека Dexie; хранилища `settings`, `tabs`, `widgetInstances`, `documents`; документ — одна запись с полями `id, moduleId, documentType, title, schemaVersion, revision, createdAt, updatedAt, content`; производные значения вычисляются, источник истины — исходные данные; запись после завершённой операции; проверка `revision` для обнаружения устаревшей записи. Гарантии автосохранения и обработка конфликта редакций — PBT-010; уровни миграций — предложения раздела 15.5 решений, вне этого ADR.

### ADR-6. Минимальный SDK (v0)

Публичный контракт `widget-sdk` первого цикла задач:

1. Регистрация типа виджета: id, название, иконка, компонент, ограничения размеров, стартовые настройки.
2. Контекст экземпляра: ссылка на выбранный документ, id вкладки и экземпляра.
3. Работа с документами: создание, открытие/выбор, подписка на изменения, операции модуля.
4. Настройки представления: чтение/запись состояния экземпляра.
5. События жизненного цикла: видимость, resize, сворачивание, закрытие.
6. Запрос дополнительного представления открытого документа.

Вне SDK v0 (осознанно): темы (базовые токены приложения), межвиджетное взаимодействие, внешние плагины. Расширения контракта — только новыми решениями.

### ADR-7. Пользовательские детали

- **Раскладки режимов:** отдельные раскладки тайлинга и каскада на каждую вкладку; возврат к режиму восстанавливает его прежнюю раскладку.
- **Скрытые/свёрнутые окна:** тяжёлая отрисовка приостанавливается, состояние представления сохраняется; экземпляр остаётся жив, документ остаётся общим.
- **Удаление вкладки:** удаляются вкладка и её экземпляры; документы не удаляются и остаются в каталоге.
- **Удаление документа:** отдельная операция каталога с подтверждением; открытые виджеты с этим документом переходят в состояние «документ отсутствует» с возможностью выбрать другой документ.

### ADR-8. Словарь сущностей

**Модуль** — подключаемый при сборке пакет с типами виджетов. **Тип виджета** — зарегистрированная разновидность содержимого в каталоге. **Экземпляр** — конкретное окно на вкладке со своими настройками и ссылкой на документ. **Документ** — сохраняемые данные, независимые от окон; один документ — много экземпляров. Платформа оперирует только этими понятиями; задачи, группы, ресурсы — внутренние сущности модуля Гантта.

## Сверка на сценариях проверки

1. **Два виджета одного чек-листа** (PBT-008, PBT-011): чек-лист — модуль с типом документа (ADR-8); два экземпляра одного документа через контекст SDK (ADR-6.2–6.3); общие изменения — подписка (ADR-6.3); независимые настройки — ADR-6.4; восстановление после перезапуска — ADR-5. Противоречий нет.
2. **Проектное и ресурсное представления одного плана** (PBT-037, PBT-047): оба — типы виджетов одного модуля Гантта; границы `gantt → widget-sdk` и запрет импортов `dashboard → gantt` (ADR-3) не нарушаются; второе представление — сценарий ADR-6.6. Противоречий нет.
3. **Смена тайлинг/каскад и возврат** (PBT-021–PBT-023): отдельные раскладки на вкладку (ADR-7) сохраняются в `widgetInstances`/`tabs` (ADR-5); пауза скрытых окон — ADR-6.5 + ADR-7. Противоречий нет.

## Последствия

- Стек, менеджер пакетов и границы зависимостей фиксируются в каркасе PBT-004 без повторного обсуждения.
- SDK v0 — основа задач PBT-006–PBT-011; нехватки контракта оформляются новыми решениями.
- Позиции `.context/project-decisions.md` переведены из «Предложено» в «Согласовано» со ссылкой на этот ADR; компоненты Гантта (SVAR, React Calendar Timeline, React Grid Layout, react-rnd) остаются кандидатами до PBT-014–PBT-017.

## Отклонённые альтернативы

| Вопрос | Отклонено | Причина |
| --- | --- | --- |
| Менеджер пакетов | pnpm workspaces | Требует сторонний инструмент; отклонено владельцем |
| Стек | SolidJS/Svelte/Vue | Переотбор всех кандидатов без выигрыша по требованиям |
| Браузеры | Только Chromium | Сужение аудитории без явной причины |
| Раскладки | Одна раскладка на оба режима | Потеря состояния при переключении |
| Скрытые окна | Размонтирование экземпляра | Потеря локального состояния представления |
| Удаление вкладки | Каскадное удаление документов | Опасная операция без явного запроса |
| Удаление документа | Блокировка при открытых виджетах | Менее предсказуемое поведение |

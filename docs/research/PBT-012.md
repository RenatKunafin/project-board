## Вопросы

1. Какой минимальный тестовый формат плана достаточен для прототипов PBT-014/015 и замеров PBT-016?
2. Как обеспечить воспроизводимость: фиксированный seed, идентичность прогонов, регресс на изменения?
3. Что войдёт в малый контрольный набор с выписанными ожиданиями?
4. Как зафиксировать сценарии измерений (состав, операции, окружение, повторы)?

## Формат данных (fixtures-only)

```text
FixturePlan { meta { title, calendar { workingDays, holidays } }, workTypes, resources,
  groups, tasks [{ id, title, groupId?, start, end (включительно, YYYY-MM-DD),
  assigneeIds, workTypeIds }], dependencies [{ fromTaskId, toTaskId, lagDays }],
  unavailability [{ id, resourceId, start, end }] }
```

Правила в данных соответствуют ADR PBT-003: включительное окончание, лаг ≥ 0, календарь пн–пт, типы работ с флагом параллельности. Формат минимален и помечен fixtures-only: продуктовый контракт определит ядро (PBT-030).

## Сценарии измерений (для PBT-016)

**Сценарий A — один план в нескольких представлениях:**
- Данные: `plan-500.json` (500 задач, ~25 групп, ~430 FS-связей).
- Состав: 6 проектных представлений + 4 ресурсных дорожки = 10 виджетов на одной вкладке.
- Измеряемые операции: первичный рендер; прокрутка таймлайна на 3 экрана; zoom ±2 шага; drag одной задачи; добавление задачи; пересчёт конфликтов после drag.

**Сценарий B — 10 независимых планов:**
- Данные: 10 планов по 50 задач (генерация `generatePlan({ seed: 42 + i, taskCount: 50 })`).
- Состав: 10 вкладок/окон, по одному проектному представлению.
- Измеряемые операции: открытие вкладки; переключение между вкладками; автосохранение после операции.

**Окружение:** Chromium последней стабильной (Playwright), macOS arm64, вкладка активна, DevTools закрыты, без троттлинга CPU/сети.

**Порядок повторов:** каждая операция — 5 прогонов после 1 разогревочного; фиксируются медиана и p95. Бюджеты времени отклика пока не установлены (открытый вопрос решений, раздел 20) — PBT-016 собирает фактические значения, пороги утвердит владелец.

## Наблюдения

- Конвертер эталона: 47 записей конвертируются; отпуска-задачи (16 шт. «ОТПУСК-*») включаются как обычные задачи — их преобразование в недоступности относится к импорту (PBT-054), fixtures-only конвертер их не интерпретирует.
- UTC-метки примера (`05:00:00Z`) соответствуют утру MSK — календарная дата при конвертации в Europe/Moscow совпадает с датой исходного инструмента.
- Dexie/DOM не участвуют: фикстуры чистые — генератор и адаптер работают и в Node (Vitest), и в браузере.

## Вывод

**Подходит.** Воспроизводимые входы для PBT-013–016 готовы: малый набор с ожиданиями (заготовка тестов арифметики), детерминированные 500 задач (регресс по golden), эталон рабочего примера с тестовым конвертером (не является полноценным импортом — PBT-052 напишет продуктовый), сценарии A/B зафиксированы.

## Актуальность на 2026-10-09

Основные наблюдения действуют (сверено с `packages/dashboard/src/document-service.ts` и текущим UI): синхронизация экземпляров, изоляция viewSettings, восстановление, автосохранение. Судьба ограничений:

- Доступ виджета к `title` документа — **закрыт в PBT-019** (дескриптор документной поддержки в определении типа виджета).
- Персистентность viewSettings — **в силе**, закрывается задачами PBT-024/025 (`viewSettings` по-прежнему `Map` в памяти, `document-service.ts`).
- Захардкоженная привязка экземпляров в bootstrap — **в силе** до PBT-024/025.
- Приостановка тяжёлой отрисовки скрытых виджетов — **в силе** (PBT-027).

## Вопросы

1. Достаточен ли текущий контракт SDK (регистрация + `DocumentService` + viewSettings) для двух экземпляров одного списка и отдельного второго списка?
2. Изолированы ли настройки представления по экземпляру?
3. Корректно ли восстановление после перезапуска (закрытие представления + перезагрузка)?
4. Какие ограничения вынести в задачи PBT-018+ / уточнения SDK?

## Окружение и запуск

- Node v22.12.0, npm 11.2.0, Chromium (Playwright 1.x).
- Запуск демо: `npm run dev` → `http://localhost:5173` (или `npm run build && npm run preview` → `:4173`).
- Автовоспроизведение сценария: `npm run test:browser` (6 e2e, `tests/e2e/shell.spec.ts`).

## Сценарий

1. Открыть приложение: панель «Экземпляр 1 · Список 1», «Экземпляр 2 · Список 1», «Экземпляр 3 · Список 2» (bootstrap гарантирует два документа).
2. Добавить пункт в экземпляре 1 → пункт появляется в экземпляре 2, отсутствует в экземпляре 3.
3. Добавить пункт в экземпляре 3 → изолирован от списка 1.
4. Отметить пункт выполненным в экземпляре 1, включить «Скрывать выполненные» → пункт скрыт в экземпляре 1, виден в экземпляре 2; редакция документа не меняется.
5. Закрыть экземпляр 1 (unmount + отписка), перезагрузить страницу → документ восстановлен, пункт на месте, панели снова открыты.
6. Индикатор сохранения: «Сохраняется…» → «Сохранено» после каждой операции.

## Наблюдения

- **Синхронизация**: подписки `DocumentService` доставляют новую редакцию обоим экземплярам сразу; операция в одном экземпляре не затрагивает другой документ. Подтверждено e2e («операция синхронизирует экземпляры 1–2 и не задевает список 2»).
- **Настройки представления изолированы**: `hideDone` живёт в `viewSettings[w-N]`; включение в экземпляре 1 не влияет на экземпляр 2; документ и подписчики не уведомляются. Подтверждено e2e и unit PBT-007.
- **Восстановление**: закрытие представления (unmount, отписка) не удаляет документ; после перезагрузки `restoreAll()` возвращает содержимое и редакцию, bootstrap досоздаёт недостающие документы (гарантия двух списков).
- **Автосохранение** прозрачно: модуль вызывает `update()`, запись в IndexedDB происходит через очередь сервиса; индикатор отражает состояние.

## Ограничения

- «Изменение размера» из карточки проверено как **локальная настройка отображения** (скрытие выполненных): реальных размеров окон ещё нет (PBT-020+). Не считать полной проверкой ресайза.
- Привязка экземпляров к документам захардкожена в bootstrap (w-1/w-2 → список 1, w-3 → список 2); выбор документа из UI — PBT-025.
- Настройки представления не персистятся (только в памяти сервиса) — перезагрузка сбрасывает `hideDone`. Персистентность настроек — вне первой версии (зафиксировать при PBT-024/025).
- Закрытие экземпляра не останавливает очередь автосохранения документа (она общая) — для первой версии корректно, уточнение жизненного цикла — PBT-027.
- Два «представления» здесь — два экземпляра одного типа виджета; проверка двух разных представлений одного документа (таблица/карточки) относится к Гантту (PBT-037/PBT-047).

## Вывод по SDK

**Подходит с ограничениями.** Контракт SDK v0 достаточен для ключевого сценария этапа 1: модуль работает только через публичный контракт (регистрация, `documentId`/`documentService`, viewSettings), платформа не знает о чек-листе. Выявленные уточнения для следующих задач:

1. Виджету нужен доступ к **title/метаданным документа** (панель показывает статичную подпись) — добавить `title` в `ManagedDocument`-контекст SDK или в контекст экземпляра (PBT-019).
2. **viewSettings не уведомляют** — для настроек, меняющих отображение из вне экземпляра, понадобится событие; сейчас не блокирует (настройку меняет сам экземпляр).
3. **Персистентность viewSettings** — решит PBT-024/025 (хранилище `widgetInstances` из схемы 15.2).

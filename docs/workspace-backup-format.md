# Формат резервной копии рабочего пространства

Файл PBT-064 — переносимый JSON-снимок всего локального пространства Project Board. Файл не зависит от версии IndexedDB. Приложение создаёт его по команде пользователя; при восстановлении текущее пространство полностью заменяется после отдельного подтверждения.

## Пример

Минимальный валидный пример находится в [`examples/workspace-backup-v1.json`](examples/workspace-backup-v1.json). Он разбирается тем же валидатором, что используется для загрузки файлов в интерфейсе.

## Поля версии 1

| Поле | Содержание |
| --- | --- |
| `format` | Маркер `project-board-workspace`. |
| `formatVersion` | Версия внешнего JSON-конверта; сейчас `1`. Не связана со схемой БД или схемой модулей. |
| `workspaceSchemaVersion` | Версия записей рабочего пространства в переносимом формате; сейчас `1`. |
| `createdAt` | Время снимка в ISO 8601 UTC. |
| `documents` | Все общие документы, в том числе те, которые не открыты ни в одном окне. Сохраняются ID, module/type, title, `schemaVersion`, revision, timestamps и непрозрачный `content`. |
| `workspace.tabs` | Вкладки, их порядок, название, режим `grid`/`cascade`, порядок окон каскада и активная вкладка. |
| `workspace.instances` | Открытые окна и ссылки на документы; геометрия сетки и каскада хранится независимо. |
| `viewSettings` | Независимые настройки живых окон, например фильтр, масштаб и видимая область. Ключи — ID окна. |

История локальных копий, служебное поколение пространства, кэш, подписки, черновики диалогов и незавершённые жесты не входят в файл. Общий документ сохраняется один раз вне зависимости от числа окон, которые на него ссылаются.

## Проверка и восстановление

До записи проверяются структура, JSON-совместимость значений, уникальность ID, ссылки окон на вкладки, ссылки cascade order на окна, геометрия и согласованность ссылок на документы. Неизвестное поле платформенной оболочки, повреждённая ссылка, циклический объект, `undefined`, `NaN`, accessor, разреженный массив и неизвестная/будущая версия внешнего формата приводят к отказу. Отдельные content-объекты модулей остаются непрозрачными для платформы.

Неизвестные типы окон и документы неизвестного модуля сохраняются без потери содержимого и показываются как предупреждение. Для известных типов существующая цепочка миграций применяется до атомарной записи; ошибка миграции отменяет всё восстановление. Будущий schemaVersion документа сохраняется как есть и после запуска остаётся защищённым от редактирования текущей версией приложения. Ссылка окна на отсутствующий документ допустима и показывается как предупреждение.

В интерфейсе **Настройки → Резервные копии** доступны ручное создание, скачивание, загрузка JSON, восстановление и удаление. Локальная история содержит не более пяти копий (обычных и созданных перед восстановлением). Автоматические копии не создаются. При подтверждении полной замены страховочная копия текущего пространства включена по умолчанию; её создание и восстановление происходят в одной транзакции.

Формат допускает только известные платформенные поля, поэтому будущая оболочка должна получить новую `formatVersion`, а не молча отбрасывать неизвестные поля. Будущие версии формата отклоняются без изменения данных.

## Хранение и обновление приложения

Локальные копии находятся в IndexedDB браузера и не синхронизируются. Скачайте файл, если нужна копия вне устройства. Очистка данных сайта/профиля браузера удаляет и документы, и локальную историю резервных копий.

PBT-064 повышает схему IndexedDB с v2 до v3. Проверка адаптера v2 показывает, что старая сборка может открыть прежние таблицы в такой БД и не удаляет таблицу backups, но сама не умеет показывать или восстанавливать новые копии. Для управления резервными копиями запустите версию приложения с поддержкой v3. JSON можно перенести в другую совместимую сборку.

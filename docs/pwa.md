# Установка Project Board и работа без сети

## Первый запуск

1. Откройте production-версию приложения с доступной сетью. Для опубликованной версии нужен HTTPS; локальная проверка работает на `http://localhost:4173` после `npm run build` и `npm run preview`.
2. Дождитесь надписи **«Готово к работе офлайн»** в верхней панели. Пока показано «Подготовка офлайн…», первоначальная загрузка ресурсов ещё не завершена.
3. Изменив документ, отдельно дождитесь **«Сохранено»**. Готовность офлайн-ресурсов и запись документов — разные состояния.

После этого приложение можно закрыть и открыть снова без сети. Доступны сохранённые вкладки, окна и документы, редактирование списков и создание новых. Новые изменения сохраняются локально и восстанавливаются после перезапуска.

Если показано **«Офлайн-режим недоступен»**, текущая онлайн-сессия продолжает работать. Восстановите доступ к сети и повторно откройте страницу, чтобы повторить подготовку. Первый запуск на новом устройстве или в новом профиле требует сети.

## Установка

- **Chrome на компьютере:** откройте приложение, выберите значок установки в адресной строке либо команду установки Project Board в меню браузера и подтвердите установку.
- **Edge на компьютере:** меню браузера → «Приложения» → установка этого сайта как приложения (названия команд зависят от версии браузера).
- **Safari на macOS:** при наличии соответствующей возможности используйте «Добавить в Dock»; поведение установки зависит от macOS и Safari.
- **Firefox:** работайте в обычной вкладке. Штатная установка отдельного приложения не входит в гарантию первой версии.

После установки запускайте Project Board через значок приложения. Оно открывается отдельным окном. Установка и обычная вкладка используют документы одного адреса и браузерного профиля. Проверяйте офлайн-готовность независимо от факта установки.

## Данные и обновления

Документы находятся в IndexedDB, ресурсы для запуска — в кэше браузера. Для работы без сети нужны оба хранилища. Очистка данных сайта может удалить документы и подготовленные ресурсы. Для переноса плана используйте собственный формат экспорта.

Другой профиль браузера или другой адрес приложения имеют собственные данные. Установка в другом браузере не переносит документы автоматически.

Когда новая версия полностью подготовлена, в верхней панели появляется «Доступна новая версия». Можно выбрать «Позже»: работа продолжится, а кнопка «Есть обновление» позволит вернуться к нему.

В модалке обновления показываются заметки именно подготовленной версии. Полный журнал прошлых выпусков доступен в настройках через пункт «Что нового» рядом с «Резервными копиями»; журнал входит в приложение и работает без сети.

Для применения оставьте **одно окно или вкладку Project Board**, включая установленное приложение. Выберите «Обновить», сохраните или отмените правки в открытых формах и подтвердите перезапуск. Приложение дождётся записи документов, вкладок, раскладок и настроек представлений, затем запустит новую версию. Пока идёт сохранение и обновление, ввод заблокирован. Неподтверждённый текст в формах не становится документом автоматически.

Если запись завершилась ошибкой или конфликтом, новая версия не применяется, сессия остаётся открытой. Проверьте состояние документов, устраните причину и нажмите «Повторить». Если сообщение просит закрыть другие окна, оставьте текущее и повторите обновление. Не открывайте дополнительные окна до завершения перезапуска. После активации обновления отменить перезапуск уже нельзя; сохранение перед активацией подтверждено.

**Первый переход с PBT-028:** уже загруженная старая версия ещё не умеет показывать кнопку обновления. Дождитесь «Сохранено», закройте все окна и вкладки Project Board и откройте приложение снова после подготовки новой версии браузером. Полная программная гарантия завершения записи перед обновлением действует начиная с клиента PBT-029. При закрытии всех окон браузер также может естественно активировать ожидающую версию без отдельной команды.

## Для разработки и проверки

`npm run dev` работает без Service Worker. Офлайн-сценарии проверяются на свежей production-сборке:

```bash
npm run build
npm run test:browser -- tests/e2e/pwa-offline.spec.ts --workers=1
```

Перед прогоном соблюдайте правила чистой среды из AGENTS.md: свободный порт 4173, отсутствие старого preview и параллельных live/dev-сессий. В тестах отдельные браузерные контексты и отключён обычный HTTP-кэш при повторном открытии: ресурсы должны обслуживаться Service Worker.

Для ручной проверки закройте все окна установленного приложения, отключите сеть и запустите его снова. Измените существующий список, создайте новый, дождитесь сохранения и повторите запуск. Отдельно проверьте имя, иконку и запуск в собственном окне.

При установленном Google Chrome можно воспроизвести проверку реальной установки через CDP:

```bash
npm run preview
# В другом терминале:
npm run verify:pwa-install
```

Проверка создаёт отдельный временный профиль, устанавливает приложение, выбирает открытие в отдельном окне, закрывает исходную страницу и запускает установленное приложение без сети. Подтверждает `display-mode: standalone`, сохраняет скриншот и JSON-отчёт в `test-results/screenshots/`, затем удаляет тестовую установку и временный профиль. Это проверка механизма Chrome; доступность и расположение команды в меню Chrome/Edge проверяются вручную.

Манифест и Service Worker формируются `vite-plugin-pwa@2.0.0`. Все файлы production-сборки, включая шрифты и иконки, включаются в precache. Файл больше 2 МиБ вызывает ошибку сборки и требует разбора размера. Системные возможности установки проверяются отдельно от обычного браузерного сценария.

Исходник иконки — `apps/project-board/pwa/icon.svg` (существующий знак LayoutDashboard из Lucide, лицензия рядом с производными иконками). Цвета берутся из `tokens.css`. После изменения знака или палитры выполните:

```bash
npx playwright install chromium
npm run generate:pwa-assets
```

Команда пересоздаёт PNG/SVG в `apps/project-board/public/icons/` и цвета манифеста в `apps/project-board/pwa/colors.json`. Эти файлы хранятся в git; обычная production-сборка не требует запуска браузера. Для иконок и манифеста нужны конкретные значения цветов, поэтому сгенерированные файлы содержат литералы, производные от единственного источника палитры `tokens.css`.

## Проверка обновления между двумя сборками

```bash
npm run test:pwa-updates
```

Команда собирает A и B, а также исходный PBT-028 из коммита `c3494ba`, запускает локальный сервер на 4184 и проверяет переход на одном адресе. Требуется история git с этим коммитом и установленный Chromium Playwright. Fixtures и сервер переключения версий не включаются в обычную production-сборку. Миграция проверяется отдельным тестовым документом, зарегистрированным через настоящий SDK; схемы рабочих планов и чек-листов не меняются ради проверки.

На статическом хостинге HTML, `sw.js` и манифест должны перепроверяться без длительного HTTP-кэша. Старые хешированные ресурсы сохраняйте на время перехода между публикациями. Настройка постоянного адреса и deployment относится к PBT-059.

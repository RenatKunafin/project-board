# Project Board — инструкции агента

PWA-дашборд: общие документы, вкладки, виджеты, сетка/каскад, чек-лист и Гантт. React18 + TypeScript + Vite, npm workspaces.

## Перед работой

Прочитай правила, если они ещё не загружены:

- [Процесс](.agents/rules/workflow.md) — scope, ревью, OpenSpec, git и статусы.
- [Код](.agents/rules/code.md) — архитектура, SDK, данные и стили.
- [Проверки](.agents/rules/testing.md) — production e2e, чистая среда, UI и артефакты.

При явном поручении скилла открой его SKILL.md; общие навыки проекта — [.agents/skills](.agents/skills). Не считай произвольную подпапку автоматически загруженной.

## Неизменные ограничения

- Одна задача PBT = один change = один PR в develop. Существенный дизайн одобряется до реализации, change архивируется после одобрения PR перед merge, Done — после merge. Уже полученное одобрение не запрашивается повторно.
- Платформа/SDK не импортируют предметные модули; IndexedDB доступна только адаптеру платформы.
- Общий документ и настройки отдельного окна разделены; закрытие окна не удаляет документ.
- Сохраняй ручную семантику планирования и offline-работу. Не ослабляй проверки/бюджеты ради зелёного результата.

## Источники и карта

- [README](README.md) — запуск, команды и карта репозитория.
- [Руководство виджета](docs/widget-development.md), [документы](docs/README.md), [ADR](docs/adr), [действующие specs](openspec/specs).
- apps/project-board — composition root; packages/dashboard — платформа; packages/widget-sdk — контракт; packages/gantt и checklist — модули; examples — учебный код вне продуктового каталога.
- Если есть локальная .context/: реестр .context/tasks/README.md содержит статусы/PR, карточки — scope/DoD, project-decisions.md — согласованные решения. Эти файлы не входят в git. В чистом checkout используй поручение/PR и openspec/changes; не создавай вымышленные статусы.
- История решений — ADR, архив OpenSpec и git/PR. В AGENTS и README нет журнала стадий.

Правила и скиллы редактируются в .agents. Конфиги инструментов подключают общий источник; личные разрешения, MCP и память пользователя сюда не переносятся. Изменения правил должны сохранять явно согласованные требования владельца.

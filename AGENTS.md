## Процесс (кратко; полная версия — `.context/openspec-workflow.md`)

- Единица работы: **одна задача PBT = один OpenSpec change = один PR**. Ветка `feature/pbt-xxx-slug` от `develop`.
- Имя change: `pbt-024-workspace-persistence` (lowercase kebab-case с ID задачи).
- Артефакты change: `proposal.md` (зачем/границы/Non-goals) → `design.md` (технические решения — здесь, не в требованиях) → `tasks.md` (шаги). Исследования и tooling без продуктового поведения — `skip_specs: true` в `.openspec.yaml`.
- Цикл: proposal + design на ревью владельца **до** кода → реализация строго в границах карточки → проверки → PR в `develop` → после одобрения владельца, заключительным коммитом **перед merge** — архивация change в ветке задачи с переносом delta specs в `openspec/specs/` (уточнение владельца 2026-10-14: не архивировать сразу после открытия PR).
- Валидация: `openspec validate <change> --strict` и `openspec validate --all --strict` (CLI 1.11.0; у `validate` нет флага `--no-interactive`, вопреки `openspec-setup.md`).
- Статусы: `Backlog → Ready → In progress → In review → Done`; статус и ссылка на PR меняются только в реестре.

## Разработка

- `npm run dev` — основное приложение, `http://localhost:5173`; selftest хранилища: `/#storage-selftest`.
- `npm run dev:load-demo` — нагрузочный стенд Гантта, `http://localhost:5176` (исследование PBT-016, сохраняется до PBT-058; не входит в прод-сборку).
- После установки новых зависимостей перезапускайте dev-сервер: устаревший кэш Vite даёт пустую страницу с `504 Outdated Optimize Dep` в консоли (лечится `rm -rf node_modules/.vite` + перезапуск).
- `npm run lint` · `npm run typecheck` · `npm test` · `npm run test:browser` (локально: `npx playwright install chromium`).
- **E2E гоняется на прод-сборке** (`npm run preview`): перед `test:browser` обязателен `npm run build` — иначе тесты проверяют устаревшую сборку (маскировало отсутствие данных в PBT-037).
- CI на каждый PR в `develop`: lint → typecheck → unit → build → `openspec validate --all --strict`.

## Правила работы агента

Единый процесс и стиль — обязательны для любой сессии. Прецеденты в скобках — конкретные случаи из истории проекта.

### Ориентация и планирование

- Вход в сессию: AGENTS.md → «Порядок погружения»; статус задачи — только из реестра, не из памяти предыдущих разговоров.
- Новая ветка — всегда от свежего `develop`: `git checkout develop && git pull` перед `git checkout -b feature/pbt-xxx-slug`.
- Задача `Ready` — только при закрытых зависимостях карточки; расхождение зависимостей с ADR/решениями — вопрос владельцу, а не самостоятельная переоценка (прецедент: снятие зависимости PBT-030 ← PBT-026).
- Коды PBT неизменяемы; новые работы получают следующие свободные номера (сейчас — после PBT-066).
- Спайки не становятся production-кодом без принятого решения. Решение PBT-017 принято: продуктовые адаптеры пишутся с нуля в `packages/gantt`; стенды `apps/gantt-spike` и `apps/resource-timeline-spike` удалены (ADR-6), `apps/load-demo` сохраняется до PBT-058.

### Цикл задачи (OpenSpec)

- Порядок неизменен: карточка → change (`proposal.md` → `design.md` → `tasks.md`, для продуктовых задач — delta specs) → `openspec validate <change> --strict` → ревью владельца **до кода** → реализация строго в границах карточки → проверки → PR в `develop` → архивация change с синком specs в ветке задачи — **заключительным этапом перед merge**, после одобрения PR владельцем (уточнение 2026-10-14).
- Исключение процесса — **делегированная серия PBT-038–049** (директива владельца 2026-10-14): change-артефакты владельцем не ревьюятся, реализация по одной задаче за другой в общей ветке `feature/pbt-038-049-gantt-editing`, каждый этап — полный набор проверок; в конце — один PR в `develop` с архивацией всех накопившихся changes и синком specs перед открытием PR. Попутные правки ядра вне границ карточки (прецедент: фикс `moveTask` в PBT-039) — заявлены в proposal «What Changes» и design.
- Начальные артефакты change не коммитятся до одобрения владельцем: до ревью живут в рабочем дереве (untracked), после одобрения — коммитятся в ветке задачи. Ветка `feature/pbt-xxx-slug` создаётся первым шагом работы над задачей, от свежего `develop` (прецедент: PBT-025).
- `skip_specs: true` в `.openspec.yaml` — только «Решение»/«Исследование»/tooling; продуктовое поведение всегда сопровождается delta spec.
- `Done` — только после merge; до этого — `In review` со ссылкой на PR.
- Вопросы владельцу — конкретной развилкой: варианты + рекомендация, а не открытое размышление.

### Реализация и стиль кода

- Строго в границах карточки. Попутные находки — явные дополнения в `design.md` (прецеденты: D7 PBT-030, D7–D8 PBT-021, D7 PBT-022) и описание в PR, не молчаливое расширение объёма.
- Иммутабельные структуры, чистые операции; доменные модули не знают об UI-библиотеках (границы ADR-3 проверяет ESLint).
- Новая библиотека: точный пин версии в `package.json` пакета, изоляция за адаптером платформы, минимальный локальный контракт типов без протекания в приложение (прецеденты: react-grid-layout 1.4.4, react-rnd 10.5.3).
- Стили — только токены `:root`; хекс-коды вне файла токенов запрещены (до PBT-066).
- Повреждённые/невалидные данные — результат с диагностикой, а не молчаливый fallback (прецедент: `parsePlanContent` против `parseChecklistContent`).
- Не выдавать «предложено» за «согласовано»: статус — по `project-decisions.md`; кандидаты и компромиссы — в `design.md`, не в требованиях.

### Тесты и проверки

- Полный набор перед PR: `lint` → `typecheck` → `test` → `test:browser` → `openspec validate --all --strict` (зеркало CI); результаты приложить к PR.
- Перед `test:browser` — чистая среда: `pkill -f "vite preview"` и проверка, что порт 4173 свободен (`lsof -nP -iTCP:4173`). Застрявший preview + `reuseExistingServer: true` = прогоны на устаревшей сборке или чужом процессе (разбор 2026-10-15: серия ложных красных SVAR-e2e). Не гонять e2e параллельно с активными dev-серверами/live-сессиями MCP; красный прогон — сначала повторить на чистой среде, потом искать корень.
- Доменные правила и целостность данных — автотестами в том же PR; новый UI-сценарий — e2e.
- Флаки-тест не ретраить вслепую: воспроизвести → найти корень (гонка статуса сохранения, кэш сборки, strict-mode локаторов) → надёжный фикс с комментарием-причиной (прецеденты: пауза автосохранения 1500 мс перед reload, клик по тексту вкладки вместо центра таба).

### Отладка (прецеденты Playwright MCP)

- Живая проверка UI — через Playwright MCP: реальные события мыши, чтение IndexedDB, **консоль браузера** — React-краши видны сразу (прецедент: селектор ручки react-rnd `'..widget-window__head'` ломал drag).
- Кэш браузера маскирует свежую сборку — контрольный query-параметр в URL.
- После установки новых зависимостей: перезапуск dev-сервера + `rm -rf node_modules/.vite` — иначе пустая страница с `504 Outdated Optimize Dep`.
- Ограничения выбранных компонентов Гантта (исключительная семантика дат SVAR, ненадёжный payload жестов, бета-линия RCT) — см. [ADR PBT-017](.docs/adr/PBT-017.md) и `.docs/research/PBT-014.md`/`PBT-015.md` перед задачами представлений (PBT-037+).
